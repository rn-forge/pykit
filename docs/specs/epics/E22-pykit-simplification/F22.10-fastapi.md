Keep asynchronous orchestration in FastAPI and use shared policy for identity
and HTTP decisions.

## Context

`idempotency.py:66-72` eagerly parses every body, even for safe methods, outside
normal validation. A Request-only endpoint can raise an unhandled
JSONDecodeError. Transfer spans response formats, parsing and five router
builders in 936 lines; auth routes/sessions/dependencies repeat neutral policy
and mix blocking work with async orchestration.

## S22.10.1 — Validate only where required

**State:** New

Bypass idempotency work for safe methods before reading/parsing their body.
Define the failure response for malformed unsafe JSON through the agreed
web/framework error contract.

**Acceptance:**

- GET with arbitrary bytes reaches its handler without idempotency parsing.
- Malformed unsafe JSON, absent key, mismatch, in-flight and successful replay
  have explicit response and handler-count assertions.
- Original response headers survive first execution and the documented replay
  contract remains unchanged.

## S22.10.2 — Keep route assembly thin

**State:** New

Consume F22.8 policy/codecs, and separate transfer parsing/serialization from
router assembly by responsibility. Preserve the existing public module imports.

**Acceptance:**

- Cookie/CSRF, inactive-account, tenant/scope and authorization-refresh cases
  pass through actual routes.
- Multipart/JSON imports, dry-run, batch atomicity, row errors and response
  headers retain integration coverage.
- Blocking provider/file/encoding work stays off the event loop where required;
  heartbeat tests use controlled coordination.
- Measured transfer memory/event-loop delay improves or stays within the target
  settled before refactoring.

## Acceptance

- S22.10.1: GET with arbitrary bytes reaches its handler without idempotency
  parsing.
- S22.10.2: Cookie/CSRF, inactive-account, tenant/scope and
  authorization-refresh cases pass through actual routes.
