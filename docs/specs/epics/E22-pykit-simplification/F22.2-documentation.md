Give package consumers a short entry path and one maintained explanation of each
contract.

## Context

The root README repeats detailed package inventories in its package table and
import-boundary list; the root landing page, choosing-packages guide and
workspace architecture also describe package relationships. The root scaffold
fixture still describes sibling requirements as git pins although E19/E21
changed them to ranges. The tooling README still recommends direct lint/import,
docs and test tool invocations instead of the required task surface. Audit drift
rather than treating every repeated package name as duplication.

## S22.2.1 — Reconcile current guidance

**State:** New

Map current setup, package selection, boundaries, auth setup and release
operations to one owning guide each. Keep concise summaries and links at entry
points. Compare examples against current facades and extras.

**Acceptance:**

- The root README package table is brief; package guides own API detail and
  workspace architecture owns graph explanation.
- Scaffold fixture documentation describes the actual range/override behavior
  and uses valid package-extra examples; tooling development commands use
  supported `task` verbs.
- A consumer can find install, minimum example, optional extras and error
  behavior from each package landing page.

## S22.2.2 — Trim prose at the source

**State:** New

Audit touched public docstrings and comments against README conventions. Keep
contracts and non-obvious constraints; move useful composition guidance into
package guides. Eliminate stale spec/consumer history without creating duplicate
reference pages.

**Acceptance:**

- Docstrings changed by this epic contain contracts and generic examples;
  comments explain constraints rather than narrating statements.
- Package README links remain absolute and package guide links stay within their
  standalone site.
- The combined and ten standalone sites pass `task docs:build`.

## Acceptance

- S22.2.1: The root README package table is brief; package guides own API detail
  and workspace architecture owns graph explanation.
- S22.2.2: Docstrings changed by this epic contain contracts and generic
  examples; comments explain constraints rather than narrating statements.
