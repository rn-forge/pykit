Preserve legitimate values and remove avoidable row materialization.

## Context

`pandas.py` string extraction uses a truthiness fallback after missing-value
handling, which drops numeric zero and False. `excel.py:393-396` materializes
all dataset rows even though the workbook is write-only. The API still returns
workbook bytes, so removing that list alone does not make the entire operation
streaming.

## S22.12.1 — Preserve non-missing false values

**State:** New

Separate absence from truthiness in string conversion. Keep pandas-native
missing-value rules and required-field errors.

**Acceptance:**

- Zero, False, empty string, None, NaN and pandas missing sentinels follow the
  documented distinct conversion behavior.
- Optional pandas remains outside base imports and existing valid
  string/number/date cases remain covered.

## S22.12.2 — Remove redundant row buffering

**State:** New · **Depends on:** S22.3.2

Iterate the dataset directly where its contract permits. Review repeated
frame/workbook conversion only where measurements show extra copies; keep
output-format behavior.

**Acceptance:**

- Large export shows a peak-memory comparison and no redundant complete row list
  in the write-only path.
- Round-trip tests preserve headers, values, sheet name, number formats and
  unknown-column errors.
- Documentation states the remaining in-memory dataset/output-bytes bounds and
  does not promise end-to-end streaming.

## Acceptance

- S22.12.1: Zero, False, empty string, None, NaN and pandas missing sentinels
  follow the documented distinct conversion behavior.
- S22.12.2: Large export shows a peak-memory comparison and no redundant
  complete row list in the write-only path.
