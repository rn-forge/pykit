Keep release preparation, mutation and recovery readable and independently
testable.

## Context

`install/lifecycle.py` mixes download preparation and filesystem transaction
work; `_activate` executes undo callbacks in a loop (`:268-278`) where one undo
exception stops remaining recovery and masks the initiating failure. The install
contract currently promises that everything is undone. The `finally` block then
removes the work directory, which may still contain the displaced working
version after a failed force-reinstall recovery. CLI lifecycle also duplicates
verb declarations in `VERBS` and `_COMMANDS`.

## S22.6.1 — Exercise recovery failures

**State:** New · **Depends on:** S22.6.3

Implement the recovery contract S22.6.3 settled, with temporary homes and
controlled injected failures, including a failure in an undo step.

**Acceptance:**

- A failed undo does not prevent independent remaining recovery attempts;
  reports retain the initiating failure and incomplete recovery details.
- Tests inspect links, current version, state and prior files after failures at
  each mutation boundary and during interruption.
- No success/fully-rolled-back message is emitted while recovery remains
  incomplete; displaced installs and needed recovery material survive failed
  restoration.

## S22.6.2 — Separate prepare from mutation

**State:** New · **Depends on:** S22.6.1

Extract focused release-preparation and activation/recovery functions only where
it removes shared mutable state or repeated work. Keep CLI orchestration thin.

**Acceptance:**

- Checksums and release validation complete before activation, and failed
  preparation leaves the prior installation usable.
- Install/upgrade/uninstall and interruption scenarios preserve locking,
  ownership and transactional behavior; advertised verbs derive from the
  registry and malformed lifecycle tables receive diagnosed errors.
- Repeated release reads/hashes are measured before caching; no speculative
  installer protocol or product package is introduced.

## S22.6.3 — Decide the recovery contract

**State:** New

The install contract promises that everything is undone. Reproduce an undo step
that fails and a forced reinstall whose restoration fails, then decide what is
recoverable, what survives a failed restoration and how the initiating and
recovery failures are both reported.

**Acceptance:**

- Failing tests reproduce the stopped recovery loop and the removed work
  directory.
- The install contract states what recovery guarantees, what is reported when it
  is incomplete, and what material survives a failed restoration.

## Acceptance

- S22.6.1: A failed undo does not prevent independent remaining recovery
  attempts; reports retain the initiating failure and incomplete recovery
  details.
- S22.6.2: Checksums and release validation complete before activation, and
  failed preparation leaves the prior installation usable.
- S22.6.3: The install contract states what recovery guarantees and reports.
