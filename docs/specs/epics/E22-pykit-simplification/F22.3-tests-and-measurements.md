Protect the behavior being simplified and measure expensive work before changing
it.

## Context

The suite is mostly named by behavior already: only nine test names carry
story-like IDs, all in commons block tests. Root `built_wheels` builds all ten
packages once per scaffold session; scaffold environments resolve third-party
requirements from the index. SQLAlchemy upsert tests write 33,000 rows. Commons
task tests directly call `_start`, renaming the pytest main thread, and inject
an impossible orphan into private pool state. These are concrete test-coupling
cases; setup/large-input work remains a measurement target.

## S22.3.1 — Keep contract tests independent of source layout

**State:** New

Inventory private patches, source-inspection assertions, duplicate test builders
and time-sensitive assertions only in areas this epic changes. Rename the nine
block tests by behavior. Preserve architecture checks that intentionally inspect
imports or examples.

**Acceptance:**

- Every removed implementation assertion has equivalent public-behavior coverage
  or a documented reason it was only an architecture check.
- Collected behavioral cases are preserved, including parameter variants,
  negative/security cases and optional-extra installs.
- Task execution tests use submit/futures/shutdown and preserve the test runner
  thread name; timing tests use synchronization or controllable clocks where
  possible, without blanket deletion of sleeps or AST checks.

## S22.3.2 — Measure representative work

**State:** New

Measure cold/warm CLI invocation and imports, disabled/enabled logging, sync
readiness with slow checks, large Excel/transfer operations, auth key refresh,
SQLAlchemy upsert, scaffold setup and strict docs builds. Use deterministic
small correctness cases and separately marked larger measurements.

**Acceptance:**

- A reproducible task-based procedure records environment, input sizes, wall
  time, peak memory and relevant query/request/build counts, including
  baseline commit.
- Distinguish CPU, I/O, buffering and tool startup; no external provider or
  production credentials are required.
- A package records a baseline before optimization and a comparison afterward;
  noisy wall-time thresholds do not become unit tests.

## S22.3.3 — Reduce repeated test setup where measured

**State:** New · **Depends on:** S22.3.2

Reuse immutable wheel outputs within a run and request only the build closure
needed if measurements justify it; keep clean virtual environments for install
tests. Keep a real large-input SQL regression even if routine fixtures become
smaller.

**Acceptance:**

- Scaffold cases still install built distributions outside workspace imports and
  verify relevant extras.
- A build/setup reduction shows fewer operations and an equivalent behavior-case
  matrix; third-party resolution is not falsely called offline.
- Do not modify generated Taskfiles or add dependencies to obtain a faster test
  command.
