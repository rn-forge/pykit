## Context

The specs occupy 104 Markdown files and 116,546 whitespace-delimited words. The
largest pages include auth design (12,000), Sonar remediation (10,292) and kiln
cutover (9,025). Volume alone does not prove redundancy: active cutover
acceptance and deferred entry criteria must survive.

## S22.1.1 — Decide the retention boundary

**State:** New

Inventory each epic by state and classify prose as future design, durable
decision, current usage, acceptance or historical evidence. Record a focused ADR
only if the existing retention/routing rules need to change.

**Acceptance:**

- Every spec page has a disposition; unfinished acceptance, dependencies, IDs
  and deferred entry criteria remain discoverable.
- No current behavior moves into replacement specs; architecture and guides own
  it.

## S22.1.2 — Cut settled briefs and repair references

**State:** New

Apply that disposition in small epic-sized edits. Retain closed feature records
and useful acceptance; replace duplicated settled explanations with links to
their current owner. Remove stale other-repository milestones from current
acceptance without changing historical outcomes.

**Acceptance:**

- Existing permanent IDs, links and anchors resolve or retain explicit
  replacement anchors.
- Active E16/E21 acceptance and deferred features retain their scope and state;
  no feature closes through editing prose.
- Before/after word counts and an itemized disposition show what was removed or
  relocated.
- `task docs:generate` is idempotent and `task docs:build` passes.

## Acceptance
