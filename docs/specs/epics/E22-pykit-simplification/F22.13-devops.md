Keep the release helper small, with a clear metadata parser and focused contract
coverage.

## Context

The package is four modules and 268 lines after CI planning moved away.
`requirements.py` parses member dependency declarations; current tests cover a
narrow path compared with versions, extras, URLs and groups. This is primarily a
coverage/readability opportunity, not evidence for a replacement graph or a new
release framework.

## S22.13.1 — Pin requirement-check behavior

**State:** New

Build tiny temporary workspaces that exercise the requirement forms the checker
supports. Specify handling of missing members, exclusions, malformed
requirements and unresolved direct references.

**Acceptance:**

- Ranges, canonicalized names, extras, direct URLs, optional dependencies and
  dependency groups are either checked correctly or explicitly outside the
  documented contract.
- CLI exit codes and diagnostic paths distinguish invalid requirements from
  incompatible internal floors.
- Release-note tests cover package changelog selection, missing sections and
  stable output.

## S22.13.2 — Simplify only demonstrated duplication

**State:** New

Use one manifest-to-requirements path within devops and remove obsolete planner
prose/imports if found. Compare repeated reads on a synthetic workspace before
adding caches.

**Acceptance:**

- The package remains independent of runtime packages, and no duplicate CI
  planner is restored.
- Supported CLI commands and generated note text remain stable under focused
  tests.
- No dependency addition, broad module split or runtime performance claim is
  required to close this feature.

## Acceptance

- S22.13.1: Ranges, canonicalized names, extras, direct URLs, optional
  dependencies and dependency groups are either checked correctly or
  explicitly outside the documented contract.
- S22.13.2: The package remains independent of runtime packages, and no
  duplicate CI planner is restored.
