Give shared identity and persisted-record policy one owner and bound cache
retention without weakening invalidation.

## Context

`context_cache.py:128-146` never removes entries for accounts no longer
requested: TTL only limits reuse. In-memory stores rebuild dictionaries during
common operations. OIDC verification/provider/logout code shares a 1,538-line
module. The two framework adapters repeat bearer account projection and record
mapping.

## S22.8.1 — Bound authorization-context retention

**State:** New · **Depends on:** S22.8.4

Implement the bound S22.8.4 chose. Keep version invalidation independent of
entry eviction; do not reset versions in a way that can make stale contexts
current.

**Acceptance:**

- Injected-clock churn over many distinct accounts has a documented finite
  retention bound.
- Account/global invalidation, inactive-account rejection and a version bump
  racing provider resolution retain security behavior.
- Lock hold time and peak memory are compared to baseline; single-flight is
  added only if measured and separately justified.

## S22.8.2 — Own shared identity and record policy

**State:** New

Extract only pure account-to-principal projection and common
SessionInfo/LoginTransaction mapping. Consider the repeated login rate-window
arithmetic in the same ownership pass. Keep cookies, CSRF, backend atomic
counters, JSON and network scheduling in adapters.

**Acceptance:**

- Django and FastAPI share tested inactive/unlinked account, scope-limit, tenant
  and external-identity rules.
- Old persisted session/transaction shapes decode identically; new encoding
  round-trips optional AMR/auth-time/token fields without exposing secrets.
- Backend adapters retain expiry/atomicity behavior; no universal session
  backend abstraction is added.

## S22.8.3 — Separate OIDC responsibilities conservatively

**State:** New

Group discovery/JWKS, token profiles, provider exchange and back-channel logout
behind the supported `rn_forge.auth.oidc` surface. Prefer focused internal
modules and explicit composition over a generic token-verifier hierarchy.

**Acceptance:**

- The oidc extra stays optional; base imports do not load its dependencies.
- Issuer/audience/algorithm/type/nonce/replay/expiry and key-rotation cases
  remain covered for each token profile; test helpers stay off the production
  import path.
- JWKS refresh request counts and latency are measured; cache changes preserve
  rotation and unknown-key denial.
- The key-set lifespan test advances a clock the verifier accepts, rather than
  patching PyJWT's internal `jwk_set_cache` module.
- Large in-memory store sweeps are optimized only after measured growth shows a
  benefit.

## S22.8.4 — Decide the retention bound

**State:** New · **Depends on:** S22.3.2

Measure account churn with an injected clock, then choose a small bounded
retention or expiry mechanism that keeps version invalidation independent of
eviction.

**Acceptance:**

- The decision records the bound, the mechanism and the rejected options.
- A baseline records churn, lock hold time and peak memory before the change.

## Acceptance

- S22.8.1: Injected-clock churn over many distinct accounts has a documented
  finite retention bound.
- S22.8.2: Django and FastAPI share tested inactive/unlinked account,
  scope-limit, tenant and external-identity rules.
- S22.8.3: The oidc extra stays optional; base imports do not load its
  dependencies.
- S22.8.4: The decision records the retention bound, mechanism and baseline.
