112,562 whitespace-delimited words, unchanged from the brief's `a97e165`
baseline. No proposed disposition has been applied.

Whole-file counts use `wc -w`; an isolated `python3 -I` counter counts each
literal `## ` section through the next such line. Each section takes its
majority class without splitting. Preamble titles and tables count as
Acceptance; remaining preamble prose takes its content class. Derived fences,
markers and contents count only as Derived, even where a fence contains
headings.

Design means future design; Decision means a durable choice not already recorded
in an ADR; Usage means current usage; Acceptance means acceptance, work-item
scope or metadata; Evidence means historical evidence. An obsolete
implementation plan is Evidence, even when its heading is Design.

Every trim or move preserves titles, metadata, story headings, State lines,
acceptance, Predecessors, Entry criteria, Considered and rejected and Open
questions; evidence shrinks only to a one-line outcome. Current-usage
explanations become links to their existing owners. A move adds no page. New and
unfinished work is preserved, with no closure, ID, filename, heading or state
changes. The two deferred epics are keep without elaboration. Record leaves the
named historical record intact. Owner paths are repository-relative; Page paths
in the in-scope tables are relative to `docs/specs/epics/`.

## ADR recommendation and owner findings

Recommend no new ADR. This proposal retains all 100 pages, including closed
feature files and legacy epic row tables. No page needs deletion.
`docs/specs/_structure.md` requires that a feature file stays when closed, that
closed work is never deleted, and that legacy closed epics keep their feature
rows; it does not require retaining all settled prose. `docs/_structure.md`
routes existing behaviour to architecture or package docs and history/evidence
to the commit message, and identifies design prose collecting in top-level pages
as a problem. Trimming explanations to current-owner links and historical
outcomes applies those rules. Acceptance and unique decisions remain.

The review of ADR-0001 through ADR-0016 found no requirement to freeze closed
spec prose. ADR-0007 adopts the shared documentation standard; ADR-0008
preserves repository-local acceptance. ADR-0015 specifically keeps the auth
threat model and auth security tests in E13, so E13's move proposal preserves
that material there while linking shipped contracts to the auth guides. ADR-0001
and ADR-0002 continue to govern design and package boundaries. The rendered
standard `.rn-forge/kiln/standard.md` assigns generated rules to kiln. No rule
change is proposed; a future change to either generated routing file or the
standard would require an upstream kiln request, with an ADR only if retention
or routing policy changes. The owner decides this recommendation and each
disposition before S22.1.2 applies them.
