## Current behaviour

All in `packages/rn-forge-web/src/rn_forge/web/health.py`.

- `run_checks_sync` (`:205`) opens
  `with ThreadPoolExecutor(max_workers=len(names) or 1)` (`:230`), submits
  every check, then loops `futures[name].result(timeout=timeout)` (`:234`) in
  name order. Each wait gets a fresh `timeout`, so the deadline is relative
  and serial: N slow checks can take up to N x timeout.
- On `TimeoutError` it records
  `CheckResult(status="fail", reason="timed out after Ns")` (`:236-238`), but
  leaving the `with` block calls `shutdown(wait=True)`, so the call still
  blocks until every stuck check returns. The timeout bounds nothing on the
  response path.
- A fresh pool per call; nothing is reused or capped across calls.
- The async path differs: `_run_one` (`:132`) uses `asyncio.to_thread`, and
  `_run_bounded` (`:150`) wraps it in `asyncio.timeout`. It returns on time
  but the thread keeps running in the loop's default executor.
- Callers: Django `readiness_view` calls it at
  `packages/rn-forge-django/src/rn_forge/django/views.py:186` (default 2.0 s).

Existing tests: `packages/rn-forge-web/tests/test_health.py`,
`test_a_hung_sync_check_times_out_without_blocking_the_run` (`:244`, uses
`run_checks`, the async path) and `test_the_sync_runner_refuses_an_async_check`
(`:108`). No test exercises `run_checks_sync` with a blocked check. Django:
`packages/rn-forge-django/tests/test_views.py` `_ready` helper (`:54`).

## Tests first

Use `threading.Event` to block checks; release them in `finally` or a fixture so
no worker outlives the test. Run the call in a helper thread and measure elapsed
time with `time.monotonic()`; assert with generous margins, never tight timings.

1. `test_run_checks_sync_waits_for_a_blocked_check_after_timeout` (strict xfail,
   reason names S22.7.1): one check blocked on an event, `timeout=0.05`;
   assert the call returns before the event is released. Fails today (it
   blocks).
1. `test_run_checks_sync_gives_each_check_a_serial_deadline` (strict xfail, same
   reason): three checks that each sleep on an event; assert total wall time
   is near one `timeout`, not three. Fails today.
1. `test_run_checks_sync_reports_timeout_as_failed_check` (passing): a check
   released after the call is observed through a side thread; records the
   `fail` / `timed out after` reason and 503 for a required check.
1. `test_run_checks_sync_creates_a_pool_per_call` (passing): count live threads
   (`threading.active_count()`) after repeated timed-out calls with checks
   released late; records that stuck workers accumulate without a cap.
1. `test_run_checks_async_leaves_the_worker_running_after_timeout` (passing):
   the async path returns on time while the thread stays alive until released.
