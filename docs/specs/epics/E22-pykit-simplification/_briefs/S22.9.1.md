# S22.9.1 — Claim before execution

Brief for [S22.9.1](../F22.9-django.md#s2291-claim-before-execution), at
`1a8da87`.

## Goal

`CacheIdempotencyStore.record_or_replay` must return `None` (execute) only after
its own `cache.add` succeeds. Today it also returns `None` when the entry it
lost the claim to has vanished, so two callers can both execute.

## Settled

- Settled by the reviewer, 2026-11-14: retry the claim up to 3 attempts when the
  observed entry is gone, then raise `IdempotencyKeyInFlight` (409); a bounded
  loop cannot spin on a cache that keeps losing entries, and 409 is the safe
  "do not execute" outcome.
- Owner scope (E22 `index.md`, Scope constraints): no lease or execution-timeout
  contract; a claim that expires while its handler still runs stays unsolved.
- Public signatures, `cache_key` format, in-flight (409), mismatch (422) and
  replay outcomes are unchanged.

## Current behaviour

`packages/rn-forge-django/src/rn_forge/django/drf/idempotency.py`:

- `record_or_replay` (48-74):
  `cache.add(slot, {"hash", "response": None}, timeout)` at line 54 returns
  `None` on success. On failure line 56 does `cache.get(slot)`; line 57-58
  returns `None` when that is `None` ("expired between add and get") without
  owning the slot. The caller then runs the handler and `complete` writes the
  slot, so a second caller that claimed in the gap also executes.
- Lines 59-74 raise reuse (hash differs), raise in-flight (`response is None`)
  or return the replay.
- `complete` (76-87) and the `idempotent` decorator (90-154) are not at fault.

Tests: `packages/rn-forge-django/tests/drf/test_idempotency.py`, class
`TestCacheIdempotencyStore` (lines 29-96) patches
`rn_forge.django.drf.idempotency.caches` with a `MagicMock` in
`test_claim_is_cache_add_with_timeout_and_alias`; reuse that patch style.

## Change

- **Change:** `drf/idempotency.py`, `record_or_replay` only: wrap add/get in a
  bounded `for` loop. A successful add returns `None`. A `None` from `get`
  continues the loop (retry the add). Any other entry follows the existing
  hash/in-flight/replay branches. After the last attempt raise
  `IdempotencyKeyInFlight` with the existing message. Keep the docstring a
  contract (no history). Add a `# ` comment only for the non-obvious why (a
  `None` from `get` means the add must be retried, never executed).
- **Change:** `packages/rn-forge-django/CHANGELOG.md`, `## [Unreleased]`, a
  `### Fixed` entry (a competing request could execute after claim expiry).
- **Leave alone:** `complete`, `cache_key`, the `idempotent` decorator, and
  `rn_forge.web` (the store protocol and `run_idempotent`).

## Tests first

Add to `TestCacheIdempotencyStore` in `tests/drf/test_idempotency.py`. Force the
interleaving with a small dict-backed fake cache (a local class with `add` using
`setdefault` semantics and `get`), patched in via
`patch("rn_forge.django.drf.idempotency.caches", {"default": fake})`.

1. `test_a_vanished_entry_is_reclaimed_before_executing`: a `MagicMock` cache
   with `add.side_effect=[False, True]` and `get.return_value=None`. Assert
   the result is `None` and `add.call_count == 2`. Before:
   `add.call_count == 1` (fails).
1. `test_competing_callers_never_both_execute`: the fake cache is seeded with
   the slot (so caller A's first `add` fails). Its `get` runs once as a hook:
   it deletes the slot (the expiry), then calls `store.record_or_replay(...)`
   as caller B (B's `add` succeeds, B gets `None`), then returns `None` to A.
   Assert B's result is `None`, and that A raises `IdempotencyKeyInFlight` (A
   retries, sees B's claim, `response is None`). Count the `None` results:
   exactly one. Before: A also returns `None` (fails).
1. `test_a_cache_that_keeps_losing_entries_is_in_flight`: `add` always `False`,
   `get` always `None`. Assert `IdempotencyKeyInFlight` and
   `add.call_count == 3`. Before: returns `None` (fails).

Existing replay, scope, TTL (`test_complete_honours_timeout`), reuse and
in-flight tests must pass unchanged.
