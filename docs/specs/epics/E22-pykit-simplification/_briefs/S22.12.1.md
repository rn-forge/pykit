# S22.12.1 — Preserve non-missing false values

Brief for
[S22.12.1](../F22.12-data.md#s22121-preserve-non-missing-false-values), at
`1a8da87`.

## Goal

`PandasUtils.get_string_field` turns a present zero or False into `""` because
of a truthiness fallback. Make absence, not truthiness, decide, and document the
conversion table.

## Settled

- Settled by the reviewer, 2026-11-14: a value that pandas does not treat as
  missing is converted with `str(value).strip()`, so `0`, `0.0` and `False`
  give `"0"`, `"0.0"`, `"False"`; the old output `""` is a bug, not a
  contract.
- Settled by the reviewer, 2026-11-14: a missing value (`None`, `float("nan")`,
  `pandas.NA`, `pandas.NaT`) gives `""` when `required=False` and raises
  `AppException("Field is required: <name>")` when `required=True`; unchanged,
  decided by `PandasUtils.is_na` in `get_field`.
- Settled by the reviewer, 2026-11-14: empty string `""` is not missing: it
  returns `""` even when `required=True`; unchanged. Whitespace-only is
  stripped to `""` and is likewise not an error.
- Settled by the owner, 2026-11-14: `get_decimal_field` keeps `""`/missing ->
  `Decimal(0)` and numeric `0` -> `Decimal("0.00")`; a `False` cell now raises
  (`Decimal("False")` is invalid) where it previously gave 0. Reason: a
  boolean is not a number.
- Optional pandas stays out of base imports; this is a behavior change for
  `False`/zero in `get_string_field`, so it needs a changelog entry and a
  versioning note (E22 `index.md` scope constraints).

## Current behaviour

`packages/rn-forge-data/src/rn_forge/data/pandas.py`:

- `get_field` (`:61-107`) returns `None` when `is_na`, else the raw value;
  raises when required and missing.
- `get_string_field` (`:110-127`): `str(field_value or "").strip()` at `:120`.
  `0`, `0.0`, `False` are falsy, so they become `""`.
- `get_decimal_field` (`:130-162`) calls `get_string_field` (`:145`), then
  `Decimal(str(field_value or 0))` (`:147`).
- Existing tests: `packages/rn-forge-data/tests/test_pandas.py`
  (`TestGetStringField` `:74`, `TestGetDecimalField` `:98`); helper
  `_row(**kwargs)` at `:21`. No test pins zero or False through
  `get_string_field`.

## Change

- **Change:** `pandas.py`: in `get_string_field`, `field_value` is `None` only
  when missing, so use
  `"" if field_value is None else str(field_value).strip()`. Keep
  `get_decimal_field` working per Settled. Rewrite the `get_string_field`
  docstring to give the table (value -> optional result / required result).
  Add the same table to `packages/rn-forge-data/docs/guides/usage.md` near
  `:66`. Add a `### Fixed` entry under `[Unreleased]` in
  `packages/rn-forge-data/CHANGELOG.md` naming the zero/False change.
- **Leave alone:** `get_field`, `is_na`, `excel.py`, base (non-pandas) imports,
  the `pandas` extra.
