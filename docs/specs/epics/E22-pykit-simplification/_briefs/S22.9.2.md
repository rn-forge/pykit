# S22.9.2 — Use unambiguous values

Brief for [S22.9.2](../F22.9-django.md#s2292-use-unambiguous-values), at
`1a8da87`.

## Goal

Page-size parsing must never raise on malformed input, and `ModelLookupCache`
composite keys must not collide when a value contains the separator.

## Settled

- Settled by the reviewer, 2026-11-14: invalid page size policy: clamp, never
  reject, as `_page_size`'s docstring and the FastAPI `page_params` already
  say (AIP-158). The raw value counts only if it fully matches ASCII
  `-?[0-9]+`. Anything else (`--1`, `²`, `٣`, `+5`, ` 5`, `5.0`, `1e3`, empty)
  is unspecified and yields the default. A negative or zero value yields the
  default, as `clamp_page_size` already does. A positive value of any length
  yields the cap (a value of more than 18 digits is the cap without converting
  it). Reason: keeps the documented contract; a 400 would change wire
  behaviour.
- Settled by the reviewer, 2026-11-14: structural cache key: a `tuple[str, ...]`
  of `str(v)` for each key value, replacing the `"."`-joined string
  (`("a.b","c") != ("a","b.c")`). Scalar normalization stays `str()`, so an
  int field still matches a lookup by `"7"` or `7`'s string form. Stored keys
  do not change: the dict is a private in-process attribute (`__cache`), never
  persisted or exposed, so there is nothing to migrate.
- `rn_forge.web.clamp_page_size` is unchanged and shared; the parse fix stays in
  the Django adapter.

## Current behaviour

- `packages/rn-forge-django/src/rn_forge/django/drf/pagination.py:37-48`
  `_page_size`: line 43
  `int(raw) if raw is not None and raw.lstrip("-").isdigit() else None`.
  `"--1"` and `"²"` pass `isdigit`, then `int` raises `ValueError`; so does an
  ASCII string over 4300 digits (Python's int-string limit). Both
  `CursorPagination.get_page_size` (180-183) and
  `LegacyPageNumberPagination.get_page_size` (298-302) call it.
- `packages/rn-forge-django/src/rn_forge/django/models/cache.py:44-71`
  `load`/`get`/`set` build keys with `AppUtils.join_string(".", ...)` (lines
  49, 60, 70), so `("a.b","c")` and `("a","b.c")` both become `"a.b.c"`; the
  later `set` overwrites the earlier. `join_string` also unpacks a lone
  sequence value.

Tests: `tests/drf/test_pagination.py`, class `TestPageSize` (lines 78-118);
`tests/test_models.py`, `TestModelLookupCacheWithoutDb` (191-270) and
`TestModelLookupCacheWithDb` (401-).

## Change

- **Change:** `drf/pagination.py`: replace line 43 with an ASCII-only parse per
  the policy (a module-level compiled `re.ASCII` pattern or an explicit
  `str.isascii() and isdigit()` check). Keep the `_page_size` signature.
- **Change:** `models/cache.py`: add a private
  `_lookup_key(values) -> tuple[str, ...]`; type the inner dicts
  `dict[tuple[str, ...], object]`; use it in `load` (wrap a single
  `attrgetter` result in a tuple), `get` and `set`. Drop the `AppUtils` import
  if unused.
- **Change:** `packages/rn-forge-django/CHANGELOG.md`, `## [Unreleased]`:
  `### Fixed` for malformed `pageSize` (was a server error) and for composite
  lookup collisions.
- **Leave alone:** `rn_forge.web.clamp_page_size`, `AppUtils.join_string`, the
  FastAPI and SQLAlchemy pagination, and the `ModelLookupCache` public API.
