# S22.4.1 — Protect logging composition

Brief for [S22.4.1](../F22.4-commons.md#s2241-protect-logging-composition),
written at the S22.4.5 close.

## Goal

Implement [ADR-0016](../../../../adr/ADR-0016.md): `AppLogger` brace-formats its
own records over whatever record factory is installed, and nothing replaces the
process factory. Also make every `AppLogger` level method report the
application's call site, not its own wrapper.

## Settled

- ADR-0016 (owner, 2026-11-14), in full:
    - `AppLogger.makeRecord` builds each record through the installed factory,
      then gives that one record `BraceLogRecord`'s message rule (`%` when the
      message contains `%`, else `str.format`, with the same dict-argument and
      format-error fallback).
    - Neither `get_logger` nor `initialize` calls `logging.setLogRecordFactory`.
    - `get_logger` still registers `AppLogger` as the logger class.
    - `BraceLogRecord` stays public and unchanged in behaviour.
- A record that is already a `BraceLogRecord` needs no change.
- Curated facades and standalone installs stay (E22 scope). This is an
  intentional behaviour change, so it needs a regression test and a changelog
  entry.
- Measurements follow F22.3's contract: pytest cases under
  `packages/rn-forge-commons/tests/measure/`, skipped unless
  `PYKIT_MEASURE_OUT` is set, recorded through the package's `measure`
  fixture.

## Current behaviour

All in `packages/rn-forge-commons/src/rn_forge/commons/logging/logger.py` unless
noted. Observed by the reviewer in this tree.

- `BraceLogRecord.getMessage` (`:94-114`) holds the message rule.

- `_register_levels_and_class` (`:957-966`) calls
  `logging.setLogRecordFactory(BraceLogRecord)` whenever the factory differs.
  `get_logger` (`:562-575`) and `initialize` (`:517`) both call it.

- With the stdlib factory restored, `log.warning("plain factory {}", 5)` prints
  `--- Logging error ---` with
  `TypeError: not all arguments converted during string formatting`.

- **Caller attribution is wrong for every level method.** The level methods
  (`:613-660`) forward to `super()`, so `findCaller` stops in this module.
  With a `%(filename)s:%(lineno)d %(funcName)s` formatter, calls from an
  application function report:

    - `logger.py:644 info`
    - `logger.py:636 warning`
    - `logger.py:660 trace`
    - `__init__.py:151 notice` (verboselogs' own frame)

    `EnrichFilter` (`:163-200`) builds `record.caller` from `funcName`, so it is
    wrong the same way.

- Tests in `packages/rn-forge-commons/tests/logging/test_logger.py`:

    - `test_initialize_registers_brace_log_record` (`:121`) pins the old global
      factory.
    - Two strict-xfail reproductions from S22.4.5:
      `test_get_logger_preserves_a_factory_installed_after_initialize` (`:130`)
      and `test_get_logger_preserves_a_factory_installed_before_first_retrieval`
      (`:149`).
    - The autouse fixture `restore_record_factory` restores the factory.
    - There is no caller-attribution test and no concurrent-retrieval test.

- Measurements: `tests/measure/test_logging.py` measures enabled and disabled
  `%s` logging (10,000 records). Commons has no cold-import measurement;
  `packages/rn-forge-cli/tests/measure/test_startup.py` (`_COLD`, run in a
  subprocess) is the pattern.

## Change

In `logger.py`:

- Move the message rule out of `BraceLogRecord.getMessage` into one private
  function. `BraceLogRecord.getMessage` calls it.
- Add `AppLogger.makeRecord`: call `super().makeRecord(...)`; when the record is
  not a `BraceLogRecord`, bind the rule as that record's `getMessage`.
- In `_register_levels_and_class`, drop the factory lines. Keep the TRACE level
  and the logger-class registration. Update its docstring, `get_logger`'s,
  `initialize`'s (it mentions `LogRecordFactory`) and `BraceLogRecord`'s (it
  says "Registered globally").
- **Caller attribution:** make each level method (`critical`, `fatal`, `error`,
  `exception`, `success`, `warning`, `notice`, `info`, `verbose`, `debug`,
  `spam`, `trace`) record its caller's frame. Add the frames the wrapper adds
  to `stacklevel`, so a caller's own `stacklevel` keeps its meaning. The
  verboselogs levels add one more frame than the stdlib ones. Choose the
  mechanism; keep the `isEnabledFor` check ahead of any frame lookup.

Elsewhere:

- `packages/rn-forge-commons/CHANGELOG.md`, `[Unreleased]`:
    - `### Changed`: `AppLogger` no longer replaces the process record factory;
      its own records format braces over any factory.
    - `### Fixed`: level methods report the caller's file, line and function.
- No guide or README mentions the record factory (the reviewer checked with
  `git grep`), so no docs page changes beyond docstrings.
