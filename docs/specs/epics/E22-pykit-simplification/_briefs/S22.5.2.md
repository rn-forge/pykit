# S22.5.2 — Keep one option and error path

Brief for [S22.5.2](../F22.5-cli.md#s2252-keep-one-option-and-error-path), at
`be88ead`.

## Goal

Prove that a generated and a hand-registered command share one inherited-option
path and one error-to-exit-code path, and make the declared surface name the key
at fault when `commands` has the wrong shape.

## Settled

- Settled by the reviewer, 2026-11-15: unknown keys in a `[cli]` table stay
  tolerated (`CliSurface` is not strict, `surface.py:43-59`); rejecting them
  is a behavior change outside this story and goes to the owner as a possible
  follow-up.
- Settled by the reviewer, 2026-11-15: the two paths already share all code, so
  no source is consolidated in `app.py` or `options.py`. `from_surface` ends
  in `self.command(name=..., help=...)(target)` (`app.py:247`), the same Typer
  registration `@app.command()` does; both go through the one `_root` callback
  (`app.py:158-180`), `CliOptions.apply` (`options.py:125-142`) and `run`
  (`app.py:69-112`). The matrix pins that sameness; it is the deliverable.
- Settled by the reviewer, 2026-11-15: the paths differ in three places, all
  kept. (1) A declared target that cannot be imported, or is neither a Typer
  app nor callable, raises `AppException` at build time (`app.py:229-246`),
  not an exit code; hand registration has no such step. (2) Help text defaults
  to the target's docstring and the command name comes from the declaration,
  not the function name. (3) A declared Typer target becomes a namespace via
  `add_typer` (`app.py:238-240`).
- Settled by the reviewer, 2026-11-15: `ExitCode.for_error` (`app.py:49-66`) and
  the `except` chain in `run` (`app.py:92-110`) stay as two forms. `run`
  prints and logs as well as mapping, and `for_error` is public and pure.
- Settled by the reviewer, 2026-11-15: invoking with no arguments exits 2 in
  both paths (`no_args_is_help=True`, Click's no-args usage error), not 0.
- Settled by the reviewer, 2026-11-15: `CliSurface.load` rejects a `commands`
  value that is not an array of tables, naming the key and, for an entry, its
  index: `[cli] commands must be an array of tables, not str` and
  `[cli] commands[1] must be a table, not int` (the table name is the `key`
  argument). Wrong scalar types and a missing `target` inside a well-formed
  entry keep dacite's messages (`help`, `commands.target`), already tested.
- Settled by the reviewer, 2026-11-15: no import deferral. See Change.
- No new dependency; no file split; patch-level change (error text only), so a
  changelog entry and versioning note are needed.

## Current behaviour

`packages/rn-forge-cli`:

- Options: `_root` applies `--quiet/--json` through `CliOptions.apply`
  (`app.py:170`) and reconfigures logging only for explicit
  `--log-level`/`--log-file` (`app.py:171-180`). A command may merge its own
  flags with `CliOptions.from_context(ctx, ...).apply(ctx)`
  (`options.py:99-142`); a quiet/JSON conflict raises `typer.BadParameter`
  (`options.py:135-136`), exit 2.
- Errors: Click errors show and map through `for_error` (`app.py:97-99`);
  `AppException` prints its `.message`, exit 1 (`app.py:100-106`); anything
  else logs, exit 1 (`app.py:107-110`); `Abort`/`KeyboardInterrupt` exit 130
  (`app.py:94-96`); `Exit`/`SystemExit` keep their code (`app.py:92-93`).
- Existing coverage is split: hand-registered only in `tests/test_app.py`
  (`TestRun`, `:58`), lifecycle only on a hand app
  (`tests/test_lifecycle.py`), generated only for `greet`/`--help`
  (`tests/test_surface.py:111-127`).
- `CliSurface.load` (`surface.py:68-95`) hands `commands` to dacite unchecked.
  Probed at `be88ead`: `commands = "x"` raises `AppException` whose text
  splits the string into characters
  (`wrong value type for field "commands" ... ('<', 'g', ...`) because
  `cast=[tuple]` accepts any iterable; `commands = [1]` says `value "(1,)"`,
  no index, no mention of tables; `commands` as a table raises
  `dictionary update sequence element #0 has length 4; 2 is required`, which
  names no key; `help = 3`, `name = 3`, `default_log_level = 3` and a
  wrong-typed `target` name their field; a missing `target` says
  `commands.target`.

## Change

- **Change:** `surface.py`: in `load`, after `data` is resolved and before
  `from_dict`, check `commands` when present: not a `list`/`tuple` raises
  `AppException("[{}] commands must be an array of tables, not {}", key, type(value).__name__)`;
  for each entry that is not a `Mapping`, raises
  `AppException("[{}] commands[{}] must be a table, not {}", ...)`. A private
  helper in the same module. Add the two cases to the `Raises:` docstring.
  `CHANGELOG.md` `[Unreleased]`: a `### Changed` entry (clearer errors for a
  malformed `commands` table) and extend the versioning note.
- **Import deferral: none.** Measured `-X importtime -c "import rn_forge.cli"`
  at `be88ead`: 153 ms cumulative; `rn_forge.commons` 112 ms of it
  (`commons.fs.documents` 28 ms with ruamel, `dacite`, logging 35 ms), `typer`
  28 ms. The `rn_forge.commons` package init imports documents and dacite
  whatever `surface.py` does, and `app.py` needs `AppLogger`, so moving the
  `DocumentUtils` import into `load` removes nothing. What `cli` alone imports
  and a plain invocation never uses is `tomllib` (0.8 ms). Rule: defer an
  import only when it is reachable solely from `from_config`/`load`, is not
  already imported by `rn_forge.commons`' package init or by typer, and
  removing it cuts at least 10 ms or 10 % of the `cli_cold_help` wall time
  (median of five runs, idle machine). Nothing qualifies, so the implementer
  re-runs `-X importtime`, records the figures in Result, and changes no
  import. If a candidate does qualify, stop and report; do not defer on your
  own.
- **Leave alone:** `app.py`, `options.py`, `ExitCode`, `run`, the measurement
  harness and `docs/guides/performance-baselines.md`, unknown-key handling.

## Tests first

New `tests/test_command_paths.py`. Module-level functions `ok`, `fail`
(`AppException`), `crash` (`RuntimeError`), `stop` (`KeyboardInterrupt`), `bail`
(`typer.Exit(3)`), `leave` (`SystemExit(4)`), `strict` (merges
`json_output=True` via `CliOptions.from_context(ctx, ...).apply(ctx)`), and
`show`, which prints the root options it sees. Register `sys.modules` under an
alias, as `test_surface.py:31` does, so declared targets import. An `app`
fixture parametrized `ids=["hand", "generated"]` builds the same command set by
`@app.command()` and by `CliApp.from_surface`.

1. `test_exit_codes`, parametrized over args: `ok` 0, `fail` 1, `crash` 1,
   `stop` 130, `bail` 3, `leave` 4, `nope` 2, no arguments 2, `--help` 0,
   `ok --help` 0, `--log-level bogus ok` 2, `ok --json` 2 (root flag after the
   command). All pass today in both ids; guards for the Settled sameness.
1. `test_inherited_options`: `--json show` and `--quiet show` report
   `json_output`/`quiet` in the command; `--quiet --json ok` and
   `--quiet strict` exit 2; the mode after each run equals the mode before.
   Guards, pass today.
1. `test_failure_output`: `fail` prints its message to stderr, never a
   traceback; `crash` prints `Unexpected error: a defect`. Guard.
1. `test_help_lists_standard_options`: `--help` stdout holds `--log-level`,
   `--log-file`, `--quiet`, `--json`, and every command name. Guard.
1. In `test_surface.py`, class `TestSurfaceShapeErrors`; the first three fail
   before the change, the last two are guards:
    - `commands = "x"` raises `AppException` matching
      `commands must be an array of tables, not str`; fails today (the message
      is the dacite text).
    - `commands = [1]` matches `commands\[0\] must be a table, not int`; fails
      today.
    - `commands` as a table (`{"name": "a", "target": "m:f"}`) matches
      `commands must be an array of tables, not dict`; fails today (the message
      names no key).
    - `commands = [{"name": "a"}]` matches `commands.target`; passes today.
    - `commands = [{"name": "a", "target": ["x"]}]` matches `commands.target`;
      passes today.
