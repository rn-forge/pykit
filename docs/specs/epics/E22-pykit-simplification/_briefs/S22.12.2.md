# S22.12.2 — Remove redundant row buffering

Brief for [S22.12.2](../F22.12-data.md#s22122-remove-redundant-row-buffering),
at `7f11a7c`.

## Goal

`write_xlsx` copies every dataset row into a list before appending to a
write-only workbook. Iterate the dataset directly, show the peak-memory effect
with the S22.3.2 harness, and document that the dataset and the output bytes
still live in memory.

## Settled

- Settled by the reviewer, 2026-11-15: the change is to drop the `rows` list in
  `write_xlsx` and loop `for row in cast("Any", dataset):`. No other code in
  `write_xlsx` changes: header row, per-column `WriteOnlyCell` formats,
  unknown-column `KeyError` before any write, and `sheet_title` are unchanged.
- Settled by the reviewer, 2026-11-15: `ExcelAdapter.from_dataframe`
  (`pandas.py:231-266`, frame to bytes to reparsed `Workbook`) stays as it is.
  Its contract is an editable, fully loaded workbook, so the reparse is the
  product, not a copy; design.md allows rejecting it. State this in the
  Result.
- Settled by the reviewer, 2026-11-15: the saving is expected to be small (tens
  of MB of traced peak is dominated by the dataset, the workbook XML and the
  output bytes). Record the measured delta whatever its size; no threshold,
  and a near-zero delta is an acceptable result, reported as such. Keep the
  change because the list is redundant, not because of a target.
- Settled by the reviewer, 2026-11-15: measure the write phase alone. Add a case
  that builds the dataset before the `measure` block, so tracemalloc sees only
  `write_xlsx`; keep the existing round-trip case unchanged.
- Settled by the reviewer, 2026-11-15: no test asserts "no full row list"; that
  property is shown by the measurement only.
- Settled by the reviewer, 2026-11-15: the documentation drops "streams" and
  states the bounds: the whole `tablib.Dataset` is held by the caller, and the
  whole workbook is returned as one `bytes` object. It does not promise
  end-to-end streaming.
- Changelog entry under `[Unreleased]`: observable output is identical, so file
  it under `### Changed` as an internal memory change plus the documentation
  correction. No new dependency; no versioning note beyond patch.

## Current behaviour

`packages/rn-forge-data/src/rn_forge/data/excel.py`:

- `write_xlsx` (`:361-404`) validates `column_formats` against the headers
  (`:383-387`), opens `openpyxl.Workbook(write_only=True)` (`:389`), appends
  the header row (`:391-392`).
- `:393-395` builds
  `rows = cast("list[tuple[Any, ...]]", list(cast("Any", dataset)))`. tablib
  iterates through `Dataset.__getitem__(int)`, which returns `row.tuple` (a
  fresh tuple per row), so the list holds one tuple per row for the whole
  call. The loop at `:396-403` reads each tuple once, in order, and never
  needs more than one row.
- `:404`: `ExcelUtils.write_workbook_bytes(workbook).getvalue()`
  (`excel.py:183-199`) saves into a `BytesIO`, then `getvalue()` copies it.
  This is the output-bytes bound; leave it.
- Repeated frame/workbook conversion exists only in
  `ExcelAdapter.from_dataframe` (`pandas.py:231-266`), which `write_xlsx` does
  not use.

Tests: `packages/rn-forge-data/tests/test_excel.py::TestWriteXlsx` (`:332`)
already covers headers, one row, date and total formats, the default `General`
format and the unknown-column `KeyError` (`:351`).

Measurement: `packages/rn-forge-data/tests/measure/test_excel.py::test_excel`
(case `excel_roundtrip`, 50,000 rows by 10 columns) builds the dataset inside
the measured block, so its peak mixes dataset build, write and load. The
recorded `1a8da87` figure is 225,496,023 bytes in
[Performance baselines](../../../guides/performance-baselines.md).

How each new test behaves today (all pass before the change; none is a
failing-first test, because behaviour is preserved):

1. `test_round_trip_preserves_values_and_sheet_title`: passes today; guard.
1. `test_round_trip_without_headers`: passes today; guard.
1. `test_formats_apply_to_every_row`: passes today; guard.
1. `test_unknown_columns_error_lists_all_sorted`: passes today; guard.
1. `test_unknown_column_with_rows_raises`: passes today; guard.

The "no complete row list" property cannot be shown by a deterministic unit test
without coupling to tablib internals; only the measurement shows it.

## Change

- **Change:** `excel.py`: delete `rows` (`:393-395`); loop
  `for row in cast("Any", dataset):  # tablib is untyped`. Update the
  `write_xlsx` docstring only if it claims streaming (it does not today).
  `packages/rn-forge-data/docs/guides/usage.md:32-34`: replace "It streams
  through a write-only workbook, so large datasets stay cheap." with the
  bounds from Settled. Add a `### Changed` entry under `[Unreleased]` in
  `packages/rn-forge-data/CHANGELOG.md`.
- **Measure:** in `tests/measure/test_excel.py` add `test_excel_write` (case
  `excel_write`, inputs `{"rows": 50_000, "columns": 10}`, kind `buffering`):
  build the dataset first, then `with measure(...)` around `write_xlsx` only,
  recording `bytes`, `rows`, `cells` in `counts`. Run it, and the existing
  round-trip case, at the unchanged code first (baseline), then again after
  the change, on the same machine with other jobs stopped. Record both in
  [`docs/guides/performance-baselines.md`](../../../guides/performance-baselines.md):
  a new `### 7f11a7c before and after S22.12.2` table with wall time, peak
  bytes and counts for `excel_write` and `excel_roundtrip`, the environment
  line, and the S22.3.2 caveats. Add the `excel_write` row to the Workloads
  table (Data). Do not add a threshold or a timing assertion.
- **Leave alone:** `ExcelAdapter.from_dataframe`, `write_workbook_bytes`,
  `pandas.py`, `__init__.py`, the measure fixture in
  `tests/measure/conftest.py` and `test_contract.py`.
