# S22.4.5 — Decide how brace records compose with other factories

## Goal

Reproduce, with a failing test, logger acquisition overwriting a record factory
the consumer installed, and compare the three composition options. This is a
decision story: do not fix the code and do not write the ADR. The owner decides.

## Current behaviour

All paths in `packages/rn-forge-commons/src/rn_forge/commons/logging/logger.py`:

- `BraceLogRecord` (lines 83-114) overrides `getMessage` only: `%` style when
  `%` is in the message, else `str.format`.
- `AppLogger._register_levels_and_class` (lines 956-966) calls
  `logging.setLogRecordFactory(BraceLogRecord)` whenever the current factory
  `is not BraceLogRecord`. It discards whatever factory is installed.
- `AppLogger.get_logger` (lines 561-574) calls it on every retrieval;
  `initialize` calls it too (line 517). Library modules call
  `AppLogger.get_logger(__name__)` at import time (for example
  `runtime/tasks.py:45`, `cli/app.py:33`), so importing a package can replace
  a consumer's factory.
- `tests/logging/test_logger.py:114-116`
  (`test_initialize_registers_brace_log_record`) pins that the factory is
  `BraceLogRecord` after `initialize`. Its autouse fixture
  `reset_logger_state` does not restore the record factory.

## Change

- **Leave alone:** every file under `src/`, the existing tests, ADRs and spec

## Tests first

Mark each
`@pytest.mark.xfail(strict=True, reason="S22.4.5: get_logger overwrites a consumer record factory")`
so the suite stays green; they fail today for the stated reason, and strict
makes the later fix visible.

- `test_get_logger_preserves_a_factory_installed_after_initialize`:
  `_configure()`, install a factory that wraps the current one and sets
  `record.trace_id = "t-1"`, call `_logger("test.keep")`, build a record with
  `logging.getLogRecordFactory()("n", logging.INFO, "", 0, "m", (), None)`.
  Assert it has `trace_id`.
- `test_get_logger_preserves_a_factory_installed_before_first_retrieval`:
  install the same factory without `initialize`, call `_logger("test.keep2")`;
  assert `logging.getLogRecordFactory()` is still the consumer's.

## Result

Write the comparison here, and keep it under 300 words. Compare, for each
option, against a tracing factory and an arbitrary consumer factory: (1)
composing over the installed factory (wrap it and apply brace formatting), (2)
an explicit opt-in install by `initialize` only, with `get_logger` never
touching the factory, and (3) a formatter-level brace style with no factory at
all. For each give what breaks (handlers that call `getMessage` directly,
third-party `%` messages, import-time retrieval, idempotency, repeated
`initialize`), the code size, and the effect on S22.4.1. End with one
recommendation and why. Then record each validation command with its exit code
and the files changed.
