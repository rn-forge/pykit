# S22.4.2 — Report actual generation effects

Brief for [S22.4.2](../F22.4-commons.md#s2242-report-actual-generation-effects),
at `1a8da87`.

## Goal

Make `ApplyResult.written` list only the paths whose bytes changed, once each,
as its docstring says. Today it lists every planned path, so unchanged, skipped
and forgotten artifacts are reported as written.

## Settled

Settled by the reviewer, 2026-11-14. The mapping is over
`Change.effective_action` and `Plan.writes`.

- Settled by the reviewer, 2026-11-14: CREATE, INSERT, UPDATE are in `written`;
  they write bytes.
- Settled by the reviewer, 2026-11-14: DELETE is in `written`; the file is
  removed (bytes change, a backup is taken).
- Settled by the reviewer, 2026-11-14: REMOVE is in `written`; the block is cut
  out of a file whose body stays.
- Settled by the reviewer, 2026-11-14: UNCHANGED and SKIP are not in `written`;
  nothing is touched.
- Settled by the reviewer, 2026-11-14: FORGET is not in `written`; only the
  state entry goes, and the state file is not an artifact.
- Settled by the reviewer, 2026-11-14: A forced (approved) DRIFT, CONFLICT or
  MISSING is in `written`; `Plan.writes` already treats it as a write, so
  `written` follows `Plan.writes` and the plan stays the single owner of what
  counts as a write. A forced MISSING that intends DELETE finds no file; it is
  still listed (the result cannot see disk). Reason: avoids a second
  classifier.
- Settled by the reviewer, 2026-11-14: Dry run: `written == ()`. `changes` still
  carries the whole plan and `dry_run` is `True`. Reason: no bytes changed,
  and a previewer already has `Plan.writes` and `diff`.
- Settled by the reviewer, 2026-11-14: Several blocks in one file: the path
  appears once, at its first position in plan order (the order `_compose`
  applies it). Reason: the docstring says paths whose bytes changed, and the
  file changed once.
- Blocking and unapproved changes never reach a result; `apply` raises first
  (`apply.py:135`).

## Current behaviour

- `generation/artifacts.py:249-252` (`ApplyResult.written`) returns
  `change.path` for every change, in plan order, with duplicates.
- `generation/apply.py:138-139` returns
  `ApplyResult(changes=planned.changes, dry_run=True)`; `apply.py:166` returns
  the same `changes` after a real apply. Both pass the whole plan.
- `Plan.writes` (`artifacts.py:216-224`) already selects the write changes via
  `WRITE_ACTIONS` plus approved blocking ones. `apply` uses it at
  `apply.py:136`.
- Nothing outside commons reads `.written` in this repository; kiln may.
- Existing tests in
  `packages/rn-forge-commons/tests/generation/test_generation.py` cover every
  action and rollback; none asserts `written`.

## Change

- **Change:**
  `packages/rn-forge-commons/src/rn_forge/commons/generation/artifacts.py`:
  `written` returns `()` when `dry_run`, else the de-duplicated paths of
  `Plan(self.changes).writes` in order (`tuple(dict.fromkeys(...))`). Fix its
  docstring to state the dry-run and uniqueness rules.
  `packages/rn-forge-commons/docs/guides/generation.md`: add a short table of
  action to reported-or-not beside the classification table.
  `packages/rn-forge-commons/CHANGELOG.md`: one entry stating that `written`
  no longer lists unchanged, skipped, forgotten or dry-run paths, and assess
  the version bump as a behaviour change.
- **Leave alone:** `apply.py` logic, `plan`/`classify`, `Plan.writes`, rollback,
  staging, the state store, and `__init__.py` exports. Do not add fields to
  `ApplyResult`.

## Tests first

In `packages/rn-forge-commons/tests/generation/test_generation.py`, class
`TestApply` (reuse `run`, `managed`, `seeded`, `block`). Each fails before the
change.

- `test_written_lists_only_paths_whose_bytes_changed`: first run
  `[managed("a.yml"), managed("b.yml"), seeded()]`, then run
  `[managed("a.yml", "v2\n"), managed("b.yml"), seeded()]`. Assert
  `written == ("a.yml",)`.
- `test_written_covers_create_delete_remove_and_excludes_forget`: set up a
  managed file, a block and a seeded file, run again with a new managed file
  only. Assert written is the new file, the deleted file and the block's path;
  not the seeded path.
- `test_written_lists_a_file_once_for_several_blocks`: in
  `TestSeveralBlocksInOneFile`, two updates in `.gitignore`; assert
  `written == (".gitignore",)`.
- `test_dry_run_reports_nothing_written`: assert `written == ()` and
  `len(changes)` equals the plan size.
- `test_forced_drift_is_reported_written`: forced drift path is in `written`.
- `test_reporting_adds_no_writes`: snapshot `st_mtime_ns` and bytes of every
  file in `tmp_path` before an all-UNCHANGED apply; assert they are equal
  after (the state file excepted). Passes before and after; it guards the
  acceptance.
