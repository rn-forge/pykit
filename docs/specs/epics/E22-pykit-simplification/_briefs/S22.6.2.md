# S22.6.2 — Separate prepare from mutation

Brief for [S22.6.2](../F22.6-tooling.md#s2262-separate-prepare-from-mutation),
at `be88ead`.

## Goal

`_install` runs release preparation (download, checksum, extract) and the
filesystem transaction in one `try` that shares one undo list, one work
directory and one recovery report. Split preparation, activation and recovery
into focused private functions, close the test gaps around preparation failure,
derive the advertised verbs from one registry, and diagnose malformed
`[lifecycle]` tables. Behaviour and messages stay as they are.

## Settled

- Settled by the reviewer, 2026-11-15: the code already separates well in
  places; leave alone `install`/`upgrade`/`uninstall`/`cleanup` (lock,
  ownership checks), `fetch_release` (`release.py:156-186`, which already
  verifies the checksum before `extract_archive`), `_place_link`,
  `_restore_file`, `_restore_current`, `ToolHome`, the doctor helpers and the
  CLI command adders. `ToolProduct.build` and `migrate` stay in activation:
  `build` writes `version_dir`.
- Settled by the reviewer, 2026-11-15: extract only in `install/lifecycle.py`
  (no new module, no protocol, no class beyond one private frozen dataclass):
  `_prepare(home, source, target) -> _Prepared` (`work`, `release_root`: makes
  `.work`, `mkdtemp`, `fetch_release`; on any failure removes `work` and
  raises through `_failure`);
  `_activate(product, home, prepared, previous, undo)` (displace, build,
  links, migrate, state, `home.activate`; appends to the caller's `undo`);
  `_recover(undo) -> list[tuple[str, Exception]]` (the reverse loop);
  `_failure(product, target, exc, failures, work, retained)` (builds the
  `AppException` or logs for an interruption, as at `:288-322`). `_install`
  keeps lock-free orchestration: prepare, then try activate, recover, finally
  remove `work` unless retained.
- Settled by the reviewer, 2026-11-15: messages are unchanged. A preparation
  failure still says "failed and was rolled back" (vacuously true; nothing was
  mutated) because `test_a_failed_download_changes_nothing` pins it and
  S22.6.3 tied the wording to "every undo step succeeded".
- Settled by the reviewer, 2026-11-15: no caching. One install downloads once,
  hashes once (`release.py:177`, `ContentHash.of_file`) and extracts once; no
  repeat read exists. Add a measurement and a once-only test; cache only if a
  measured count exceeds one. Whole-file hashing memory belongs to S22.4.4.
- Settled by the reviewer, 2026-11-15: verbs derive from one registry. Make
  `_COMMANDS` the only declaration and `VERBS = tuple(_COMMANDS)` (defined
  after it); `LifecycleSurface.verbs` uses
  `field(default_factory=lambda: VERBS)`. `lifecycle_commands` iterates
  `_COMMANDS`. The public `VERBS` name and order are unchanged.
- Settled by the reviewer, 2026-11-15: `LifecycleSurface.load` raises
  `AppException` for a non-table `[lifecycle]` and for `verbs` that is not a
  list of strings. Extra keys and empty `verbs` stay accepted (unchanged).

## Current behaviour

`packages/rn-forge-tooling/src/rn_forge/tooling/`:

- `install/lifecycle.py` `_install` (`:238-325`): `fetch_release` at `:253` runs
  inside the `try` that owns `undo`, so a download, checksum or archive
  failure goes through the recovery loop (`:288-322`) with an empty `undo`.
  `work`, `displaced`, `retained` and `undo` are shared by both phases and the
  `finally` (`:323`). Activation is `:255-287`.
- Locking: `install` takes `home.lock()` at `:119` around `_install`;
  `uninstall` `:161`, `cleanup` `:187`. Ownership: `uninstall` `:161-166`,
  `_place_link` `:334-355`.
- `cli/lifecycle.py`: verbs are declared twice, `VERBS` (`:23`) and `_COMMANDS`
  (`:303-310`); `lifecycle_commands` loops `VERBS` and indexes `_COMMANDS`
  (`:50-52`). `LifecycleSurface.load` (`:89-112`): `lifecycle = "x"` raises a
  bare `ValueError` from `dict(data)`; `verbs = "status"` is split into
  characters and reported as `Unknown lifecycle verb(s): s, t, a, ...`.
  Verified by running them. Duplicate/unknown verbs and bad scalar types are
  already diagnosed (`__post_init__` `:72-86`, `from_dict`); only unit tests
  of `lifecycle_commands`/namespace exist, none for the table cases.
- Existing coverage in `tests/install/test_lifecycle.py`: checksum mismatch is
  tested only on `fetch_release` (`:170`); rollback for download, migration,
  interruption in the swap, build, link in the way (`:177-240`); recovery
  failures and boundaries (`:243-363`); uninstall ownership (`:385-410`). No
  test covers: a checksum or archive failure through `install`, an
  interruption during preparation, the lock held during preparation, or a
  single download/hash.
- No `tests/measure/` exists in the tooling package.

## Change

- **Change:** `install/lifecycle.py` per Settled; `cli/lifecycle.py` registry
  and `load` checks; add `packages/rn-forge-tooling/tests/measure/` (copy
  `conftest.py` and `test_contract.py` from
  `packages/rn-forge-data/tests/measure/`; `test_install.py` skips unless
  `PYKIT_MEASURE_OUT` is set). The case installs a 64 MiB archive from a
  `LocalArchive` with a sha256, kind `buffering`, counts `downloads`, `hashes`
  (wrap `ContentHash.of_file`), `extracts`. Add a row for it to the workloads
  table in `docs/guides/performance-baselines.md`; do not record a baseline.
  Docstrings keep the contract only; comments say the non-obvious why.
- **Leave alone:** messages, `fetch_release`, `release.py`, `ToolProduct`,
  `ToolHome`, the doctor path, `cleanup`'s double call, `ContentHash`.

## Tests first

In `tests/install/test_lifecycle.py` (class `TestPreparation`, helpers from
`TestRollback`) and `tests/cli/test_lifecycle_commands.py`. Items 1-7 pass today
and guard the refactor; only 8 fails before it.

1. `test_a_checksum_mismatch_leaves_the_prior_install_usable`: install 1.0.0,
   then
   `install(..., source=LocalArchive(make_archive(.., "2.0.0"), "2.0.0", "0"*64))`
   with `fail_build=True`: raises "Checksum mismatch" (not "build
   exploded"), `_assert_still_one`, no `2.0.0` directory. Guard.
1. `test_a_malformed_archive_leaves_the_prior_install_usable`: a two-root
   archive: "exactly one root directory", `_assert_still_one`. Guard.
1. `test_an_interrupted_download_restores_nothing_and_reraises`: source raising
   `KeyboardInterrupt`; raised as-is, `_assert_still_one`, `.work` has no
   entries. Guard.
1. `test_preparation_runs_under_the_lock`: `download` tries
   `ToolHome("tool", home.root).lock(timeout=0.1).__enter__()` and records the
   `AppException`; the install succeeds and the exception was recorded. Guard.
   If `home.lock()` does not conflict within one process (check its primitive
   first), drop this test and say so in the Result.
1. `test_a_release_is_downloaded_and_hashed_once`: counting source and a
   monkeypatched `ContentHash.of_file` give 1 and 1 for an install with a
   checksum. Guard against added re-reads or caching.
1. `test_a_failed_preparation_never_builds_or_migrates`: `fail_migration=True`
   and `fail_build=True` with a failing download: neither runs (assert error
   is the download's). Guard; it fails only if the split reorders preparation.
1. CLI `test_the_advertised_verbs_are_the_mounted_ones`: names of
   `lifecycle_commands(PRODUCT).registered_commands` equal `list(VERBS)` and
   `LifecycleSurface(product="x:y").verbs == VERBS`. Guard (structure test is
   not possible without private access).
1. CLI parametrized `test_a_malformed_lifecycle_table_is_diagnosed`:
   `{"lifecycle": "x"}` and `{"product": "a:b", "verbs": "status"}` via
   `LifecycleSurface.load`, plus duplicate and unknown verbs: each raises
   `AppException`. The first two fail today (`ValueError`; character-split
   message, assert `match="verbs"`); duplicates and unknown pass.
