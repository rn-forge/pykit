# S22.10.2 — Keep route assembly thin

Brief for [S22.10.2](../F22.10-fastapi.md#s22102-keep-route-assembly-thin), at
`bca98e9`.

## Goal

Make the FastAPI transfer adapter meet the targets the owner set in S22.10.3,
and split `transfer.py` so parsing and serialization are not mixed with router
assembly. Three behaviour changes, each proved by a test and by the S22.10.3
measurement re-run three times: CSV export streams chunks of 1,000 rows; batch
create parses, validates and serializes once, off the event loop; every public
name of `rn_forge.fastapi.transfer` stays importable from it. The auth
acceptance cases are proved through the existing routes, plus one new gap
closed. No auth source changes.

- Settled by the reviewer, 2026-11-16: CSV chunk size is 1,000 rows, a module
  constant `CSV_CHUNK_ROWS = 1_000`, the header row in the first chunk, no
  empty trailing chunk. Cause (S22.10.3): `lines()` at `transfer.py:179-190`
  yields one string per row from a sync generator, and Starlette's
  `iterate_in_threadpool`
  (`.venv/lib/python3.14/site-packages/starlette/concurrency.py:51-59`) does
  one `anyio.to_thread.run_sync` per item, about 66 microseconds each.
  Prototype (reverted), three runs: 100,000 rows 0.81-0.90 s wall (baseline
  12.14 s), 10,000 rows 0.09-0.11 s, `peak_bytes` 624,273-651,865 (bound
  1,048,576), lag max 0.010-0.016 s (baseline 0.0094-0.0115 s). Peak grows
  with chunk size, so do not raise it; do not make it a parameter or an
  option.

- Settled by the reviewer, 2026-11-16: batch create. Evidence on this commit
  (Python 3.14.2, `tracemalloc` on as the harness runs it): the
  15,977,794-byte 100,000-row body is parsed by FastAPI itself, before any
  dependency runs
  (`.venv/lib/python3.14/site-packages/fastapi/routing.py:458-471` calls
  `request.json()`), and `json.loads` of it takes 0.82 s on the event loop
  against 0.51 s in a worker thread (lag max 0.502-0.505 s in the thread:
  `json.loads` holds the GIL for the whole call, so a thread does not shorten
  it, but it is faster under tracing). Without tracing it takes 0.11 s. The
  parse happens once, not twice: Starlette caches `Request.json()`
  (`starlette/requests.py:262-266`) and the guard at `transfer.py:457` reads
  the cached value. What happens twice is validation: the guard validates
  every item (`transfer.py:476-498`) and FastAPI then validates the same body
  into `request_model` (`transfer.py:667`), and a third and fourth time on the
  way out (`transfer.py:658-665` dumps each row, then `serialize_response` at
  `.venv/.../fastapi/routing.py:338-348` validates and dumps again, on the
  loop because the endpoint is `async`). Decision:

    1. **Parse in a worker thread** with a private `Request` subclass whose
       `json()` is `await run_in_threadpool(json.loads, await self.body())`,
       installed through a private `APIRoute` subclass passed as `route_class`
       to the batch-create router only (the pattern in FastAPI's documented
       custom request and route classes). FastAPI's own call then runs there, so
       its `json.JSONDecodeError` handling and the 422 `json_invalid` problem
       are unchanged.
    1. **Validate each item once**, in the guard, in a worker thread, and hand the
       models to the handler as the guard's return value. FastAPI's own body
       validation is turned into a pass-through for this route only: the request
       model's list field is `Annotated[list[item], SkipValidation]`, which
       keeps the documented schema (the existing OpenAPI test proves it) and
       skips the second validation. The guard keeps the order the wire contract
       states: member present, non-empty list, cap, then item errors.
    1. **Build the response once**, in a worker thread, and return a `Response` so
       FastAPI does not validate it again:
       `result_model.model_validate({resource_name: created}, from_attributes=True)`
       then `.model_dump_json(by_alias=True)`, media type `application/json`.
       `response_model=result_model` stays on the route for OpenAPI. The bytes
       are identical (prototype: 15,977,790 bytes before and after). Prototype
       (reverted), three runs: 100,000 rows lag max 0.544-0.560 s, wall
       1.09-1.12 s, `peak_bytes` 224,836,030 (bound 367,001,600); 10,000 rows
       lag max 0.047-0.053 s, wall 0.10-0.12 s, `peak_bytes`
       22,579,201-22,579,393 (bound 37,748,736). **L2 is reachable with this
       plan on this machine:** 0.55 s against 0.75 s at 100,000 rows (1.35 times
       of margin) and 0.05 s against 0.075 s at 10,000 (1.4 times). The floor is
       the 0.51 s thread parse, which only a streaming parser would remove, and
       that needs a new dependency or a hand-written parser, both out of scope.
       Without step 1 a prototype measured 0.99 s (FastAPI's parse left on the
       loop; it also still validated twice), which misses the bound. If a run on
       the reviewer's machine or the implementer's exceeds 0.750 s or 0.075 s,
       do not widen the plan: record the figures, say which stage the lag sits
       in (a throwaway lag trace per stage, deleted before finishing) and stop.

    def csv_chunks(rows, model, columns):
        buffer = io.StringIO()
        writer = csv.writer(buffer)
        writer.writerow(columns)
        count = 0
        for record in records(rows, model, "json"):
            writer.writerow([record[c] for c in columns])

    def validate_items[T: BaseModel](
        items: TypeAdapter[T], entries: Sequence[object]
    ) -> tuple[list[T], list[RowError]]:
        valid, errors = [], []
        for index, item in enumerate(entries):
            try:
                valid.append(items.validate_python(item))
            except ValidationError as exc:
                errors.extend(item_errors(index, exc))
        return valid, errors

    def models_guard[T: BaseModel](key, max_rows, item_model: type[T]) -> DependsParam:
        items = TypeAdapter(item_model)

        async def guard(request: Request) -> list[T]:
            entries = await checked_list(request, key, max_rows)
            valid, errors = await run_in_threadpool(validate_items, items, entries)
            if errors:
                raise RowsInvalid(errors, root=key)
            return valid

        return Depends(guard)

    class ThreadedJsonRequest(Request):
        async def json(self) -> Any:
            if not hasattr(self, "_json"):
                self._json = await run_in_threadpool(json.loads, await self.body())
            return self._json

    class ThreadedJsonRoute(APIRoute):
        def get_route_handler(self) -> Callable[[Request], Coroutine[Any, Any, Response]]:
            handler = super().get_route_handler()

            async def route(request: Request) -> Response:
                return await handler(ThreadedJsonRequest(request.scope, request.receive))

            return route
