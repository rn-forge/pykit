# S22.6.1 — Exercise recovery failures

Brief for [S22.6.1](../F22.6-tooling.md#s2261-exercise-recovery-failures),
written at the S22.6.3 close.

## Goal

Implement the recovery contract S22.6.3 settled (option B) in the install
transaction: every undo step is attempted, both the initiating failure and any
recovery failures are reported, and a displaced version whose restoration
failed survives on disk at a reported path.

## Settled

From S22.6.3's acceptance (owner, 2026-11-14), verbatim in substance:

- Recovery attempts every undo step in reverse, even after one fails.
- An `Exception` is re-raised as an `AppException` whose `__cause__` is the
  initiating failure. Its message says "rolled back" only when every undo step
  succeeded. Otherwise it says `recovery is incomplete` and names each failed
  step with its error.
- If restoring a displaced version fails, the transaction directory under
  `.work` is retained, and the message names that directory.
- `cleanup` leaves a retained directory in place. A new transaction never
  reuses or deletes one. `uninstall` still removes everything.
- An interruption (`BaseException` that is not an `Exception`) is re-raised
  as-is after recovery; any recovery failures and the retained path are logged
  at error level.
- No `doctor` finding and no recover verb.
- E22 constraints: locking, ownership and transaction guarantees stay.

## Current behaviour

All in `packages/rn-forge-tooling/src/rn_forge/tooling/install/lifecycle.py`
unless noted.

- `_install` (`:226-280`): `work = home.work_dir / f"{target}-{os.getpid()}"`
  is `rmtree`d up front (`:235-236`), so a directory left by an earlier process
  with the same pid would be deleted. `undo` is a list of bare callables.
- `except BaseException` (`:268-278`) runs `for step in reversed(undo): step()`;
  the first step that raises stops the loop and its error replaces `exc`.
- `finally` (`:279-280`) always removes `work`, including `work/displaced`.
- `cleanup` (`:189`) removes the whole `home.work_dir`.
- `ToolHome.work_dir` docstring (`home.py:78`): "removed when it finishes".
- Contract text: `packages/rn-forge-tooling/docs/guides/lifecycle.md`, section
  "What `install` guarantees" ("the steps already taken are undone in reverse,
  and the previous version is active again"), and the `install` docstring
  `Raises:` "everything it did has been undone".
- `tests/install/test_lifecycle.py::TestRecoveryFailure` holds two strict-xfail
  reproductions. Observed without the markers:
    - `test_a_failed_undo_step_does_not_stop_remaining_recovery`:
      `pytest.raises(AppException, match="migration exploded")` fails because
      `OSError: undo failed` escapes from the link restore.
    - `test_a_failed_restoration_keeps_the_displaced_version`: the final
      `assert any(... == "tool 1.0.0\n" ...)` fails with `assert False`; no copy
      of the old tool survives.

## Change

In `lifecycle.py`:

- **Work directory:** create it with
  `tempfile.mkdtemp(prefix=f"{target}-", dir=home.work_dir)` (after
  `home.work_dir.mkdir(parents=True, exist_ok=True)`), and drop the up-front
  `rmtree`. A retained directory can then never be reused.
- **Undo steps:** store each with a short label, e.g. `restore displaced
  version`, `remove versions/<target>`, `restore link <link.path>`,
  `restore state.json`, `restore current`. `_place_link` and the
  `_restore_*` helpers keep their behavior.
- **Recovery:** run every step in reverse; catch `Exception` per step and
  collect `(label, error)`. A `BaseException` from a step is not caught.
- **Retention:** after recovery, retain `work` when `displaced` still exists.
  The `finally` removes `work` only when it is not retained (a successful
  forced reinstall still removes its displaced copy).
- **Report:** with no recovery failures, keep today's message
  (`Install of {} {} failed and was rolled back: {}`). Otherwise raise
  `AppException("Install of {} {} failed: {}; recovery is incomplete: {}", ...)`
  where the last field lists `label: error` pairs, followed by
  `; the previous version is kept at <work>` when retained. Keep `from exc`.
  For an interruption, log the same details with `_LOGGER.error`, then
  re-raise.
- **cleanup:** remove each entry of `home.work_dir` except a directory that
  contains `displaced`; log a warning naming each one kept. `CleanupResult` is
  unchanged.

Docs and docstrings:

- `install` docstring `Raises:` and `ToolHome.work_dir` docstring: state the
  settled contract in one or two sentences each.
- `docs/guides/lifecycle.md`, "What `install` guarantees": replace the
  rollback paragraph with the settled contract, including where a retained
  version lives, that `cleanup` keeps it, and that the person removes it after
  recovering by hand.
- `packages/rn-forge-tooling/CHANGELOG.md`, `[Unreleased]` → `### Fixed`: a
  failed undo step no longer stops recovery or hides the initiating failure,
  and a failed restoration no longer deletes the displaced version.
