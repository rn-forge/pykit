# S22.3.2 — Measure representative work

Brief for
[S22.3.2](../F22.3-tests-and-measurements.md#s2232-measure-representative-work),
at `1a8da87`.

## Goal

Add a repeatable, dependency-free procedure that records wall time, peak memory
and operation counts for the epic's representative workloads, and record the
baseline at `1a8da87`. Later stories (S22.4.4, S22.5.2, S22.8.4, S22.10.3,
S22.12.2) re-run it for after-comparisons.

## Settled

- Settled by the reviewer, 2026-11-14: measurements are pytest cases under
  `packages/<pkg>/tests/measure/`, skipped unless `PYKIT_MEASURE_OUT` names an
  output directory. Package cases run as `PYKIT_MEASURE_OUT=<dir> task test`
  (every suite runs; only these unskip). Only a case that runs solely in the
  root suite (scaffold setup) uses
  `PYKIT_MEASURE_OUT=<dir> SUITE_ARGS="-q <node ids>" task ci:suites`
  (`tasks/ci.yml:112-115`, CI-only, read from the shell environment, not a
  task var). That use is interim until `task test -- <package> <args>` exists
  (kiln S18.13.4). No task file, marker, dependency or pyproject change.
- Settled by the reviewer, 2026-11-14: each case appends one JSON line (`case`,
  `commit`, `python`, `platform`, `inputs`, `wall_s`, `peak_bytes`, `counts`,
  `kind`) to `$PYKIT_MEASURE_OUT/results.jsonl`, through a `measure` fixture
  (about 25 lines: `perf_counter`, `tracemalloc`, `git rev-parse HEAD`) in
  each package's `tests/measure/conftest.py`. Existing shared support is
  `rn_forge.commons.testing` (`commons/testing.py`), a published module;
  adding to it would change a public API, need a facade, docs and changelog
  entry, and not every package depends on commons. Trade-off: duplicating the
  short fixture in six linted, typed test files versus one public addition;
  choose duplication, and merge into `commons.testing` later if the owner
  wants.
- Settled by the reviewer, 2026-11-14: results live in
  `docs/guides/performance-baselines.md` (procedure plus a table per baseline
  commit); reason: a guide survives the spec cut, a spec page does not.
- Docs builds are timed around the existing `task docs:build`
  (`/usr/bin/time -l` on macOS, `-v` on Linux); count is 11 strict builds
  (`tasks/docs.yml:13-39`).
- Wall-time never gates a test (F22.3 acceptance; `design.md` measurement plan).
  Operation counts may be asserted only where ordinary tests already would.

## Change

- **Change:**
    - Create `packages/<pkg>/tests/measure/conftest.py` per package below, holding
      the `measure(case, inputs, kind)` fixture described in Settled; it yields
      a `counts` dict and writes the line on exit.
    - Create `packages/<pkg>/tests/measure/test_<topic>.py` with a module-level
      `pytest.mark.skipif(not os.environ.get("PYKIT_MEASURE_OUT"), ...)`. Cases
      and what each records:
        - `rn-forge-cli`: cold (fresh `python -c`) and warm (second in-process)
          `run(app, ["--help"])`, plus
          `python -X importtime -c "import rn_forge.cli"`; wall, child
          `ru_maxrss`, import count; kind `tool startup`.
        - `rn-forge-commons`: 10,000 `AppLogger` records with logging disabled vs
          enabled to an in-memory handler; wall, peak, record count; kind `cpu`.
        - `rn-forge-web`: `run_checks_sync` with 8 checks sleeping 0.2 s, `timeout`
          unset and set; wall vs sum of sleeps; kind `io`.
        - `rn-forge-data`: `write_xlsx` then `load_workbook` of 50,000 rows by 10
          columns; byte size, wall, peak; kind `buffering`. Add the matching
          `web.transfer` export if it reaches `write_xlsx`.
        - `rn-forge-auth`: 100 verifications against a local JWKS server with a
          counting handler, forcing key rotation once; records fetch (request)
          count; kind `io`. Follow the server pattern in `tests/oidc/conftest.py`.
        - `rn-forge-sqlalchemy`: `upsert` of 33,000 rows then 33,000 mixed rows on
          SQLite; count statements through the `before_cursor_execute` engine
          event; kind `io`.
        - `rn-forge-cli` scaffold (root suite only): `built_wheels` build count and
          time, one `scaffold_venv` install time; kind `tool startup`.
    - Create `docs/guides/performance-baselines.md`: the procedure, the
      environment recorded (CPU, OS, Python, `uv --version`), and the `1a8da87`
      baseline table. Run `task docs:generate`; add the guide to
      `docs/guides/index.md` if generation does not.
- **Leave alone:** `Taskfile.yml`, `tasks/*.yml`, all `pyproject.toml`, root
  `conftest.py`, `rn_forge.commons.testing`, package `src/`, and existing
  tests.

## Tests first

The measurement cases are the tests. Each must be skipped with
`PYKIT_MEASURE_OUT` unset and, when set, append exactly one line with a nonzero
`wall_s`. Add one test per package asserting the skip and the line shape; it
fails before the helper exists.
