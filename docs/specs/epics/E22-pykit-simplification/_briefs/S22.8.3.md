# S22.8.3 — Separate OIDC responsibilities conservatively

Brief for
[S22.8.3](../F22.8-auth.md#s2283-separate-oidc-responsibilities-conservatively),
at `335293c`.

## Goal

`rn_forge.auth.oidc` is one 1,538-line module. Audit its responsibilities and
split only what a split can remove; close the coverage gaps named below; give
the key-set lifespan test a clock instead of a patch of PyJWT internals; measure
JWKS refresh latency and request counts; and remove the quadratic sweep in the
in-memory stores, which the measurement shows is worth removing.

## Settled

- Settled by the reviewer, 2026-11-16: no module split. Every public class and
  function is in `__all__` (`oidc.py:57-76`), and moving a public symbol means
  a re-export, which ADR-0002 forbids. The private helpers
  `_require_secure_url` (`:121`), `_new_jwks_client` (`:168`) and
  `_signing_key` (`:177`) all raise or depend on `TokenVerificationError`
  (`:95`, public), so a private module holding them would import `oidc` while
  `oidc` imports it (a cycle). A split would shed no dependency either: the
  `oidc` extra is one set (`pyproject.toml:26-31`) and importing
  `rn_forge.auth.oidc` loads all of it however the code is laid out. The module
  is already layered one way: discovery and key sets (`:78-190`), the three
  profiles (`:198-759`), the authenticator (`:764-905`), the provider
  (`:908-1470`), back-channel logout (`:1473-1538`). Leave that order; add no
  module and no base class.
- Settled by the reviewer, 2026-11-16: the clock seam is a private subclass of
  `jwt.PyJWKClient` in `oidc.py`, `_KeySetClient`, built by `_new_jwks_client`
  (the only constructor of key-set clients, `:168-174`; `from_jwks_url` of all
  three profiles goes through it). Today no verifier or client accepts a
  clock: the lifespan runs on `time.monotonic` inside PyJWT
  (`jwt/jwk_set_cache.py` `is_expired`), and the existing test patches
  `jwt.jwk_set_cache.time.monotonic`, which is the global `time` module, so it
  patches the whole process (`tests/oidc/test_verifier.py:150-156`). The seam:
  `_new_jwks_client(url, *, lifespan, cooldown_duration, clock=time.monotonic)`
  returns a `_KeySetClient` that
    - calls
      `super().__init__(url, lifespan=lifespan, cooldown_duration=cooldown_duration, timeout=5.0)`
      unchanged, so PyJWT still rejects `lifespan <= 0`, then sets
      `self.jwk_set_cache.lifespan = math.inf` so PyJWT's own expiry never fires
      (assert `jwk_set_cache is not None` for pyright);
    - overrides `fetch_data` to call `super().fetch_data()` and stamp
      `self._fetched_at = clock()`;
    - overrides `get_jwk_set(refresh=False)` to pass `refresh=True` when
      `_fetched_at` is set and `clock() > _fetched_at + lifespan` (strict, as
      PyJWT's `>`), then calls `super().get_jwk_set(refresh)`. The cooldown
      stays on PyJWT's `time.monotonic` (every successful fetch, including a
      lifespan refetch, still starts it); no test needs it clocked. Prototyped
      and run: with a fake clock, 100 s after the first fetch is still cached
      and 101 s refetches; `lifespan=0` still raises `PyJWKClientError`. Public
      signatures of `from_issuer`/`from_jwks_url` and `__all__` do not change;
      no `clock` argument is added to any public method (that would be a public
      API change and is not made here).
- Settled by the reviewer, 2026-11-16: the access-token profile has no replay (a
  bearer token is reusable until `exp`), and the ID-token profile has no
  replay store (single use comes from the consumed `LoginTransaction` nonce,
  covered by `tests/test_stores.py:129`). The ID-token profile also checks no
  `typ` header (`:507-555`): the docstring at `:8-9` is satisfied through
  required claims (`test_profiles.py:66`). Add no `typ` check and no test that
  pins the absence.
- Settled by the reviewer, 2026-11-16: the test-helper rule is already enforced
  by `.importlinter:240-242` (the core, `oidc` included, never imports
  `rn_forge.auth.testing`) and by `test_facade.py:20`, but nothing proves
  `import rn_forge.auth.oidc` leaves `rn_forge.auth.testing` unloaded, and the
  optional-extra guard (`test_facade.py:51-59`) checks only `jwt`, `authlib`
  and `redis`. Measured on this commit: after `import rn_forge.auth` none of
  `jwt`, `authlib`, `joserfc`, `requests`, `cryptography`, `redis` is loaded,
  and after `import rn_forge.auth.oidc` `rn_forge.auth.testing` is not loaded.
  `FakeIdP` (`tests/oidc/conftest.py:28`) is test-only. No source change for
  either item.
- Settled by the reviewer, 2026-11-16: the store sweeps are worth removing.
  `InMemoryReplayStore._purge` (`stores.py:160-162`), the inline rebuild in
  `InMemoryTransactionStore.save` (`:184`) and `InMemorySessionStore._purge`
  (`:275-276`) rebuild whole dicts on every write and read. Measured on this
  commit, filling `InMemoryReplayStore` with live records: 1,000 take 0.017 s,
  4,000 take 0.273 s, 16,000 take 4.522 s (16x then 16.6x for each 4x growth:
  quadratic). The fix keeps a lower bound on the earliest expiry and sweeps
  only when `now >= bound`; below. `context_cache.py` retention is S22.8.4's
  and is not touched.

## Change

- **Source, `oidc.py`:** add `_KeySetClient` and the `clock` parameter as
  settled; add `import math` (`time` is imported). `Callable` is imported. One
  comment saying why PyJWT's own lifespan is disabled (its expiry reads
  `time.monotonic` and cannot be clocked).
- **Source, `stores.py`:** in each store keep `_next_expiry` (`math.inf`, or
  `datetime.max` with UTC for the session store) as a lower bound on every
  stored expiry. `_purge(now)` returns at once while `now < _next_expiry`;
  otherwise it rebuilds as today and sets `_next_expiry` to the survivors'
  minimum (or infinity). Every write that stores an expiry lowers the bound to
  `min(bound, expiry)`: `record_once`, `revoke_sid`, `create`, `touch`,
  `rotate`, `save`. Move `save`'s inline rebuild into a `_purge` method. An
  entry is removed when `expiry <= now`, so the early return must be
  `now < bound`, not `<=`. One comment states the invariant. The shared replay
  bound covers `_seen` and `_revoked` together.
- **Leave alone:** every public signature and `__all__`; `context_cache.py`;
  `redis.py`; the cooldown; verification order and messages; `testing.py`;
  `.importlinter`.
- **Changelog:** `packages/rn-forge-auth/CHANGELOG.md` `[Unreleased]`: a
  `### Changed` entry (in-memory replay, transaction and session stores sweep
  expired records only when one can have expired, instead of on every call)
  and a patch-level versioning note, as S22.4.4 did for its measured fixes.
