# S22.5.1 — Specify and restore console lifetime

Brief for [S22.5.1](../F22.5-cli.md#s2251-specify-and-restore-console-lifetime),
at `1a8da87`.

## Goal

A root invocation of a `CliApp` must not leak its console mode or its log level
and file into the next same-process invocation. Today JSON or quiet mode
persists and later `--log-level`/`--log-file` values are ignored.

## Settled

- (reviewer, 2026-11-14) Console mode is captured on entry to
  `rn_forge.cli.app.run` and restored in a `finally` there, after the error
  report; this is the one boundary every embedded call (`app()`, `app.run`,
  `run`) crosses, and restoring in a Click close callback would run before
  `run()` reports an `AppException`, changing what a failed `--json`/`--quiet`
  command prints.
- (reviewer, 2026-11-14) A plain invocation sets nothing; it runs in the mode
  `run()` found on entry, which restoration keeps equal to the process
  baseline; the story's "effective mode" then holds without the CLI guessing
  the commons default.
- (owner, 2026-11-14) A root invocation reconfigures logging only when
  `--log-level` or `--log-file` was passed explicitly; otherwise existing
  logging configuration, including a host app's, is left alone. The first
  invocation in a process with nothing configured still initializes with the
  app default. Logging is not restored on exit, so the last explicit options
  stay active.
- (reviewer, 2026-11-14) Nested invocations restore last-in-first-out; inner
  explicit logging options replace the outer's for the rest of the process.
- Console mode stays owned by `rn_forge.commons.runtime.console`; `CliOptions`
  stays a value object (story acceptance). `--quiet` with `--json` stays a
  usage error, exit 2.
- E22 scope constraints: a behaviour change needs a regression test, a changelog
  entry and a versioning assessment.

## Current behaviour

- `options.py:135-141`: `apply` sets `JSON` or `QUIET` and never resets, so a
  plain invocation inherits the previous mode. A command-level conflict raises
  after the root callback already set a mode.
- `app.py:68-107` (`run`): no restore on any path, including the `except`
  branches.
- `app.py:153-170` (`_root`): `AppLogger.initialize(...)` without
  `force_reconfigure`, so only the first call ever applies.
  `commons/logging/logger.py:513-515` returns early when already configured,
  so level and file are ignored after the first call.
- `tests/test_options.py:26-34`: an autouse fixture resets logger and console
  state, hiding all of the above.

## Change

- **Change:**
    - `packages/rn-forge-cli/src/rn_forge/cli/app.py`: in `run`,
      `prior = console.mode` before invoking, and `console.set_mode(prior)` in a
      `finally` wrapping the existing `try`. In `_root`, call
      `AppLogger.initialize(..., force_reconfigure=explicit)`, where `explicit`
      is true when `ctx.get_parameter_source("log_level")` or `("log_file")` is
      not the default source (`ParameterSource` comes from Typer's vendored
      Click, like `ClickException`). Add one sentence to the `run` docstring:
      the console mode on return is the mode on entry.
    - `packages/rn-forge-cli/tests/test_lifecycle.py`: new, see below.
    - `packages/rn-forge-cli/CHANGELOG.md`: `[Unreleased]`, `### Fixed`, one entry
      per behaviour, plus a versioning assessment (patch).
- **Leave alone:** `options.py` logic, `rn-forge-commons` (console and logger),
  `surface.py`, `tests/test_options.py` (keep its fixture), the tooling
  package.

## Tests first

New `packages/rn-forge-cli/tests/test_lifecycle.py`. It has no autouse console
reset. Its fixture clears only logging (`AppLogger._configured`, root handlers)
and restores `console.mode` at teardown as a safety net. The app has commands
`show` (`console.print("hello")`; suppressed in quiet/JSON), `boom` (raises
`AppException`), `say TEXT` (logs TEXT at warning on `lifecycle.cmd`), `nested`
(calls `app.run(["--quiet", "show"])`, recording `console.mode` before and
after), and `strict` (calls
`CliOptions.from_context(ctx, json_output=True).apply(ctx)`). Drive everything
through `app.run` (the `run()` path that restores state), with `capsys`; no new
or changed test uses bare `CliRunner.invoke`. Each test below fails before the
change unless marked guard.

- `test_json_then_plain_prints_plain_output`: `["--json","show"]` then
  `["show"]` both return 0; the second prints `hello`.
- `test_quiet_then_plain_prints_plain_output`: same with `--quiet`.
- `test_failed_json_then_plain`: `["--json","boom"]` returns 1; then `["show"]`
  prints `hello`.
- `test_mode_after_run_equals_mode_before` (parametrized `--json show`,
  `--quiet show`, `--json boom`): mode after equals mode before.
- `test_conflict_at_root_does_not_leak` (guard): `["--quiet","--json","show"]`
  returns 2; mode unchanged.
- `test_conflict_at_command_level_does_not_leak`: `["--quiet","strict"]` returns
  2; mode unchanged; a following `["show"]` prints `hello`.
- `test_nested_run_restores_outer_mode`: `["--json","nested"]` records JSON
  before and after the inner run; the mode after the outer run equals the mode
  before it.
- `test_log_level_follows_each_invocation`: `--log-level info` then
  `--log-level debug`; the root level is `INFO` then `DEBUG`. A third run with
  no option leaves it `DEBUG` (fails before only for the first two steps).
- `test_host_logging_survives_invocation_without_log_options`: the test calls
  `AppLogger.initialize(root_logger_name="host", level=AppLogger.WARNING)` and
  adds a marker handler to the root logger. `app.run(["show"])` returns 0,
  then the root level is still `WARNING` and the marker handler is still
  attached. A guard before the change; it fails if `force_reconfigure` is
  unconditional.
- `test_log_file_follows_each_invocation`: `--log-file a.log say one` then
  `--log-file b.log say two` in `tmp_path`: `a.log` holds `one` and not `two`,
  `b.log` holds `two`, and no root handler still writes to `a.log`. Use `.log`
  suffixes so no timestamp is appended.

Existing tests that bypass `run()`: the ten `runner.invoke` tests of
`TestCliApp` in `tests/test_options.py` (lines 61-173). They do not move: they
assert single-invocation behaviour, and their autouse fixture
(`test_options.py:26-34`) stays. `TestJsonStaysParseable` and
`tests/test_app.py` already use `run()`. Add no lifecycle assertions to the
bypassing tests.

## Out of scope

Restoring logging on exit; a context-manager API on `console`; changes to
`AppConsole`, `AppLogger` or `CliOptions` fields; S22.5.2 consolidation;
rewriting the `test_options.py` fixture.
