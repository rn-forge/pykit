# S22.13.1 — Pin requirement-check behavior

Brief for [S22.13.1](../F22.13-devops.md#s22131-pin-requirement-check-behavior),
at `1a8da87`.

## Goal

Pin what `rn-forge-devops requirements` checks and how it exits, with tests on
temporary workspaces. A malformed requirement or manifest must exit differently
from an incompatible internal floor, and the documented contract must say which
forms are out.

## Settled

- Settled by the reviewer, 2026-11-14: exit 0 means no problems; exit 1 means at
  least one incompatible requirement (URL, excludes the member's version, no
  `<`/`<=` ceiling), one stderr line each, as today; exit 2 means invalid
  input and nothing was judged; 2 matches argparse's usage exit.
- Settled by the reviewer, 2026-11-14: invalid input is a malformed requirement
  string, a member manifest that lacks `[project]` or `name`, an unparsable
  `[project].version`, a workspace table without `members`, or no workspace
  found; the message is `<manifest path>: <reason>` and names the requirement
  text; no traceback.
- Settled by the reviewer, 2026-11-14: in contract and checked: `dependencies`,
  every `optional-dependencies` list, string items of `[dependency-groups]`;
  canonicalized names (`Rn_Forge.Cli` matches `rn-forge-cli`); extras
  (`a[x]>=1,<2`); a direct URL or path (`a @ https://...`) on a member,
  reported as URL; markers are ignored, so a marked requirement is checked as
  if unmarked.
- Settled by the reviewer, 2026-11-14: outside the contract, silently skipped
  and documented: a requirement on a non-member, including an excluded one;
  `include-group` entries in groups; a member glob matching no manifest; a
  member with no `version` (the version check is skipped, the ceiling check
  still runs); a self-reference.
- Settled by the reviewer, 2026-11-14: the ceiling stays `<` or `<=` only, so
  `~=` and `==` report "no ceiling"; this pins today's behaviour without
  changing it.
- The story says "package changelog selection", but `notes.py` selects release
  pages, not package changelogs; the release-note tests pin page selection.

## Current behaviour

- `requirements.py:68-95` `check_requirements`: `Requirement(text)` at line 89
  raises `InvalidRequirement` uncaught, so a traceback and exit 1, the same
  code as an incompatible floor.
- `requirements.py:32-55` `_members`: a missing `[project]`, `name` or `members`
  raises `KeyError`; a bad version string raises `InvalidVersion` at line 103.
- `requirements.py:98-107` `_problems`: URL, then excludes, then no ceiling.
- `cli.py:59-79`: `_requirements` returns 1 for problems; no workspace is
  `sys.exit(str(error))`, which is exit 1.
- `notes.py:42-79`: newest shipped page wins; `ValueError` when the H1 or
  `## Shipped` is missing, uncaught in `cli._umbrella` (`cli.py:51`).
- Tests: `tests/test_cli.py:12` covers one `no ceiling` case;
  `tests/test_notes.py` covers selection, tag exists, none, and one body case.

## Change

- **Change:**
    - `packages/rn-forge-devops/src/rn_forge/devops/requirements.py`: add
      `class InvalidManifest(ValueError)`. Raise it with the manifest path for
      the invalid-input cases above; thread each manifest's path through
      `_members`.
    - `packages/rn-forge-devops/src/rn_forge/devops/cli.py`: `main` catches
      `InvalidManifest` and `FileNotFoundError` from `find_root`, prints the
      message to stderr, and returns 2. Return an int instead of `sys.exit`.
    - `packages/rn-forge-devops/docs/reference/subcommands.md`: exit codes 0, 1
      and 2, and the in-contract and outside-contract lists. Update the
      `check_requirements` docstring to match.
    - `packages/rn-forge-devops/CHANGELOG.md`: under `[Unreleased]`,
      `### Changed`, one entry for the exit-2 path, and a one-line versioning
      assessment.
    - Tests below.
- **Leave alone:** `notes.py` behaviour (tests only), the `umbrella` exit codes,
  the packaging dependency, anything outside `packages/rn-forge-devops`.
