# S22.4.3 — Split only distinct responsibilities

Brief for
[S22.4.3](../F22.4-commons.md#s2243-split-only-distinct-responsibilities), at
`bef7973`.

## Goal

Decide whether logging record/configuration mechanics should leave `AppLogger`'s
module, and remove the duplicate logic the collection, dataclass and document
helpers hold beside libraries the package already uses. Keep what is a contract,
not a copy.

## Settled

- Settled by the reviewer, 2026-11-15: do **not** split `logging/logger.py`. The
  mechanics (`_brace_message`, `BraceLogRecord`, `EnrichFilter`,
  `RedactFilter`, `LoggingConfig`, `_configure_logging`,
  `_build_rich_console`, `_enable_otel_log_correlation`) never reference
  `AppLogger`; only `AppLogger.initialize`/`makeRecord` call them, so the
  dependency is already one-way. The convenience methods (level wrappers,
  audit, variables) hold no mechanics. A split would therefore move code
  without removing a dependency, and `_configure_logging` builds a dictConfig
  that names `EnrichFilter` and `RedactFilter`, so a partial split makes a
  cycle. A full split moves public documented classes
  (`docs/reference/logging/logger.md`, strict mkdocs) and rewrites
  `tests/logging/test_logger.py` imports for a size gain only. Record this
  verdict and its evidence in the F22.4 story; change no logging code.
- Settled by the reviewer, 2026-11-15: the S22.4.1/S22.4.5 contracts are fixed
  and untouched (ADR-0016: no process-factory replacement; disabled-call cost;
  caller attribution). This story changes no logging file.
- Settled by the reviewer, 2026-11-15: remove only two duplicates, each with a
  replacement in the same package (none comes from `dacite`, `ruamel.yaml` or
  `tomlkit`; they are internal copies):
    1. The JSON text `json.dumps(x, indent=2, sort_keys=True) + "\n"` is spelled
       twice, `documents.py:521` (`DocumentUtils.dumps`) and `:645`
       (`DocumentUtils.write_document`). One private `_json_document(value)`.
    1. The dotted-key-path join (`str(key).replace(".", "\\.")` then
       `f"{prefix}.{escaped}"`) is spelled in `collections.py:534-536`
       (`DictUtils.flatten`) and `:785-787` (`_deep_merge_layer`), the inverse
       of `_split_key_path` (`:769`). One private `_join_key_path(prefix, key)`
       beside it.
- Settled by the reviewer, 2026-11-15: these are intentional contract wrappers
  and stay: `DataclassMixin.from_dict` over `dacite`
  (`dataclasses.py:143-218`; adds dotted-path strict errors, the `ValueError`
  catch for enum values and the `cast` list), `_unknown_key_paths` (dacite
  strict reports one level, undotted), `_dataclass_to_dict` (`asdict` cannot
  read the `exclude` metadata and copies leaves), `_to_plain`
  (`documents.py:760`; stringifies keys and turns tuples into lists, which
  `tomlkit.unwrap` does not), `_yaml_load`/`_yaml_dump*` (typing isolation for
  ruamel), `_deep_update_document` (its docstring says why it is not
  `DictUtils.merge`), and `DictUtils.merge` versus `_deep_merge_layer`
  (different semantics: in place vs provenance and append paths).
  `ListUtils.sort/filter/get` stay: public API with logging.
- The curated public API (`rn_forge.commons` facade, each `__all__`) is
  unchanged; no symbol moves, so ADR-0002 aliasing does not arise. No new
  dependency or package. Optional template/Markdown/generation imports stay
  out of the base facade, guarded by `tests/test_facade.py`.

  add `_join_key_path(prefix: str, key: object) -> str` beside

  `YamlUtils`, `ListUtils`, `DictUtils.merge`, `_to_plain`, facades and
