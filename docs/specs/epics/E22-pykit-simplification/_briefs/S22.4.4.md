# S22.4.4 — Remove measured allocation and algorithm costs

Brief for
[S22.4.4](../F22.4-commons.md#s2244-remove-measured-allocation-and-algorithm-costs),
at `7f11a7c`.

## Goal

`ContentHash.of_file` reads a whole file into memory, `TaskPool.submit` counts
names with a quadratic scan, and `DictUtils.merge` deep-copies override subtrees
again at every level. Stream the digest now; change the other two only if a
recorded measurement shows the cost.

## Settled

- Settled by the reviewer, 2026-11-15: `of_file` uses
  `hashlib.file_digest(handle, algorithm)` on a file opened `"rb"`. The
  package requires Python `>=3.14` (`pyproject.toml:18`), and `file_digest`
  exists since 3.11, so no fallback and no hand-rolled chunk loop.
- Settled by the reviewer, 2026-11-15: the contract is unchanged: `None` when
  the path is not a regular file (missing or a directory), the same hex string
  as `ContentHash.of` over the full bytes, an unknown algorithm still raises
  `ValueError`, and `of`'s signature and behavior are untouched.
- Settled by the reviewer, 2026-11-15: record baselines for all three workloads
  before changing any source. Record order is baseline, change, comparison,
  with the same inputs.
- Settled by the reviewer, 2026-11-15: duplicate detection changes only if the
  baseline wall time grows faster than linearly across the three sizes (about
  16x time for 4x names at the larger step) and the largest size takes more
  than 50 ms. The replacement is one pass with `collections.Counter`, keeping
  `sorted(...)` of the names with a count above one, so the error text and
  order are identical. If the measurement does not show it, leave the code and
  record the numbers.
- Settled by the reviewer, 2026-11-15: deep merge changes only if the nested
  workload's peak traced memory or wall time falls by more than 30% with the
  change; the check is the comparison record, not a unit test. The change is
  copy-on-assignment: recurse with the uncopied `value` when both sides are
  dicts, otherwise assign `copy.deepcopy(value)`. If the measurement does not
  show it, leave the code and record the numbers.
- Settled by the reviewer, 2026-11-15: no timing threshold becomes a test; the
  digest memory bound below is a retention bound, not a timing.
- Settled by the reviewer, 2026-11-15: `DictUtils.merge_layers` and
  `_deep_merge_layer` (`collections.py:776`) are not touched; they copy once
  per assignment already.

## Current behaviour

`packages/rn-forge-commons/src/rn_forge/commons/`:

- `fs/hashing.py:21-26`: `of_file` returns
  `ContentHash.of(p.read_bytes(), algorithm=algorithm)` when `p.is_file()`,
  else `None`. The whole file is in memory, then hashed. Callers:
  `rn-forge-tooling` `install/release.py:177` (archive checksum) and tooling
  `tests/install/test_lifecycle.py:166`.
- `runtime/tasks.py:260-263`: `TaskPool.submit` builds `task_names`, then
  `sorted({name for name in task_names if task_names.count(name) > 1})`, which
  is O(n^2) in batch size. A non-empty result logs a warning and raises
  `AppException("Duplicate task names in submit(): {}", duplicate_names)`
  (`:264-269`) before any task starts. A name already in `self._tasks` raises
  `"Task name already submitted: {}"` later (`:271-277`).
- `lang/collections.py:430-441`: `_merge_key` deep-copies `value` first
  (`:432`), then, if both sides are dicts, recurses with the copy (`:435`),
  which copies every nested value again at the next level. A subtree is copied
  once per level of depth. The final assignment is the copy (`:441`). `merge`
  skips empty/`None` overrides (`:413`) and mutates `target` in place.
- Existing tests: `tests/fs/test_state.py:97` `TestContentHash` (digest,
  str/bytes, missing and directory give `None`, small file);
  `tests/runtime/test_tasks.py:205` (duplicate in batch, duplicate from prior
  submit, message only); `tests/lang/test_collections.py:132-182` (merge,
  `test_deep_copy_prevents_shared_refs`).
- Measurement harness (S22.3.2): `tests/measure/conftest.py` provides the
  `measure(case, inputs, kind)` context manager, which appends one line with
  commit, wall time, traced peak and `counts` to
  `$PYKIT_MEASURE_OUT/results.jsonl`. Each case module sets
  `pytestmark = pytest.mark.skipif(not os.environ.get("PYKIT_MEASURE_OUT"), ...)`
  (`test_logging.py:17`), and `test_contract.py` requires it. Procedure and
  tables: `docs/guides/performance-baselines.md`.

## Change

- **Change:** `fs/hashing.py`: open the file `"rb"` and return
  `hashlib.file_digest(handle, algorithm).hexdigest()`; keep the `is_file()`
  check and `None`. Update the docstring only if the contract text changes.
- **Change:** add `tests/measure/test_costs.py` with the skip marker and three
  cases using `measure`: `file_digest` (kind `io`; files of 8, 64 and 256 MiB
  written in 1 MiB chunks under `tmp_path`; counts `bytes`),
  `task_duplicate_check` (kind `cpu`; 1,000, 4,000 and 16,000 unique names
  through `TaskPool.submit` with trivial tasks, `max_workers=1`; counts
  `names`), `dict_merge` (kind `cpu`; a tree of depth 8 with fan-out 4 merged
  into an empty and into an equal tree; counts `leaves`). Set `max_workers`
  and shut the pool down in every case.
- **Change:** run the three cases at `7f11a7c` for the baseline, then after the
  source change; add one section to `docs/guides/performance-baselines.md`
  (commit, same environment lines, table of inputs, wall, peak, counts, and a
  sentence per workload saying changed or left, with the rule from Settled).
  Add a `### Changed` line under `[Unreleased]` in
  `packages/rn-forge-commons/CHANGELOG.md`: file digests no longer read the
  whole file into memory. Add a line for each of the other two only if
  changed.
- **Change (conditional):** `runtime/tasks.py` and `lang/collections.py` as in
  Settled, only where the rule is met.
- **Leave alone:** `ContentHash.of`, `merge_layers`, tooling callers, the
  `logging` package, every dependency.
