consumer find install, a minimum example, optional extras and error behaviour.

nothing else.

### C. Scaffold fixture and tooling commands (15 edits)

Scaffold behaviour, from `conftest.py`: `built_wheels` builds each workspace
wheel once per session; `scaffold_venv(*requirements)` makes a clean venv and
installs the requirements with a uv `--override` file that maps **every** built
wheel to `name[extras] @ file://wheel`. A requirement naming a workspace package
is served by its wheel; anything else resolves from the index. The override
replaces each sibling requirement whole (its version range and its extras), so
an extra a sibling needs is named in the `install(...)` call; the call sites do
this (`rn-forge-web[security]` beside `rn-forge-fastapi[sse]`). The override
ignores the range, so a scaffold install does not prove a range resolves;
`ci:verify-release` does (see
[workspace boundaries](../../../../architecture/workspace.md) on the same
point). Extras in the existing call sites (`pydantic`, `pandas`, `security`,
`drf`, `transfer`, `openapi`, `cors`, `otel`, `sse`) all exist in the
`pyproject.toml` files; only the docstring example is invalid.
