# S22.10.1 — Validate only where required

Brief for [S22.10.1](../F22.10-fastapi.md#s22101-validate-only-where-required),
at `1a8da87`.

## Goal

The FastAPI `idempotent` decorator must not read or parse a safe request's body,
and must answer malformed JSON on an unsafe request with a problem response, not
an unhandled exception.

## Settled

- Settled by the reviewer, 2026-11-14: malformed unsafe JSON: raise
  `fastapi.HTTPException(400, "Request body is not valid JSON")`; the problem
  handlers already render it as the `bad-request` 400 row
  (`fastapi/problem.py:136-146`), matching DRF, where malformed JSON is a
  `ParseError` rendered as a 400 problem
  (`django/tests/drf/test_problem_details_exception_handler.py:84`). No new
  `rn_forge.web` exception.
- The body is still parsed before the key check on an unsafe request (existing
  order); both outcomes are 400 problems.
- Documented replay contract, status codes (400 missing key, 422 reuse, 409
  in-flight) and `run_idempotent_async` are unchanged.

## Current behaviour

`packages/rn-forge-fastapi/src/rn_forge/fastapi/idempotency.py`, `wrapper`
(54-78):

- Line 66 `raw_body = await request.body()` and line 72
  `json.loads(raw_body) if raw_body else None` run for every method, before
  `run_idempotent_async` can bypass a safe one (web `idempotency.py:282-284`).
  A GET with non-JSON bytes, or a POST with malformed JSON, raises
  `json.JSONDecodeError`/`UnicodeDecodeError` (both `ValueError`) out of the
  route: an unhandled 500.
- `execute` (61-64) keeps the original `Response`, so first-execution headers
  survive; replay (76-77) builds a `JSONResponse`.

Tests: `packages/rn-forge-fastapi/tests/test_idempotency.py` (`build_app` counts
handler calls in `app.state.calls`; `problem()` asserts status and
`PROBLEM_MEDIA_TYPE`). Existing tests assert statuses but not handler counts for
the key-required, reuse and replay cases.

## Change

- **Change:** `fastapi/idempotency.py`, `wrapper`: for a method in
  `rn_forge.web.SAFE_METHODS` (compare `request.method.upper()`) pass
  `body=None` without calling `request.body()`. For others, read the body and
  `json.loads` it inside `try/except ValueError`, raising the 400
  `HTTPException` `from` the cause. Update the docstring (contract: a
  malformed JSON body on an unsafe method is a 400 problem; a safe method's
  body is not read).
- **Change:** `packages/rn-forge-fastapi/CHANGELOG.md`, `## [Unreleased]`, a
  `### Fixed` entry.
- **Leave alone:** `rn_forge.web` (including the `SAFE_METHODS` definition,
  import it), `fastapi/problem.py`, the Django decorator.
