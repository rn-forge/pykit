# S22.11.2 — Remove measured bulk overhead

Brief for
[S22.11.2](../F22.11-sqlalchemy.md#s22112-remove-measured-bulk-overhead), at
`be88ead`.

## Goal

`upsert` keeps the keyed input, a list of its keys, every existing row it
fetched and the full write list alive at once. Classify one read chunk at a
time, drop each chunk's records after use, and prove with the S22.3.2 harness
that the S22.11.1 targets are met.

## Settled

- Settled by the owner, 2026-11-14 (S22.11.1): counts are the pre-write
  snapshot; `upsert` takes no locks; the 33,000-row targets are at most 16 MiB
  traced peak for all-new rows and 12 MiB for mostly unchanged rows (today
  about 28.4/29.5 and 14.1/15.7 MiB, single/composite), at most 38/75
  statements, zero statements for empty input and rejected duplicates, no
  write for unchanged rows, and no median time regression over five runs.
- Settled by the reviewer, 2026-11-15: the write stays one
  `INSERT … ON CONFLICT` execution, not batches. The target is 38/75
  statements, which is exactly 37/74 reads plus one write, so any extra write
  statement breaks it. The write list is bounded by the changed rows only, and
  the docstring says so.
- Settled by the reviewer, 2026-11-15: validation stays a full first pass
  (missing columns, duplicate keys) before any query, so a rejected input runs
  zero statements and error order is unchanged. The identity set is freed
  before the first read.
- Settled by the reviewer, 2026-11-15: classification moves into the read loop,
  one chunk at a time. The counts are still the snapshot of reads made before
  the single write; `_existing` keeps its name and is called once per chunk
  (the concurrency tests wrap it).
- Settled by the reviewer, 2026-11-15: if the 16 MiB all-new target is still
  missed after the change, the write list is the remainder. Then, and only
  then, bind the four audit values once with `insert.values(...)` instead of
  copying them into every row dict. Verify on SQLite and PostgreSQL. If the
  target is still missed, report the measured figures; do not raise the target
  or `_MAX_PARAMETERS`.
- Settled by the reviewer, 2026-11-15: keyset code and tests are not changed
  unless a gap below proves real. No new dependency; the SQLite and Alembic
  wrappers stay.

## Change

- **Change:** `upsert.py` only. After validation, keep the key identities as a
  set only until the dialect check, then free it. Replace `_keyed`'s dict with
  that validation set plus the `rows` sequence; remember `len(rows)` for
  `skipped`. Loop `itertools.batched(rows, _MAX_PARAMETERS // len(key))`:
  build the chunk's identities, `await _existing(...)` for that chunk,
  classify it into `to_write`, and let the chunk's records go. Delete
  `_chunks`. Build each write row once (`{c: row[c] for c in columns}` then
  `.update(stamps)` with a shared stamps dict). Execute the single upsert
  after the loop. Update the docstring: the write list holds the changed rows
  only.
- **Leave alone:** duplicate-key message, `ValueError`/`TypeError`/
  `NotImplementedError` order, zero statements for empty or rejected input,
  audit columns, never committing, `_MAX_PARAMETERS`, `pagination.py`,
  `sqlite.py`, `migrate.py`.

## Tests first

Add to `tests/test_upsert.py` (`_upsert` and `_rows` exist):

1. `test_existing_rows_are_read_and_released_per_chunk`: seed 2,000 rows,
   commit, upsert the same rows. Wrap `_existing` as the race test does,
   return a `dict` subclass and hold a `weakref` to each result. Assert three
   calls, each with at most 900 identities, and that every earlier result is
   dead when the next call starts. Fails today: one call with 2,000
   identities.
1. `test_a_duplicate_in_the_last_chunk_runs_no_query`: 2,000 rows, last row
   repeats the first; `ValueError` match `duplicate key`, zero statements
   (`before_cursor_execute` as in `test_empty_rows_runs_no_query`). Passes
   today; guards the validate-first design.
1. `test_a_row_missing_a_column_in_the_last_chunk_runs_no_query`: same, with the
   last row lacking `qty`. Passes today; guard.
1. `test_statement_count_is_reads_plus_one`: 2,000 changed rows, assert
   `ceil(2000 / 900) + 1` statements and one write. Passes today; guard.

Existing guards that must keep passing: `:104` (33,000 rows), `:54`, `:70`
(audit), `:82` (rollback), `:92` (duplicates), the composite key test, and both
S22.11.1 concurrency tests on SQLite.
