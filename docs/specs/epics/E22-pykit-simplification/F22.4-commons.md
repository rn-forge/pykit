Simplify logging and generation around accurate contracts and a single owner for
process-wide configuration.

## Context

`logging/logger.py` has 1,138 lines. `_register_levels_and_class` replaces the
process LogRecord factory when it differs from `BraceLogRecord`; logger
acquisition calls this registration. `generation/artifacts.py:250-252` reports
every change path as `written`, irrespective of action. `fs/hashing.py:25` reads
complete files; task duplicate detection uses repeated `list.count` calls
(`runtime/tasks.py:260-263`), and deep merge recopies override subtrees
(`lang/collections.py:430-438`). These prove avoidable work, not user-visible
bottlenecks.

## S22.4.1 — Protect logging composition

**State:** New · **Depends on:** S22.4.5

Separate one-time explicit configuration from ordinary retrieval, and compose
brace records with other factories as S22.4.5 decided.

**Acceptance:**

- After explicit initialization, installing a custom record factory and
  retrieving another logger preserves the chosen composition and custom
  fields.
- Brace formatting, redaction, exception logging, caller attribution and
  concurrent retrieval retain behavioral tests; disabled levels do not inspect
  frames or format values unnecessarily.
- Record disabled/enabled-call and cold-import costs before and after; named
  application calls retain their actual source location rather than
  forwarding-wrapper locations.

## S22.4.2 — Report actual generation effects

**State:** New

Make `ApplyResult.written` match its documented byte-change semantics. Define
deletion, dry-run, state-only forget and multiple-block behavior explicitly
before changing reporting.

**Acceptance:**

- Mixed CREATE/UPDATE/UNCHANGED/SKIP/FORGET/REMOVE and dry-run plans produce
  documented results, with unique paths where bytes changed.
- Atomic apply, CRLF preservation, drift detection, managed-block replacement
  and rollback failure cases retain coverage.
- Classification/reporting has one owner; reporting fixes do not cause new
  filesystem writes.

## S22.4.3 — Split only distinct responsibilities

**State:** New · **Depends on:** S22.4.1

Separate logging record/configuration mechanics from convenience methods if it
reduces coupling. Review collection/dataclass/document helpers against already
adopted libraries; keep intentional contract wrappers.

**Acceptance:**

- Every moved responsibility has one implementation and the curated public API
  remains supported.
- The change lists removed duplicate logic and shows equivalent contract cases;
  no new dependency or new package is required.
- Optional template/Markdown/generation imports remain outside the base facade.

## S22.4.4 — Remove measured allocation and algorithm costs

**State:** New · **Depends on:** S22.3.2

Use standard-library streaming hashing for file digests. Measure duplicate
detection and deep merge before replacing repeated scans/copies with one-pass or
copy-on-assignment logic.

**Acceptance:**

- Empty, small and multi-chunk files have identical digests and preserve the
  missing-file contract; large-file peak memory no longer includes a complete
  archive copy.
- Task duplicate rejection preserves ordering/error behavior and configuration
  merges preserve mutation isolation, deletion and override semantics.
- Record time/memory at increasing input sizes; no new library or broad utility
  rewrite is required.

## S22.4.5 — Decide how brace records compose with other factories

**State:** New

Reproduce logger acquisition overwriting a consumer-installed record factory.
Compare composing over the installed factory, an explicit opt-in install and a
formatter-level brace style, against tracing and consumer factories.

**Acceptance:**

- A failing test reproduces the overwrite.
- An ADR records the chosen composition, when it is installed, and the rejected
  options.
