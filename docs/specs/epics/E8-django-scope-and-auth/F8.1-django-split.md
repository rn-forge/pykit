# F8.1 — Decide Django package scope

**Status:** done · **Implemented:** 2026-09-26 (decision; no code change) · **Owner:** pykit · **Epic:** [E8](index.md) · **Release:** [release-1](../../../releases/release-1/index.md)

**Depends on:** the current import graph and [ADR-0002](../../../adr/ADR-0002.md).

**Source:** `plans/archive/plan-board.md`, "Backlog (revisit later, not scheduled)"; `plans/archive/standards-rebaseline-plan.md`, R6.

`rn-forge-django` carries four optional areas: SAML, Celery, fixtures and messaging. Once its first coordinated tag exists, moving any of them to another package breaks consumers' imports, and compatibility re-exports are not allowed. So the owner decides the package boundary before [F9.6](../E9-release-readiness/F9.6-tag-cut.md) cuts tags.

## Stories

### S8.1.1 — Record the split decision

**Status:** done (2026-09-26)

**Acceptance:**

- The owner records, for each of SAML, Celery, fixtures and messaging, whether it stays in `rn-forge-django` or moves, and the resulting package graph.
- If any area moves, a new feature for the move exists and is in release-1's scope, and the [release-1 matrix](../E9-release-readiness/F9.4-batch-scope.md#scope) reflects the new packages.

## Decision

All four areas stay in `rn-forge-django` for release-1, behind their existing extras (Q4, answered 2026-09-26). The package graph is unchanged, so the [release-1 matrix](../E9-release-readiness/F9.4-batch-scope.md#scope) needs no new packages.

The owner will revisit the boundary when the auth flow is designed, in [F8.2](F8.2-auth-review.md). A split after release-1 breaks imports, so it would ship as a breaking version of `rn-forge-django`.
