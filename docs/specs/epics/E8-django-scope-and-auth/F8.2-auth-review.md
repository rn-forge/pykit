## Stories

### S8.2.1 — Review the complete auth surface

**Status:** deferred

**Acceptance:** Owner schedules a consumer-led review and records login, session and token boundaries before any behavior change.

## Scope

Review `rn_forge.django.auth` and the related web and FastAPI auth surfaces together. Preserve existing behavior until a separate design decision and implementation task exist.

## Owner note

> SAML is a login flow into the provider. once logged in, it is a post back into the backend from where it could issue a JWT and all furture frontend to backend conversations happen using that JWT

This sentence is carried verbatim from the source. It raises a design question; it does not change the current session or token flow.

## Acceptance

- The review states the desired login, session and token boundaries with a named consumer.
- Any approved behavior change receives its own implementation acceptance before code changes.

## Open questions

Should a SAML post-back establish a session, issue a JWT for subsequent frontend requests, or support both? Resolve the owner note against a named consumer and record login, session and token boundaries before implementation.
