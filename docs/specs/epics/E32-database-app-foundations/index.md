A FastAPI application on PostgreSQL, built on `rn-forge-sqlalchemy`, starts by
writing the same plumbing every such application writes again: a test fixture
that gives each test its own PostgreSQL schema and skips without a database, an
Alembic `env.py` copied from the usage guide, and a typed settings object read
from prefixed environment variables. This epic moves those three into the
packages that already own their neighbours: the fixture and the `env.py` helper
into `rn-forge-sqlalchemy` ([F32.1](F32.1-postgres-test-schema.md),
[F32.2](F32.2-alembic-env-helper.md)), and typed settings into
`rn-forge-commons` ([F32.3](F32.3-typed-env-settings.md)). Each feature ships
alone.

## Context

Requested by the owner on 2026-11-22, from a review of SpendLens's foundation
epic. SpendLens is a household-finance FastAPI application on PostgreSQL 17. Its
foundation work splits three ways:

| SpendLens foundation work | Where it goes |
| -- | -- |

| Alembic `env.py` and migrations into a named schema | [F32.2](F32.2-alembic-env-helper.md) |
| Typed settings from `<APP>_*` environment variables | [F32.3](F32.3-typed-env-settings.md) |
| `asyncpg` and `alembic` dependencies | Already here: the `postgres` and `migrations` extras ([F30.1](../E30-postgresql-support-in-rn-forge-sqlalchemy/F30.1-postgresql-engine-and-driver-extras.md)) |

## Considered and rejected

- **A `db upgrade` command shipped by `rn-forge-sqlalchemy`.** It would make the
  package depend on `rn-forge-cli` for about ten lines that call
  `run_migrations`. The application keeps the command.
- **An identity-key or `created_at` mixin.** `Base`, `AuditMixin` and
  `NAMING_CONVENTION` already set the conventions. An application that wants
  `created_at` instead of `create_time` loses `upsert`, which is a reason to
  adopt `AuditMixin`, not to add a second mixin.
- **`VARCHAR` plus `CHECK` enumeration helpers.** SQLAlchemy's
  `Enum(native_enum=False, create_constraint=True)` already does it.
