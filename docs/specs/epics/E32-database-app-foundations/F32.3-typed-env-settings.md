An application declares its settings as typed fields with an environment prefix
and loads them from a mapping in one call: strings, paths, booleans, integers
and decimals are parsed, a bad value fails naming its variable, and every bad
variable is reported at once.

## Context

Every application writes this loader by hand: a frozen dataclass, one
`env.get(...)` per field, and a parse helper for each type. `Environment` in
`rn-forge-commons` reads single variables, and `AppUtils.parse_bool` parses one
value, but nothing builds a typed object from a prefix. ADR-0001 rule 1 says a
maintained library comes before a hand-rolled one, and `pydantic-settings` is
that library, so how to build it is a decision of its own
([S32.3.1](#s3231-decide-the-settings-foundation)).

## Design

[ADR-0018](../../../adr/ADR-0018.md) settles it: `EnvSettings`, its `load`
classmethod and `SettingsError` in `rn_forge.commons.lang.settings`, wrapping
`pydantic-settings` behind the `settings` extra. The contract, which S32.3.2's
acceptance checks:

- A settings class declares typed fields with defaults and an environment
  prefix, such as `APP_`; field `database_url` reads `APP_DATABASE_URL`.
- Loading takes an explicit mapping, defaulting to `os.environ`, so a test
  passes a dict. It never reads a `.env` file unless the class asks for one.
- `str`, `Path`, `bool`, `int` and `Decimal` fields are parsed. A boolean
  accepts the tokens `AppUtils.parse_bool` accepts, in any case. A `Decimal`
  is parsed from the text, never through `float`.
- Invalid values raise one `AppException` subclass whose message names every
  invalid variable, not only the first, the same way `Environment.require`
  does.
- The result is immutable.

## S32.3.1 — Decide the settings foundation

**State:** Closed (2026-11-22)

**Acceptance:**

- The owner chooses one of the options below, and the choice is recorded in an
  ADR with the API it fixes: the class or function names, the module and the
  extra.
- If the choice adds a dependency, the ADR records the owner's approval of it.

| Option | For | Against |
| -- | -- | -- |
| **A. Wrap `pydantic-settings`** in a new `rn-forge-commons[settings]` extra, next to the existing `pydantic` extra | ADR-0001 rule 1: a maintained library, already the FastAPI norm. Nested models, secrets directories and `.env` support come for free when an application wants them. | A new dependency (`pydantic-settings`, which brings `python-dotenv`). Pydantic's `ValidationError` has to be translated into an `AppException`. |
| **B. A stdlib loader** for frozen dataclasses, parsing by field annotation, in core `rn-forge-commons` | No dependency; matches the frozen-dataclass configuration rule in ADR-0001 rule 2. Fits a command-line tool that has no pydantic. | Hand-rolled. It meets ADR-0001's exception only if it stays a few lines, and every new field type grows it. |

Recommendation: **A**. Every web application on pykit already installs pydantic
through `rn-forge-web`, so the extra adds one small package, and the loader
never has to grow its own type parsing.

Outcome: the owner chose **A** and approved the dependency on 2026-11-22
([ADR-0018](../../../adr/ADR-0018.md)).

## S32.3.2 — Build typed settings

**State:** Closed (2026-11-22) · **Depends on:**
[S32.3.1](#s3231-decide-the-settings-foundation)

**Acceptance:**

- The API recorded in [ADR-0018](../../../adr/ADR-0018.md) exists in
  `rn_forge.commons.lang.settings`, outside the `rn_forge.commons` facade
  ([ADR-0003](../../../adr/ADR-0003.md)), and its docstrings follow the
  README's conventions. `pyproject.toml` declares the `settings` extra, and
  `all` includes it.
- `test_settings_defaults_with_empty_mapping`: loading from `{}` returns every
  default.
- `test_settings_prefix_maps_fields`: each `APP_<FIELD>` in a mapping overrides
  its field, and each value has its annotated type.
- `test_settings_bool_rejects_unknown_token`: `APP_ENABLED=maybe` raises the
  settings error naming `APP_ENABLED`.
- `test_settings_decimal_kept_exact`: `APP_CAP=0.10` gives `Decimal("0.10")`.
- `test_settings_reports_every_invalid_variable`: two invalid variables raise
  one error naming both.
- `test_settings_ignores_dotenv_file`: a `.env` file in the working directory
  changes nothing.
- `test_settings_are_immutable`: assigning to a field raises.
- The `rn-forge-commons` usage guide gains a *Settings* section.
