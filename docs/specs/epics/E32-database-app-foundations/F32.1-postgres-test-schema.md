`rn-forge-sqlalchemy` ships a pytest fixture that gives each test a fresh
PostgreSQL schema and an engine whose connections use it, skips when no database
is configured, and drops the schema afterwards. `create_postgres_engine` gains
the `search_path` setting the fixture needs.

## Context

Every PostgreSQL application writes this fixture, and pykit's own tests have a
weaker one: `packages/rn-forge-sqlalchemy/tests/conftest.py` runs `create_all`
and `drop_all` on the shared database, so two workers under `-n auto` share
tables. A schema per test removes that, and a fixture with a random schema name
needs no cleanup between runs.

## Design

**`create_postgres_engine(..., search_path: str | None = None)`.** When given,
it joins `timezone`, `application_name` and `statement_timeout` in the asyncpg
`server_settings`. An empty string raises `ValueError`.

**`rn_forge.sqlalchemy.testing`**, behind a new `testing` extra:

```toml
testing = ["pytest>=9.1.1", "pytest-asyncio>=1.4.1.post1"]
```

The floors are the versions `uv.lock` resolves today. The fixture also needs the
`postgres` extra, for asyncpg. The root `rn_forge.sqlalchemy` package does not
import `testing`.

- An application loads it explicitly with
  `pytest_plugins = ["rn_forge.sqlalchemy.testing"]` in its root
  `conftest.py`. There is no `pytest11` entry point, so installing the extra
  never changes another project's test run.
- The plugin registers the marker
  `postgres: needs a PostgreSQL server (DSN from rn_forge_postgres_dsn_env)`
  and an ini option `rn_forge_postgres_dsn_env`, the name of the environment
  variable holding the DSN. The default is `RN_FORGE_TEST_POSTGRES_DSN`.
- The fixture `postgres_schema`, function scoped, yields a frozen dataclass:

```python
@dataclass(frozen=True)
class PostgresSchema:
    name: str            # "t_" + uuid4().hex
    url: str             # the DSN with the postgresql+asyncpg driver
    engine: AsyncEngine  # create_postgres_engine(url, search_path=name)
```

- With the variable unset or empty, the fixture calls `pytest.skip` naming the
  variable.
- On teardown it disposes the engine, then drops the schema with `CASCADE` over
  a separate connection, even when the test failed.

## S32.1.1 — `search_path` on `create_postgres_engine`

**State:** New

**Acceptance:**

- `create_postgres_engine` takes `search_path` as in the Design, and its
  docstring documents it.
- `test_postgres_engine_search_path_in_server_settings`: with
  `search_path="s1"`, the engine's connect arguments carry
  `server_settings["search_path"] == "s1"`; without it, the key is absent.
- `test_postgres_engine_rejects_empty_search_path`: `search_path=""` raises
  `ValueError`.
- `test_postgres_engine_connection_uses_search_path` (marked `postgres`):
  `SHOW search_path` on a connection returns the value given.
- The usage guide's PostgreSQL engine section lists the parameter.

## S32.1.2 — The `postgres_schema` fixture

**State:** New · **Depends on:** S32.1.1

**Acceptance:**

- `rn_forge.sqlalchemy.testing` defines `PostgresSchema` and the
  `postgres_schema` fixture as in the Design, and `pyproject.toml` declares
  the `testing` extra.
- `test_postgres_schema_skips_without_dsn`: through `pytester`, a test using the
  fixture with the variable unset is reported as skipped, and the skip reason
  names the variable.
- `test_postgres_schema_reads_configured_variable`: through `pytester`, with
  `rn_forge_postgres_dsn_env = "APP_DSN"` in the ini and only `APP_DSN` unset,
  the skip reason names `APP_DSN`.
- `test_postgres_schema_registers_marker`: through `pytester` with
  `--strict-markers`, a test marked `postgres` is collected without error.
- `test_postgres_schema_isolates_tables` (marked `postgres`): a table created in
  one test is not visible to a second test.
- `test_postgres_schema_dropped_after_test` (marked `postgres`): after the
  fixture's teardown, including after a failing test, the schema is absent
  from `information_schema.schemata`.
- `test_package_root_does_not_import_testing`: importing `rn_forge.sqlalchemy`
  leaves `rn_forge.sqlalchemy.testing` and `pytest_asyncio` out of
  `sys.modules`.
- The usage guide gains a *Testing against PostgreSQL* section: loading the
  plugin, the ini option, the marker, and the CI integration table that
  exports the DSN.

## S32.1.3 — pykit's own PostgreSQL tests use the fixture

**State:** New · **Depends on:** S32.1.2

**Acceptance:**

- The `postgres` branch of `packages/rn-forge-sqlalchemy/tests/conftest.py`
  builds its engine from `postgres_schema` and no longer runs `drop_all` on
  the shared database. The SQLite branch is unchanged.
- The `postgres` marker is no longer declared in the package's
  `[tool.pytest.ini_options]`, since the plugin registers it.
- `task test` passes with `RN_FORGE_TEST_POSTGRES_DSN` set, and again without
  it, with the `postgres` tests skipped.

## Acceptance

```bash
set -euo pipefail
task test       # S32.1.1, S32.1.2, S32.1.3: postgres tests skip without a DSN
task validate   # S32.1.1, S32.1.2, S32.1.3
rg -q 'testing = \[' packages/rn-forge-sqlalchemy/pyproject.toml          # S32.1.2
rg -q 'postgres_schema' packages/rn-forge-sqlalchemy/tests/conftest.py    # S32.1.3
RN_FORGE_TEST_POSTGRES_DSN=postgresql://ci:ci@localhost:5432/ci task test  # S32.1.1–3, with a server up
```

Not scriptable: starting a PostgreSQL server for the last line.
