# S32.2.1 — `run_env`

Brief for [S32.2.1](../F32.2-alembic-env-helper.md#s3221-run_env), written on
`feature/release-12` while S32.1.3 runs. S32.1.3 touches only
`tests/conftest.py`, `tests/test_testing.py` and the pytest ini. Read the
feature's Design first. `run_env`'s behaviour is settled there.

## Goal

`rn_forge.sqlalchemy.migrate.run_env(target_metadata, **configure)` replaces the
`env.py` that applications copy from the usage guide.

## Settled

- **File:** `packages/rn-forge-sqlalchemy/src/rn_forge/sqlalchemy/migrate.py`.
  Set `__all__ = ["run_env", "run_migrations"]`.

- **Signature:**
  `def run_env(target_metadata: MetaData | None, **configure: Any) -> None`.
  It has a Google-style docstring with `Args:` and `Raises:`, and an example
  that shows the two-line `env.py`.

- **Behaviour,** in order:

    1. `config = context.config`, using `from alembic import context`.
    1. If `config.config_file_name` is set and
       `config.attributes.get("configure_logger", True)` is true, call
       `logging.config.fileConfig(config.config_file_name)`.
    1. If `context.is_offline_mode()`, raise `NotImplementedError` with a message
       that names offline mode and `--sql`, for example
       `"run_env runs migrations online only; offline mode (alembic upgrade --sql) is not supported"`.
    1. Online mode builds
       `async_engine_from_config(config.get_section(config.config_ini_section, {}), prefix="sqlalchemy.", poolclass=pool.NullPool)`.
       It connects, then calls `await connection.run_sync(_configure_and_run)`
       and disposes the engine, all inside `asyncio.run(...)`.
    1. `_configure_and_run(connection)` calls
       `context.configure(connection=connection, **{"target_metadata": target_metadata, "render_as_batch": connection.dialect.name == "sqlite", **configure})`.
       The caller's keywords win. It then runs `context.run_migrations()`
       inside `context.begin_transaction()`.

- **Schema:** S32.2.2 adds `schema`, so leave it out here. Keep
  `_configure_and_run` small, so S32.2.2 can add the `search_path` step and
  `version_table_schema` to it.

- **`run_migrations`:** its docstring's paragraph about `configure_logger`
  changes to say that `run_env` honours the attribute.

- **Usage guide** (`packages/rn-forge-sqlalchemy/docs/guides/usage.md`): the
  `### env.py` subsection shows this, in place of the copied module:

    ```python
    from rn_forge.sqlalchemy.migrate import run_env
    from myapp.db.models import Base

    run_env(Base.metadata)
    ```

    Also add one paragraph and short bullets covering these points:

    - The stock Alembic `env.py` template is replaced, not extended.
    - Offline mode is not supported.
    - `render_as_batch` is on only for SQLite.
    - Keyword arguments override `context.configure`'s defaults, for example
      `run_env(Base.metadata, compare_type=True)`.
    - `run_env` honours `configure_logger`. Remove the old bullets that told the
      reader to copy the logger check. Update the sentence above it, "the async
      `env.py` below calls `asyncio.run()`", so it refers to `run_env`.

- **Changelog:** add to `CHANGELOG.md` `## [0.2.5]` `### Added`:
  "`rn_forge.sqlalchemy.migrate.run_env`, a whole Alembic `env.py` in one
  call, with `target_metadata` for autogenerate." Do not bump the version.

## Current behaviour

`from rn_forge.sqlalchemy.migrate import run_env` raises `ImportError`, so the
new tests fail at import. If the existing tests in `tests/test_migrate.py` stop
running, put the new tests in a new file, `tests/test_migrate_env.py`. That is
the preferred place anyway.

## Tests first

These go in a new file,
`packages/rn-forge-sqlalchemy/tests/test_migrate_env.py`, with
`pytestmark = pytest.mark.unit` and asyncio-marked async tests where needed.

- Reuse the shape of `tests/test_migrate.py`'s helpers: a script directory with
  unique module names, the `_url` helper and the SQLite `_state` reader. Copy
  them into the new file, because there is no shared helpers module. Its
  `env.py` is:

    ```python
    from sqlalchemy import Column, Integer, MetaData, Table
    from rn_forge.sqlalchemy.migrate import run_env

    metadata = MetaData()
    Table("thing", metadata, Column("id", Integer, primary_key=True))
    run_env(metadata)
    ```

    Each test may append keywords to the `run_env(...)` call.

- Call `run_migrations` and the Alembic commands through
  `asyncio.to_thread(...)` from async tests, or directly from sync tests.
  `run_env` calls `asyncio.run`.

The tests:

- `test_run_env_reaches_head`: two revisions that create tables `one` and `two`.
  `run_migrations` to head gives both tables, and `alembic_version` holds the
  head.
- `test_run_env_leaves_root_logger_alone`: with an `alembic.ini` that has
  logging sections, which you can copy from `test_migrate.py`'s `_INI`, passed
  as `alembic_ini=`, the root logger's handlers and level are unchanged.
- `test_run_env_passes_target_metadata`: use a script directory with no
  revisions and an empty SQLite database. Build a `Config` the way
  `run_migrations` does, with `script_location`, `sqlalchemy.url` and
  `configure_logger=False`. Then
  `alembic.command.revision(config, message="init", autogenerate=True)` writes
  a file under `versions/` whose text contains `op.create_table('thing'` or
  `op.create_table("thing"`.
- `test_run_env_offline_raises`:
  `alembic.command.upgrade(config, "head", sql=True)` raises
  `NotImplementedError`.
- `test_run_env_configure_overrides_default`: monkeypatch
  `alembic.runtime.environment.EnvironmentContext.configure` with a wrapper
  that records its kwargs and calls the original. With
  `run_env(metadata, render_as_batch=False)` on SQLite, the recorded
  `render_as_batch` is `False`. Without the keyword, it is `True`. Use two
  script directories.
