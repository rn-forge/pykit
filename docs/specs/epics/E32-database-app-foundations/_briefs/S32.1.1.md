# S32.1.1 — `search_path` on `create_postgres_engine`

Brief for
[S32.1.1](../F32.1-postgres-test-schema.md#s3211-search_path-on-create_postgres_engine),
on `feature/release-12`. Read the feature's Design first. The signature there is
settled.

## Goal

`create_postgres_engine` takes `search_path`, and every connection it opens sets
that `search_path`.

## Settled

- File: `packages/rn-forge-sqlalchemy/src/rn_forge/sqlalchemy/postgres.py`.
- Add the keyword-only parameter `search_path: str | None = None` after
  `application_name`.
- `search_path == ""` raises `ValueError("search_path must not be empty")`.
  Check it with the existing number checks, before the `asyncpg` import and
  before the engine is built.
- When `search_path` is not `None`, `server_settings` gains
  `"search_path": search_path`, next to `timezone`, `application_name` and
  `statement_timeout`. When it is `None`, the key is absent.
- Docstring: an `Args:` entry. *search_path* is the schema search path every
  connection sets, given as PostgreSQL's comma-separated list, and `None`
  leaves the server default. Add a `Raises:` line for an empty *search_path*.
- Usage guide: `packages/rn-forge-sqlalchemy/docs/guides/usage.md` has no
  PostgreSQL section yet. Add `## PostgreSQL engine` right after
  `## SQLite engine`, in the same style: a short example of
  `create_postgres_engine`, what each connection sets (UTC `timezone`, plus
  `application_name`, `statement_timeout` and `search_path` when given), the
  `postgres` extra, and the accepted URL schemes. Read
  `create_postgres_engine`'s docstring for the facts.
- Changelog: `packages/rn-forge-sqlalchemy/CHANGELOG.md`. Version 0.2.5 is not
  released yet, so add the entry to the existing `## [0.2.5]` section's
  `### Added` and change that section's date to `2026-11-22`. Do not bump the
  version. The entry: "`create_postgres_engine` takes `search_path`."

## Current behaviour

`create_postgres_engine(url, search_path="s1")` raises
`TypeError: create_postgres_engine() got an unexpected keyword argument 'search_path'`.
So each new test fails with that `TypeError`.

## Change

1. Write the tests below first, and confirm each fails with the `TypeError`.
1. Make the parameter change, then the docstring, the guide section and the
   changelog.

## Tests first

These go in `packages/rn-forge-sqlalchemy/tests/test_postgres.py`. Use the
existing `make_engine` fixture and the `_cparams` helper.

- `test_postgres_engine_search_path_in_server_settings`, unit: with
  `search_path="s1"`, `cparams["server_settings"]["search_path"] == "s1"`.
  Without it, `"search_path"` is not a key.
- `test_postgres_engine_rejects_empty_search_path`, unit: `search_path=""`
  raises `ValueError` matching `search_path`.
- `test_postgres_engine_connection_uses_search_path`, marked
  `pytest.mark.postgres`. It skips without the DSN, the way
  `test_create_postgres_engine_connection_reports_utc` does. With
  `search_path="rn_forge_probe"`, `SHOW search_path` on a connection returns
  `rn_forge_probe`. The schema need not exist.
