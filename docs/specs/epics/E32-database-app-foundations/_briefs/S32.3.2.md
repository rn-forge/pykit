# S32.3.2 — Build typed settings

Brief for [S32.3.2](../F32.3-typed-env-settings.md#s3232-build-typed-settings),
on `feature/release-12`. Read the feature's Design and
[ADR-0018](../../../../adr/ADR-0018.md) first. The API there is settled.

## Goal

`rn_forge.commons.lang.settings` provides `EnvSettings`, `EnvSettings.load` and
`SettingsError` over `pydantic-settings`, behind the new `settings` extra of
`rn-forge-commons`.

## Settled

- **Dependency, approved by the owner.** In
  `packages/rn-forge-commons/pyproject.toml`, add
  `settings = ["pydantic-settings>=<floor>"]` under
  `[project.optional-dependencies]`, and add the same requirement to the `all`
  list, which is kept sorted. Use the version `uv.lock` resolves after
  `task setup` as `<floor>`. Use a placeholder such as `>=2` for the first
  `task setup`, then tighten it and run `task setup` again. `task setup`
  updates the lock, and editing it this way is allowed for this story. No
  other dependency changes.
- **Module:** `packages/rn-forge-commons/src/rn_forge/commons/lang/settings.py`,
  modelled on `lang/models.py`. It has a module docstring saying it requires
  the `settings` extra and is not imported by the `rn_forge.commons` facade,
  and it sets `__all__ = ["EnvSettings", "SettingsError"]`. Do not import it
  from `rn_forge/commons/__init__.py` or `lang/__init__.py` (ADR-0003).
- **`EnvSettings(pydantic_settings.BaseSettings)`.** Its
  `model_config = SettingsConfigDict(frozen=True, case_sensitive=False, env_file=None, secrets_dir=None, extra="ignore")`.
  An application subclasses it and sets its own `env_prefix`, for example
  `model_config = SettingsConfigDict(env_prefix="APP_")`. pydantic merges that
  with the parent's config. Check this with a test, not by assuming.
- **`EnvSettings.load(cls, environ: Mapping[str, str] | None = None) -> Self`**,
  a classmethod. It reads *environ*, or `os.environ` when *environ* is `None`,
  and never writes to `os.environ`. Feed the mapping in through
  `settings_customise_sources`, keeping the dotenv and secrets sources so a
  subclass that turns them on still gets them. One working way is a private
  `EnvSettingsSource` subclass whose `_load_env_vars` returns
  `parse_env_vars(<mapping>, self.case_sensitive, self.env_ignore_empty, self.env_parse_none_str)`,
  with the mapping passed through a `ContextVar` that `load` sets and
  resets. Verify that against the `pydantic-settings` version installed, and
  record the mechanism you used in `## Result`. Construction without `load`,
  as `MySettings()`, still reads `os.environ`, as `BaseSettings` does.
- **Booleans:** a `mode="before"` validator on every `bool`-annotated field
  passes a `str` value through `AppUtils.parse_bool(value)` (strict). A
  `ValueError` from it becomes a validation error for that field. Values that
  are not strings pass through unchanged.
- **Errors:** `load` catches `pydantic.ValidationError` and raises
  `SettingsError` from it. Each error's field is `loc[0]`. Its variable name
  is `(env_prefix + field_name).upper()`. Missing required fields count too.
  The message is `"Invalid settings: {}"`, joining
  `"<VARIABLE>: <pydantic msg>"` for each variable, sorted by variable name.
  `SettingsError(AppException)` has `variables: tuple[str, ...]`, the sorted
  distinct names. Its docstring follows `ModelValidationError`'s.
- **Docs:**
    - Add a reference page,
      `packages/rn-forge-commons/docs/reference/lang/settings.md`, shaped like
      `reference/lang/models.md` ("Requires the `settings` extra.").
    - Add a nav entry `- Settings: reference/lang/settings.md` after `Models` in
      `packages/rn-forge-commons/mkdocs.yml`.
    - In the README's `lang/` list, add a **`settings`** (`settings` extra) bullet
      after `models`.
    - In `docs/guides/installation.md`'s extras list, add a `settings` line after
      `pydantic`.
    - In `docs/guides/config.md`, add a new `## Settings` section at the end: a
      subclass with an `APP_` prefix and `str`, `Path`, `bool`, `int` and
      `Decimal` fields, `load()` and `load({...})` in a test, the error that
      names every variable, the boolean tokens, and that `.env` files are off
      unless a subclass sets `env_file`.
- **Changelog:** `packages/rn-forge-commons/CHANGELOG.md`. 0.10.2 is not
  released yet, so add an `### Added` subsection to the existing `## [0.10.2]`
  section, above `### Changed`, and change the section's date to `2026-11-22`.
  The entry: "`rn_forge.commons.lang.settings`: `EnvSettings` loads typed
  settings from prefixed environment variables, raising one `SettingsError`
  that names every invalid variable. Needs the new `settings` extra." Do not
  bump the version.

## Current behaviour

`rn_forge.commons.lang.settings` does not exist, so every new test fails at
import with
`ModuleNotFoundError: No module named 'rn_forge.commons.lang.settings'`.

## Change

1. Write the module, then the docs and the changelog.

## Tests first

New file: `packages/rn-forge-commons/tests/lang/test_settings.py`, with
`pytestmark = pytest.mark.unit` and assertions in `assertpy` style, as in
`tests/lang/test_models.py`. Define one test class `_App(EnvSettings)` with
`env_prefix="APP_"` and these fields: `name: str = "app"`,
`data_dir: Path = Path("data")`, `enabled: bool = False`, `workers: int = 1` and
`cap: Decimal = Decimal("1.00")`.

- `test_settings_defaults_with_empty_mapping`: `_App.load({})` returns every
  default.
- `test_settings_prefix_maps_fields`: each `APP_<FIELD>` in a mapping overrides
  its field, and each value is of its annotated type. Include a lower-case key
  such as `app_workers` to cover `case_sensitive=False`.
- `test_settings_bool_accepts_parse_bool_tokens`: parametrized over `"Enabled"`,
  `"YES"`, `"off"` and `"none"`. The result matches `AppUtils.parse_bool`.
- `test_settings_bool_rejects_unknown_token`: `APP_ENABLED=maybe` raises
  `SettingsError` whose `variables == ("APP_ENABLED",)` and whose message
  contains `APP_ENABLED`.
- `test_settings_decimal_kept_exact`: `APP_CAP=0.10` gives `Decimal("0.10")`,
  and its `as_tuple().exponent == -2`.
- `test_settings_reports_every_invalid_variable`: `APP_WORKERS=x` and
  `APP_ENABLED=maybe` raise one `SettingsError` naming both, with
  `variables == ("APP_ENABLED", "APP_WORKERS")`.
- `test_settings_reports_missing_required_variable`: a subclass with a required
  `database_url: str` loaded from `{}` names `APP_DATABASE_URL`.
- `test_settings_load_ignores_os_environ_when_mapping_given`:
  `monkeypatch.setenv("APP_NAME", "env")`, then `_App.load({})` gives `"app"`,
  while `_App.load()` gives `"env"`.
- `test_settings_ignores_dotenv_file`: `monkeypatch.chdir(tmp_path)`, write
  `.env` with `APP_NAME=dotenv`, then `_App.load({})` gives `"app"`.
- `test_settings_are_immutable`: assigning `settings.name = "x"` raises
  `pydantic.ValidationError`.
- `test_settings_error_is_app_exception`: `SettingsError` subclasses
  `AppException`.
- `test_settings_not_imported_by_facade`: in a subprocess,
  `import rn_forge.commons` leaves `rn_forge.commons.lang.settings` and
  `pydantic_settings` out of `sys.modules`. If a facade-import test pattern
  already exists, for example in `tests/test_facade.py`, follow it.
