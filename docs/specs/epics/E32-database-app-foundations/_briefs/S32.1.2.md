# S32.1.2 — The `postgres_schema` fixture

Brief for
[S32.1.2](../F32.1-postgres-test-schema.md#s3212-the-postgres_schema-fixture),
written at the S32.1.1 merge on `feature/release-12`. Read the feature's Design
first. The module, the extra, the marker, the ini option and `PostgresSchema`
are settled there.

## Goal

`rn_forge.sqlalchemy.testing` is a pytest plugin that an application loads
explicitly. It gives each test a fresh PostgreSQL schema and an engine whose
connections use it, skips when no DSN is configured, and drops the schema
afterwards.

## Settled

- **Module:** `packages/rn-forge-sqlalchemy/src/rn_forge/sqlalchemy/testing.py`.
  It has a module docstring saying how to load it
  (`pytest_plugins = ["rn_forge.sqlalchemy.testing"]`) and that it needs the
  `testing` and `postgres` extras. It sets
  `__all__ = ["PostgresSchema", "postgres_schema"]`. Do not import it from
  `rn_forge/sqlalchemy/__init__.py`. Do not add a `pytest11` entry point.
- **Extra:** add `testing = ["pytest>=9.1.1", "pytest-asyncio>=1.4.1.post1"]` to
  `[project.optional-dependencies]`, exactly as the Design says. `task setup`
  updates the lock. No other dependency changes.
- **Hooks:**
    - `pytest_addoption(parser)` calls
      `parser.addini("rn_forge_postgres_dsn_env", help=..., default="RN_FORGE_TEST_POSTGRES_DSN")`.
    - `pytest_configure(config)` calls
      `config.addinivalue_line("markers", "postgres: needs a PostgreSQL server (DSN from rn_forge_postgres_dsn_env)")`.
- **`PostgresSchema`:** a frozen dataclass with exactly the fields in the
  Design, and a docstring.
- **`postgres_schema`:** a `pytest_asyncio.fixture`, function scoped. It works
  in pytest-asyncio's strict mode, which this package uses.
    1. Read the variable name with `request.config.getini(...)`. If `os.environ`
       has it unset or empty, call `pytest.skip(f"{name} is not set")`.
    1. `name = "t_" + uuid4().hex`.
    1. Create the schema with an admin engine from `create_postgres_engine(dsn)`:
       `CREATE SCHEMA "<name>"` inside `begin()`.
    1. `engine = create_postgres_engine(dsn, search_path=name)`, and
       `url = engine.url.render_as_string(hide_password=False)`, so the driver
       is `postgresql+asyncpg`.
    1. Yield `PostgresSchema(name, url, engine)` inside `try`. In `finally`,
       dispose `engine`, run `DROP SCHEMA IF EXISTS "<name>" CASCADE` over the
       admin engine, and dispose the admin engine. A yield fixture's teardown
       already runs after a failed test. The `finally` covers an error inside
       the fixture itself.
    - The fixture's docstring says what it yields, when it skips, and that it
      drops the schema.
- **Docs:**
    - In `packages/rn-forge-sqlalchemy/docs/guides/usage.md`, add
      `## Testing against PostgreSQL` after `## PostgreSQL engine`. Cover the
      install (`rn-forge-sqlalchemy[postgres,testing]`), loading the plugin in
      the root `conftest.py`, the `rn_forge_postgres_dsn_env` ini option with
      its default, the `postgres` marker, and a short test using
      `postgres_schema.engine`.
    - The same section shows the CI integration table that exports the DSN. Copy
      this package's own `[tool.workspace-ci.integration.postgres]` tables from
      `pyproject.toml`.
    - The README's module table gains a `testing` row, in the style of the
      `postgres` row.
- **Changelog:** in `packages/rn-forge-sqlalchemy/CHANGELOG.md`, add to the
  existing `## [0.2.5]` section's `### Added`: "`rn_forge.sqlalchemy.testing`,
  a pytest plugin whose `postgres_schema` fixture gives each test its own
  PostgreSQL schema; needs the new `testing` extra." Do not bump the version,
  and leave the date as it is.

## Current behaviour

`rn_forge.sqlalchemy.testing` does not exist, so each new test fails.

- A `pytester` test fails because the inner run's
  `pytest_plugins = ["rn_forge.sqlalchemy.testing"]` errors with
  `ModuleNotFoundError`, and the expected outcome is not reported.
- A direct test fails at import or with `fixture 'postgres_schema' not found`.
- `test_package_root_does_not_import_testing` passes before the change. It
  guards the change. Say so in `## Result`.

## Change

1. Write the tests below first, and confirm they fail as stated above.
1. Add the extra and run `task setup`.
1. Write the plugin, then the docs and the changelog.

## Tests first

New file: `packages/rn-forge-sqlalchemy/tests/test_testing.py`.

- Mark the tests `unit` unless the story says `postgres`. Use `assertpy` where
  it applies.
- Enable `pytester` in that file with `pytest_plugins = ["pytester"]`. If pytest
  refuses `pytest_plugins` in a non-root conftest or a test module, put it in
  `tests/conftest.py` instead, and say so in `## Result`.
- Every inner `pytester` run gets a `conftest.py` with
  `pytest_plugins = ["rn_forge.sqlalchemy.testing"]`, plus `-p no:randomly`
  and `-p no:cacheprovider`.
- Inner async tests carry `@pytest.mark.asyncio`.

The tests:

- `test_postgres_schema_skips_without_dsn`: `monkeypatch.delenv` the default
  variable. An inner test using `postgres_schema`, run with `-rs`, reports
  `skipped=1`, and stdout matches `*RN_FORGE_TEST_POSTGRES_DSN is not set*`.
- `test_postgres_schema_reads_configured_variable`: the inner ini
  (`pytester.makeini`) sets `rn_forge_postgres_dsn_env = APP_DSN`, and
  `APP_DSN` is deleted. The run reports `skipped=1`, and stdout matches
  `*APP_DSN is not set*`.
- `test_postgres_schema_registers_marker`: an inner test marked
  `@pytest.mark.postgres`, run with `--strict-markers`, reports `passed=1`.
- `test_postgres_schema_isolates_tables`, marked `postgres` and `asyncio`, used
  directly rather than through `pytester`: parametrize over `[1, 2]`. Each run
  executes `CREATE TABLE probe (id int)` on `postgres_schema.engine`, which
  would fail on the second run if the schema were shared. Then
  `SELECT current_schema()` equals `postgres_schema.name`. To use the fixture
  directly before S32.1.3, load the plugin in this test module with
  `pytest_plugins = ["pytester", "rn_forge.sqlalchemy.testing"]`. If that
  clashes with the package's own `postgres` marker in
  `[tool.pytest.ini_options]`, record it and keep both. S32.1.3 removes the
  ini marker.
- `test_postgres_schema_dropped_after_test`, marked `postgres`, run through
  `pytester` with the DSN inherited from the environment. It skips without the
  DSN, using the default variable. The inner file has two async tests that use
  `postgres_schema`. Each appends `postgres_schema.name` to `names.txt` in the
  inner run's directory. One passes and one ends with `assert False`. The
  outcomes are `passed=1, failed=1`. Then, over the outer test's own engine
  from `create_postgres_engine(dsn)`, neither name is in
  `information_schema.schemata`.
- `test_postgres_schema_yields_asyncpg_url`, marked `postgres`: used directly,
  `make_url(postgres_schema.url).drivername == "postgresql+asyncpg"`, and the
  name matches `^t_[0-9a-f]{32}$`.
- `test_package_root_does_not_import_testing`: a
  `subprocess.run([sys.executable, "-c", ...])` imports `rn_forge.sqlalchemy`
  and prints whether `rn_forge.sqlalchemy.testing` and `pytest_asyncio` are in
  `sys.modules`. Both are absent.

report.
