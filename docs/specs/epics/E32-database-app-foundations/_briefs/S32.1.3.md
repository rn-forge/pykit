# S32.1.3 — pykit's own PostgreSQL tests use the fixture

Brief for
[S32.1.3](../F32.1-postgres-test-schema.md#s3213-pykits-own-postgresql-tests-use-the-fixture),
written at the S32.1.2 merge on `feature/release-12`.

## Goal

The `postgres` branch of `rn-forge-sqlalchemy`'s shared `engine` fixture runs on
a schema of its own from `postgres_schema`. It no longer runs `create_all` and
`drop_all` on the shared database. The package's `postgres` marker now comes
from the plugin.

## Settled

- **Load the plugin** in `packages/rn-forge-sqlalchemy/tests/conftest.py` with
  `pytest_plugins = ["rn_forge.sqlalchemy.testing"]`. In
  `tests/test_testing.py`, remove `"rn_forge.sqlalchemy.testing"` from that
  module's `pytest_plugins` and keep `"pytester"`.
- **Restructure `engine`.** Keep its name, its params (`sqlite`, plus `postgres`
  with the `postgres` mark) and its contract: it yields an `AsyncEngine` with
  `Base.metadata` created on it. Tests use it unchanged.
    - The SQLite branch keeps today's behaviour: the same URL, the same
      `create_async_engine`, `create_all`, `drop_all` and `dispose`.
    - The postgres branch takes `postgres_schema.engine`, runs `create_all` on it,
      and does not dispose it or run `drop_all`, because the fixture drops the
      schema.
- An async fixture cannot call `request.getfixturevalue` on another async
  fixture while its event loop runs. One working shape is:
    - a sync, parametrized `pytest.fixture` that picks the dialect: it returns
      `request.getfixturevalue("sqlite_engine")` or
      `request.getfixturevalue("postgres_schema").engine`;
    - a new async `sqlite_engine` fixture that holds the SQLite branch;
    - the async `engine` fixture, which depends on the dialect fixture and runs
      `create_all`. Pick any shape that works, and record it in `## Result`.
- **`POSTGRES_DSN`.** Keep the constant in `tests/conftest.py`, because other
  tests import it. Its only use in the `engine` fixture goes away, and the
  skip now comes from `postgres_schema`.
- **The marker.** Remove the `postgres` line from `markers` in
  `packages/rn-forge-sqlalchemy/pyproject.toml`'s `[tool.pytest.ini_options]`.
  Keep `unit`.
- **Changelog.** No entry: the change is internal to the tests.

## Current behaviour

- `tests/conftest.py`'s postgres branch builds
  `create_async_engine(dsn.replace(...))` and runs `create_all` and `drop_all`
  on the shared database.
- The ini declares the `postgres` marker.
- The acceptance's
  `rg -q 'postgres_schema' packages/rn-forge-sqlalchemy/tests/conftest.py`
  fails.

## Change

1. Restructure the fixture and load the plugin.
1. Remove the ini marker.
1. Run the existing suite with and without the DSN. This story adds no new test.
   The proof is that the existing dialect-parametrized tests pass on both
   dialects.

## PostgreSQL

reconfigure containers. DSN:
`RN_FORGE_TEST_POSTGRES_DSN=postgresql://ci:ci@localhost:5432/ci`. If the server
does not answer, stop and report.
