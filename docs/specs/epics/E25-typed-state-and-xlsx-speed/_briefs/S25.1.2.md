# S25.1.2 — Build typed application state

Brief for
[S25.1.2](../F25.1-typed-application-state.md#s2512-build-typed-application-state),
at `d86b1200`. The settled contract is under S25.1.1 on the same page; read it
first.

## Goal

`rn-forge-fastapi` gains `app_state` and `state_lifespan`, so an application
declares its long-lived resources once as a typed class and a route receives
them through `Depends`. A misspelt or mistyped attribute then fails
`task typecheck` instead of returning a 500.

## Settled

- New module `packages/rn-forge-fastapi/src/rn_forge/fastapi/state.py`, with two
  public functions, both exported from `rn_forge.fastapi` (add them to the
  imports and to `__all__` in `__init__.py`, keeping its order rules).

- `app_state[T](cls: type[T]) -> Callable[[Request], T]`, decorated with
  `functools.cache`, so each class has one dependency object and
  `app.dependency_overrides[app_state(S)]` replaces it.

    - The dependency reads a private registry, a `dict[type, object]` stored on
      `app.state` under one private attribute name (for example
      `"_rn_forge_states"`), and returns the entry for `cls`.
    - No entry:
      `RuntimeError(f"no {cls.__name__} registered on this application")`.

- `state_lifespan[T](cls: type[T], opener: Callable[[FastAPI], AbstractAsyncContextManager[T]], inner: Lifespan[FastAPI] | None = None) -> Lifespan[FastAPI]`.

    - The returned lifespan enters `opener(app)`. A value that is not an instance
      of `cls` raises
      `TypeError(f"{cls.__name__} expected, got {type(value).__name__}")` before
      anything is registered, so the application never serves.
    - It registers the value under `cls`, then enters `inner(app)` if given and
      yields. Teardown is the reverse: `inner` exits, the entry for `cls` is
      removed from the registry, then the opener exits.
    - Several state classes on one application are allowed: nest `state_lifespan`
      calls through `inner`, each registering its own class.

- `FastApiApp`, `AppConfig` and every other existing public API are unchanged.

- No permanent test of pyright behaviour (the owner's decision in S25.1.1).

- Reference prototype that passed in S25.1.1 (adapt it; it lacks teardown
  removal):

    ```python
    @cache
    def app_state[T](cls: type[T]) -> Callable[[Request], T]:
        def dependency(request: Request) -> T:
            states = cast("dict[type, object]", getattr(request.app.state, _KEY, {}))
            found = states.get(cls)
            if found is None:
                raise RuntimeError(f"no {cls.__name__} registered on this application")
            return cast("T", found)
        return dependency


    def state_lifespan[T](cls, opener, inner=None) -> Lifespan[FastAPI]:
        @asynccontextmanager
        async def lifespan(app: FastAPI) -> AsyncGenerator[None]:
            async with opener(app) as value:
                if not isinstance(value, cls):
                    raise TypeError(f"{cls.__name__} expected, got {type(value).__name__}")
                if not hasattr(app.state, _KEY):
                    setattr(app.state, _KEY, {})
                cast("dict[type, object]", getattr(app.state, _KEY))[cls] = value
                if inner is None:
                    yield
                else:
                    async with cast("AbstractAsyncContextManager[None]", inner(app)):
                        yield
        return lifespan
    ```

## Current behaviour

At `d86b1200` there is no `rn_forge.fastapi.state` module, so every new test
fails at collection with
`ModuleNotFoundError: No module named 'rn_forge.fastapi.state'`, and importing
`app_state` from `rn_forge.fastapi` fails with `ImportError`.

## Change

1. `src/rn_forge/fastapi/state.py`: the two functions, with Google-style
   docstrings (Args, Returns, Raises) per the README Conventions.
1. `src/rn_forge/fastapi/__init__.py`: export both.
1. `docs/guides/state.md` (new): why (`request.app.state.<name>` is untyped),

## Tests first

New `packages/rn-forge-fastapi/tests/test_state.py`, using
`fastapi.testclient.TestClient` as a context manager so the lifespan runs. Write
these before `state.py` and confirm they fail as above:

- `test_a_route_reads_the_state_set_at_startup`
- `test_an_opener_yielding_the_wrong_type_fails_at_startup`: `TypeError` with
  the message above; the opener's teardown still runs.
- `test_an_unregistered_state_fails_at_request_time`: an app without the
  lifespan; with `raise_server_exceptions=True` the request raises
  `RuntimeError("no AppState registered on this application")`.
- `test_teardown_is_the_reverse_of_setup`: events are
  `["state up", "inner up", "inner down", "state down"]`.
- `test_teardown_removes_the_registration`: after the client exits, the registry
  has no entry for the class.
- `test_dependency_overrides_replace_the_state`
- `test_two_state_classes_are_kept_apart`: nested `state_lifespan` calls; a
  route reads both.
- `test_the_facade_exports_both`:
  `rn_forge.fastapi.app_state is rn_forge.fastapi.state.app_state`, and the
  same for `state_lifespan`.
- One route built through `FastApiApp` (not bare `FastAPI`) with
  `lifespan=state_lifespan(...)`, to show it composes with the package's own
  application factory. Read `src/rn_forge/fastapi/app.py` for how it takes
  `lifespan`.
