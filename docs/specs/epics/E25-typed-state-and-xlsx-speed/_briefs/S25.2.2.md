# S25.2.2 — Implement the faster XLSX path

Brief for
[S25.2.2](../F25.2-faster-xlsx-transfer.md#s2522-implement-the-faster-xlsx-path),
at `b1949212`. The settled contract is under S25.2.1 on the same page; read it
first.

## Goal

`rn_forge.data.write_xlsx` writes 100,000 rows × 10 columns in at most 4.8 s
(from about 6.5 s), and the file it writes loads through tablib in at most 5.5 s
(from about 8 s), untraced, with the same values and number formats read back.

## Settled

All in `packages/rn-forge-data/src/rn_forge/data/excel.py`, `write_xlsx`:

- Values in columns not named in `column_formats` are appended as plain values.
  `WriteOnlyCell` is created only for the formatted columns' values.
- Before the first `append`, the write-only sheet's dimension is declared: set
  `sheet.calculate_dimension` to a zero-argument callable returning
  `"A1:<last column letter><row count>"`, where the row count is the data rows
  plus one when there is a header row (`openpyxl.utils.get_column_letter`).
  openpyxl 3.1.5's `WorksheetWriter.write_dimensions` reads this through
  `getattr(ws, "calculate_dimension", None)` and emits `<dimension ref=.../>`;
  it is undocumented, so a test guards it. Pyright strict may need a narrow
  `# pyright: ignore[<rule>]` with a reason on that assignment.
- With no headers and no rows, keep writing a valid file; declare `A1:A1` or
  skip the dimension, whichever openpyxl reads back without error.
- Unchanged: the signature, header handling, the `KeyError` for unknown
  `column_formats` names, the docstring's contract, and `rn-forge-fastapi`. No
  new dependency.
- A short comment at the dimension assignment says why (a write-only sheet has
  no dimension, so a read-only loader scans the sheet twice), per the README
  comment rules.
- Changelog: `packages/rn-forge-data/CHANGELOG.md`, `[Unreleased]`,
  `### Changed`: `write_xlsx` writes large tables faster, and its files
  declare their dimension, so they load faster.

## Current behaviour

At `b1949212`, `write_xlsx` wraps every value in a `WriteOnlyCell` and writes no
`<dimension>` element. So the new dimension test fails: the sheet XML
(`xl/worksheets/sheet1.xml` in the zip) has no `<dimension`. Round-trip tests
already pass and must keep passing.

## Tests first

In the data package's existing `write_xlsx` tests (find them with
`grep -rn write_xlsx packages/rn-forge-data/tests`), add:

- `test_the_sheet_declares_its_dimension`: for 3 data rows × 2 columns with
  headers, the sheet XML contains `<dimension ref="A1:B4"/>`; for the same
  data without headers, `A1:B3`. Fails today.
- `test_round_trip_keeps_values_and_formats`: a dataset with an int, a str, a
  float, a `date`, a `bool` and a `None`, one column in `column_formats`,
  written and read back with `openpyxl.load_workbook(read_only=True)`; values
  and the formatted column's `number_format` match, and unformatted cells keep
  `General`. Passes today; it pins behaviour.
- `test_an_empty_dataset_writes_a_valid_file`: no headers, no rows; the bytes
  load with openpyxl. Passes today.

No timing assertion in any test.
