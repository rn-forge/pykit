# S25.1.1 — Settle the typed-state API

Brief for
[S25.1.1](../F25.1-typed-application-state.md#s2511-settle-the-typed-state-api),
at `502723d3`. This is a decision story: you produce a reproduction and a
comparison of options. The owner decides; do not build the feature.

## Goal

A FastAPI application reads long-lived resources back as
`request.app.state.<name>`, which is untyped, so a misspelt or missing resource
fails at request time, not under `task typecheck`. Compare ways for
`rn-forge-fastapi` to give a route typed access to application state through
`Depends`, and recommend one.

## Settled

- The feature lives in `rn-forge-fastapi`
  (`packages/rn-forge-fastapi/src/rn_forge/fastapi/`). `create_app` in
  `app.py` already takes `lifespan: Lifespan[FastAPI] | None`.
- Routes receive the state through `Depends` (or an `Annotated` alias of it).
- Pyright strict is the type checker (`task typecheck`).
- No new runtime dependency.

## Current behaviour

There is no typed-state support. Confirm this with a reproduction: a small
FastAPI app whose route reads `request.app.state.misspelt` passes
`task typecheck` and fails only when the route is called (an `AttributeError`
surfacing as a 500). Record how it fails, as observed, in `## Result`.

## Change

Write only throwaway prototypes and the reproduction, under
`packages/rn-forge-fastapi/tests/` in a file named
`test_typed_state_options.py`. No change under `src/`. Keep the reproduction
test (it shows today's failure); delete the prototypes before you finish, or
keep them only if they pass `task validate` and are clearly marked as option
sketches.

Compare at least these options; add others if you find better ones:

1. **One typed state object on `app.state`.** The application defines a
   dataclass (or class) of its resources, stores one instance under a fixed
   key at startup, and a generic dependency factory returns it typed, for
   example `Annotated[AppState, Depends(app_state(AppState))]`.
1. **Starlette lifespan state.** The lifespan yields a mapping, which Starlette
   copies into `request.state`; typed with a `TypedDict`.
1. **One dependency per resource**, each a typed function reading its own
   attribute.

For each option, state, with evidence from the prototype:

- how an application declares its state, and what a route's signature looks
  like;
- whether a misspelt attribute or a wrong type is a pyright error, shown by
  running the prototype through `task typecheck` (a temporary misspelling,
  reverted afterwards), and how a test could prove that permanently without
  failing the repository's own type check (for example a file pyright excludes
  plus a test that asserts its errors, or `# pyright: ignore[<rule>]` that
  pyright reports as unnecessary once the error is gone — check what pyright
  strict reports);
- what happens when a declared resource is absent at startup or at request time;
- how it interacts with `lifespan` (setup and teardown order) and with
  `create_app`;
- the public symbols it would add and the module that exports them, and whether
  any existing public API changes;
- how it works in tests that override dependencies (`app.dependency_overrides`).

End with a recommendation and a draft settled contract for it, in the shape
S25.1.1's acceptance asks for, so the owner can accept or amend it.
