# F14.2 — Pipeline hardening

| | |
| --- | --- |
| **State** | Active |

F14.1 made the pipeline generic. This feature makes it safe to run unattended and to copy as a template. Each change applies one of these rules:

1. **The published release is the record.** A package version is shipped when its GitHub Release is published with its assets. A tag alone does not count, and a rerun finishes a half-done release.
2. **Every change is planned exactly once.** A package's change is verified and released even when the run for its commit was superseded, failed, or its base was rewritten.
3. **Pinned, bounded, cancellable.** Every third-party action is pinned to a commit SHA; every job has a timeout; superseded pull-request runs are cancelled, and pushes to `main` never are.
4. **A failed quality gate fails CI**, and a fork's pull request is not failed for lacking a secret.
5. **One copy of the toolchain setup.**

Every change stays package-agnostic: `main.yml` and `workspace_ci.py` still name no package, and the files added here name none either.

## Design

### Why today's pipeline breaks these rules

- **Tag before release.** `release` runs `git tag`, `git push`, then `gh release create`. When the create or an upload fails, the tag is public with no release. Every later run finds the tag with `git ls-remote`, prints "already exists", and skips, so that version is never released.
- **Plan base is `github.event.before`.** A push's changes are planned only against the previous push:
  - a run that fails leaves its packages unreleased, and the next push's plan does not select them again unless they change again;
  - with a concurrency group (rule 3), GitHub replaces a pending run with a newer one, and the replaced run's changes are never planned;
  - after a force-push, `before` may not be an ancestor of `HEAD`, and `git diff before...HEAD` fails the `plan` job.
- **Floating actions.** `actions/checkout@v7`, `upload-artifact@v7`, `download-artifact@v8`, `configure-pages@v6`, `upload-pages-artifact@v5` and `deploy-pages@v5` follow moving tags.
- **Sonar.** The scan does not wait for the quality gate, so a failed gate passes CI; a fork's pull request has no `SONAR_TOKEN`, so the job fails there.
- **Repeated setup.** Checkout and `setup-uv` are repeated in nine jobs, plus `uv sync` in five.
- No `concurrency`, no `timeout-minutes`, no Dependabot.

### Plan base

On a push to `main`, the base is the head SHA of the **last successful run of this workflow on `main`**, not `before`. Every commit since that run is then planned, whatever happened to the runs in between. A pull request keeps `pull_request.base.sha`; `workflow_dispatch` keeps "everything".

`workspace_ci.py plan BASE` also guards itself: when `BASE` is not a commit, or is not an ancestor of `HEAD`, it plans every package. That covers the all-zeros SHA and rewritten history without the workflow having to.

### Release

For each releasable package, in the order `releasable` prints, with `tag=<name>-v<version>`:

| Published release for `tag`? | Tag exists on `origin`? | Do                                                                                                 |
| --- | --- | --- |
| yes | — | skip: already shipped |
| no | no | build from `HEAD`; `gh release create "$tag" dist/<name>/* --target "$GITHUB_SHA" --title … --generate-notes` |
| no | yes | **resume**: build from the tag (`git worktree add` at the tag), then `gh release create "$tag" … --verify-tag` |

`gh release create` with assets creates a draft, uploads, and publishes only after every upload succeeds; with `--target` it creates the tag itself. No step runs `git tag` or `git push`. A leftover draft for the tag is deleted before the create. "Published" means `gh release view "$tag" --json isDraft --jq .isDraft` prints `false`.

The tags `gh` creates are lightweight; `released` and the `external-install` and `docs` jobs read tags with `git tag --points-at HEAD`, which lists lightweight tags too. A resumed release is for an older commit, so `external-install` and `docs` in that run do not act on it; the next run whose `HEAD` carries the tag would, and the runbook says to check a resumed release by hand.

### Sonar and release gating

Sonar keeps running after `verify` and does not gate `release`. With `sonar.qualitygate.wait=true` and `sonar` in `ci-ok`, a pull request whose quality gate fails cannot merge, so the push to `main` that would release it never happens. Gating `release` as well would let one repository-wide scan hold back every package's release.

### Considered and rejected

- **Keep `github.event.before` and drop concurrency.** Failed runs would still leave changes unplanned, and two runs on `main` could race to tag the same version.
- **Build the resumed release from `HEAD`.** The assets would not match the tagged source.

**Out of scope.** Routing CI steps through a single task runner, and moving the planner out of `.github/scripts/`: both are decisions for whatever maintains the template, not for this repository.

### S14.2.2 — Composite setup action

**State:** Closed (2026-10-02)

`.github/actions/setup/action.yml`, a composite action with one input, `sync` (default `"true"`):

- `astral-sh/setup-uv` with `enable-cache: true`;
- when `sync` is `"true"`: `uv sync --all-packages --all-extras --locked`.

A local action can only be loaded from a checked-out tree, so every job keeps its own `actions/checkout` first (with `fetch-depth: 0` where it has it today), then `uses: ./.github/actions/setup`. `import-boundaries`, `verify`, `postgres`, `suites` and `sonar` use the default; `smoke`, `release`, `external-install` and `docs` pass `sync: "false"`. `plan` uses neither, and keeps running on the runner's `python3`.

**Acceptance:**

- `astral-sh/setup-uv` and `uv sync` appear in `.github/actions/setup/action.yml` and nowhere in `main.yml`.
- Every job except `plan` and `ci-ok` has `actions/checkout` followed by `./.github/actions/setup`.
- `actionlint .github/workflows/main.yml` passes.

### S14.2.3 — Plan from the last successful run

**State:** Active

- `workspace_ci.py plan BASE`: when `git cat-file -e "$BASE^{commit}"` fails or `git merge-base --is-ancestor BASE HEAD` fails, select every package, and say so on stderr.
- In `plan`, on a push, resolve `BASE` with `gh run list --workflow main.yml --branch main --event push --status success --limit 1 --json headSha --jq '.[0].headSha // ""'` (`GH_TOKEN: ${{ github.token }}`; job permissions `contents: read`, `actions: read`). Pull requests and `workflow_dispatch` keep today's base.

**Acceptance:**

- `python3 .github/scripts/workspace_ci.py plan 0000000000000000000000000000000000000000` exits 0 and its `release-order` lists every workspace member.
- `plan <a SHA not in this history>`, created by committing on a detached orphan branch in a temporary clone, does the same.
- `plan HEAD~1` still selects only the packages changed in `HEAD` and their dependents (same result as before the change).
- On GitHub: after a push whose run fails, the next push's run selects the failed push's packages again.

**Validation (2026-10-02):** zero SHA, missing ref and an existing orphan commit select all packages and report the fallback on stderr. `plan HEAD~1` produces the same output as before the change; a scoped commit in a temporary clone selects its package and dependents only. The workflow shell was checked with mocked commands for push, no previous successful run, pull request, manual dispatch and a failed API lookup. `actionlint`, Ruff lint and format checks pass. The failed-push/next-push GitHub check remains pending.

### S14.2.4 — Concurrency

**State:** Closed (2026-10-02)

This depends on S14.2.3: without it, a replaced pending run on `main` loses its changes.

- Workflow level: `concurrency: { group: "ci-${{ github.ref }}", cancel-in-progress: "${{ github.event_name == 'pull_request' }}" }`.
- `docs` job: `concurrency: { group: pages, cancel-in-progress: false }`, so two deployments never race to push `gh-pages`.

**Acceptance:** both blocks are present (checked below); `actionlint` passes.

### S14.2.5 — The release is the record

**State:** Active

Rewrite `release`'s loop to the Design's table. Remove `git tag`, `git push` and the `git ls-remote` skip. Keep: `releasable` decides the packages, the order, `uv build --package <name> --out-dir dist/<name>`, and "build but do not publish" off `main`.

**Acceptance:**

- `main.yml` contains no `git tag -a`, `git push origin "$tag"` or `git ls-remote --exit-code --tags`; it contains `gh release view` with `isDraft` and `gh release create` with `--target`.
- On GitHub (owner-run, once): delete a package's latest GitHub Release but keep its tag, then rerun the `main` workflow. The run recreates the release from the tag, with its wheel and sdist, and the tag still points at its original commit.
- A second rerun skips that package as already shipped.

**Validation (2026-10-02):** the workflow shell passed eight local scenarios with mocked `gh` and `uv` and real temporary Git repositories: fresh release and rerun, published-release skip, tag-only resume, drafts with and without a tag, pull-request build without publication, failed build preserving a draft, and failed publication followed by recovery and skip. Resumed assets contain the tagged source, and the remote tag stays at its original commit. The workflow's static acceptance and `actionlint` pass. The owner-run GitHub resume and rerun checks remain pending.

## Acceptance

```bash
set -euo pipefail
absent() { local rc=0; rg -q --hidden --glob '!.git' "$@" </dev/null || rc=$?; [ "$rc" -eq 1 ]; }
wf=.github/workflows/main.yml
# S14.2.1
absent --pcre2 -e 'uses: [^.][^@]*@(?![0-9a-f]{40} # v[0-9]+\.[0-9]+\.[0-9]+)' .github
# S14.2.2
absent -e 'astral-sh/setup-uv|uv sync' "$wf"
rg -q 'uv sync --all-packages --all-extras --locked' .github/actions/setup/action.yml
[ "$(yq '[.jobs | to_entries[] | select(.key != "plan" and .key != "ci-ok") | select(([.value.steps[].uses] | map(select(. == "./.github/actions/setup")) | length) == 0)] | length' "$wf")" = 0 ]
actionlint "$wf"
# S14.2.3
all=$(python3 -c 'import sys; sys.path.insert(0, ".github/scripts"); import workspace_ci as w; print(len(w.load_packages()))')
out=$(python3 .github/scripts/workspace_ci.py plan 0000000000000000000000000000000000000000)
[ "$(sed -n 's/^release-order=//p' <<<"$out" | jq length)" = "$all" ]
# S14.2.4
[ "$(yq '.concurrency.group' "$wf")" = 'ci-${{ github.ref }}' ]
[ "$(yq '.jobs.docs.concurrency.group' "$wf")" = pages ]
# S14.2.5
absent -e 'git tag -a|git push origin "\$tag"|git ls-remote --exit-code --tags' "$wf"
rg -q 'isDraft' "$wf"
rg -q 'gh release create .*--target' "$wf"
# S14.2.6
rg -q 'head.repo.full_name == github.repository' "$wf"
rg -q 'sonar.qualitygate.wait=true' "$wf"
# S14.2.7
[ "$(yq '[.jobs[] | select(has("timeout-minutes") | not)] | length' "$wf")" = 0 ]
[ "$(yq '.updates[0]["package-ecosystem"]' .github/dependabot.yml)" = github-actions ]
# S14.2.8
rg -q 'actions/setup/action.yml' .github/workspace-ci-handoff.md
rg -q 'dependabot.yml' .github/workspace-ci-handoff.md
```
