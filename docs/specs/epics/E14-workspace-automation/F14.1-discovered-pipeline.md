## Design

**Outcome:** the planner began as `.github/scripts/workspace_ci.py` and moved
into the `rn-forge-devops` package
([F16.1](../E16-kiln-adoption/F16.1-devops-package.md)). Release gating kept the
S9.3.2 decision: a failed check blocks only its package and the selected
packages that depend on it.

### Considered and rejected

- **Generating the YAML from a template (kiln codegen).** This keeps a named job
  per package in the Actions UI. But the file goes stale until it is
  regenerated, which is the drift this feature removes.
- **A reusable workflow in a shared repository.** This is the eventual home once
  more than pykit uses it. Until then, pykit carries the reference copy and
  kiln's templates copy it (S14.1.4).
- **Releasing only when every check passes.** This is simpler, but it reverses
  the owner's S9.3.2 decision that a failure blocks only its dependents.

## S14.1.3 — Workflow on the plan

**State:** Closed (2026-10-03)

**Acceptance:**

- `main.yml` names no package, and `_package-ci.yml` is gone. `actionlint`
  passes.
- `sonar-project.properties` lists no package.
- A pull request run shows `verify` for each selected package, `postgres` and
  `smoke` for `rn-forge-django`, `suite (scaffold)`, `release` building
  without tagging, and `ci-ok` passing.
- The first push to `main` after the merge tags only packages whose version
  changed. `external-install` and `docs` handle those tags as before.

```bash
set -euo pipefail
absent() { local rc=0; rg -q --hidden --glob '!.git' "$@" </dev/null || rc=$?; [ "$rc" -eq 1 ]; }
absent 'rn-forge-|rn_forge' .github/workflows/main.yml sonar-project.properties
test ! -e .github/workflows/_package-ci.yml
actionlint .github/workflows/main.yml
```

The pull-request and `main` runs are checked on GitHub.

**Amended 2026-10-03:** making `ci-ok` the required check is repository
configuration, not repo content, and moved to ideas, and was done on 2026-10-03.
GitHub reported `main` as not protected until then.

**Outcome:** PR 4's rerun at `8d62729` passed every job and the push to `main`
at `ca04bca` tagged nothing, as no version changed (2026-10-03).
