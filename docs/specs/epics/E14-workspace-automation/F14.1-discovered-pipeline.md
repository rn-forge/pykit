`.github/workflows/main.yml` named every package: one job each, a hand-written `needs:` chain copying the dependency graph, and package lists in the `sonar`, `docs` and `sonar-project.properties` inputs. `changed_packages.py` already read the graph from the manifests, so the YAML repeated it. The copies drifted: `sonar-project.properties` left out `rn-forge-fastapi` and `rn-forge-sqlalchemy`. Every new package meant editing CI by hand ([adding a package](../../../runbooks/adding-a-package.md), step 5).

## Design

One script, `.github/scripts/workspace_ci.py`, reads the workspace and supports the workflow through four subcommands:

| Subcommand | Does |
| --- | --- |
| `plan [BASE]` | Selects packages the way `changed_packages.py` did, and writes every job's matrix and package list as `$GITHUB_OUTPUT` lines. |
| `releasable OK_DIR NAME...` | Prints, in dependency order, the selected packages whose checks all passed and whose selected prerequisites are releasable. |
| `released` | Prints `name dir module version` for each `<name>-v<version>` tag at `HEAD`, for `external-install` and `docs`. |
| `smoke PACKAGE [EXTRA]` | Generalizes `check_django_extra.py`: builds the package and its internal requirements as wheels, installs one extra into a clean venv from the wheels' metadata, and imports the configured modules. |

What it discovers:

- **Packages:** the members of the root `[tool.uv.workspace]`, including `exclude`. No name prefix is assumed.
- **Internal requirements:** workspace members named in a package's dependencies, optional dependencies and dependency groups.
- **Import name:** `[tool.uv.build-backend].module-name`, used for `--cov`, the external-install import and the smoke imports.
- **Optional jobs:** `sonar` runs only if `sonar-project.properties` exists; `docs` only if `mkdocs.yml` exists; `lint-imports` only if `.importlinter` exists.

What a repository declares, in `[tool.workspace-ci]` tables:

| Table | Where | Holds |
| --- | --- | --- |
| `[tool.workspace-ci]` | root | `pytest-args` for package test runs. |
| `[tool.workspace-ci.suites]` | root | A named workspace-wide pytest run per key, each its own job (pykit: `scaffold`). |
| `[tool.workspace-ci.postgres]` | package | `env`: the variable that receives a PostgreSQL DSN; the package's tests run again against a service container. |
| `[tool.workspace-ci.smoke]` | package | `modules` imported for every smoke run, an optional `setup` script run first, and `extras`: one smoke job per extra with its own modules. |

Workflow shape: `import-boundaries` and `plan` run first. Then the `verify`, `postgres`, `smoke` and `suites` matrices run in parallel over the selected packages. Then a single `release` job runs, followed by `sonar`, `external-install` and `docs`. `ci-ok` aggregates every job and is the one required status check, because matrix job names change with the packages.

Release gating keeps the S9.3.2 decision: a failed check blocks only its package and the selected packages that depend on it. A matrix reports one result for all its entries, so each passing entry uploads an `ok-<marker>` artifact. `release` downloads them, asks `releasable` which packages may go, and tags them in dependency order. Tagging moves out of the package jobs into this one job; the tags, releases and build artifacts stay the same.

What changes in behavior:

- Package checks no longer wait on their prerequisites' jobs; they all start together. Correctness is unchanged, because each check already tests against its prerequisites' workspace source. Order now matters only when tagging, and `release` tags in dependency order.
- A package's `postgres` and `smoke` results now gate its tag. Before, only its package job did.
- `docs` and `external-install` follow `release`: they act on whichever tags this run created, and a failed check elsewhere no longer holds them back.
- `sonar` analyses all seven packages, with sources and tests passed from the plan.

### Considered and rejected

- **Generating the YAML from a template (kiln codegen).** This keeps a named job per package in the Actions UI. But the file goes stale until it is regenerated, which is the drift this feature removes.
- **A reusable workflow in a shared repository.** This is the eventual home once more than pykit uses it. Until then, pykit carries the reference copy and kiln's templates copy it (S14.1.4).
- **Releasing only when every check passes.** This is simpler, but it reverses the owner's S9.3.2 decision that a failure blocks only its dependents.

### S14.1.2 — Planner script

**State:** Closed (2026-09-28)

**Acceptance:** `workspace_ci.py` replaces `changed_packages.py` and `check_django_extra.py`. `plan` selects the same packages as `changed_packages.py` for each of the last 40 commits. `releasable` withholds a package whose marker is missing, and every selected dependent of it. `smoke` passes for `rn-forge-django`'s extras and exits non-zero when a module fails to import.

### S14.1.3 — Workflow on the plan

**State:** Closed (2026-10-03)

**Acceptance:**

- `main.yml` names no package, and `_package-ci.yml` is gone. `actionlint` passes.
- `sonar-project.properties` lists no package.
- A pull request run shows `verify` for each selected package, `postgres` and `smoke` for `rn-forge-django`, `suite (scaffold)`, `release` building without tagging, and `ci-ok` passing.
- The first push to `main` after the merge tags only packages whose version changed. `external-install` and `docs` handle those tags as before.

```bash
set -euo pipefail
absent() { local rc=0; rg -q --hidden --glob '!.git' "$@" </dev/null || rc=$?; [ "$rc" -eq 1 ]; }
absent 'rn-forge-|rn_forge' .github/workflows/main.yml sonar-project.properties
test ! -e .github/workflows/_package-ci.yml
actionlint .github/workflows/main.yml
```

The pull-request and `main` runs are checked on GitHub.

**Amended 2026-10-03:** making `ci-ok` the required check is repository configuration, not repo content, and moved to [ideas](../../ideas.md#require-ci-ok-on-main). GitHub reports `main` as not protected.

**Evidence (2026-10-03):** [PR 4's rerun](https://github.com/rn-forge/pykit/actions/runs/37159037047) at `8d62729` passed every job, including `sonar` and `ci-ok`; a PR run builds release artifacts without tagging. The [push to `main`](https://github.com/rn-forge/pykit/actions/runs/37159567899) at `ca04bca` changed no package version, so no package was tagged or published; `external-install` and `docs` succeeded.

- This feature's *Design* records the source of each package list, the `[tool.workspace-ci]` tables and the release gating (S14.1.1).
