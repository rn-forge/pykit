Let a consumer who pins a package tag verify where it came from and what it
contains. Each package tag gets a CycloneDX SBOM, and release tags get artifact
attestations. This is the largest E20 feature, because it changes the release
workflow.

## Design

Decided in [ADR-0015](../../../adr/ADR-0015.md):

- The SBOM is `cyclonedx-py` CycloneDX JSON.
- Attestations are GitHub artifact attestations on the built files, plus the
  PyPI attestations that trusted publishing
  ([E21](../E21-pypi-distribution/index.md)) produces.
- Verification covers the PyPI and GitHub Release files. A `git+…@<tag>` source
  build is not covered, tags are not signed, and the guide steers consumers to
  PyPI.

## Stories

### S20.4.1 — SBOM per package tag

**State:** Active

**Acceptance:** each package release uploads a CycloneDX SBOM beside its wheel
and sdist on the GitHub Release.

### S20.4.2 — Attest release artifacts

**State:** New

**Acceptance:** release artifacts carry an attestation, and a documented
verification command succeeds for a released tag and fails for a modified file.

### S20.4.3 — Consumer verification guide

**State:** New

**Acceptance:** a guide shows a consumer how to verify a pinned tag's origin and
read its SBOM.

## Acceptance

- S20.4.1: the release job attaches the SBOM.
- S20.4.2: the verification command passes on a real release tag.
- S20.4.3: the docs build passes with the guide.
