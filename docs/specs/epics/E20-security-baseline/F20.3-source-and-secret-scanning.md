# F20.3 — Source and secret scanning

Catch insecure code patterns and committed secrets. CI runs a security linter
with Django rules over first-party source, gitleaks scans the full git history,
and GitHub push protection is on for the repository.

## Design

Decided in [ADR-0015](../../../adr/ADR-0015.md): the source scan is ruff's `S`
rules (Bandit's checks) over `packages/`, and both scans fail CI.

## Stories

### S20.3.1 — Source scan with Django rules

**State:** Closed

**Acceptance:** CI runs the scanner over `packages/` with Django rules, and a
seeded insecure pattern is flagged as F20.1 decides (fail or report).

### S20.3.2 — Secret scan over full history

**State:** Closed

**Acceptance:** CI runs gitleaks over the full git history, not only the change,
and a seeded secret is caught.

### S20.3.3 — Enable push protection

**State:** New

**Acceptance:** GitHub secret scanning push protection is enabled on the
repository, confirmed from the repository's security settings.

## Acceptance

- S20.3.1: the source scan step runs in CI.
- S20.3.2: the gitleaks step runs with full history (`fetch-depth: 0`).
- S20.3.3: push protection shows as enabled (not scriptable; owner confirms).
