The login methods, each ending in an `ExternalIdentity`: OIDC and OAuth 2.0,
SAML 2.0, local passwords and the development provider, behind `rn-forge-auth`'s
extras.

## Context

It covers:

- The OIDC and OAuth 2.0 adapter over the library S13.1.3 chose: PKCE, the login
  transaction, the RFC 9207 `iss` check, the UserInfo `sub` check, `max_age`,
  claim mapping, OAuth 2.0-only providers, RP-initiated logout
  ([OIDC login](design.md#oidc-login-authorization-code-with-pkce)).
- Back-channel logout token handling under the logout-token profile
  ([Logout](design.md#logout)).
- The SAML adapter over python3-saml with strict defaults, the RelayState
  handle, `InResponseTo`, the assertion replay cache, `ForceAuthn`, opt-in
  IdP-initiated SSO, SP metadata and optional SLO
  ([SAML login](design.md#saml-login-sp-initiated-http-post-binding)).
- The local-password and development adapters
  ([Local password login](design.md#local-password-login-optional-provider)).
- Where S13.1.3 assigns a flow on a framework to a library's integration
  (allauth on Django, say), this feature adapts that integration's result
  instead of writing the adapter.
- The optional, non-gating Keycloak job for the broker profile
  ([Testing](design.md#testing)).

Its stories are written by S13.1.4 ([F13.1](F13.1-auth-design.md)) once the
library evaluation names what pykit binds; S13.1.4 then sets `Iteration` to
Release 7. Until then no code change starts here.
