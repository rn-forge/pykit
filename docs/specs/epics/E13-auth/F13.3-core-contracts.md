# F13.3 — Core contracts and token profiles

|  |  |

The framework-neutral core of `rn-forge-auth`: the contracts every login method,
binding and application builds on, the three token validation profiles, the
stores, and the offline fakes every later feature tests against.

## Context

It covers:

- `ExternalIdentity`, `IdentityProvider`, `AccountResolver`,
  `AuthorizationContext`, `AuthorizationContextProvider` and `ResourcePolicy`
  ([Contracts](design.md#contracts)).
- The `Principal` fields and `Requirement` changes in
  [Contracts](design.md#contracts): permission clauses, no role clauses; the
  neutral action-to-key helper; the scope-to-permission limit
  ([Authorization model](design.md#authorization-model)).
- The versioned, invalidatable authorization context cache.
- The access-token, ID-token and logout-token profiles
  ([Token validation](design.md#token-validation)), including the
  audience-equals-client-ID refusal.
- `return_to` validation and the session-body schema
  ([HTTP surface](design.md#http-surface)).
- The `SessionStore`, transaction and replay store protocols, in-memory stores
  for tests, and the Redis store behind the `redis` extra, with atomic consume
  and set-if-absent ([Revocation](design.md#revocation),
  [Supported storage](design.md#supported-storage)).
- In-process fake OIDC and SAML IdPs with a switch for each failure the
  [security controls](design.md#security-controls) cover
  ([Testing](design.md#testing)).

Its stories are written by S13.1.4 ([F13.1](F13.1-auth-design.md)) once the
library evaluation names what pykit binds; S13.1.4 then sets `Iteration` to
Release 7. Until then no code change starts here.
