`rn-forge-django` binds the shared HTTP surface, sessions, CSRF and
authorization over `rn-forge-auth`, as
[Package responsibilities](design.md#package-responsibilities) lists for it.

## Context

It covers:

- The [HTTP surface](design.md#http-surface) as views and URLconf, with provider
  configuration built from `rn-forge-auth`'s types and no `AUTH.OIDC` settings
  block.
- Sessions through `django.contrib.sessions` with the cookie, timeout, rotation
  and revocation rules in
  [Sessions and cookies](design.md#sessions-and-cookies); transactions and
  replay records in Django's Redis cache; refusal of unsafe stores outside
  debug mode.
- CSRF through `CsrfViewMiddleware`, the `csrf-failed` problem and the origin
  check ([CSRF](design.md#csrf)).
- A DRF authentication class for session principals; bearer callers resolved to
  an account; one credential per request.
- The default `AccountResolver` and external-account link model
  ([Account linking](design.md#account-linking)), and the default context
  provider from groups and permissions.
- DRF permissions from `Requirement` and `ResourcePolicy`, and queryset scoping.
- Rate limiting and audit events
  ([Security controls](design.md#security-controls)), and the revocation race
  tests ([Revocation](design.md#revocation)).

Its stories are written by S13.1.4 ([F13.1](F13.1-auth-design.md)) once the
library evaluation names what pykit binds; S13.1.4 then sets `Iteration` to
Release 7. Until then no code change starts here.
