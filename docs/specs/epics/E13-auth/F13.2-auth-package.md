# F13.2 — rn-forge-auth package

|  |  |
| -- | -- |
| **State** | New |
| **Parent** | [E13](index.md) |
| **Iteration** | [Release 7](../../../releases/release-7/index.md) |
| **Predecessors** | [F13.1](F13.1-auth-design.md), [F15.1](../E15-package-boundaries/F15.1-package-boundary-rule.md), [F16.2](../E16-kiln-adoption/F16.2-conform-to-the-standard.md), [F16.3](../E16-kiln-adoption/F16.3-cutover.md) |
| **Source** | Owner-approved package split analysis, 2026-10-13 |

Create `rn-forge-auth` and move into it the existing token verification,
`Principal` and OIDC code that
[the library evaluation](design.md#library-evaluation) keeps, as
[the package placement](design.md#package-placement) proposes. Token code a
library replaces is deleted instead of moved. This feature moves or deletes
existing code only. The new adapters, the session
surface, authorization policy and the removal of the JWT flows are the other E13
features, which build on it and ship in the same release.

## Context

F13.1 must settle the package placement, its proposed decision 6 and the
library evaluation (S13.1.3) before this feature starts, so the move follows an
accepted design and carries only code that survives the evaluation.
[F16.2](../E16-kiln-adoption/F16.2-conform-to-the-standard.md) lands first too,
so the moved code and the new package's docs and changelog are held to the
shared standard from the start. [F16.3](../E16-kiln-adoption/F16.3-cutover.md)
lands first as well, so the package joins a kiln-managed workspace through
[adding a package](../../../runbooks/adding-a-package.md). E15's
[design](../E15-package-boundaries/design.md#rn-forge-auth-contents) lists the
symbols that move and the wiring that changes. The move is a breaking release of
`rn-forge-commons`, `rn-forge-web`, `rn-forge-django` and `rn-forge-fastapi`,
because [ADR-0002](../../../adr/ADR-0002.md) forbids aliases.

## Stories

### S13.2.1 — Scaffold the package and its workspace wiring

**State:** New

**Acceptance:**

- `packages/rn-forge-auth/` exists with a `pyproject.toml` (version `0.1.0`,
  pinned tag dependencies), `README.md`, `CHANGELOG.md`, `docs/`, a strict
  `mkdocs.yml`, `src/rn_forge/auth/__init__.py` and a `tests/` tree with no
  `__init__.py`.
- The root `pyproject.toml` lists it as a workspace member, and `.importlinter`
  lists `rn_forge.auth` in `root_packages` and the layers contract between the
  framework packages and `rn_forge.web`, and holds a forbidden contract that
  its core never imports an adapter module.
- `.rn-forge/kiln/config.toml` lists it in `packages` and `modules`.
- `uv run lint-imports` and `uv run pyright` pass.

### S13.2.2 — Move or retire the commons token code

**State:** New

**Acceptance:**

- None of `JwtVerifier`, `JwksCache`, `discover_oidc` and `fetch_json` exists in
  `rn_forge.commons.integration`.
- Each one the library evaluation keeps is importable from `rn-forge-auth`, with
  its tests in `rn-forge-auth/tests/`, mirroring the source layout, passing.
- Each one it replaces is deleted, and its in-repo callers use the chosen
  library.
- `rn-forge-commons` has no `auth` extra.

### S13.2.3 — Move the web auth types

**State:** New

**Acceptance:**

- `Principal`, `Requirement`, `Authenticator`, `AsyncAuthenticator`,
  `Authorizer`, `ScopeAuthorizer`, `principal_from_claims` and
  `OidcAuthenticator` are importable from `rn-forge-auth` and gone from
  `rn-forge-web`.
- `rn-forge-web` still exports `Credentials`, `parse_authorization`,
  `challenge_header`, `AUTH_FAILED_DETAIL`, `AuthenticationFailed`,
  `PermissionDenied` and the problem responses, and has no `auth` extra.
- Every in-repo import of a moved symbol points at `rn-forge-auth`, and the web
  conformance tests pass.

### S13.2.4 — Repoint the framework packages

**State:** New

**Acceptance:**

- `rn-forge-django`'s and `rn-forge-fastapi`'s `oidc` extras name
  `rn-forge-auth` and no commons or web auth extra.
- Their tests pass with the moved imports. Django's `jwt` extra is untouched.
- Each package's isolated-install check for the `oidc` extra passes.

### S13.2.5 — Document the package

**State:** New

**Acceptance:**

- The package has a site with a guide for the moved contracts, and its API
  reference builds.
- The root `README.md` package table, `docs/index.md`,
  `docs/architecture/workspace.md`, `docs/guides/choosing-packages.md` and the
  root `mkdocs.yml` name `rn-forge-auth`.
- The changed packages' changelogs record the breaking moves.
- `uv run --group docs mkdocs build --strict` passes for the package site and
  the combined site.

## Acceptance

- The package exists, is wired into the workspace and passes the boundary checks
  (S13.2.1).
- The commons token code is gone from commons, kept in `rn-forge-auth` or
  replaced by the chosen library (S13.2.2).
- The web auth types live only in `rn-forge-auth`, and web keeps the wire
  contract (S13.2.3).
- The framework packages' `oidc` extras name `rn-forge-auth` (S13.2.4).
- The package, the root pages and the changelogs are documented and both strict
  builds pass (S13.2.5).
- `uv run pytest`, `uv run lint-imports`, `uv run pyright` and
  `sh docs/_update_board.sh --check` pass.
