On a push to `main`, `main.yml`'s `release` job uploads each released package to
PyPI by trusted publishing. A manual run can upload to TestPyPI instead. Each
per-package GitHub release takes its changelog section as notes and is never
marked "Latest". A separate reusable workflow creates the umbrella `release-<n>`
release when a release page is shipped. `external-install` installs from PyPI.

## Design

### `rn-forge-devops`: two commands

These are release logic, so per [ADR-0012](../../../adr/ADR-0012.md) they belong
in the package and not in the workflow. Neither is a planner command, so they
stay in pykit after
[S16.3.4](../E16-kiln-adoption/F16.3-cutover.md#s1634-the-planner-leaves-and-e19s-files-are-declared).

**Core module `packages/rn-forge-devops/src/rn_forge/devops/notes.py`** (new).
It imports no adapter and no planner module.

```python
def changelog_section(changelog: str, version: str) -> str:
    """The body under `## [<version>]` up to the next `## [` heading, stripped.

    Raises:
        ValueError: no `## [<version>]` heading, or its body is empty.
    """


@dataclass(frozen=True, slots=True)
class Umbrella:
    tag: str    # "release-6"
    title: str  # the page's H1 text: "Release 6 — kit upgrades for kiln"
    body: str


def pending_umbrella(
    releases_dir: Path, existing_tags: Collection[str], site_url: str
) -> Umbrella | None:
    """The umbrella release for the newest shipped release page, unless it is tagged."""
```

**`changelog_section`:**

- The heading matches `## [<version>]` followed by the end of the line or
  ` - <date>`.
- It matches the version exactly, so `0.7.1` does not match `0.7.10`.

**`pending_umbrella`:**

- It reads each `releases_dir/release-<n>/index.md` and finds the highest `<n>`
  whose metadata row `| **Status** | … |` has a value starting `shipped`.
- It returns `None` if there is none, or if `release-<n>` is in `existing_tags`.
  Only the newest shipped page is considered, so older pages are never
  backfilled.
- The body is the page's `## Shipped` section, up to the next `## ` heading or
  the end of the file, followed by a blank line and
  `Release page: <site_url>releases/release-<n>/`.

**CLI** (`cli.py`), both commands handled before the workspace is loaded, like
`index`:

- `rn-forge-devops notes CHANGELOG VERSION` prints `changelog_section` of the
  file. It exits 1 with the `ValueError` message on stderr.
- `rn-forge-devops umbrella RELEASES_DIR BODY_FILE --site-url URL`:
    - reads `git ls-remote --tags --refs origin` output from stdin and takes the
      tag names from it;
    - when there is a pending umbrella, writes its body to `BODY_FILE` and prints
      `tag=<tag>` and `title=<title>`, as `$GITHUB_OUTPUT` lines;
    - otherwise prints nothing;
    - exits 0 either way.

**`.importlinter`:** add `rn_forge.devops.notes` to the `source_modules` of
`devops-core-has-no-adapter` and of `devops-requirements-is-standalone`, and
update both contracts' `name` lines.

**Tests** (`packages/rn-forge-devops/tests/`):

- `test_notes.py`:
    - section between two headings;
    - the last section in the file;
    - a dated heading;
    - `0.7.1` not matching `0.7.10`;
    - a missing version raises;
    - an empty section raises;
    - `pending_umbrella` picks the highest shipped page over a higher planned one;
    - it returns `None` when that tag exists, and `None` with no shipped page;
    - the body holds the Shipped section and the page link, and stops at the next
      `## `.
- `test_cli.py`:
    - `notes` prints a section, and exits 1 on a missing version;
    - `umbrella` with stdin tags and a temporary releases tree prints the two
      output lines and writes the body, and prints nothing when the tag is
      listed;
    - the existing subprocess test that asserts no planner module is loaded also
      imports `rn_forge.devops.notes`.

**Docs:** `rn-forge-devops`' README lists `notes` and `umbrella`. Its changelog
`[Unreleased]` *Added* names both commands.

### `main.yml`

**Trigger:** `workflow_dispatch` gains an input
`testpypi: { type: boolean, default: false, description: "Upload every package to TestPyPI; no tags or releases" }`.

**`release` job:**

- `permissions`: `contents: write`, `id-token: write`.

- `environment`:
  `${{ (github.event_name == 'push' && github.ref_name == 'main') && 'pypi' || (github.event_name == 'workflow_dispatch' && inputs.testpypi) && 'testpypi' || '' }}`.
  An empty name means no environment, so pull requests still build without
  approval.

- The step env gains
  `TESTPYPI: ${{ github.event_name == 'workflow_dispatch' && inputs.testpypi }}`.

- In the loop, after each `uv build`, every event runs
  `uvx twine@<exact version, 6.1 or later> check --strict dist/"$name"/*`.

- A helper in the step decides whether to upload:

    ```bash
    on_index() { curl -fsS -o /dev/null "https://$1/pypi/$2/$3/json"; }
    ```

- On a TestPyPI run (`TESTPYPI` true, so `PUBLISH` false):

    - if `on_index test.pypi.org "$name" "$version"` succeeds, it skips;
    - otherwise it runs
      `uv publish --trusted-publishing always --publish-url https://test.pypi.org/legacy/ dist/"$name"/*`;
    - it creates no tags and no releases.

- On a publish run, for a package whose GitHub release is not already published:

    - it builds as today;
    - then, unless `on_index pypi.org "$name" "$version"` succeeds, it runs
      `uv publish --trusted-publishing always dist/"$name"/*`;
    - then it creates the GitHub release.

    Uploading first means a published GitHub release always implies the version is
    on PyPI. A package whose GitHub release is already published is skipped as
    today, PyPI included.

- Both `gh release create` lines:

    - drop `--generate-notes`;
    - gain `--latest=false --notes-file "$notes"`, where `notes` is a temporary
      file written by
      `uv run rn-forge-devops notes "packages/$name/CHANGELOG.md" "$version"`.

- A failed upload fails the job, as a failed `gh release create` does today.
  Rerunning the run resumes, skipping what PyPI and GitHub already have.

**`external-install` job:**

- It keeps the remote tag fetch.
- It replaces the git-URL install with
  `uv pip install -q --refresh "$name==$version"`.
- It retries up to 10 times, 30 seconds apart, while PyPI's CDN catches up.
- Its comment says it proves the PyPI upload installs on its own.

**Umbrella release**, as a new reusable workflow
`.github/workflows/umbrella-release.yml`:

- `on: workflow_call`, and `permissions: contents: write`.
- One job that:
    - checks out, using the setup action with `sync: "false"`;
    - runs
      `git ls-remote --tags --refs origin | uv run rn-forge-devops umbrella docs/releases "$RUNNER_TEMP/umbrella.md" --site-url https://rn-forge.github.io/pykit/ >> "$GITHUB_OUTPUT"`;
    - when `tag` is set, runs
      `gh release create "$tag" --target "$GITHUB_SHA" --title "$title" --notes-file "$RUNNER_TEMP/umbrella.md" --latest`.

`main.yml` calls it as job `umbrella-release`:

- `if: ${{ github.event_name == 'push' && github.ref_name == 'main' }}`;
- `needs: [import-boundaries]`;
- `permissions: contents: write`.

It does not wait on `release`, because the commit that ships a release page
changes only docs and runs no `release`. `ci-ok`'s `needs` gains
`umbrella-release`.

The first push after this merges creates `release-6`, which takes "Latest" from
`rn-forge-sqlalchemy v0.2.1`. Release 7's ship commit then creates `release-7`.

**Runbook:** [F21.4](F21.4-consumer-docs.md) owns the release runbook text. This
feature only changes the workflow.

## Stories

### S21.3.1 — `notes` and `umbrella` commands

**State:** Closed

**Acceptance:** the module, CLI, contracts and tests are as under *Design*, and
`rn-forge-devops`' tests, `lint-imports` and `pyright` pass.

### S21.3.2 — PyPI upload, TestPyPI dry run and release notes in `main.yml`

**State:** New · **Depends on:** S21.3.1, S21.1.2

**Acceptance:**

- A pull request run builds and runs `twine check` for every selected package
  and uploads nothing.
- A manual run with `testpypi` from the release branch uploads every package to
  test.pypi.org.
- A second identical run uploads nothing and succeeds.
- `zizmor` and `actionlint`, wherever the repository runs them, pass on the
  changed workflows.

### S21.3.3 — First PyPI release and the umbrella

**State:** New · **Depends on:** S21.3.2

The story closes after Release 7 merges to `main` and its ship commit is pushed.

**Acceptance:**

- Every package's Release 7 version is on pypi.org.
- `external-install` passed from PyPI.
- Each per-package release has its changelog section as notes and is not
  "Latest".
- `release-7` exists and is "Latest".
