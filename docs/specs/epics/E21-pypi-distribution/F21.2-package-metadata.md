PyPI shows a package's metadata as its project page and keeps it with each
version forever. Today no package declares a licence, and the repository has no
`LICENSE` file. This feature completes every package's metadata and gives each
package a new version, so the first PyPI upload is complete.

## Design

**Licence.**

- A root `LICENSE` holds the MIT text, `Copyright (c) 2026 Rohit Narayanan`.
- An identical copy sits in each `packages/<pkg>/`. PEP 639 forbids
  `license-files` paths outside the project directory, so a member cannot
  reference the root file.

**Each `packages/<pkg>/pyproject.toml`**, in `[project]` after `authors`:

```toml
license = "MIT"
license-files = ["LICENSE"]
classifiers = [
  "Development Status :: 3 - Alpha",
  "Intended Audience :: Developers",
  "Operating System :: OS Independent",
  "Programming Language :: Python :: 3",
  "Programming Language :: Python :: 3 :: Only",
  "Programming Language :: Python :: 3.14",
  "Typing :: Typed",
]
```

- `rn-forge-django` adds `"Framework :: Django"`.
- `rn-forge-fastapi` adds `"Framework :: FastAPI"`.
- No package carries a `License ::` classifier, which PEP 639 forbids alongside
  `license`.

**A version for every package.** Each package's version goes up by one patch
over its latest `<name>-v<version>` tag, unless Release 7 already bumps it
further. Each `CHANGELOG.md` gets this under `[Unreleased]`, *Changed*: "The
package declares the MIT licence and is published to PyPI." Internal requirement
floors do not move.

**Keeping it complete.** The `release` job runs `twine check --strict` on every
build ([F21.3](F21.3-publish-from-release.md)), including on pull requests, so a
member with broken metadata fails CI.
[Adding a package](../../../runbooks/adding-a-package.md) gains a step: copy
`LICENSE` and the `license`, `license-files` and `classifiers` block from an
existing member.

## Stories

### S21.2.1 — Licence, classifiers and a new version for every package

**State:** Closed

**Acceptance:**

- Every member's wheel and sdist pass `twine check --strict` with twine 6.1 or
  later, which reads metadata 2.4.
- Each wheel's `METADATA` has `License-Expression: MIT` and
  `Classifier: Programming Language :: Python :: 3.14`.
- No member's version equals a version that already has a tag.

## Acceptance

```bash
set -euo pipefail
rm -rf dist
test -f LICENSE
for d in packages/*/; do
  name=$(basename "$d")
  cmp -s LICENSE "$d/LICENSE"
  uv build -q --package "$name" --out-dir "dist/$name"
  version=$(uv version --package "$name" --short)
  [ -z "$(git ls-remote --tags origin "refs/tags/$name-v$version")" ]
done
uvx 'twine>=6.1' check --strict dist/*/*
for w in dist/*/*.whl; do
  unzip -p "$w" '*.dist-info/METADATA' | grep -qx 'License-Expression: MIT'
  unzip -p "$w" '*.dist-info/METADATA' | grep -qx 'Classifier: Programming Language :: Python :: 3.14'
done
```
