This feature records the distribution decision in
[ADR-0004](../../../adr/ADR-0004.md) and has the owner set up the PyPI side, so
CI can upload.

## Design

The owner accepted these on 2026-10-26 ([E21](index.md#context)):

- **Index.** Every `rn-forge-*` package is published to pypi.org. A consumer
  declares no index. `https://rn-forge.github.io/pykit/simple/` keeps serving
  until [F21.5](F21.5-retire-index.md).
- **Ownership.** The projects belong to the PyPI organization `rn-forge` once
  PyPI approves it. Until then they are created by the owner's account through
  pending publishers and transferred afterwards.
- **Upload.** Trusted publishing (OIDC) from `rn-forge/pykit`'s workflow
  `main.yml`, under the GitHub environment `pypi`, with `testpypi` for the dry
  run. No API token is stored.
- **Immutability.** A published version is never replaced. A rerun skips
  versions PyPI already has, and a bad release is yanked and superseded by the
  next patch.
- **Licence.** MIT ([F21.2](F21.2-package-metadata.md)).
- **GitHub Releases.**
    - Each package keeps its tag `<name>-v<version>` and a GitHub release, whose
      notes are the package's changelog section and which is never "Latest".
    - When a release page becomes `shipped`, an umbrella release `release-<n>` is
      created from it and marked "Latest"
      ([F21.3](F21.3-publish-from-release.md)).

**ADR-0004 is revised in place:**

- `## Background` gains a dated line for the change.
- `**Status:**` gains `revision accepted (<date>)` after the existing revision.
- *Decision*: the sentences "pykit publishes a PEP 503 index … or pin a tag by
  direct URL, as before." become: "Every package is published to PyPI by
  trusted publishing from pykit's release workflow. A consumer requires
  packages by name and range with no index declaration, or pins a tag by
  direct URL. A published version is never replaced: a bad one is yanked and
  superseded by the next patch."
- *Decision*: "A coordinated batch records the selected packages and tag
  evidence on its release page" gains: "and, when that page is shipped, an
  umbrella GitHub release `release-<n>` marked Latest".
- *Consequences* gains: "kiln and other libraries can depend on pykit by range,
  and can publish to PyPI themselves."

### S21.1.2 — The PyPI projects can accept uploads from CI

**State:** Active

The owner completes these steps; none of them can be scripted:

1. Make the owner's membership of the `rn-forge` GitHub organization public.
1. Link the owner's PyPI and GitHub accounts under PyPI's *Account
   associations*.
1. Tell PyPI staff both are done, and correct the organization request's URL to
   `https://github.com/rn-forge`.
1. Create the GitHub environments in `rn-forge/pykit`:
    - `pypi`, with a deployment branch policy allowing only `main`;
    - `testpypi`, with no branch policy, so the dry run can run from a release
      branch.
1. For each of the nine package names, add a pending trusted publisher with
   owner `rn-forge`, repository `pykit` and workflow `main.yml`:
    - on pypi.org, with environment `pypi`;
    - on test.pypi.org, with environment `testpypi`. A pending publisher does not
      reserve a name, so this step comes shortly before F21.3's first upload.

**Acceptance:**

- Both environments exist, and `pypi` allows only `main`.
- The owner's membership is public.
