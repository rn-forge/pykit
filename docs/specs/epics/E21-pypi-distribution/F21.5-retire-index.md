# F21.5 — Retire the self-hosted index

Once consumers no longer declare it, the index at
`https://rn-forge.github.io/pykit/simple/` and the code that builds it go away.

Owner decision, 2026-11-03: this feature is scheduled now. Its entry criteria
are met: Release 7 shipped every package through PyPI, kiln F7.5 is closed so
kiln's archetypes emit no pykit index, and no consumer lock names it. It lands
before [F16.3](../E16-kiln-adoption/F16.3-cutover.md)'s cutover, on
`feature/release-8`.

## Context

A consumer's `uv.lock` records the index each package came from. Removing
`simple/` while a lock still names it breaks that consumer's `uv sync --locked`.
As of 2026-11-03 no local rn-forge repository's `uv.lock` or `pyproject.toml`
names the index, and kiln F7.5 resolves rn-forge packages from PyPI and refuses
the index (`deps.pykit-index`).

## Design

- Remove from `rn-forge-devops`:
    - `rn_forge.devops.index`, `rn_forge.devops.releases` and their tests;
    - the `index` subcommand;
    - their `.importlinter` entries. This is a breaking minor bump, recorded in
      the README, changelog and docs site.
- Delete `.github/actions/package-index/`, and remove the package-index step
  from the `docs` job of `main.yml`, so the deploy publishes no `simple/`.
- Update `docs/guides/consuming-packages.md` and
  `docs/runbooks/releasing-packages.md` to say PyPI only.
- Add a dated Background line to ADR-0004 recording that the index is retired.

## S21.5.1 — Remove the index and its builder

**State:** Active

**Acceptance:**

- `rn-forge-devops --help` does not list `index`.
- `.github/actions/package-index` does not exist.
- After a run on `main`, `https://rn-forge.github.io/pykit/simple/` returns 404.
- `rn-forge-devops`' tests, `lint-imports` and `pyright` pass.

*What the build settled that the story did not say*

- The breaking change is recorded under `rn-forge-devops`' `[Unreleased]`
  changelog section; the version moves to 0.4.0 at release, as other packages'
  versions do.
- `.importlinter`'s devops contracts drop `index` and `releases`, and `notes`
  joins the standalone contract. No other subcommand served only those modules.
- The runbook had no index instructions; it gains one sentence saying Pages
  carries documentation and no package index.
- The 404 line needs a run on `main`, so the story stays `Active` until then.
