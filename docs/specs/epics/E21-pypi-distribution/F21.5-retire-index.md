# F21.5 — Retire the self-hosted index

|  |  |
| -- | -- |
| **State** | New |
| **Parent** | [E21](index.md) |
| **Tags** | deferred |
| **Predecessors** | [F21.3](F21.3-publish-from-release.md), [F21.4](F21.4-consumer-docs.md) |
| **Source** | Owner request, 2026-10-26 |
| **Entry criteria** | one pykit release shipped through PyPI, and a kiln release whose archetypes emit no pykit index |

Once consumers no longer declare it, the index at
`https://rn-forge.github.io/pykit/simple/` and the code that builds it go away.

## Context

A consumer's `uv.lock` records the index each package came from. Removing
`simple/` while a lock still names it breaks that consumer's `uv sync --locked`,
so the index outlives the switch by at least one release.

## Design

- Remove from `rn-forge-devops`:
    - `rn_forge.devops.index`, `rn_forge.devops.releases` and their tests;
    - the `index` subcommand;
    - their `.importlinter` entries. This is a breaking minor bump, recorded in
      the README, changelog and docs site.
- Delete `.github/actions/package-index/` and its `[ci.hooks] docs` entry in
  `kiln.toml`.
- Add a dated Background line to ADR-0004 recording that the index is retired.
