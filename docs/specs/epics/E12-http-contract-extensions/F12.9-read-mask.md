Google AIP-157 partial responses: a read accepts
`readMask=displayName,address.city`, and the response holds only those fields.
The API conventions list AIP-157 as "not adopted (deferred)"; this feature
adopts it for `GET` of one resource, `GET` of a collection, and `:batchGet`, on
both stacks. The mask is applied to the wire representation after serialization.
Every stack therefore validates and prunes identically, and the stacks'
serializers do not change.

## Context

**Outcome:** the owner scheduled this feature for release 3 on 2026-10-04, ahead
of its original trigger; F12.1 is a predecessor because the mask also applies to
`:batchGet`'s items.

## Design

**Outcome:** `readMask` shipped on both stacks (2026-10-04). The
[API conventions](../../../rn-forge-web/guides/api-conventions.md) §20 own the
wire rules; the [DRF views guide](../../../rn-forge-django/guides/drf-views.md)
and the
[FastAPI wiring guide](../../../rn-forge-fastapi/guides/wiring.md#partial-responses)
show the bindings.

### Shared pieces in `rn-forge-web`

**Outcome:** the
[read-mask reference](../../../rn-forge-web/reference/read_mask.md) documents
`rn_forge.web.read_mask`.

### New conformance cases

**Outcome:** the `read-mask` area's cases are in `CASES`, documented in the

## Considered and rejected

- **`drf-flex-fields` (checked 2026-10-04).** The parameter can be renamed
  (`REST_FLEX_FIELDS["FIELDS_PARAM"]`) and dotted paths and `*` are supported,
  but it fails the other tests. Its latest release is 1.0.2 (March 2023), with
  no `Typing :: Typed` classifier and no declared `requires_python`, so strict
  pyright sees untyped code. It silently ignores a name that matches no field,
  so an unknown path cannot return 400 without a second validation pass that
  duplicates the work. It reads the query only on the root serializer and
  prunes before serialization, which differs from the wire rules here and
  would leave the FastAPI side with a different implementation. It also adds a
  dependency. Adopting it would not delete any code.
- **Pydantic `model_dump(include=...)`.** It prunes nested models and lists
  (`{"phones": {"__all__": {"number": True}}}`), but it takes attribute names,
  not aliases (`include={"displayName"}` returns `{}` for a field aliased from
  `display_name`), and it silently ignores unknown names. It would need the
  same alias translation and validation as a wire-level pruner, and it would
  give FastAPI different semantics from Django. A shared pruner over the wire
  representation gives both stacks one contract.
- **Query projection (`only()`, `load_only`).** It would cut database work as
  well as payload, but it ties the mask to each ORM's loader, and a serializer
  method field can depend on columns the mask does not name. Pruning the
  serialized representation is identical on every stack. Projection can be
  added later behind the same wire rules.
- **JSON:API sparse fieldsets (`fields[type]=...`).** The conventions follow
  AIPs for naming where no RFC applies (§19), and AIP-157 is the AIP for this.
- **Making response properties optional in OpenAPI.** Every unmasked client
  would lose its required-field types to serve the masked case.
- **Always including `id`.** AIP-157 returns exactly the mask. A client that
  needs the id asks for it.
- **Ignoring unknown paths.** A typo would silently return an empty object,
  which is the failure §4 already rules out for `orderBy`.
