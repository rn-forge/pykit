Google AIP-157 partial responses: a read accepts `readMask=displayName,address.city`, and the response holds only those fields. The API conventions list AIP-157 as "not adopted (deferred)"; this feature adopts it for `GET` of one resource, `GET` of a collection, and `:batchGet`, on both stacks. The mask is applied to the wire representation after serialization. Every stack therefore validates and prunes identically, and the stacks' serializers do not change.

## Context

The owner scheduled this feature for release 3 on 2026-10-04, ahead of its original trigger ("payload size makes partial responses necessary"). F12.1 is a predecessor because the mask also applies to `:batchGet`'s items.

## Design

### Wire rules

- **`readMask`** is a query parameter holding a comma-separated list of field paths. A path is made of wire field names (camelCase, §8) joined by `.`. Whitespace around a path is ignored, and an empty path (`a,,b`, a trailing comma) is 400, detail `Unknown readMask path ''`. An absent or blank mask returns the whole resource.
- **`*` alone is the whole resource.** `*` combined with any path is 400, detail `readMask '*' cannot be combined with other paths`.
- **Every path must name a declared field.** The first segment names a field of the resource. Each later segment names a field of the declared object the previous segment reaches. A path through a list of objects (`phones.number`) applies to every element. A path that names nothing, or goes inside a scalar or a free-form JSON-valued field, is 400, detail `Unknown readMask path '{path}'`. An unknown path is never ignored, as an unknown `orderBy` field is not (§4).
- **Overlapping paths merge.** `address,address.city` returns the whole `address`.
- **No field is added implicitly.** A mask without `id` returns no `id`.
- **What it applies to.** A single `GET` masks the resource. A collection `GET` masks each element of `items`, and leaves `nextPageToken` and `totalSize` alone. `:batchGet` masks each element of its resource list. Writes, problem bodies and tabular exports ignore `readMask`.
- **Preconditions are unchanged.** A masked `GET` carries the resource's `ETag`. The validator is weak and names the version, so a client can read a few fields and then send `If-Match` on a merge patch. `If-None-Match` compares the same validator, and 304 behaves as today.
- **OpenAPI.** Each read operation that accepts a mask documents `readMask`. Response schemas are not changed. A client that sends a mask treats the response as a partial of the declared type, as a proto3 client does.

### Shared pieces in `rn-forge-web`

All of these live in `rn_forge.web.read_mask`.

| Symbol | Contract |
| --- | --- |
| `READ_MASK_PARAM` | `"readMask"` |
| `FieldTree` | `Mapping[str, FieldTree \| None]`, the declared shape of a representation by wire name: a subtree for a declared object or a list of declared objects, `None` for a leaf |
| `ReadMask` | A frozen value holding the merged path tree. `apply(body: Mapping[str, Any]) -> dict[str, Any]` returns the pruned copy and recurses through lists. |
| `parse_read_mask(raw, *, fields: FieldTree) -> ReadMask \| None` | `None` for absent, blank or `*`. Raises `InvalidReadMask` per the rules above. |
| `InvalidReadMask` | A `WebError` registered as `bad-request` (400) in `default_registry()` |

### Django — `rn_forge.django.drf`

`ReadMaskMixin` for a viewset applies the mask to `retrieve`, `list` and `batch_get` responses with status 200. It builds the `FieldTree` from the view's serializer:

- A nested `Serializer` becomes a subtree, and a `ListSerializer` becomes its child's subtree.
- Every other field, `JSONField` included, is a leaf.
- Names are camelized with the package's casing rules, because `response.data` is still snake_case when the mixin runs. The mask is translated to snake_case and applied before the camelCase renderer.

`BaseModelViewSet` includes the mixin. A drf-spectacular extension documents `readMask` on those three actions.

### FastAPI — `rn_forge.fastapi`

`read_mask_param(model)` is a dependency factory. It builds the `FieldTree` from a pydantic model's aliases (a nested model or `list[model]` becomes a subtree, anything else a leaf), and yields `ReadMask | None`. The route applies it with `mask.apply(...)` to the dumped body, or with `masked(page, mask)` for an AIP-158 `Page`. `batch_get_router` gains a `read_mask: bool = True` parameter and applies the mask itself.

### New conformance cases

A new `read-mask` area. Each driver serves `/conformance/profiles` (an AIP-158 list) and `/conformance/profiles/{id}` (with `ETag`). Profile `1`, at version 1:

```json
{"id": "1", "displayName": "Ada",
 "address": {"city": "London", "postcode": "N1"},
 "phones": [{"kind": "home", "number": "1"}, {"kind": "work", "number": "2"}],
 "settings": {"theme": "dark"}}
```

Profile `2` is `Grace` in `Arlington`, with no phones and empty settings. `address` and each phone are declared objects; `settings` is free-form JSON.

| Case id | Request | Expect |
| --- | --- | --- |
| `read-mask.get-returns-only-the-masked-fields` | `GET /conformance/profiles/1?readMask=displayName,settings` | 200 `{"displayName": "Ada", "settings": {"theme": "dark"}}` |
| `read-mask.nested-path-selects-a-sub-field` | `?readMask=address.city` | 200 `{"address": {"city": "London"}}` |
| `read-mask.path-through-a-list-applies-to-each-element` | `?readMask=phones.number` | 200 `{"phones": [{"number": "1"}, {"number": "2"}]}` |
| `read-mask.overlapping-paths-merge` | `?readMask=address,address.city` | 200 `{"address": {"city": "London", "postcode": "N1"}}` |
| `read-mask.star-is-the-whole-resource` | `?readMask=*` | 200, the whole profile |
| `read-mask.list-masks-each-item` | `GET /conformance/profiles?readMask=id,displayName` | 200 `{"items": [{"id": "1", "displayName": "Ada"}, {"id": "2", "displayName": "Grace"}], "nextPageToken": null}` |
| `read-mask.unknown-path-is-400` | `?readMask=nickname` | 400, detail `Unknown readMask path 'nickname'` |
| `read-mask.path-inside-a-free-form-field-is-400` | `?readMask=settings.theme` | 400, detail `Unknown readMask path 'settings.theme'` |

| `read-mask.masked-read-keeps-the-etag` | `?readMask=displayName` | 200, `ETag: W/"1:1"` |

## Considered and rejected

- **`drf-flex-fields` (checked 2026-10-04).** The parameter can be renamed (`REST_FLEX_FIELDS["FIELDS_PARAM"]`) and dotted paths and `*` are supported, but it fails the other tests. Its latest release is 1.0.2 (March 2023), with no `Typing :: Typed` classifier and no declared `requires_python`, so strict pyright sees untyped code. It silently ignores a name that matches no field, so an unknown path cannot return 400 without a second validation pass that duplicates the work. It reads the query only on the root serializer and prunes before serialization, which differs from the wire rules here and would leave the FastAPI side with a different implementation. It also adds a dependency. Adopting it would not delete any code.
- **Pydantic `model_dump(include=...)`.** It prunes nested models and lists (`{"phones": {"__all__": {"number": True}}}`), but it takes attribute names, not aliases (`include={"displayName"}` returns `{}` for a field aliased from `display_name`), and it silently ignores unknown names. It would need the same alias translation and validation as a wire-level pruner, and it would give FastAPI different semantics from Django. A shared pruner over the wire representation gives both stacks one contract.
- **Query projection (`only()`, `load_only`).** It would cut database work as well as payload, but it ties the mask to each ORM's loader, and a serializer method field can depend on columns the mask does not name. Pruning the serialized representation is identical on every stack. Projection can be added later behind the same wire rules.
- **JSON:API sparse fieldsets (`fields[type]=...`).** The conventions follow AIPs for naming where no RFC applies (§19), and AIP-157 is the AIP for this.
- **Making response properties optional in OpenAPI.** Every unmasked client would lose its required-field types to serve the masked case.
- **Always including `id`.** AIP-157 returns exactly the mask. A client that needs the id asks for it.
- **Ignoring unknown paths.** A typo would silently return an empty object, which is the failure §4 already rules out for `orderBy`.
