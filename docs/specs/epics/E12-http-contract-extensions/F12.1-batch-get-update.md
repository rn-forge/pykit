The API conventions' §19 spells `:batchGet` and `:batchUpdate` (AIP-231, AIP-234) and says they are built when a consumer needs them. Neither stack has them. This feature adds the handlers on both stacks, with the wire rules in `rn-forge-web` and conformance cases that pin them. It follows [F12.15](F12.15-fastapi-resource-operations.md)'s pattern: Django mixins, FastAPI route factories over application stores, one wording for both.

## Context

The owner scheduled this feature for release 3 on 2026-10-04, ahead of its original trigger ("a consumer needs the handlers"), to complete the batch set that `:batchCreate` and `:batchDelete` started. F12.15 already built the shared list rules (`REQUIRED_FIELD_DETAIL`, `NON_EMPTY_LIST_DETAIL`, `row_cap_problem`, `ItemsDenied`), so this feature reuses them.

## Design

**Wire.** Both methods are all or nothing, and both answer with the resources under the plural resource name, in request order, as `:batchCreate` does.

### `:batchGet` — `GET {collection}:batchGet?ids=1&ids=2`

AIP-231 makes `:batchGet` a `GET` with a repeated query parameter, so the ids arrive as `ids`, repeated. A comma-joined value is one id. Query-parameter faults are 400, as `orderBy` and `pageToken` faults already are (§4). A body fault is 422.

| Step | Failure | Answer |
| --- | --- | --- |
| 1. `ids` present with at least one non-empty value | absent, or every value empty | 400 `bad-request`, detail `A non-empty ids parameter is required.` |
| 2. Count within the cap | more ids than the configured cap | 400 `bad-request`, detail `The batch exceeds the limit of {cap} rows.` |
| 3. Every id exists within the caller's scope | the first missing id, in request order | 404, detail `{Label} {id} not found` |
| — | success | 200 `{"<resources>": [...]}`, one entry per requested id in request order, duplicates repeated |

An id outside the caller's scope is a 404, not a 403, so `:batchGet` reveals nothing a `GET` on that id would not. A soft-deleted resource ([F12.2](F12.2-soft-delete.md)) is returned, as a `GET` returns it (AIP-164).

### `:batchUpdate` — `POST {collection}:batchUpdate`

AIP-234's items carry a field mask, and §10 does not adopt field masks. Each item is therefore a JSON Merge Patch (RFC 7396), the convention's one partial-update language. A precondition cannot ride in a header per item, so an item carries its own `ifMatch` with the header's syntax and meaning. The outer body is `application/json`; only `PATCH` takes `application/merge-patch+json` (§10).

```json
{"requests": [
  {"id": "2", "patch": {"name": "beta"}, "ifMatch": "W/\"2:1\""},
  {"id": "3", "patch": {"note": null}}
]}
```

The first failing step answers:

| Step | Failure | Answer |
| --- | --- | --- |
| 1. `requests` is a non-empty list | missing / empty or not a list | 422 at `/requests`, `REQUIRED_FIELD_DETAIL` / `NON_EMPTY_LIST_DETAIL` |
| 2. Count within the cap | over the cap | `row_cap_problem("batch", cap)` |
| 3. Each item's shape | `id` missing; `patch` not a JSON object; `ifMatch` not a string | 422, every failing item reported: `/requests/<i>/id` `REQUIRED_FIELD_DETAIL`; `/requests/<i>/patch` `A merge patch must be a JSON object.`; `/requests/<i>/ifMatch` `Not a valid string.` |
| 4. No id twice | a repeated id | 422 at `/requests/<i>/id`, detail `Duplicate id in batch.`, for each later occurrence |
| 5. Every id exists within the caller's scope | the first missing id | 404, detail `{Label} {id} not found` |
| 6. Each item's precondition, when the resource is versioned | the first item that fails, in request order | 428 / 400 / 412, with the detail `check_precondition` gives and `errors` `[{"pointer": "/requests/<i>/ifMatch", "detail": <same>}]` |
| 7. Each merged document validates | field errors | 422 `One or more rows are invalid.`, every failing item reported at `/requests/<i>/patch/<field>` |
| 8. Each item is allowed | an application denial | 403 `ItemsDenied(root="requests")`, pointer `/requests/<i>` |
| — | success | every item written in one transaction, each versioned resource's `version` bumped; 200 `{"<resources>": [...]}` in request order |

The merge follows §10 exactly: `rn_forge.web.merge_representation`, a top-level `null` sets a field to `null`, read-only and unknown members are ignored. A route may require preconditions, as a single `PATCH` may: then an item without `ifMatch` is the 428 of step 6. An unversioned resource ignores `ifMatch`, as `MergePatchMixin` does. A batch response carries no per-item `ETag`. A client that needs one reads the resource, or the application exposes `version` as a field.

Step 3 comes before the precondition, unlike a single `PATCH`, because the precondition is inside the body.

### Shared pieces in `rn-forge-web`

| Symbol | Contract |
| --- | --- |
| `InvalidBatchGet` | A `WebError` registered as `bad-request` (400) in `default_registry()`. |
| `batch_get_ids(values, *, cap)` | Takes the raw repeated `ids` values and returns them with empty values dropped. Raises `InvalidBatchGet` for steps 1 and 2. |
| `NON_EMPTY_IDS_DETAIL` | `A non-empty ids parameter is required.` |
| `DUPLICATE_ID_DETAIL` | `Duplicate id in batch.` |
| `BatchUpdateItem` | A frozen dataclass of `index`, `id: str`, `patch: dict[str, JsonValue]` and `if_match: str \| None`. |
| `parse_batch_update(body, *, cap, instance, registry=None)` | Steps 1–4. Returns `list[BatchUpdateItem]`, or raises `RowsInvalid(root="requests")` for steps 3–4. A cap breach returns the `row_cap_problem` for the caller to render, as the existing batch handlers do. |
| `check_item_precondition(item, *, current_version, entity_id, codec, required)` | Step 6 for one item. Raises the exception `check_precondition` raises for the same input, with an `errors` extension pointing at `/requests/<index>/ifMatch`. |

`PreconditionRequired`, `MalformedPrecondition` and `VersionConflict` gain an optional `errors` argument. They implement `HasProblemExtensions` and emit `errors` only when it is given, so every existing response stays the same.

### Django — `rn_forge.django.drf.transfer`

| Mixin | Route | Hooks |
| --- | --- | --- |
| `BatchGetMixin` | `@action(detail=False, methods=["get"], url_path="batchGet")` | Looks up ids in `filter_queryset(get_queryset())` and serializes with the view's serializer. The response key is `batch_resource_name`, shared with `BatchCreateMixin` and moved to a common base. |
| `BatchUpdateMixin` | `@action(detail=False, methods=["post"], url_path="batchUpdate")` | `batch_update_requires_if_match: ClassVar[bool] = False`. `validate_batch_update_item(instance, data) -> str \| None`, as `validate_batch_create_item`. Applies `AuditFieldsViewMixin.prepare_update_data` when present. Saves in `transaction.atomic()`. |

### FastAPI — `rn_forge.fastapi.transfer`

| Protocol | Method | Contract |
| --- | --- | --- |
| `BatchGetStore` | `async get_many(ids: Sequence[str]) -> Mapping[str, Any]` | The rows that exist within the caller's scope, keyed by id as a string. |
| `BatchUpdateStore[T]` | `async current(ids: Sequence[str]) -> Mapping[str, Current]` | Each row that exists, with its `version` (`None` when unversioned). `Current` is a small structural protocol: `row: Any`, `version: int \| None`. |
| | `async update_many(items: Sequence[tuple[str, T]]) -> Sequence[Any]` | Write every validated document in one transaction, bump each version, and return the updated rows in the order given. May raise `ItemsDenied(root="requests")` before writing. |

| Factory | Route |
| --- | --- |
| `batch_get_router(collection, *, response_model, resource_name, resource_label, store, max_rows=None, dependencies=())` | `GET {collection}:batchGet` |
| `batch_update_router(collection, *, model, response_model, resource_name, resource_label, store, max_rows=None, require_if_match=False, codec=None, dependencies=())` | `POST {collection}:batchUpdate`. The current row is dumped through *model* by alias, merged, and validated as *model*. |

Both declare their request and response shapes for OpenAPI, with operation ids `<resource>BatchGet` and `<resource>BatchUpdate`. `FastApiApp`'s problem repair adds the 400, 403, 404, 412, 422 and 428 responses they can produce.

### New conformance cases

Each driver seeds `/conformance/books`: three versioned books, `1` `alpha`, `2` `beta`, `3` `gamma`, each at version 1. A book's representation is `{"id", "name"}`, and `name` is required and non-nullable. `/conformance/capped-books:batchGet` and `:batchUpdate` serve the same books under a cap of 1. `RequestSpec.query` accepts a tuple of values for a repeated parameter.

| Case id | Request | Expect |
| --- | --- | --- |
| `transfer.batch-get-returns-resources-in-request-order` | `GET /conformance/books:batchGet?ids=3&ids=1` | 200 `{"books": [{"id": "3", "name": "gamma"}, {"id": "1", "name": "alpha"}]}` |
| `transfer.batch-get-with-an-unknown-id-is-404` | `?ids=1&ids=999` | 404, detail `Book 999 not found` |
| `transfer.batch-get-without-ids-is-400` | no `ids` | 400, detail `A non-empty ids parameter is required.` |
| `transfer.batch-get-over-the-cap-is-400` | `GET /conformance/capped-books:batchGet?ids=1&ids=2` | 400, detail `The batch exceeds the limit of 1 rows.` |
| `transfer.batch-update-applies-each-merge-patch` | `POST /conformance/books:batchUpdate` `{"requests": [{"id": "2", "patch": {"name": "beta2"}, "ifMatch": "W/\"2:1\""}]}` | 200 `{"books": [{"id": "2", "name": "beta2"}]}` |
| `transfer.batch-update-stale-if-match-is-412-pointer` | `{"requests": [{"id": "1", "patch": {"name": "x"}}, {"id": "3", "patch": {"name": "y"}, "ifMatch": "W/\"3:9\""}]}` | 412, `errors` `[{"pointer": "/requests/1/ifMatch", ...}]` |
| `transfer.failed-batch-update-changes-nothing` | `GET /conformance/books:batchGet?ids=1&ids=3`, depends on the previous case | 200 with `alpha` and `gamma` unchanged |
| `transfer.batch-update-item-validation-is-422-pointer` | `{"requests": [{"id": "1", "patch": {"name": null}}]}` | 422, `errors` `[{"pointer": "/requests/0/patch/name", "detail": "This field may not be null."}]` |
| `transfer.batch-update-with-an-unknown-id-is-404` | `{"requests": [{"id": "999", "patch": {}}]}` | 404, detail `Book 999 not found` |
| `transfer.batch-update-with-a-duplicate-id-is-422` | `{"requests": [{"id": "1", "patch": {}}, {"id": "1", "patch": {}}]}` | 422, `errors` `[{"pointer": "/requests/1/id", "detail": "Duplicate id in batch."}]` |
| `transfer.batch-update-with-an-empty-list-is-422` | `{"requests": []}` | 422, `errors` `[{"pointer": "/requests", "detail": "A non-empty list is required."}]` |

### Out of scope

- **Partial success.** AIP-234 allows an `allow_missing` upsert and partial results. Both batch methods stay all or nothing, as `:batchCreate` and `:batchDelete` are.
- **`readMask` on `:batchGet`.** [F12.9](F12.9-read-mask.md) adds it.

## Stories

### S12.1.1 — Shared batch rules in `rn-forge-web`

**State:** Closed (2026-10-04)

**Acceptance:**

- `rn_forge.web` exports `InvalidBatchGet`, `batch_get_ids`, `NON_EMPTY_IDS_DETAIL`, `DUPLICATE_ID_DETAIL`, `BatchUpdateItem`, `parse_batch_update` and `check_item_precondition`, with the contracts in [Shared pieces](#shared-pieces-in-rn-forge-web).
- `PreconditionRequired`, `MalformedPrecondition` and `VersionConflict` accept an optional `errors` argument. Without it, their rendered bodies are unchanged; every existing concurrency case still passes.
- `tests/test_transfer.py` and `tests/test_concurrency.py` cover each new function: every step of both tables, ids given as strings or integers, empty `ids` values dropped, and `*` as an item's `ifMatch`.

### S12.1.2 — Conformance cases

**State:** New

**Acceptance:** `RequestSpec.query` accepts `str | tuple[str, ...]` values, and both drivers send a tuple as a repeated parameter. `CASES` gains the cases in [New conformance cases](#new-conformance-cases), in the `transfer` area. Both drivers run every case with no skips.

### S12.1.3 — Django binding

**State:** Closed (2026-10-04)

**Acceptance:**

- `rn_forge.django.drf.transfer` exports `BatchGetMixin` and `BatchUpdateMixin`, served by `CustomMethodRouter` at `{collection}:batchGet` and `{collection}:batchUpdate`.
- The Django conformance fixture serves `/conformance/books` and `/conformance/capped-books` through them, and the new cases pass.
- `tests/drf/` covers what the cases do not reach: `validate_batch_update_item` denying an item (403, nothing written), `batch_update_requires_if_match` (428 with the pointer), audit fields set on every updated row, an unversioned model ignoring `ifMatch`, and a `filter_queryset` scope hiding an id (404).
- The drf-spectacular schema names the operations `booksBatchGet` and `booksBatchUpdate`.

### S12.1.4 — FastAPI binding

**State:** New

**Acceptance:**

- `rn_forge.fastapi.transfer` exports `BatchGetStore`, `BatchUpdateStore`, `batch_get_router` and `batch_update_router`.
- The FastAPI conformance fixture serves `/conformance/books` and `/conformance/capped-books` through them over an in-memory store, with no hand-written handler for those paths, and the new cases pass.
- `tests/test_transfer.py` covers a store raising `ItemsDenied` (403, `update_many` writes nothing), `require_if_match=True`, integer ids, a `dependencies=` guard, and the store never being asked to write after a validation failure.
- The OpenAPI document has `booksBatchGet` with a repeated `ids` query parameter and `booksBatchUpdate` with the `requests` item schema, and both list their problem responses.

## Considered and rejected

- **`POST :batchGet` with the ids in a body.** It escapes URL length limits, but AIP-231 makes the method a `GET`, and a `GET` is cacheable and safe to retry. The row cap keeps the URL short.
- **AIP-234's per-item `updateMask`.** §10 rejects field masks for updates. A merge patch per item keeps one partial-update language across `PATCH` and `:batchUpdate`.
- **`PUT` semantics per item (full replacement).** A UI that edits several rows sends only the changed members, which is what a merge patch expresses.
- **Partial success with a per-item status list.** Every existing batch method is all or nothing. A mixed outcome would need a second response shape and client logic to reconcile it.
