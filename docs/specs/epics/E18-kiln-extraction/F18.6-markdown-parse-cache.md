# F18.6 — Cache Markdown structure by text

|  |  |
| -- | -- |
| **State** | New |
| **Parent** | [E18](index.md) |
| **Iteration** | [Release 8](../../../releases/release-8/index.md) |
| **Predecessors** | [F18.4](F18.4-markdown-structure.md) |
| **Source** | Owner request, 2026-11-10 |

A caller that asks for headings, anchors, links and tables from the same page
currently pays for repeated Markdown parsing. Cache the parsed structure inside
`MarkdownUtils`, so applications need no cache wrappers of their own.

## Design

Keep the existing public API and its values unchanged. `headings`, `links` and
`tables` return fresh lists, `anchors` returns a fresh set, `title` returns a
string or `None`, and `strip_fenced_code` returns a string. `slugify` and
`is_external` need no parsing and remain unchanged.

Use one private `functools.lru_cache(maxsize=2048)` keyed by the complete input
text. On a miss, parse with the existing CommonMark plus GFM tables parser once,
and extract a private, frozen, slotted result containing:

- headings as `tuple[MarkdownHeading, ...]`;
- decoded link and image targets as `tuple[str, ...]`;
- tables as `tuple[MarkdownTable, ...]`;
- fenced-code line ranges as `tuple[tuple[int, int], ...]`.

All six parsing helpers use that result. Derive anchors and title from its
headings; remove fenced lines using its ranges and the caller's original text.
Do not retain mutable parser tokens or expose the cached object. Existing
heading and table records are already frozen and contain immutable fields. Never
cache a public mutable list or set directly.

The cache is process-local, retains at most 2048 document entries, and keys on
content rather than paths or timestamps. Changed text misses automatically;
evicted text may be parsed again. This is an entry bound, not a byte bound.
Concurrent misses may compute the same entry more than once, as with ordinary
`lru_cache`; do not introduce locking or promise single-flight parsing. Cache
management remains private; add no public cache API, option, dependency or
export. Tests clear the private cache before and after cache-specific cases.

Keep the existing parser behavior, including heading order and duplicate-anchor
suffixes, plain heading text, source line positions, decoded link targets, table
padding, and preservation of unfenced text and line endings.

## S18.6.1 — Share a bounded Markdown parse cache

**State:** New

**Build:**

- `packages/rn-forge-commons/src/rn_forge/commons/text/markdown.py`: add the
  private immutable result and bounded cached extraction, and route the
  existing parsing helpers through it. Reuse the existing extraction logic.
  Keep optional imports behind the `markdown` extra and out of the commons
  facade.
- `packages/rn-forge-commons/tests/text/test_markdown.py`: add deterministic
  cache and mutation-isolation tests alongside the existing behavior tests.
- `packages/rn-forge-commons/docs/guides/text.md`: describe automatic reuse, the
  process-local entry bound, content keys, eviction and fresh mutable public
  results. State that no caller cache is required; do not promise each page is
  parsed only once for the life of a process.
- `packages/rn-forge-commons/CHANGELOG.md`: add an `[Unreleased]` performance
  entry describing shared bounded Markdown parsing without an API change.

**Acceptance:**

- A cold-cache test wraps the parser's `parse` method and calls `headings`,
  `anchors`, `title`, `links`, `tables` and `strip_fenced_code` on one
  document, then repeats them in a different order. There is exactly one
  parser call for that text in this sequential test. Each helper can populate
  a cold cache correctly, independent of which helper is called first.
- Mutating a returned headings list, links list, tables list or anchors set
  leaves all later results unchanged. The returned mutable containers are
  distinct across calls, including for empty input.
- A different string produces a cache miss and the changed result. A distinct
  string object with equal content reuses the same entry. After 2049 distinct
  texts, the cache has at most 2048 entries and querying an evicted entry
  parses it again. Cache-specific tests clean up even when an assertion fails.
- Existing Markdown tests pass unchanged. Add a mixed document covering setext
  and repeated headings, inline markup and code, inline/reference/image links,
  percent-encoded targets, GFM tables and fenced code. All six helpers return
  the same expected values on cold and warm calls. Preserve CRLF and the
  absence of a final newline when removing fenced code.
- `task test`, `task typecheck` and `task docs:build` pass; the existing import
  contracts still pass through `task lint`. Performance acceptance is the
  parser call count, not a machine-dependent elapsed-time threshold.

## Considered and rejected

- **A separate cache on each helper.** It still parses one document separately
  for headings, links and tables.
- **Caching public lists and sets.** One caller's mutation changes another
  caller's result.
- **Caching the mutable token stream.** A compact immutable extracted result
  keeps parser internals private and makes result isolation explicit.
- **An unbounded cache or one keyed only by a file path.** The former retains
  every document in a long-lived process; the latter can return stale content.

Adoption by consumers and their dependency upgrades are separate work and do not
gate this feature.
