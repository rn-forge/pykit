# F18.1 — Templates, generation and state move to commons

|  |  |
| -- | -- |
| **State** | Closed |
| **Parent** | [E18](index.md) |
| **Iteration** | [Release 6](../../../releases/release-6/index.md) |
| **Start Date** | 2026-10-25 |
| **Closed Date** | 2026-10-25 |
| **Predecessors** | — |
| **Source** | Owner decision, 2026-10-24 ([ADR-0002](../../../adr/ADR-0002.md), rule 3 as amended) |

Rendering templates and owning generated files move from `rn-forge-tooling` to
`rn-forge-commons`, so an application that writes files from templates gets the
whole capability without the CLI and installer layers:

- `TemplateEngine` moves to `rn_forge.commons.text.templates`, behind a
  `templates` extra.
- The generation engine (artifacts, plan, apply) moves to
  `rn_forge.commons.generation`, which the facade does not import.
- `StateStore` moves to `rn_forge.commons.fs.state`.

Tooling keeps the lifecycle verbs and install mechanics. The engine gains
`autoescape` and a process-wide `cached` constructor, and stops crashing on a
Jinja error containing a brace. The import contracts that guard these modules
are written so they can actually break.

## Context

ADR-0002's rule 3 named "file-generating" layers as tooling. On 2026-10-24 the
owner dropped that word. A web application that generates files from templates
wants plan, diff, atomic apply with rollback, and drift detection, as much as a
developer tool does. Nothing in those signatures is CLI or installer policy, so
rule 1 places them in commons.

The move costs no new dependency. `generation` and `state` import only the
standard library and commons, about 900 lines in all, and nothing in tooling's
`cli` or `install` imports them.

**Why the facade must not import `generation` or `text`.** `rn_forge/commons/__init__.py`
imports its modules eagerly. Importing any commons module, such as
`from rn_forge.commons.findings import Finding`, runs the whole facade first. If
the facade re-exported anything from `generation` or `text`, every commons user
would load the generation engine, Jinja and markdown-it on import. That includes
a web worker and a linter that only wants `Finding`. kiln's `doctor` checks are
such a user, and kiln's tests assert the engine never loads with them.

**Why the contracts change shape.** import-linter 2.15 never breaks a
`forbidden` contract whose forbidden module sits *inside* its source package.
This was checked on 2026-10-24 against this workspace. A contract with source
`rn_forge.commons` and forbidden `rn_forge.commons.fs.paths` stays `KEPT`,
though `fs.documents` imports `fs.paths`. The same contract with source
`rn_forge.commons.fs.documents` is `BROKEN`, as it should be. The existing
`data-core-has-no-adapter` contract (source `rn_forge.data`, forbidden
`rn_forge.data.pandas`) has the first shape, so it holds nothing today. The
contracts here name **sibling** source modules, and a subprocess test covers the
package `__init__` modules, which no contract can.

**Why `cached`.** A `jinja2.Environment` compiles each template once. A caller
that builds an engine per call compiles every template again. kiln wraps the
constructor in `functools.cache` in ten modules to avoid that.

**Why brace-safe errors.** `AppException` formats its message with
`str.format(*args)` even with no arguments. `RenderError(str(exc))` therefore
raises `ValueError: Single '}' encountered in format string` when Jinja's
message contains a brace.

### Template engine changes (`text/templates.py`)

1. Add a keyword `autoescape: bool = False` after `strict`, and pass it to
   `jinja2.Environment(autoescape=autoescape, ...)` in place of the hard-coded
   `False`. Docstring line: *autoescape: HTML-escape every rendered value.
   Enable it when the output is HTML.*
1. Add a classmethod with this signature:

    ```python
    @classmethod
    def cached(
        cls,
        *,
        directory: str | None = None,
        package: str | None = None,
        package_path: str = "templates",
        strict: bool = True,
        autoescape: bool = False,
        **environment_kwargs: Any,
    ) -> TemplateEngine:
    ```

    It returns the engine already built in this process for equal arguments,
    building it on first use. Implement it with a module-level
    `@functools.cache` function `_cached_engine(cls, directory, package, package_path, strict, autoescape, environment_items)`,
    with `environment_items = tuple(sorted(environment_kwargs.items()))`.
    Every argument must be hashable. The docstring says the engine is shared,
    so a caller must not mutate `environment`.
1. Both `raise RenderError(str(exc)) from exc` become
   `raise RenderError("{}", exc) from exc`.

`generation-core-renders-nothing` names `generation.templated`, which
[F18.2](F18.2-templated-artifacts-and-diffs.md) creates. Until then, no module
imports `text` from `generation`, and the contract holds. If a new commons
subpackage is added later, it joins `commons-core-has-no-extras`' sources. The
facade test below catches the case where it is forgotten.

Rewrite the file's header comment to state the contracts as they now are.
Rule 1 becomes: *commons never reaches into cli or tooling and never imports
Typer. Jinja and the Markdown parsers enter only through `rn_forge.commons.text`,
and `rn_forge.commons.generation` and `text` are imported directly, never by
commons' core or facade.* Add rule 9's fix: *the data contract names its core
module, not the package that contains its adapter.*

## Considered and rejected

- **Keep `rn_forge.tooling.*` aliases for one release.** ADR-0002 rule 5 forbids
  them, and kiln, the only consumer, moves its imports in one change.
- **Put `generation` behind an extra.** It needs no third-party package. Keeping
  it out of the facade is what keeps it off a commons user's import path, and
  the facade test proves it.
- **Re-export `generation` from the facade.** The facade imports eagerly. Every
  commons user, a web worker included, would load the engine to get a
  `Finding`.
- **A package of its own (`rn-forge-generation`).** It fails ADR-0011's first
  test: it has no dependency set of its own.
- **`StateStore` under `generation`.** It is a generic locked JSON key-to-entry
  store with no generation vocabulary in its signature, so `fs` holds it.
