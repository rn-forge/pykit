# F18.7 — A managed block's end marker can sit at a different indent

|  |  |
| -- | -- |
| **State** | New |
| **Parent** | [E18](index.md) |
| **Iteration** | [Release 8](../../../releases/release-8/index.md) |
| **Predecessors** | [F18.2](F18.2-templated-artifacts-and-diffs.md) |
| **Source** | Owner request, 2026-11-11 |

`ManagedBlock` writes both of its markers at one `indent`. A YAML formatter
moves a comment that ends a block to the left margin, so a block whose body is
indented but whose last line is the end marker cannot stay formatter-clean: the
begin marker belongs at two spaces and the end marker at column 0. A consumer
works around it today by subclassing `ManagedBlock` and overriding the private
`_marker`. This feature adds the public field that makes the subclass
unnecessary, and releases `rn-forge-commons` 0.9.0 with it.

## Design

**`packages/rn-forge-commons/src/rn_forge/commons/fs/blocks.py`.**
`ManagedBlock` gains one field after `indent`:

```python
end_indent: str | None = None
```

`None` means the end marker uses `indent`, so every existing caller renders the
same bytes. Any other value, including `""`, is the end marker's own leading
whitespace. `__post_init__` does not validate `indent` (it checks `name` and
`comment` only), so it does not validate `end_indent` either.

`_marker(keyword)` computes the leading whitespace as `self.end_indent` when
`keyword == "END"` and `self.end_indent is not None`, and `self.indent`
otherwise, and builds the marker as it does today. Nothing else changes:
`_locate` already compares stripped lines, so it finds a marker at any indent,
and `render`, `remove` and `_block_text` already take the end marker from
`self.end`.

The `Args:` entry for `indent` keeps its text. Add this entry after it:

```text
end_indent: Leading whitespace of the end marker alone. ``None`` (the default)
    uses *indent*; ``""`` puts the end marker at the left margin.
```

**Release.** [ADR-0004](../../../adr/ADR-0004.md) bumps the minor before 1.0 for
a breaking change and the patch otherwise, and this change is additive. The
owner asked for a minor release, `rn-forge-commons` 0.8.1 to 0.9.0, and
`[Unreleased]` already holds a changed default (log redaction on). A 0.x minor
is outside every dependent's `<0.9` ceiling, so the release also widens six
dependents' ceilings (S18.7.2).

## S18.7.1 — `ManagedBlock` takes an optional `end_indent`

**State:** New · **Depends on:** —

**Tests first,** in `packages/rn-forge-commons/tests/fs/test_blocks.py`, beside
`test_indent_applies_to_markers_only` in `class TestMarkers` (the first five)
and in a new `class TestEndIndent` after `TestRender` (the rest). Run them and
show them failing (`TypeError: ... unexpected keyword argument 'end_indent'`)
before the build.

1. `test_s18_6_1_1_end_indent_defaults_to_indent`:
   `ManagedBlock("n", indent="  ").end == "  # END n"`, and
   `ManagedBlock("n", indent="  ", end_indent=None).render("", "- a\n")`
   equals `ManagedBlock("n", indent="  ").render("", "- a\n")`.
1. `test_s18_6_1_2_end_indent_applies_to_the_end_marker_only`:
   `block = ManagedBlock("n", indent="  ", end_indent="")`;
   `block.begin == "  # BEGIN n"`; `block.end == "# END n"`.
1. `test_s18_6_1_3_html_end_indent`:
   `ManagedBlock("n", comment="<!--", indent="  ", end_indent="    ").end == "    <!-- END n -->"`.
1. `test_s18_6_1_4_render_writes_begin_indented_and_end_at_the_margin`:
   `ManagedBlock("n", indent="  ", end_indent="").render("", "- a\n") == "  # BEGIN n\n- a\n# END n\n"`.
1. `test_s18_6_1_5_end_indent_is_not_validated`:
   `ManagedBlock("n", indent="  ", end_indent="\t")` and
   `ManagedBlock("n", end_indent="  ")` construct without error, as `indent`
   does.
1. `test_s18_6_1_6_extract_reads_either_end_form`: with
   `block = ManagedBlock("n", indent="  ", end_indent="")`, both
   `block.extract("  # BEGIN n\n- a\n# END n\n")` and
   `block.extract("  # BEGIN n\n- a\n  # END n\n")` return `"- a\n"`.
1. `test_s18_6_1_7_render_replaces_either_end_form`: the same block, given each
   of the two texts of the previous test and body `"- b\n"`, returns
   `"  # BEGIN n\n- b\n# END n\n"` from both.
1. `test_s18_6_1_8_remove_and_round_trip`: for the same block,
   `block.remove(block.render("head\n", "- a\n")) == "head\n"` and
   `block.render(block.render("head\n", "- a\n"), "- a\n")` equals
   `block.render("head\n", "- a\n")`.
1. `test_s18_6_1_9_default_output_is_unchanged`: for a table of
   `ManagedBlock("n")`, `ManagedBlock("n", comment="<!--")` and
   `ManagedBlock("n", indent="  ")`, the `render("head\n", "x\n")` result
   equals the literal bytes the pre-change code wrote, written out in the test
   (`"head\n\n# BEGIN n\nx\n# END n\n"`,
   `"head\n\n<!-- BEGIN n -->\nx\n<!-- END n -->\n"` and
   `"head\n\n  # BEGIN n\nx\n  # END n\n"`).

**Build.**

1. Write the nine tests above and show them failing.

1. In `blocks.py`, add the field after `indent` and the docstring entry from
   *Design*; change `_marker` as *Design* says. Touch nothing else in the
   file.

1. In `packages/rn-forge-commons/CHANGELOG.md`, under `## [Unreleased]` and
   `### Added` (after the last entry), add:

    ```text
    - `ManagedBlock.end_indent`: leading whitespace of the end marker alone,
      for a block whose body is indented but whose end marker sits at a
      different indent. `None` (the default) uses `indent`, so existing blocks
      render the same bytes.
    ```

1. In `packages/rn-forge-commons/docs/guides/generation.md`, no change: the
   guide shows no `indent`. Run `uv run --group docs mkdocs build --strict`
   from `packages/rn-forge-commons` to prove the docstring renders.

1. Run the commands under *Acceptance*.

**Acceptance:**

- The nine tests pass, and the rest of `tests/fs/test_blocks.py` passes
  unchanged.
- `uv run pyright` and `uv run ruff check .` and `uv run ruff format --check .`
  pass.
- The package site builds with `--strict`.
- Not scriptable: the owner reads the `_marker` diff for any change to the
  default path.
