# F18.3 — Fast, complete document reads and writes

|  |  |
| -- | -- |
| **State** | Active |
| **Parent** | [E18](index.md) |
| **Iteration** | [Release 6](../../../releases/release-6/index.md) |
| **Start Date** | 2026-10-25 |
| **Predecessors** | — |
| **Source** | Owner request, 2026-10-24 |

`DocumentUtils` and `YamlUtils` become the fastest way to read a config
document, not a slower convenience. They also cover the shapes a tool writes:

- YAML loads through libyaml.
- Plain TOML reads use `tomllib`.
- A document can be read from a package resource.
- A TOML document can be written with a comment header and one array element per
  line.

`DictUtils` and `ListUtils` gain typed reads of a bare value. Every
`DocumentError` built from parser text stops crashing on braces.

## Context

Measured 2026-10-24 on Python 3.14, over a real repository's documents:

| Read | Per file |
| -- | -- |
| YAML: `YamlUtils.load` (ruamel, pure Python) | 1.69 ms |
| YAML: ruamel safe loader with `ruamel.yaml.clib` | 0.35 ms |
| YAML: PyYAML `CSafeLoader` | 0.12 ms |
| TOML: `DocumentUtils.loads` (`tomlkit` then `unwrap`) | 1.07 ms |
| TOML: `tomllib.loads` | 0.15 ms |

kiln imports PyYAML's C loader and `tomllib` directly for these reasons. Its
test suite reads the same Taskfiles and workflows hundreds of times. The PyYAML
import is also a dependency kiln never declared.

ruamel.yaml 0.19.1 uses its C parser only when `ruamel.yaml.clib` is installed.
It ships through ruamel's `oldlibyaml` extra; the `libyaml` extra installs
`ruamel.yaml.clibz`, which 0.19.1 never imports. Wheels exist for CPython 3.14
on manylinux x86_64 and aarch64, macOS arm64 and Windows.

ruamel's C *emitter* must not be used. It folds long lines differently from the
pure emitter, so serialized output would change. It also raises
`OverflowError` for `width=sys.maxsize`, the documented way to stop folding.
Loading in C with the pure emitter gives byte-identical output, measured on
eleven Taskfiles and workflows.

`AppException` formats its message with `str.format(*args)`. A `DocumentError`
built with an f-string that embeds parser text breaks when that text contains a
brace. `DocumentUtils.loads("a: {b", "yaml")` raises `KeyError`, not
`DocumentError`.

## Design

All in `packages/rn-forge-commons`.

**S18.3.1 — YAML through libyaml** (`fs/documents.py`, `pyproject.toml`):

- The base requirement becomes `"ruamel.yaml[oldlibyaml]>=0.19.1"`.
- `_safe_yaml` sets `yaml.Emitter = Emitter` (`from ruamel.yaml.emitter import Emitter`)
  right after constructing `YAML(typ="safe")`. Add the comment
  `# libyaml loads; its emitter folds lines differently and rejects width=sys.maxsize.`
- `_round_trip_yaml` is unchanged: round-trip mode is pure Python by design.
- `docs/guides/data.md`, in the documents section, gets a short note. Plain YAML
  loads use libyaml. YAML 1.2 rules apply, so `on`, `yes` and `no` load as
  strings, not booleans. A GitHub Actions workflow's `on:` key is the string
  `"on"`.

**S18.3.2 — TOML reads and package resources** (`fs/documents.py`):

- `DocumentUtils.loads`, TOML branch: `value = tomllib.loads(text)`.
  `tomlkit` remains for `read_document`, `write_document`, `update` and
  `dumps`.
- `DocumentUtils.read(path: str | Path | Traversable, *, missing_ok: bool = False)`,
  with `Traversable` from `importlib.resources.abc`. A `str` becomes a
  `Path`. "Missing" means `not source.is_file()`. The format is
  `ConfigFormat.of(Path(source.name))`, and the text is
  `source.read_text(encoding="utf-8")`. The docstring adds an example:
  `DocumentUtils.read(files("my_tool").joinpath("defaults.toml"))`.
- `read` names the source in a parse error: it re-raises `loads`' error as
  `DocumentError("{}: {}", source, exc)`, chained from it.
- Every `DocumentError` raised in `documents.py` passes its variable parts as
  arguments, never pre-formatted: for example,
  `DocumentError("Invalid {} document: {}", fmt.value.upper(), exc)`. Apart
  from `read`'s path prefix, the messages read exactly as before.

**S18.3.3 — TOML output style** (`fs/documents.py`):

```python
@staticmethod
def dumps(
    data: Mapping[str, Any],
    fmt: ConfigFormat | str,
    *,
    header: str | None = None,
    multiline_arrays: bool = False,
) -> str: ...

@staticmethod
def write(
    path: str | Path,
    data: Mapping[str, Any],
    *,
    header: str | None = None,
    multiline_arrays: bool = False,
) -> None: ...

@staticmethod
def multiline_arrays(document: Any, *key_paths: str) -> None: ...
```

1. `header` is comment text without markers. `dumps` prefixes each of its lines
   with `"# "` (a bare `"#"` for an empty line) and places them before the
   document. For JSON it raises `DocumentError("JSON has no comments; header is not supported")`.
1. `multiline_arrays=True` applies to TOML only; YAML and JSON already write one
   element per line, and ignore it. The TOML text is
   `tomlkit.dumps(document)`, where `document` is
   `tomlkit.parse(tomlkit.dumps(plain))` after
   `DocumentUtils.multiline_arrays(document)`.
1. `multiline_arrays(document, *key_paths)` works on a round-trip TOML
   document (`read_document`'s result, or `tomlkit.parse`'s). With no key
   paths, it formats every non-empty `tomlkit.items.Array` found by recursing
   through tables and through the tables of an array of tables. With key paths,
   it formats only the arrays at those dotted paths (`DictUtils.get`'s syntax)
   and skips a path that is missing or not a non-empty array. Formatting an
   array does two things:
    - It replaces each `InlineTable` element with
      `tomlkit.parse("x = { " + ", ".join(f"{tomlkit.key(k).as_string()} = {tomlkit.item(v).as_string()}" for k, v in table.items()) + " }")["x"]`,
      the `{ key = value }` spacing taplo and uv write.
    - It then calls `array.multiline(True)`.
1. `write` passes both keywords to `dumps`.

**S18.3.4 — Typed reads of a bare value** (`lang/collections.py`):

```python
# DictUtils
@staticmethod
def as_mapping(value: object) -> dict[str, object]: ...
# ListUtils
@staticmethod
def as_list(value: object) -> list[object]: ...
@staticmethod
def as_strings(value: object) -> list[str]: ...
```

- `as_mapping` returns a shallow, `str`-keyed copy of a `Mapping`, else `{}`.
- `as_list` returns a copy of a `list`, `[]` for `None`, else `[value]`.
- `as_strings` returns the `str` elements of `as_list(value)`.
- `get_mapping`, `get_list` and `get_strings` are rebuilt on them, with their
  contracts unchanged.
- The docstrings carry one example each, such as
  `DictUtils.get_mapping(DictUtils.as_mapping(YamlUtils.load(text)), "jobs")`
  for a document whose root may not be a mapping.

## Considered and rejected

- **PyYAML's `CSafeLoader` behind `YamlUtils`.** It is about 2.5 times faster
  again, but it is a second YAML library beside ruamel, with YAML 1.1 rules
  (`on` loads as `True`). ruamel with libyaml is within 0.25 ms per file.
- **Reusing one `YAML` instance per process.** It saves about 0.07 ms per load,
  and a `YAML` object is not safe to share between threads.
- **`tomllib` for round-trip reads.** It discards comments and formatting, which
  is what the round-trip methods exist to keep.
- **`multiline_arrays` on by default.** It changes the output of every existing
  `dumps` caller.
- **The `libyaml` extra (`ruamel.yaml.clibz`).** ruamel.yaml 0.19.1 never
  imports it, so it installs a compiled module and still parses in pure Python.
  Revisit when a ruamel release uses it.
