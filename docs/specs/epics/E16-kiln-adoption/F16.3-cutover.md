pykit adopts kiln's `python-lib` archetype in place: `kiln init`, then kiln's
generated CI replaces `main.yml`, with the docs tooling already converted
(S16.3.3). The cutover follows `rn-forge-devops` and `rn-forge-data`, so kiln
renders their members, Sonar sources and import contracts from the start.
`rn-forge-auth` ([F13.2](../E13-auth/F13.2-auth-package.md)) may land before or
after the cutover; whichever lands second lists it in the kiln config, through
the [adding a package](../../../runbooks/adding-a-package.md) step below.

## Context

This is the one Release 8 feature that waits on another repository's software:
pykit cannot adopt kiln before kiln's release-1 tags exist. The dependency is a
version pin and an observable entry criterion, not acceptance checked in kiln,
so [ADR-0008](../../../adr/ADR-0008.md) still holds for every acceptance line.

What pykit sets, and what it stops owning:

| pykit sets in `.rn-forge/kiln/config.toml` | Why |
| -- | -- |
| `archetype = "python-lib"`, `packages` = all ten workspace members | The workspace kiln renders for. The derived nav lists the package sites in this order, so it keeps the hand nav's: commons, cli, django, fastapi, sqlalchemy, tooling, web, devops, data, then auth. |
| `modules` = `rn_forge.<name>` for each member | pykit's members are namespace packages (kiln S6.1.3). |
| `import_contracts = "own"` | pykit's `.importlinter` contracts describe its layering; kiln's generic workspace contracts forbid it (kiln S6.1.4). pykit's contracts, including E15's per-package adapter contracts and `rn-forge-devops`'s contracts, move below kiln's END marker. |
| `[ci] release = "pypi"` | `python-lib` defaults to `tag-exists`, which renders none of [F21.3](../E21-pypi-distribution/F21.3-publish-from-release.md)'s publishing. `init` does not set it. |

[Adding a package](../../../runbooks/adding-a-package.md) gains a step: add the
member to `packages` and `modules` in `.rn-forge/kiln/config.toml`. A
repository-owned check that E15 adds, such as S15.1.2's adapter-to-extra check
if it is not in the planner, is wired through `[tasks] extra_refs`.

| pykit stops owning | Replaced by |
| -- | -- |
| `.github/workflows/main.yml`, and the hand-written `.github/actions/setup/action.yml` | kiln's generated `ci.yml`, and the setup action kiln renders in place of pykit's (a generated file, with kiln's provenance header). `ci.yml` runs kiln's planner, `kiln-devops`, through `task ci:*` (kiln F6.7); S16.3.4 removes pykit's copy. |
| The package-site deploy in `main.yml`'s `docs` job (versioned sites at `packages/<package>/latest/`) | The `docs` job of kiln's generated `ci.yml`, after `release`, which deploys the versioned package sites with mike. kiln renders no separate `docs.yml` for `python-lib`. |
| `.github/dependabot.yml` for GitHub Actions | kiln's pin table, through kiln upgrades; a Dependabot PR would edit a generated file (kiln F6.3) |
| Direct `uv run …` gates in docs and CI | `task` verbs (`setup validate lint format typecheck test …`) |
| `sonar-project.properties` sources passed by CI | kiln's template lists them from `packages` (kiln ADR-0014) |
| `docs/_update_board.sh` and pykit's own area rules | kiln's `docs:generate` derived regions and kiln's `_structure.md` files; pykit's specs and release pages already follow kiln's work model (S16.3.3) |

`kiln init` changes `pyproject.toml` only to add the task tools it lacks to its
dependency groups (kiln S6.6.2), so these stay as they are. The cutover must not
replace them with kiln's defaults:

| pykit keeps | Why |
| -- | -- |
| The root `[tool.ruff.lint.per-file-ignores]`, `[tool.ruff.lint.isort]` and `[tool.ruff.lint.flake8-bugbear]` tables, verbatim | A member has no `[tool.ruff]` table, so ruff applies the root's in a member-directory run. With kiln's default test ignore and no `known-third-party` or FastAPI immutable calls, every member fails `ruff check`. |
| The root `conftest.py` and the root pytest markers | The scaffold suite runs from the root ([F16.4](F16.4-member-gate.md)). |
| `packages/rn-forge-web/docs/guides/examples/` | `rn-forge-web`'s tests execute `asgi_app.py`, and the guides include all three examples. |
| `broker-profile.yml`, `internal-ranges.yml`, `umbrella-release.yml` and `scorecard.yml` | Hand-written workflows for work `ci.yml` does not do. Each stays, and S16.3.2 changes the first three to meet kiln's rules. |

### The 2026-10-18 trial

A `kiln init` on branch `feature/kiln-adoption` was a trial and was reverted. It
exited 1 with 27 findings, all in `.github/workflows/main.yml`: 20
`ci.entrypoint` findings for its direct `uv` steps and 7 for jobs with no
`permissions:` key. That is expected: `main.yml` is repo-owned and retires in
S16.3.2. Generated `task setup` syncs `--all-packages --group dev --group docs`,
with no `--all-extras`, and `task ci:verify` passed for `rn-forge-data` (78
passed) and `rn-forge-fastapi` (361 passed), because each member's dev group
brings the extras its tests need.

### The 2026-10-19 trial

A second trial `kiln init`, from kiln's working tree after kiln S4.10.1, on
`feature/kiln-adoption`, was also reverted. It ended with the same 27 findings.
Every file it rendered matched the config. It also showed:

- `task lint` cannot run until `taplo` and kiln are dev dependencies: kiln's
  tasks run both, and pykit has neither.
- 11 TOML files fail kiln's `quality:lint:toml` until `task format` runs: the
  nine member `pyproject.toml` files, `.mdformat.toml` and kiln's own
  `config.toml`. kiln F6.6 makes `init` write a taplo-clean `config.toml` and
  add the missing tools except kiln. `init` formats nothing: the rest is a
  separate `task format` commit.
- The derived nav drops every package site until `docs/_areas.yml` has the
  `packages` area with `nav: include`, which S16.3.3's branch adds.
- `init` records the `--config` file as `[source]`. A seed under `dist/` is
  git-ignored and deleted by `task clean`, so `kiln config-update` could not
  read it again.

### The 2026-11-01 trial

A third trial on throwaway branch `feature/kiln-adoption-run-3`, from
`feature/release-8` with all ten members, used kiln `feature/v1` (`a8876b8` by
the end). `kiln init --force --yes` exited 1 with 41 findings: 38 in `main.yml`,
and one `ci.entrypoint` finding each in `broker-profile.yml`,
`internal-ranges.yml` and `umbrella-release.yml`. After `task format`, and with
`main.yml` deleted:

| Stage | Result |
| -- | -- |
| `task typecheck` | Passes for every member. |
| `task test` | Passes for every member: 4,085 tests. |
| Ruff and import contracts, within `task lint` | Pass. All 15 contracts hold. |
| `task docs:build` | Fails. `mkdocs --strict` stops on 33 warnings because the derived nav has no Packages section. |
| `kiln doctor . --full` | Fails with 16 findings, and 18 once `feature/v1` moved mid-run. |

The "pykit keeps" tables came through unchanged apart from taplo's formatting,
and `init` added `actionlint-py`, `pip-audit`, `taplo` and `zizmor` to the dev
group. It showed:

- `init` left `[ci] release` unset. Setting it to `"pypi"` and running
  `kiln apply` rendered `twine check --strict`, a `testpypi` dispatch input,
  environment `pypi` or `testpypi`, and the upload.
- `init` seeded `rn_forge/tooling/settings.py` and `tests/test_settings.py` into
  `rn-forge-tooling`, a published package, adding a public module nothing
  wants. kiln's `seedable` looks only at `*.py` files directly in the package
  directory, and `rn-forge-tooling` is the one member whose code is all in
  subpackages. Deleting the files does not last: `kiln apply --dry-run` then
  plans `seeded create` for both. kiln's ADR-0010 says a starter is written
  once, at `kiln new`, and never by `apply`.
- kiln's generated setup action requires `github-token`, has no `sync` input,
  and installs only uv and go-task. The three hand-written workflows call it
  with no token, `umbrella-release.yml` passes `sync`, and two of them rely on
  it to sync. `kiln doctor` does not flag this, so they would fail only when
  run.
- The three workflows' `uv` steps fail S16.3.2's `kiln doctor . --full`, while
  S16.3.4, which held their task and declarations, depended on S16.3.2.
  `main.yml` also publishes `simple/`, so that hook cannot wait until after
  `main.yml` goes.
- kiln no longer warns `init.kiln-dev-dependency-missing`: since kiln F7.4 the
  generated tasks run kiln through `uvx`, so it needs no dev dependency and no
  `override-dependencies`.
- `feature/kiln-docs-model` adds the `packages` area but is 136 commits behind
  `feature/release-8`, and it leaves `docs/specs/ideas.md` where doctor
  refuses it.
- `doctor` also finds no `packages/rn-forge-devops/docs/guides`, and links to
  the excluded `_structure.md` pages from `docs/specs/index.md`,
  `F13.1-auth-design.md` and `F14.3-generated-board.md`.

The real `kiln init` runs again only after kiln has built the behaviour S16.3.2
lists and kiln F6.6, is tagged, and no longer seeds starter source into a
repository it adopts.

## Stories

### S16.3.1 — `kiln init`

**State:** New · **Depends on:** S16.5.3

**Build:**

- Entry criteria, observed from outside kiln: kiln's release-1 tags exist, and
  the kiln version pinned in `tasks/` renders the behaviour S16.3.2 lists,
  which pykit requires in full, includes kiln F6.6, and neither `init` nor
  `apply` seeds starter source into an existing member.
- In order:
    1. Move aside any leftover `.rn-forge/kiln/backups` and
       `.rn-forge/kiln/rendered`.
    1. Run `kiln init` on the cutover branch as `python-lib` with the config in
       "What pykit sets". `init` adds `actionlint-py`, `pip-audit`, `taplo` and
       `zizmor` to the dev group (kiln S6.6.2). If the `--config` file is not
       committed, delete the `[source]` table from `.rn-forge/kiln/config.toml`.
       Commit `init`'s change on its own.
    1. Reconcile `CLAUDE.md` with kiln's generated block, and rewrite the
       `uv run …` instructions to `task` verbs in `CLAUDE.md`,
       `docs/guides/development.md`, `README.md` and
       `docs/runbooks/releasing-packages.md`.
    1. Land branch `feature/kiln-docs-model` (commit `4558752`, S16.3.3) after
       init, keeping init's version of any kiln-owned `_structure.md`. Run
       `task docs:generate`, then fix every `docs.state-contradicts-work`
       finding.
- Do not add kiln as a dev dependency or write
  `[tool.uv] override-dependencies`: the generated tasks run kiln through
  `uvx` (kiln F7.4).
- Leave `pyproject.toml` tables, the root `conftest.py` and the `rn-forge-web`
  examples as the "pykit keeps" table lists.

**Acceptance:**

- `task validate`, which runs ruff, pyright and pytest once per member, and
  `kiln doctor . --full` exit 0, apart from the `ci.entrypoint` and missing
  `permissions:` findings in `.github/workflows/main.yml` and the
  `ci.entrypoint` findings in `broker-profile.yml`, `internal-ranges.yml` and
  `umbrella-release.yml`, which S16.3.2 removes.
- The "pykit keeps" tables are unchanged by the run.
- `rn_forge/tooling/settings.py` and `rn-forge-tooling`'s `test_settings.py` do
  not exist, and `kiln apply --dry-run` plans to create neither.
- `CLAUDE.md`, `docs/guides/development.md`, `README.md` and the release runbook
  name no `uv run` gate.

### S16.3.2 — Generated CI replaces `main.yml`

**State:** New · **Depends on:** S16.3.1

**Build:**

- With `[ci] release = "pypi"`, the pinned kiln version renders this behaviour,
  which pykit requires in full:
    - each per-package task takes the member's `dir` from the plan matrix
      (`PACKAGE_DIR`), not from a hard-coded layout
    - `release` publishes only on a push to the default branch and waits on Sonar;
      a pull request's packaging check is `smoke`, not `release`
    - `ci.yml` has a `docs` job after `release` that deploys the versioned package
      sites with mike (`task ci:docs-publish`), and no separate `docs.yml` is
      rendered
    - [F21.3](../E21-pypi-distribution/F21.3-publish-from-release.md)'s release
      behaviour:
        - `twine check --strict` on every build;
        - a trusted-publishing upload to PyPI under environment `pypi`, made before
          the GitHub release and skipped when PyPI already has the version;
        - a `testpypi` manual dry run;
        - per-package GitHub releases with `--latest=false` and the package's
          changelog section as notes, from `rn-forge-devops notes`;
        - `external-install` from PyPI
- Before the merge, the owner adds a trusted publisher for workflow `ci.yml` on
  pypi.org (environment `pypi`) and test.pypi.org (environment `testpypi`) for
  each package, beside the `main.yml` ones F21.1 created.
- kiln's `kiln-devops` is `rn-forge-devops` 0.2.0, the release S16.5.3 tags,
  ported (kiln F6.7), so the matrices kiln reads include the no-extras smoke
  entry.
- `.rn-forge/kiln/config.toml` declares `[[ci.jobs]] name = "internal-ranges"`,
  `uses = "./.github/workflows/internal-ranges.yml"`,
  `[[ci.jobs]] name = "umbrella-release"`,
  `uses = "./.github/workflows/umbrella-release.yml"`, `events = ["push"]`
  ([F21.3](../E21-pypi-distribution/F21.3-publish-from-release.md)), and
  `[ci.hooks] docs = ["./.github/actions/package-index"]`.
- A pykit-owned task file, included through `[tasks] includes`, holds a task for
  each hand-written workflow's direct `uv` step, so `ci-entrypoint` passes:
    - `internal-ranges.yml`: `uv run rn-forge-devops requirements`;
    - `broker-profile.yml`:
      `pytest packages/rn-forge-auth -m broker -p no:randomly`; the Docker
      Compose steps stay in the workflow;
    - `umbrella-release.yml`:
      `git ls-remote … | uv run rn-forge-devops umbrella …`, with the pipe
      inside the task, writing to `$GITHUB_OUTPUT`.
- Those three workflows pass `github-token` to the generated setup action and
  run `task setup` after it, since it installs only uv and go-task.
  `umbrella-release.yml` drops its `sync` input.
- Delete `.github/workflows/main.yml`. Keep `.github/actions/setup/action.yml`:
  `kiln init` replaced it with kiln's generated setup action, which `ci.yml`
  uses, and deleting it would be drift.

**Acceptance:**

- `main.yml` no longer exists, and `kiln doctor . --full` exits 0 with no
  finding.
- A pull request run and a run on `main` pass; `ci-ok` is the only required
  check.
- After the run on `main`, each package's site is served at
  `packages/<package>/latest/` beside the root site, and `simple/` is served
  beside it.
- The run on `main` runs `internal-ranges` and `umbrella-release`, and a manual
  run of `broker-profile.yml` passes.

Do not merge this story's change while both `main.yml` and kiln's `docs.yml`
exist: each push to `main` would run two Pages deploys in the `pages`
concurrency group, and the root-only deploy landing last would remove the
package sites from the live site. The `docs` job above is why the two never
coexist.

### S16.3.3 — Docs tooling

**State:** Active

Decided 2026-10-17: every rn-forge repository keeps its docs in one structure,
so pykit takes kiln's work model rather than owning its own. Done ahead of the
cutover, on branch `feature/kiln-docs-model`, which lands with it. The branch is
136 commits behind `feature/release-8`, so it is redone on the cutover branch
rather than merged: every page added since then needs the same changes.

**Build:**

- Every story heading is `## S<n>.<m>.<k> — <Title>`, with no `## Stories`
  heading.
- The board, release Scope, epic features and feature stories tables are kiln's
  derived regions, and `docs/specs/epics/index.md` lists every epic.
- Each epic's hand-written `Scope` column became its feature's summary
  paragraph, where the summary did not already say it.
- `_areas.yml` is kiln's `python-lib` seed, with `specs` as `nav: work` and the
  `packages` area as `nav: include`.
- `docs/_update_board.sh` is deleted.
- kiln's area rules carry pykit's rules for renumbering moved work, a feature's
  `## Context`, the release `Shipped` table and an epic's state agreeing with
  its work.
- `docs/specs/ideas.md` moves to `docs/specs/ideas/index.md`, and `CLAUDE.md`
  and every page that links it follow.
- Links to an excluded `_structure.md` page become plain text.
- `packages/rn-forge-devops/docs/guides/` exists.

**Acceptance:**

- The derived regions are rewritten by S16.3.1's `task docs:generate` and
  `task lint` finds none stale.
- `docs/_update_board.sh` does not exist.
- `task docs:build` passes, and `kiln doctor . --full` has no docs finding.

The story closes when the branch lands with the cutover.

### S16.3.4 — The planner leaves

**State:** New · **Depends on:** S16.3.2

kiln's ADR-0017 moves the planner into kiln as `kiln-devops` (kiln F6.7). E19's
range check and package index stay in pykit, and S16.3.2 declares them to kiln's
generated CI.

**Build:**

- `rn-forge-devops` loses the planner: `ci.py`, `uv.py`, `github.py`, their
  tests, and the `plan`, `releasable`, `released`, `smoke`, `adapters` and
  `sonar-target` subcommands. It keeps `index`, `releases`, `requirements`,
  `notes` and `umbrella`, and takes a breaking minor bump. Its README, docs
  site and changelog say so, and its `.importlinter` contract names only the
  modules that remain.
- [ADR-0012](../../../adr/ADR-0012.md) gains a dated Background line: kiln's
  ADR-0017 supersedes it for the planner, and `rn-forge-devops` keeps only
  pykit's release commands.

**Acceptance:**

- `uv run rn-forge-devops --help` lists `index` and `requirements` and no
  planner subcommand.
