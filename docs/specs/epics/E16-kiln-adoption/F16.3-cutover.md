Entry criteria: the work runs first as rehearsals from kiln `feature/v1` on the
cutover branch, and merges once `task kiln:apply` re-renders with no change
(`task kiln:diff` prints no difference) at the configured `[kiln] ref`
(S16.3.1). This page holds the whole cutover, so it can be rerun from the page
alone, many times, before the cutover merges: the `kiln new` input (three files
beside this page), every step as a script and the acceptance block. kiln keeps
only the general
[cutover runbook](https://github.com/rn-forge/kiln/blob/main/docs/runbooks/cutover.md),
and its S7.2.4 is a gate that links here.

The cutover runs on kiln's `feature/v1` with `[kiln] ref = "feature/v1"`, so
kiln keeps being refined from pykit's findings, and it may merge on that ref.
Moving `[kiln] ref` to a tag later is a ref bump followed by `task kiln:apply`,
not part of this feature. The steps are S16.3.1's numbered list; a rerun follows
them verbatim.

**Outcome:** pykit adopted kiln's `python-lib` archetype in place, by an overlay
that kept its git history. F16.3's stories closed on `feature/kiln-cutover`,
which merged locally into `feature/release-8` (owner decision 2026-11-13), and
the `feature/release-8` → `main` pull request ships Release 8; the `kiln apply`
check held on 2026-11-13 at `9783dee`.

(kiln `c94f5e0`): the overlay copied every managed file and block from a
`kiln new` reference byte for byte, applied pykit's nuances as explicit steps,

block is a kiln finding, never an edit of the copy.

**Acceptance:**

the block a rerun executes. It asserts:

- the four legacy workflows, `src` and `docs/_update_board.sh` are gone, and
  kiln's workflows are in;
- the board and scope fences are kiln's, with none of the old `board:start` or
  `scope:start` fences left;
- every managed file is the reference's, byte for byte, and `.yamlfmt.yaml`
  exists;
- the three managed blocks (`AGENTS.md`, `.importlinter`, `.gitignore`) are the
  reference's, `git diff --numstat -- AGENTS.md` is `31 0`, and `.gitignore`
  is the reference's plus the `.out/` line;
- `config.toml` has no `[source]` table and holds the input's values;
- the service tables are replaced, no guide names a removed workflow or the
  board script, and no gate runs through `uv`;
- the root `pyproject.toml` differs from the reference's only by pykit's
  nuances, with a blank line before every table and `[tool.pyright]` sorted;
- every member has the reference's build pin, pyright table and
  `source-exclude`, and no `site_dir`;
- nothing under `src/` or `tests/` changed, nothing is staged, and the changed
  non-Markdown files and the untracked files are exactly the two lists in the

Expected `git status`: the four legacy workflows deleted (` D`); `src/pykit/`
and `docs/_update_board.sh` deleted; the Markdown files steps 3, 10 and 13

**Outcome:** three findings went to kiln: `mkdocs.yml` is managed but its nav is
derived, `state.json`'s `config_hash` follows `config.toml`'s bytes, and kiln's
`.gitignore` block has no `.out/`. kiln is not a dev dependency: the generated

## S16.3.10 — Test output moves from `.out/` to `.tmp/`

**State:** Closed (2026-11-12)

The `output_path` fixture in `rn_forge.commons.testing`
(`packages/rn-forge-commons/src/rn_forge/commons/testing.py`) writes under
`<rootdir>/.out/<scope>/tests/output/<node-id>/`. kiln's standard names `.tmp/`
for scratch output, ignores it and cleans it, so the fixture follows. Entry
criterion, observable from outside kiln: the `.gitignore` block that S16.3.1
step 3 copies from the reference lists `.tmp/`. Until then this story does not
start.

**Outcome:** `output_path` writes under `.tmp/<scope>/tests/output/`, the root
`.gitignore` no longer lists `.out/`, and the `rn-forge-commons` changelog
records the breaking change for its next minor release
([ADR-0004](../../../adr/ADR-0004.md)).

**Acceptance:**

- `rg -n '\.out' packages/rn-forge-commons/src` prints nothing, and
  `test_testing.py` asserts `.out` is not in the path.
- `task test` exits 0 and, afterwards, `packages/rn-forge-commons/.tmp` exists
  and `packages/rn-forge-commons/.out` does not.
- `git status --short --ignored packages/rn-forge-commons/.tmp` shows the
  directory ignored (`!!`).
- `rg -n '^\.out' .gitignore` prints nothing.
- `task lint` exits 0.
