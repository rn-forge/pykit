pykit adopts kiln's `python-lib` archetype in place. Stories are written once
kiln's release-1 is tagged; this is the outline, so the shape of the change is
known now. The cutover follows `rn-forge-devops` and `rn-forge-data`, so kiln
renders their members, Sonar sources and import contracts from the start.
`rn-forge-auth` (F13.2) joins after the cutover, in the same release, through
the [adding a package](../../../runbooks/adding-a-package.md) step below.

## Context

This is the one Release 5 feature that waits on another repository's software:
pykit cannot adopt kiln before kiln's release-1 tags exist. The dependency is a
version pin and an observable entry criterion, not acceptance checked in kiln,
so [ADR-0008](../../../adr/ADR-0008.md) still holds for every acceptance line.

What pykit sets, and what it stops owning:

| pykit sets in `.rn-forge/kiln/config.toml` | Why |
| -- | -- |
| `archetype = "python-lib"`, `packages` = every workspace member, nine including `rn-forge-devops` and `rn-forge-data` | The workspace kiln renders for. |
| `modules` = `rn_forge.<name>` for each member | pykit's members are namespace packages (kiln S6.1.3). |
| `import_contracts = "own"` | pykit's `.importlinter` contracts describe its layering; kiln's generic workspace contracts forbid it (kiln S6.1.4). pykit's contracts, including E15's per-package adapter contracts and `rn-forge-devops`'s contracts, move below kiln's END marker. |

[Adding a package](../../../runbooks/adding-a-package.md) gains a step: add the
member to `packages` and `modules` in `.rn-forge/kiln/config.toml`. A
repository-owned check that E15 adds, such as S15.1.2's adapter-to-extra check
if it is not in the planner, is wired through `[tasks] extra_refs` like the
board script.

| pykit stops owning | Replaced by |
| -- | -- |
| `.github/workflows/main.yml`, `.github/actions/setup/action.yml` | kiln's generated CI, which runs `rn-forge-devops` through `task ci:*` (kiln F6.4). pykit's tasks run its own workspace member rather than kiln's pinned version, so its CI keeps testing the planner it ships. |
| `.github/dependabot.yml` for GitHub Actions | kiln's pin table, through kiln upgrades; a Dependabot PR would edit a generated file (kiln F6.3) |
| Direct `uv run …` gates in docs and CI | `task` verbs (`setup validate lint format typecheck test …`) |
| `sonar-project.properties` sources passed by CI | kiln's template lists them from `packages` (kiln ADR-0014) |
| `docs/_update_board.sh` | kiln's `docs:generate` derived regions, once pykit's specs adopt kiln's work model; a separate story, since the board formats differ |

## Stories

Outlines only.

- **S16.3.1 — `kiln init`** as `python-lib` with the config above;
  `task validate` and `kiln doctor . --full` pass.
- **S16.3.2 — Generated CI** replaces `main.yml`; a pull request and a release
  run pass, and `ci-ok` stays the only required check.
- **S16.3.3 — Docs tooling**: the board script retires, or stays as a
  repository-owned lint wired through `[tasks] extra_refs`, by owner decision.
