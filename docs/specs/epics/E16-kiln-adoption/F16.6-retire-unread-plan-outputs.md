# F16.6 — Retire the plan outputs generated CI does not read

|  |  |
| -- | -- |
| **State** | New |
| **Parent** | [E16](index.md) |
| **Iteration** | [Release 8](../../../releases/release-8/index.md) |
| **Predecessors** | [F16.3](F16.3-cutover.md), [F16.5](F16.5-devops-meets-kiln-ci.md) |
| **Source** | Owner decision, 2026-10-18: split from F16.5 so F16.5 closes with rn-forge-devops 0.2.0 |

kiln's generated `ci.yml` reads only six of the twelve `rn-forge-devops plan`
outputs. This feature settles, once pykit runs on that workflow, whether the
other six and the `sonar-target` subcommand stay or go.

## Context

[F16.5](F16.5-devops-meets-kiln-ci.md) documents the `plan` outputs as a
contract and releases `rn-forge-devops` 0.2.0 without removing any of them.
pykit's own `main.yml` still reads the four coverage and Sonar outputs and
`sonar-target`, so nothing can be removed before the cutover
([F16.3](F16.3-cutover.md)) retires it. A removal is a major bump of
`rn-forge-devops`, and kiln has to drop the same keys, so this feature waits for
the cutover.

## Stories

### S16.6.1 — Retire the outputs generated CI does not read

**State:** New · **Depends on:** S16.3.2

Revisit the [open question](#open-questions) once pykit runs on kiln's generated
CI, with `main.yml` gone.

**Build:**

- Find every remaining reader of `cov-args`, `test-paths`, `sonar-sources`,
  `sonar-tests`, `sonar`, `docs` and the `sonar-target` subcommand: kiln's
  rendered `ci.yml` and `_PLAN_KEYS`, pykit's own tasks and scripts, and any
  other repository that runs `rn-forge-devops`. Record the result in this
  story.
- The owner decides, per output, to keep or remove it. Write the decision down
  as an ADR if outputs are removed, or as a rejected option on this feature if
  all are kept.
- If any are removed: delete them from `plan` (and the subcommand from `cli.py`,
  if it goes), update the `plan` outputs page and its test, add a `Removed`
  entry to `CHANGELOG.md`, and release `rn-forge-devops` 1.0.0 with the
  [release runbook](../../../runbooks/releasing-packages.md). kiln drops the
  same keys from `_PLAN_KEYS` and pins 1.0.0. That is kiln's work and does not
  gate this story ([ADR-0008](../../../adr/ADR-0008.md)).

**Acceptance:**

- The decision is recorded, and the open question is removed from this feature.
- If any output was removed: `uv run pytest packages/rn-forge-devops` passes,
  the outputs page lists exactly the keys `plan` returns, and the tag
  `rn-forge-devops-v1.0.0` exists with a published GitHub Release.

## Acceptance

```bash
set -euo pipefail
uv run pytest packages/rn-forge-devops          # S16.6.1, if any output was removed
git ls-remote --exit-code --tags origin rn-forge-devops-v1.0.0   # S16.6.1, if any output was removed
```

Not scripted: S16.6.1's decision, and the 1.0.0 release when outputs are
removed. If none are, neither command applies.

## Open questions

- Should `plan` stop emitting the outputs no kiln-generated job reads, and
  should the `sonar-target` subcommand go? kiln's `ci.yml` reads only
  `release-order`, `packages`, `postgres`, `smoke`, `suites` and
  `pytest-args`. The other six are unread: `cov-args`, `test-paths`,
  `sonar-sources` and `sonar-tests`, because kiln renders Sonar's sources into
  `sonar-project.properties` and `task test:coverage` loops over the members
  itself; and `sonar` and `docs`, because kiln decides whether to render those
  jobs when it generates the workflow. kiln inlines the Sonar branch argument
  rather than calling `sonar-target`. kiln's renderer still forwards all
  twelve keys as `plan` job outputs (`_PLAN_KEYS`), so a removal needs a
  matching kiln change. pykit's `main.yml` reads the four coverage and Sonar
  outputs and `sonar-target` until S16.3.2 retires it, so nothing can go
  before the cutover. Removing any of them is a major bump, as S16.5.2's
  outputs page states. S16.6.1 settles this after the cutover; nothing before
  it removes them.
