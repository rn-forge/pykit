Create `rn-forge-devops` and move `.github/scripts/workspace_ci.py` into it,
released as `rn-forge-devops` 0.1.0. kiln's generated workflows then reach the
planner through `task ci:*` and the version kiln pins, never through a copied
script. [ADR-0012](../../../adr/ADR-0012.md) records why it is a package of its
own and why it depends on no other rn-forge package.

## Context

kiln generates a repository's workflows and forbids a step from calling a
wrapped tool directly (`python3 .github/scripts/…` included), and `scripts/**`
is not a generated path. A seeded copy would never get fixes, and a generated
copy would make kiln own pykit's code. A package is versioned, tested and pinned
like any other dependency. kiln's
[F6.4](https://github.com/rn-forge/kiln/blob/feature/v1/docs/specs/epics/E6-rebuild-the-repos/F6.4-workspace-pipeline.md)
waits on the `rn-forge-devops-v0.1.0` tag.

The package depends on no other rn-forge package. It releases on its own tag and
does not wait for the rest of Release 4, and Release 4's commons changes never
re-release it ([ADR-0004](../../../adr/ADR-0004.md)).

This feature moves the planner and lays the seams for later adapters: the core,
the uv workspace adapter and the GitHub Actions adapter. An Azure DevOps adapter
and Node or Java workspace adapters wait in the [ideas list](../../ideas.md).

### Package shape

| Module | Holds |
| -- | -- |
| `rn_forge.devops.ci` | The core: the member graph, change selection, check matrices and release gating. It knows neither the CI platform nor the stack. |
| `rn_forge.devops.uv` | The uv workspace adapter: it reads `[tool.uv.workspace]` members, their internal requirements and their `[tool.workspace-ci]` tables into the core's graph. `smoke` lives here too: it installs one extra from the built wheels into a clean virtual environment. |
| `rn_forge.devops.github` | The GitHub Actions adapter: it reads the event context from the environment and writes `$GITHUB_OUTPUT` lines. |
| `rn_forge.devops.cli` | The `rn-forge-devops` console script (`argparse`), which wires the subcommands to the core and the adapters. |

The facade re-exports the core only ([ADR-0003](../../../adr/ADR-0003.md)). The
manifest table keeps its name, `[tool.workspace-ci]`, so no package's
`pyproject.toml` changes.

### S16.1.2 — rn-forge-devops and the planner

**State:** Closed (2026-10-16)

**Build:**

- Create `packages/rn-forge-devops/` by
  [adding a package](../../../runbooks/adding-a-package.md):
    - `pyproject.toml` at version `0.1.0`, with `packaging>=24` as its only
      dependency and
      `[project.scripts] rn-forge-devops = "rn_forge.devops.cli:main"`
    - `README.md`, `CHANGELOG.md`, `docs/`, a strict `mkdocs.yml`, the `py.typed`
      marker and a `tests/` tree with no `__init__.py`
    - the root workspace member, development group and `[tool.uv.sources]`
      entries; the root `mkdocs.yml` nav and mkdocstrings path; `docs/index.md`;
      the root `README.md` package table; `docs/architecture/workspace.md`; and
      `docs/guides/choosing-packages.md`
- Move the script into the modules in the shape table above, with `git mv` for
  the bulk so history follows. Behaviour, subcommands, arguments and output
  stay exactly as F14.1 and F14.2 define them: `plan [BASE]`,
  `releasable OK_DIR NAME...`, `released`, `smoke PACKAGE [EXTRA]` and
  `sonar-target`.
- The planner finds the workspace from the current directory, not from the
  module's location.
- `.importlinter`:
    - list `rn_forge.devops` in `root_packages`
    - a forbidden contract keeps `rn_forge.devops` from importing any other
      `rn_forge` package
    - a forbidden contract keeps `rn_forge.devops.ci` from importing
      `rn_forge.devops.uv` or `rn_forge.devops.github`
- Move `.github/scripts/tests/test_workspace_ci.py` into
  `packages/rn-forge-devops/tests/`, split to mirror the modules. Every
  existing test passes unchanged in substance.
- `.github/workflows/main.yml`:
    - every `python3 .github/scripts/workspace_ci.py …` becomes
      `uv run rn-forge-devops …`, and the smoke step drops
      `--no-project --with packaging`
    - a job that ran the script before setting up uv now runs the setup action
      first
    - the header comment names the package
- `.github/workspace-ci-handoff.md`: replace "Files to copy verbatim" with a
  pointer to the package and kiln's F6.4, and delete the script row.
  `docs/runbooks/releasing-packages.md` names the package instead of the
  script.
- The package docs say what it is for: CI and release automation for rn-forge
  repositories in any language, run with uv. They also hold a reference page
  for the subcommands (F14.1's table, moved there).

**Acceptance:**

- `.github/scripts/workspace_ci.py` and its tests no longer exist.
  `uv run rn-forge-devops plan` at the repository root prints every job's
  matrix, as the script did.
- `uv run pytest packages/rn-forge-devops`, `uv run pyright` and
  `uv run lint-imports` pass, and both strict docs builds pass.
- A pull request run of `main.yml` plans, verifies and passes `ci-ok` as before.

### S16.1.3 — Release rn-forge-devops 0.1.0

## Acceptance

- `rn-forge-devops` exists with a platform- and stack-neutral core and its uv
  and GitHub adapters, and pykit's own CI runs the planner from it (S16.1.2).
- `rn-forge-devops-v0.1.0` is published, and `uvx` can run it from git
  (S16.1.3).
- `uv run pytest`, `uv run lint-imports`, `uv run pyright` and
  `sh docs/_update_board.sh --check` pass.
