# F16.4 — Every member passes its own gate

|  |  |
| -- | -- |
| **State** | New |
| **Parent** | [E16](index.md) |
| **Iteration** | [Release 5](../../../releases/release-5/index.md) |
| **Predecessors** | — |
| **Source** | kiln's pykit-shaped repository run, 2026-10-16, reproduced in pykit the same day |

kiln's `python-lib` gate runs each per-package tool once per workspace member,
from that member's own directory:
`uv run --directory packages/<member> --package <member> <tool>`. Only the
member's own `pyproject.toml` tables, and its `tests/conftest.py`, apply. Two
member suites fail that run in pykit's own tree today, independently of kiln.
This feature fixes them before the cutover, so [F16.3](F16.3-cutover.md) changes
tooling only.

## Stories

### S16.4.1 — Member test runs leave the scaffold suite to the root

**State:** New

The scaffold tests build every workspace wheel and install them into fresh
virtual environments, so they need the whole workspace and run once, from the
root. Each member that has them (`rn-forge-cli`, `rn-forge-tooling`,
`rn-forge-fastapi`, `rn-forge-django`) deselects them in its own pytest table:

```toml
[tool.pytest.ini_options]
addopts = "-ra --import-mode=importlib -m 'not scaffold'"
```

A root-level run reads only the root table, so `uv run pytest` and
`uv run pytest -m scaffold` still run them. The root `[tool.workspace-ci]`
`pytest-args` deselect is now redundant, and is removed.

**Acceptance:**

- For every workspace member,
  `uv run --directory packages/<member> --package <member> pytest -q` exits 0,
  with no `fixture 'scaffold_venv' not found` error.
- `uv run pytest -m scaffold --collect-only -q` at the root collects the six
  scaffold tests.
- No member's `tests/` has a `conftest.py` that imports the root `conftest.py`.

### S16.4.2 — Decision: `FastApiApp` owns server tracing

**State:** Closed (2026-10-16)

`AppConfig.tracing` is the one switch for server spans. `FastApiApp` turns
FastAPI's native tracing off by default, with `telemetry={"tracing": False}`,
and instruments through `FastAPIInstrumentor` when `tracing` is true, as it does
today. An application that passes its own `telemetry=` to `FastApiApp` owns
FastAPI's native telemetry instead.

`FastAPI.__init__` accepts and ignores unknown keyword arguments before 0.142,
so the `fastapi>=0.141.1` floor stays.

**Acceptance:**

- `rn-forge-fastapi`'s wiring guide, under its tracing rule, states that
  `FastApiApp` turns off FastAPI's native tracing unless the application
  passes `telemetry=`, and that `AppConfig.tracing` alone decides whether
  server spans are recorded.

### S16.4.3 — `AppConfig(tracing=False)` records no spans on current FastAPI

**State:** Closed (2026-10-16)

Implements S16.4.2. `FastApiApp.__init__` does
`fastapi_kwargs.setdefault("telemetry", {"tracing": False})`. The lock moves to
FastAPI 0.142 or later (`uv lock --upgrade-package fastapi`), so the suite tests
the native path. `test_problem.py`'s `build(tracing=False)` constructs
`FastAPI(telemetry={"tracing": False})`, since it builds a bare `FastAPI` rather
than a `FastApiApp`.

**Acceptance:**

- `uv.lock` resolves `fastapi` at 0.142 or later.
- A new test sets an SDK `TracerProvider` with an in-memory exporter. It asserts
  that a request to `FastApiApp(config=AppConfig(tracing=False))` finishes no
  span, and that a request with `tracing=True` finishes exactly one
  `SpanKind.SERVER` span.
- `uv run --directory packages/rn-forge-fastapi --package rn-forge-fastapi pytest -q`
  exits 0.
- `rn-forge-fastapi`'s `CHANGELOG.md` has a `Fixed` entry under `[Unreleased]`.

## Acceptance

```bash
set -euo pipefail
members=$(ls packages)

# S16.4.1, S16.4.3: every member's suite passes from its own directory.
for m in $members; do
  uv run --directory "packages/$m" --package "$m" pytest -q
done

# S16.4.1: the scaffold suite still runs from the root.
uv run pytest -m scaffold --collect-only -q | grep -qE '^6/[0-9]+ tests collected'

# S16.4.3: the lock carries native-tracing FastAPI.
uv run python -c 'import fastapi; v = tuple(map(int, fastapi.__version__.split(".")[:2])); assert v >= (0, 142), v'

uv run pytest
uv run pyright
uv run lint-imports
sh docs/_update_board.sh --check
```

S16.4.2's guide sentence is checked by reading it.

## Considered and rejected

- **Make `scaffold_venv` reachable from each member.** A per-member
  `conftest.py` cannot import the root one, which the testing rules forbid.
  Moving the fixture into `rn_forge.commons.testing` would ship a fixture that
  only knows pykit's own `packages/` layout. Either way, every member run
  would build all nine wheels and install them from the index.
- **Override kiln's per-member test task in pykit's kiln config.** It moves a
  property of pykit's suites into generated-tooling configuration. The
  member's own pytest table is where a member-directory run already looks.
- **Narrow pykit's test lint ignore to kiln's default** (`ANN`, `D`, `PLR2004`,
  `S101` in place of `ALL`). It is not needed for the gate, and costs 486
  findings across every member's `tests/`, 337 of them auto-fixable. That is
  separate work, if the owner wants it.
- **Cap `fastapi<0.142`.** It defers the bug to whoever lifts the cap, and keeps
  applications that depend on `rn-forge-fastapi` from current FastAPI.
