# F16.5 — rn-forge-devops meets kiln's CI contract

|  |  |
| -- | -- |
| **State** | New |
| **Parent** | [E16](index.md) |
| **Iteration** | [Release 5](../../../releases/release-5/index.md) |
| **Predecessors** | [F16.1](F16.1-devops-package.md) |
| **Source** | Owner decision, 2026-10-18: kiln's generated CI follows one contract for every archetype, with `rn-forge-devops` as its planner |

kiln's generated `ci.yml` reads `rn-forge-devops plan` for every repository it
manages, whatever the stack. This feature makes the planner meet that contract:
a no-extras smoke entry for every selected package, a documented set of `plan`
outputs, and a release of `rn-forge-devops` that carries both.

## Context

kiln's generated release job stops running on pull requests and publishes only
on a push to the default branch. A pull request's packaging check is then the
`smoke` matrix, so it must cover every selected package, not only those that
declare `[tool.workspace-ci.smoke]`. Today `plan` emits a smoke entry, with an
empty extra, only for a package that declares a smoke table.

The `plan` outputs kiln's generated workflow no longer reads are `sonar-target`,
`sonar-sources`, `sonar-tests`, `cov-args` and `test-paths` (kiln takes Sonar
sources from `sonar-project.properties`). Two outputs are less informative than
their names suggest: `sonar` only reports that `sonar-project.properties`
exists, and `docs` that `mkdocs.yml` exists; neither is scoped to the change.
`suites` always lists every suite.

kiln's ADR-0016 makes `rn-forge-devops` the standard CI planner for every
kiln-managed repository whatever its stack, so its outputs are a
cross-repository contract.

The dependency on kiln is a version pin and an observable result, not acceptance
checked in kiln ([ADR-0008](../../../adr/ADR-0008.md)).

## Stories

### S16.5.1 — No-extras smoke for every selected package

**State:** New

**Build:**

- Tests first, in `packages/rn-forge-devops/tests/`:
    - `plan` emits, for a selected package with no smoke declaration, one smoke
      entry `{"name": …, "extra": "", "marker": "<name>.smoke"}`
    - for a package that declares extras, `plan` still emits the empty-extra entry
      first and one entry per declared extra, with the markers it has today
      (`<name>.smoke`, `<name>.smoke-<extra>`)
    - a package not selected emits no entry
    - `Package.checks()` includes the `<name>.smoke` marker for every package, and
      `releasable` blocks a package whose marker is missing, including a package
      with no smoke declaration
    - `smoke` on a package with no declaration builds its wheels, installs the
      base package into a clean venv and imports the package's own module
      (`Package.module`)
- `Package.checks()` always lists the empty-extra smoke check; the declared
  extras add theirs as before.
- `uv.smoke` no longer requires a declaration: with none, the modules to import
  are the package's own module. A declared `modules` list and `setup` apply as
  today.
- The reference page and `CHANGELOG.md`'s `[Unreleased]` section say a package
  with no `[tool.workspace-ci.smoke]` table is still smoke-tested.

**Acceptance:**

- `uv run pytest packages/rn-forge-devops`, `uv run pyright` and
  `uv run lint-imports` pass.
- `uv run rn-forge-devops plan` at the repository root lists a smoke entry with
  an empty extra for every package, including `rn-forge-devops`.
- `uv run rn-forge-devops smoke rn-forge-devops` exits 0.

### S16.5.2 — The plan's outputs are a documented contract

**State:** New

**Build:**

- In the package docs' reference (`docs/reference/subcommands.md` or a page
  beside it), document every `plan` output key and the shape of every matrix
  row: `release-order`, `packages`, `postgres`, `smoke`, `suites`,
  `pytest-args`, `cov-args`, `test-paths`, `sonar-sources`, `sonar-tests`,
  `sonar` and `docs`. State that generated CI workflows read these outputs, so
  a removed or renamed key, or a changed row shape, is a breaking change and
  takes a major version bump. A new key or row field is a minor change.
- Note in that page which outputs the current kiln workflow no longer reads
  (listed in the Context above), without changing or removing any of them.
- Add a test that fails when `plan` returns a key the page does not name, or the
  page names a key `plan` does not return.

**Acceptance:**

- The page lists exactly the keys `plan` returns, and the test enforces it.
- The strict docs build for `rn-forge-devops` passes.

### S16.5.3 — Release rn-forge-devops 0.2.0

**State:** New · **Depends on:** S16.5.1

**Build:**

- Bump `packages/rn-forge-devops/pyproject.toml` to `0.2.0`, a minor bump (each
  package versions on its own, [ADR-0004](../../../adr/ADR-0004.md)): a new
  smoke entry and documentation, no removed key. S16.5.2's documentation ships
  in the same release if it is closed by then.
- Move `[Unreleased]` to a dated `[0.2.0]` section in `CHANGELOG.md`.
- Release with the [release runbook](../../../runbooks/releasing-packages.md).

**Acceptance:**

- The tag `rn-forge-devops-v0.2.0` exists with a published GitHub Release.
- From outside the workspace,
  `uvx --from "rn-forge-devops @ git+https://github.com/rn-forge/pykit@rn-forge-devops-v0.2.0#subdirectory=packages/rn-forge-devops" rn-forge-devops plan`,
  run at pykit's root, prints a smoke entry with an empty extra for every
  package.

## Acceptance

```bash
set -euo pipefail
uv run pytest packages/rn-forge-devops          # S16.5.1, S16.5.2
uv run rn-forge-devops smoke rn-forge-devops    # S16.5.1
git ls-remote --exit-code --tags origin rn-forge-devops-v0.2.0   # S16.5.3
```

Not scripted: the `uvx` run from the tag and the published GitHub Release
(S16.5.3).

## Open questions

- Should `plan` stop emitting `sonar-target`, `sonar-sources`, `sonar-tests`,
  `cov-args` and `test-paths`, which the current kiln workflow does not read?
  Removing any is a major bump (S16.5.2). The owner decides; nothing here
  removes them.
