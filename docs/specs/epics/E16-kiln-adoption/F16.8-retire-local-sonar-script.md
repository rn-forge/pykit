pykit keeps `.github/scripts/sonar_local.py` because kiln had no local Sonar
scan when F16.3 cut over. kiln F6.10 adds one: a `task` verb backed by a
`kiln-devops` subcommand. Once pykit adopts the kiln release that carries it,
the script, its tests and their configuration go away.

## Context

The script reads the planner's `cov-args`, `test-paths`, `sonar-sources` and
`sonar-tests`, runs the coverage tests, then runs `sonar-scanner` against the
checked-out branch and exits with the quality gate's status. It is the only
reader of those four outputs, as F16.6's reader table records.

kiln's work does not gate this feature ([ADR-0008](../../../adr/ADR-0008.md)):
it starts only once a kiln release with F6.10 exists, and is not scheduled in
any release until then.

## S16.8.1 — Use kiln's verb and delete the script

**State:** Closed (2026-11-13)

**Build:**

- Move `[kiln] ref` in `.rn-forge/kiln/config.toml` to the kiln release that
  carries F6.10, and run `task kiln:apply`; the verb renders because Sonar is
  on.
- Run the verb's dry run and compare its target and commands with
  `python3 .github/scripts/sonar_local.py --dry-run` on the same branch.
  Record any difference in this story before deleting anything.
- Delete `.github/scripts/sonar_local.py` and
  `.github/scripts/tests/test_sonar_local.py`, and the `.github/scripts/*`
  entry in the root `pyproject.toml`'s per-file ruff ignores if nothing else
  is left under `.github/scripts/`.
- In `docs/guides/development.md`, *Sonar feedback*, replace the two script
  commands with the kiln verb, keeping the prerequisites.
- Update the `full-local-sonar-scan` idea and F16.3's file-disposition row for
  the script, which say pykit keeps it.

**Acceptance:**

- `.github/scripts/sonar_local.py` does not exist, and no file outside
  `docs/specs/` names it.
- The kiln verb's dry run prints a target and both commands.
- `task kiln:diff` is clean, and `task validate` passes.

*What the build settled that the story did not say*

- `[kiln] ref` stayed `feature/v1`: kiln carries F6.10 on that branch and no
  release tag exists yet.
- The verb is `task sonar:local`; it takes `--dry-run` after `--`.
- kiln S6.10.1 retired the planner outputs `cov-args`, `test-paths`,
  `sonar-sources`, `sonar-tests` and `sonar` from `plan()`, so the old script
  fails on `feature/release-8-close` with `KeyError: 'cov-args'`. The
  comparison below is therefore of the verb against the script's documented
  behavior, not a side-by-side run.
- Dry run of `task sonar:local -- --dry-run` on `feature/release-8-close`:
  target `feature/release-8-close`; a note that the working tree has
  uncommitted changes; commands `task test:coverage` and
  `sonar-scanner -Dsonar.branch.name=feature/release-8-close -Dsonar.qualitygate.wait=true`.
  The verb runs coverage tests through `task test:coverage` and takes
  sources from `sonar-project.properties`, where the script passed them as
  arguments.
- Full scan, run by the owner with a real `SONAR_TOKEN` on 2026-11-13: the
  coverage tests ran and the analysis uploaded, then reading the quality gate
  failed with "Organization is not allowed to access data from non main
  branches". That is the SonarCloud plan limit the
  [`sonar-branch-analysis-plan` idea](../../ideas/index.md#sonar-branch-analysis-plan)
  records, not a fault of the verb.
