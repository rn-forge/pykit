# S31.1.1 — `--version` on CliApp

Brief for
[S31.1.1](../F31.1-version-flag-and-install-route.md#s3111-version-on-cliapp),
at `afb8d5f5` plus S29.1.2 (which bumps `rn-forge-cli` to 0.2.2 and `typer` to
0.29.1). Read the feature's Design first.

## Goal

A `CliApp` built with a version answers `--version` with `<name> <version>`, and
a `[cli]` table's `distribution` key supplies that version from the installed
distribution.

## Settled

- `packages/rn-forge-cli/src/rn_forge/cli/app.py`: `CliApp.__init__` gains a
  keyword-only `version: str | None = None`, documented in its `Args:`.
- When `version` is given, the root callback `_root` takes an eager `--version`
  boolean option (Typer `is_eager=True`, `is_flag`), whose callback prints
  `f"{name} {version}"` with `typer.echo` (stdout) and raises
  `typer.Exit(ExitCode.OK)`. Being eager, it runs before the command is
  resolved and before `_root`'s body, so no command is needed and logging is
  not set up. Help text: "Show the version and exit."
- When `version` is `None`, the callback has no `--version` parameter at all, so
  `--version` is a usage error (exit 2, "No such option") and `--help` does
  not list it. Build the two callback shapes without duplicating `_root`'s
  body, for example by registering a separate callback signature only when
  `version` is set, or by a parameter added through `typer`'s
  `Annotated`/`Option` in a nested function. Keep it readable.
- `packages/rn-forge-cli/src/rn_forge/cli/surface.py`: `CliSurface` gains
  `distribution: str | None = None`, documented in its `Args:`. In
  `__post_init__`, a `distribution` that is given but blank raises
  `AppException` (same style as the blank-name check). The strict dataclass
  already rejects a non-string.
- `CliApp.from_surface`: when `surface.distribution` is set, it passes
  `version=importlib.metadata.version(surface.distribution)`. A
  `PackageNotFoundError` becomes `AppException` naming the distribution, for
  example `"Distribution {!r} is not installed"`, chained with `from`. No
  `distribution`, no `version`.
- `build_tool_app` in `rn-forge-tooling` already goes through
  `CliApp.from_surface`, so it needs no code change; it gets a test.
- Docs: `packages/rn-forge-cli/docs/guides/cli.md`, where it lists the options
  every app gets for free, adds `--version` (present only when the app has a
  version). `packages/rn-forge-cli/docs/guides/declaring.md`'s `[cli]` key
  table adds a `distribution` row: the installed distribution whose version
  `--version` prints; without it, no `--version`.
- Changelog: `packages/rn-forge-cli/CHANGELOG.md` gets `### Added` lines in the
  existing `## [0.2.2]` section (S29.1.2 created it; the version is already
  0.2.2), e.g. "`CliApp(version=...)` adds an eager `--version` that prints
  `<name> <version>`." and "The `[cli]` table's `distribution` key supplies
  that version from the installed distribution." If that section does not
  exist, stop and report.

## Current behaviour

Checked at `afb8d5f5`:

- `CliApp(name="t", version="1.2.3")` raises
  `TypeError: Typer.__init__() got an unexpected keyword argument 'version'`,
  because unknown keywords go to `typer.Typer`.
- `run(CliApp(name="t") with one command, ["--version"])` returns 2 and prints
  `No such option: --version`. This already holds and must stay true.
- `CliSurface.load({"cli": {"name": "t", "distribution": "rn-forge-cli"}})`
  raises `AppException` "Invalid CliSurface: unknown key(s) distribution".

## Tests first

In `packages/rn-forge-cli/tests/test_app.py` (follow its existing style and
fixtures, such as `capsys`):

- `test_version_flag_prints_name_and_version`: an app with `version="1.2.3"` and
  one command; `run(app, ["--version"])` is `ExitCode.OK`, and stdout is
  exactly `t 1.2.3\n`. Fails today with `TypeError`.
- `test_no_version_flag_without_version`: an app without `version` returns
  `ExitCode.USAGE` for `["--version"]`, and `--help` output has no
  `--version`. Passes today; it guards the behaviour.
- `test_from_surface_distribution_sets_version`: a surface with
  `distribution="rn-forge-cli"`; `--version` prints
  `t {importlib.metadata.version("rn-forge-cli")}`. Fails today on the unknown
  key.
- `test_from_surface_unknown_distribution_raises`: `distribution` set to a name
  that is not installed raises `AppException` whose message names it.
- `test_blank_distribution_rejected`: in `test_surface.py`, `distribution="  "`
  raises `AppException`.

In `packages/rn-forge-tooling/tests/` (the test file that covers
`build_tool_app`): `test_build_tool_app_answers_version`: a document with
`[cli]` including `distribution = "rn-forge-tooling"` and a `[lifecycle]` table,
