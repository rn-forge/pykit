# S31.1.2 — The install route is documented

Brief for
[S31.1.2](../F31.1-version-flag-and-install-route.md#s3112-the-install-route-is-documented),
at `afb8d5f5`. Read the feature's Context and Design first.

## Goal

The `rn-forge-tooling` lifecycle guide,
`packages/rn-forge-tooling/docs/guides/lifecycle.md`, says how a tool gets onto
a new machine, and why `uv tool install` and `uv add` are not supported routes.

## Settled

- A new `## Installing on a new machine` section, placed directly before
  `## Installing a branch, tag or commit`.
- Content, in this order:
    1. The prerequisite: `uv` is on `PATH`.

    1. The bootstrap, as a `sh` block, for a tool whose lifecycle verbs live under
       `self` (`namespace = "self"`, described in "Exposing the verbs on a
       command line" in the same guide; link to that heading):

        ```sh
        uvx --from "git+https://github.com/<org>/<tool>@<ref>" <tool> self install --ref <ref>
        source "$RNF_HOME/env.sh"
        ```

        One sentence: `uvx` runs the tool once from its repository, and the tool's
        own `install` builds the tool home. Link `--ref` to the "Installing a
        branch, tag or commit" section.

    1. After that, `<tool> self upgrade`, `self status` and `self doctor` manage
       the install.

    1. Why `uv tool install` and `uv add` are not supported: `uv tool install`
       installs a wheel and writes console-script shims but runs none of the
       package's code (a wheel has no post-install hook), so there is no tool
       home, no `state.json`, no `current` link for version switching, no
       completions and nothing for `doctor` to check. `uv add` makes the tool a
       dependency of another project, which is the route for libraries.
- Keep it short: about 20–30 lines. Plain, direct sentences, matching the
  guide's existing voice. No new page, so no nav or index change.
- `rn-forge-tooling` is not versioned for this story and gets no changelog line.

## Current behaviour

The guide has no install section; nothing in the repo documents the bootstrap.

## Change
