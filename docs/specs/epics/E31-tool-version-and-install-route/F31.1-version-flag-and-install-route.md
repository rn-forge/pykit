A `CliApp` whose version is known answers `--version`, and the
`rn-forge-tooling` docs name the one supported install route for a tool: `uvx`
runs the tool once from its repository, and the tool installs itself.

## Context

A `python-tool` CLI has no way to print just its version. The lifecycle `status`
verb prints the version inside an install report, and an app built without
lifecycle verbs cannot report a version at all.

There is also no written install route. `uv tool install` runs none of the
package's code: it installs a wheel into an isolated environment and writes the
console-script shims. A wheel has no post-install hook, and a build backend runs
only when the install starts from source, at build time, and not at all for a
cached or prebuilt wheel. So `uv tool install` cannot create the tool home,
`state.json`, the `current` link or the completions, and `upgrade`, `cleanup`
and `doctor` have nothing to act on. `uv add` makes the tool a dependency of
another project, which is the route for libraries, not tools. The owner chose
not to support either route for a tool.

kiln owns the generated `python-tool` repository. These follow-ups are kiln
work, not pykit stories: render `distribution` into the packaged `cli.toml` from
`[project] name`, and give the generated README an Install section with the
bootstrap line below.

## Design

Settled by the owner on 2026-11-21.

**A flag, not a command.** `--version` is the convention (`git`, `uv`, `ruff`),
it cannot collide with a command a repository declares in `[cli]`, and it lives
in the root callback, so an app without lifecycle verbs has it too. `status`
keeps the full install report.

**`rn-forge-cli`.**

- `CliApp.__init__` gains `version: str | None = None`. When it is given, the
  root callback takes an eager `--version` option. The option prints
  `<name> <version>` to stdout and exits with `ExitCode.OK` before any command
  or the logging setup runs. When it is `None`, the app has no `--version`.
- The `[cli]` table gains an optional `distribution` key, the installed
  distribution's name, for example `distribution = "rn-forge-kiln"`.
  `CliApp.from_surface` passes `importlib.metadata.version(distribution)` as
  `version`. When the distribution is not installed it raises `AppException`
  naming it. No `distribution`, no `--version`.
- Nothing else reads a version. `build_tool_app` takes it from the surface, like
  every other app.

**The install route,** for a tool whose lifecycle verbs live under `self`. `uv`
must be on `PATH`:

```sh
uvx --from "git+https://github.com/<org>/<tool>@<ref>" <tool> self install --ref <ref>
source "$RNF_HOME/env.sh"
```

After that, `<tool> self upgrade`, `self status` and `self doctor` manage the
install.

**Version.** [ADR-0004](../../../adr/ADR-0004.md): the flag is additive, so
`rn-forge-cli` goes from 0.2.1 to 0.2.2. `rn-forge-tooling` changes only its
docs and is not versioned for this feature.

## S31.1.1 — `--version` on CliApp

**State:** New

**Acceptance:**

- `run(CliApp(name="t", version="1.2.3"), ["--version"])` returns `ExitCode.OK`
  and prints exactly `t 1.2.3`. It does this without a command even when the
  app declares commands.
- `CliApp(name="t")` without `version` rejects `--version` as a usage error, and
  `--help` does not list it.
- A `[cli]` table with `distribution` set to an installed distribution builds an
  app whose `--version` prints that distribution's installed version.
- A `[cli]` table whose `distribution` is not installed raises `AppException`
  naming it, and `distribution` must be a non-blank string.
- `build_tool_app` with a `[lifecycle]` table and `distribution` answers
  `--version` too.
- The CLI guide lists `--version` with the standard options, the declaring
  guide's `[cli]` table lists `distribution`, and `CHANGELOG.md` has the entry
  under `[Unreleased]`. The version is 0.2.2 when the feature closes.
- `task validate` passes.

## S31.1.2 — The install route is documented

**State:** Closed (2026-11-21)

**Acceptance:**

- The `rn-forge-tooling` lifecycle guide gains a section, "Installing on a new
  machine", with the prerequisite, the bootstrap lines above, and the `self`
  verbs that take over after it.
- The section says that `uv tool install` and `uv add` are not supported routes
  for a tool, and why: no package code runs at install, so there is no tool
  home, state, version switching, completions or `doctor`.
- `task docs:build` passes in strict mode.

## Acceptance

- Both stories' acceptance holds, and `rn-forge-cli` 0.2.2 is among Release 12's
  patched packages.
