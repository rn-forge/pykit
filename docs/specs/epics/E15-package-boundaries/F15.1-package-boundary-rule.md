Decide when a part of commons becomes its own package, and how every such
package holds its adapters, then make the structure checkable.
[The design](design.md) holds the evidence and
[ADR-0011](../../../adr/ADR-0011.md) holds the decision.

## Stories

### S15.1.1 — Decide the rule and adapter structure

**State:** Closed

**Acceptance:**

- The owner has accepted [ADR-0011](../../../adr/ADR-0011.md), so its status is
  `accepted` and the [decision log](../../../adr/index.md) says so.
- Each [open question](design.md#answered-questions) in the design is answered,
  or deferred with a trigger, and the design agrees with the answers.

### S15.1.2 — Enforce the adapter structure

**State:** Closed (2026-10-15)

**Acceptance:**

- `.importlinter` holds a forbidden contract that `rn-forge-data`'s core never
  imports an adapter module, and `uv run lint-imports` passes. `rn-forge-auth`
  gains the same contract when E13's
  [F13.2](../E13-auth/F13.2-auth-package.md) creates it.
- A check or a documented convention in
  [adding a package](../../../runbooks/adding-a-package.md) states that each
  adapter module maps to an extra of the same name, and the check fails when a
  module has no extra. If the check reads the workspace manifests, it belongs
  in the workspace planner, which lives in `rn-forge-devops` after
  [F16.1](../E16-kiln-adoption/F16.1-devops-package.md). Do not add it to
  `.github/scripts/`.

## Acceptance

- ADR-0011 is accepted and the design's open questions are closed (S15.1.1).
- `uv run lint-imports` passes with the per-package contracts, and the
  adapter-to-extra mapping is checked or documented (S15.1.2).
- `sh docs/_update_board.sh --check` passes.

An approval cannot be scripted: S15.1.1 closes when the owner says so.
