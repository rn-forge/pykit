# F15.6 — Framework-neutral fixtures

|  |  |
| -- | -- |
| **State** | New |

| **Tags** | deferred |
| **Predecessors** | [F15.3](F15.3-data-package.md) |

| **Entry criteria** | a SQLAlchemy application needs seed data from workbooks, and the `model-vocabulary` natural-key rules are adopted |

Move workbook reading, sheet and column validation and `ColumnType` conversion
from `rn_forge.django.fixtures` into `rn-forge-data`, leaving Django's
`loaddata` JSON output and `load_data` in `rn-forge-django`, and add a
SQLAlchemy loader that follows the shared natural-key rules.

## Context

The [design](design.md#fixtures) separates the two halves. A SQLAlchemy loader
needs natural-key rules that both ORMs share, which is the
[model-vocabulary](../../ideas.md#model-vocabulary) idea.

Stories wait until the owner schedules the feature. Do not start or elaborate it
before then.
