Create `rn-forge-data` and move the Excel and pandas helpers out of commons,
then repoint the Django and FastAPI extras that use them. The move also fixes
the undeclared openpyxl dependency of `rn_forge.django.drf.transfer`. The
[design](design.md#rn-forge-data-contents) lists what moves and who calls it.

## Stories

### S15.3.1 — Scaffold the package and its workspace wiring

**State:** Closed

**Acceptance:**

- `packages/rn-forge-data/` exists with a `pyproject.toml` (version `0.1.0`;
  base dependencies `openpyxl` and `tablib[xlsx]`; a `pandas` extra),
  `README.md`, `CHANGELOG.md`, `docs/`, a strict `mkdocs.yml`,
  `src/rn_forge/data/__init__.py` and a `tests/` tree with no `__init__.py`.
- The root `pyproject.toml` lists it as a workspace member and replaces the
  development group's `rn-forge-commons[excel]` entry. `.importlinter` lists
  `rn_forge.data`, and a forbidden contract keeps the core from importing the
  `pandas` adapter module.
- `uv run lint-imports` and `uv run pyright` pass.

### S15.3.2 — Move the Excel and pandas code

**State:** Closed

**Acceptance:**

- `rn_forge.commons.data.excel`, `rn_forge.commons.data.pandas` and the pandas
  aliases in `rn_forge.commons.lang.types` (`SeriesRow`, `series_value`,
  `series_columns`) are importable from `rn-forge-data` and gone from commons.
- Commons has no `excel` or `pandas` extra. `json`, `structlog`, `otel`,
  `pydantic`, `resilience` and `testing` remain, with `auth` until
  [F13.2](../E13-auth/F13.2-auth-package.md) removes it. The `all` extra is
  updated to match.
- Their tests live in `rn-forge-data/tests/` and pass. Importing the base
  package loads no pandas.

### S15.3.3 — Repoint the framework extras

**State:** Closed

**Acceptance:**

- `rn-forge-django`'s `transfer` extra names `rn-forge-data`, its `fixtures`
  extra names `rn-forge-data[pandas]`, and `rn-forge-fastapi`'s `transfer`
  extra names `rn-forge-data`. None names a commons extra.
- A clean install of Django's `transfer` extra without
  `django-import-export[xlsx]`'s help still imports
  `rn_forge.django.drf.transfer`, shown by the extra's smoke check.
- The three callers' tests pass with the moved imports.

### S15.3.4 — Document the package

**State:** Closed

**Acceptance:**

- The package has a site with a guide and its API reference, and the root pages
  and `mkdocs.yml` name `rn-forge-data` as in S13.2.5.
- The changed packages' changelogs record the breaking moves.
- `uv run --group docs mkdocs build --strict` passes for the package site and
  the combined site.

## Acceptance

- The package exists and passes the boundary checks (S15.3.1).
- The Excel and pandas code lives only in `rn-forge-data`, and commons has six
  extras (S15.3.2).
- The Django and FastAPI extras name `rn-forge-data`, and the openpyxl defect is
  gone (S15.3.3).
- The package and root pages are documented and both strict builds pass
  (S15.3.4).
- `uv run pytest`, `uv run lint-imports`, `uv run pyright` and
  `sh docs/_update_board.sh --check` pass.
