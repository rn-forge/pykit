# S30.1.3 — Missing-driver errors

Brief for
[S30.1.3](../F30.1-postgresql-engine-and-driver-extras.md#s3013-missing-driver-errors),
at the S30.1.2 merge on `feature/release-12`. Read the feature's Design first.

## Goal

`create_postgres_engine` and `create_sqlite_engine` raise an `ImportError` that
names the extra to install when their driver is missing, while
`import rn_forge.sqlalchemy` still works without either driver. The package is
released as 0.2.5.

## Settled

- In each function, before building the engine, import the driver lazily with
  `importlib.import_module("asyncpg")` or
  `importlib.import_module("aiosqlite")` inside `try`. On `ImportError`, raise
  `ImportError("create_postgres_engine needs asyncpg; install rn-forge-sqlalchemy[postgres]")`
  (respectively `create_sqlite_engine`, `aiosqlite`,
  `rn-forge-sqlalchemy[sqlite]`) `from` the original. Share one small private
  helper if both modules can use it without a new public name; otherwise
  repeat the four lines.
- Neither module imports its driver at module level.
- Each docstring's `Raises:` gains the `ImportError` line.
- `create_sqlite_engine`'s check runs after its argument validation, so a bad
  `synchronous` still raises `ValueError` first. Do the same in
  `create_postgres_engine` (after the URL and number checks).
- Version: `packages/rn-forge-sqlalchemy/pyproject.toml` goes 0.2.4 → 0.2.5, and
  `CHANGELOG.md` moves everything under `[Unreleased]` into a new
  `## [0.2.5] - 2026-11-21` section below an empty `## [Unreleased]`, adding
  `### Changed` (or `### Added`, matching the existing entries) "A missing
  driver raises `ImportError` naming the `postgres` or `sqlite` extra." Follow
  the file's existing format. `task setup` updates the lock.

## Current behaviour

Checked on the repo's environment: with `sys.modules["aiosqlite"] = None`,
`create_sqlite_engine(":memory:")` raises
`ModuleNotFoundError: import of aiosqlite halted; None in sys.modules`, and
`create_async_engine("postgresql+asyncpg://...")` likewise for `asyncpg`. The
messages do not name an extra, so the two tests asserting the extra fail on the
message. `import rn_forge.sqlalchemy` already succeeds with both drivers
blocked, so `test_import_without_drivers_succeeds` passes today; it guards the
behaviour.

## Change

1. Tests first, below; confirm the first two fail on the message.
1. The lazy imports, docstrings, version and changelog.

## Tests first

Unit-marked, `assertpy` style:

- `test_create_postgres_engine_without_asyncpg_names_the_extra`, in
  `tests/test_postgres.py`:
  `monkeypatch.setitem(sys.modules, "asyncpg", None)`, then
  `create_postgres_engine("postgresql://u@h/d")` raises `ImportError` whose
  message contains `rn-forge-sqlalchemy[postgres]`.
- `test_create_sqlite_engine_without_aiosqlite_names_the_extra`, in
  `tests/test_sqlite.py`: the same for `aiosqlite`,
  `create_sqlite_engine(":memory:")` and `rn-forge-sqlalchemy[sqlite]`.
- `test_import_without_drivers_succeeds`, in `tests/test_package.py`: runs
  `sys.executable -c` with a script that sets `sys.modules["asyncpg"] = None`
  and `sys.modules["aiosqlite"] = None`, then imports `rn_forge.sqlalchemy`
  and references `create_postgres_engine` and `create_sqlite_engine`; the
  subprocess exits 0. A subprocess keeps the test independent of what earlier
  tests imported.
