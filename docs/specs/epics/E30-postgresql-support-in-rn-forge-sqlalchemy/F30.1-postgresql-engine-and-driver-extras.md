`rn-forge-sqlalchemy` gains `create_postgres_engine`, driver extras for
PostgreSQL and SQLite, and a clear error when a driver is missing.

## Context

Today the package declares no driver. `create_sqlite_engine` hard-codes the
`sqlite+aiosqlite` driver, but `aiosqlite` is declared nowhere, so the call
fails at runtime unless the application adds `aiosqlite` itself. Consumers, such
as a FastAPI web app on PostgreSQL 17, each re-add `asyncpg` and repeat the
engine boilerplate.

## Design

Settled by the owner on 2026-11-21.

**Extras.** The core install stays driver-free, so a SQLite-only consumer never
installs `asyncpg` (a compiled wheel) and the reverse. Drivers come from extras:

```toml
postgres = ["asyncpg>=0.32.0"]
sqlite = ["aiosqlite>=0.22.1"]
```

The floors are the versions `uv.lock` resolves today. `migrations` is unchanged.

**`rn_forge.sqlalchemy.postgres.create_postgres_engine`**, exported from the
package root and mirroring `create_sqlite_engine`:

```python
def create_postgres_engine(
    url: str | URL,
    *,
    pool_size: int = 5,
    max_overflow: int = 10,
    pool_pre_ping: bool = True,
    pool_recycle_s: int = 1800,
    statement_timeout_ms: int | None = None,
    application_name: str | None = None,
    prepared_statement_cache_size: int = 100,
) -> AsyncEngine: ...
```

- It accepts `postgresql://`, `postgres://` and `postgresql+asyncpg://` and
  rewrites the driver to `postgresql+asyncpg`. Any other scheme or driver,
  such as `postgresql+psycopg` or `sqlite`, raises `ValueError` naming the
  scheme.
- Every connection sets `server_settings` through asyncpg's
  `connect_args={"server_settings": ...}`: `timezone=UTC`, which matches
  `UTCDateTime`, plus `application_name` and `statement_timeout` when given.
- `prepared_statement_cache_size` sets both caches: SQLAlchemy's asyncpg dialect
  argument `prepared_statement_cache_size`, and asyncpg's own
  `statement_cache_size` in `connect_args`. `0` turns both off, which is the
  documented setting for PgBouncer transaction pooling.
- A negative `pool_size`, or any other invalid numeric argument, raises
  `ValueError`.
- It creates no tables and does not connect at creation.
- When `asyncpg` is not installed, the call raises `ImportError` whose message
  names the `rn-forge-sqlalchemy[postgres]` extra.
  `import rn_forge.sqlalchemy` itself still succeeds without `asyncpg`.

**`create_sqlite_engine`** likewise raises `ImportError` naming
`rn-forge-sqlalchemy[sqlite]` when `aiosqlite` is missing.

**Version.** [ADR-0004](../../../adr/ADR-0004.md): before 1.0, a release with a
breaking change bumps the minor and any other release bumps the patch. This
addition is backward compatible, so `rn-forge-sqlalchemy` goes from 0.2.4 to
0.2.5, and consumers ranged `>=0.2,<0.3` take it without a range change. No open
point.

## S30.1.2 — create_postgres_engine

**State:** Closed (2026-11-21) · **Depends on:** S30.1.1

**Acceptance:**

- `test_create_postgres_engine_rewrites_accepted_schemes` covers
  `postgresql://`, `postgres://` and `postgresql+asyncpg://`, each giving the
  `postgresql+asyncpg` driver.
- `test_create_postgres_engine_rejects_other_schemes` covers
  `postgresql+psycopg` and `sqlite`, and the `ValueError` names the scheme.
- `test_create_postgres_engine_sets_utc_timezone_server_setting` and
  `test_create_postgres_engine_adds_optional_server_settings_only_when_given`
  prove `timezone=UTC` is always set, and `application_name` and
  `statement_timeout` only when passed.
- `test_create_postgres_engine_passes_pool_arguments` proves `pool_size`,
  `max_overflow`, `pool_pre_ping` and `pool_recycle_s` reach the engine.
- `test_create_postgres_engine_passes_prepared_statement_cache_size` proves the
  value reaches both the dialect and asyncpg's `statement_cache_size`,
  including 0.
- `test_create_postgres_engine_rejects_negative_arguments` proves a negative
  numeric argument raises `ValueError`.
- A `postgres`-marked test,
  `test_create_postgres_engine_connection_reports_utc`, skips without
  `RN_FORGE_TEST_POSTGRES_DSN`. With it, a connection reads `SHOW timezone` as
  `UTC` and `current_setting('application_name')` as the given name.
- `create_postgres_engine` is exported from `rn_forge.sqlalchemy`, and the
  README's module table and CHANGELOG name it.

## Considered and rejected

- **psycopg 3 as the driver.** `asyncpg` is SQLAlchemy's default async
  PostgreSQL driver and the fastest. One driver keeps the helper and its tests
  simple; psycopg can be a later extra if a consumer needs sync and async from
  one driver.
- **`asyncpg` as a hard dependency.** It would force a compiled PostgreSQL
  driver on SQLite-only consumers.
- **A settings and session-factory layer.** Out of scope: applications own their
  settings, and the helper only builds the engine.
