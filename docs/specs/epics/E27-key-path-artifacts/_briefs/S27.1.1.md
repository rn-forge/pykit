# S27.1.1 — `ArtifactKind.KEYS` plans, diffs and applies

Brief for
[S27.1.1](../F27.1-keys-artifact-kind.md#s2711-artifactkindkeys-plans-diffs-and-applies),
at `a921e01b`. Read the feature's Context and Design first: they are the
contract, and this brief only adds what the feature leaves to the builder.

## Goal

`rn_forge.commons.generation` gains `ArtifactKind.KEYS`, with the model,
classification, diff and apply behaviour the feature's Design states, and
`DocumentUtils.serialize_document`. The fourteen acceptance cases and the
`serialize_document` test pass.

## Settled

- **Everything in the feature's Design is settled.** Do not reopen it.
- **Splitting a key path** uses `_split_key_path` from
  `rn_forge.commons.lang.collections`, so `\.` escapes a dot exactly as
  `DictUtils` does. Import it; do not copy it.
- **Reading disk values** (plan): `DocumentUtils.read(path)` gives a plain
  mapping. Walk each recorded path segment by segment through mappings only; a
  path whose walk leaves a mapping, or whose segment is absent, is left out.
  Hash the canonical form of what remains.
- **Writing** (apply): walk segments through the round-trip document; create a
  missing intermediate as a new table (`tomlkit.table()` for TOML, a `dict`
  for JSON); raise
  `AppException("{}: key path {!r} runs through a non-table", path, key_path)`
  when an existing intermediate is not a mapping. Do not use `DictUtils.set`:
  it indexes into lists, which the Design forbids.
- **Pruning:** after a deletion, walk back up that path and remove each table
  left empty, stopping at the root.
- **Where `_render_keys` lives:** `diff` (plan.py) and `_compose` (apply.py)
  both need it. Put it in `artifacts.py` beside `block_from_entry`, as a
  module-level function named `render_keys(root, change, previous) -> str`,
  and call it from both. `apply.py` already imports from `artifacts.py`.
- **Classification order** for a keys artifact, in `classify`: file absent →
  `create` or `missing`; entry `None` → `insert`; entry kind not `KEYS` →
  `conflict`; disk hash differs → `drift`; then `unchanged` / `update`.
- **Stale keys entries** go in `_stale_action` before the whole-file fallback.
- **A forced `conflict`** reaches `_compose` with `effective_action` still
  `CONFLICT` (no intent). `render_keys` treats every action except `REMOVE` as
  "set the owned keys", and deletes only paths in a previous entry that is a
  keys entry.
- **`StateEntry.key_paths`** is `tuple[str, ...] | None`. `DataclassMixin` casts
  lists to tuples on load, so the JSON list in a state file round-trips.
- Test helper: `def keys(path="settings.json", values=None)` beside `block`,
  defaulting to `{"editor.theme": "dark"}`, building
  `Artifact(path=path, kind=ArtifactKind.KEYS, content="", keys=values)`.

## Current behaviour

At `a921e01b`:

- `ArtifactKind.KEYS` raises `AttributeError`, so every case in `TestKeys` fails
  at the `keys()` helper.
- `Artifact(..., keys=...)` raises
  `TypeError: unexpected keyword argument 'keys'`.
- `StateEntry(..., key_paths=...)` raises `TypeError` likewise.
- `DocumentUtils.serialize_document` raises `AttributeError`.
- `diff(root, change, entries=...)` raises `TypeError` on the keyword.
- Case 12 (old state file) passes today; it must still pass after.

## Change

1. `fs/documents.py`: `serialize_document(path, document) -> str` holding
   today's `write_document` body up to the write; `write_document` calls it
   then `PathUtils.atomic_write`.
1. `generation/artifacts.py`: the `KEYS` member, `Artifact.keys`, validation,
   `content_hash`, `to_entry`, `StateEntry.key_paths`, widened `Action.INSERT`
   and `Action.REMOVE` docstrings, and `render_keys`.
1. `generation/plan.py`: keys classification, stale keys entries, and the
   `entries` keyword on `diff`.
1. `generation/apply.py`: `_compose` splits keys changes out, refuses a keys
   change sharing a path with any other change, and calls `render_keys`.
1. Docs and changelog as the story's acceptance lists.
