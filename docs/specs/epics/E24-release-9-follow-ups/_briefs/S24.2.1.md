# S24.2.1 — Check the ID token's typ

Brief for [S24.2.1](../F24.2-id-token-type.md#s2421-check-the-id-tokens-typ), at
`c3fc2b8`.

## Goal

`IdTokenVerifier.verify` accepts a `typ` header that is absent or `JWT` (any
case) and rejects every other value, the rule `JwtVerifier` already applies in
`mode="rfc7519"`.

## Settled

- Settled by the owner, 2026-11-17: reverse S22.8's "ID tokens keep no `typ`
  check". Reject other profiles' types; accept none or `JWT`.
- In `packages/rn-forge-auth/src/rn_forge/auth/oidc.py`,
  `IdTokenVerifier.verify` keeps the header `_signing_key` returns (today
  discarded as `_`) and, right after it, raises
  `TokenVerificationError("Token typ {} is not an ID token", header.get("typ"))`
  when `_media_type(header) not in (None, "jwt")`. Raise it outside the
  `try` so it is not rewrapped as "ID token verification failed".
- `IdTokenVerifier`'s class docstring states the rule in one line. The module
  docstring already claims it and stays as is.
- `OidcProvider` needs no change; it calls `verify`.
- Changelog: `packages/rn-forge-auth/CHANGELOG.md`, `[Unreleased]`,
  `### Changed`: an ID token whose `typ` header is neither absent nor `JWT` is
  rejected.

## Current behaviour

At `c3fc2b8`, `verify` never reads `typ`. With the `idp` fixture in
`tests/oidc/conftest.py` (`idp.sign(claims, typ=...)`, default `"JWT"`), a valid
ID-token claim set signed with `typ="at+jwt"` or `typ="logout+jwt"` verifies and
returns its claims, so a `pytest.raises(TokenVerificationError)` around it fails
with "DID NOT RAISE". `typ=None` and `typ="jwt"` verify today and must keep
doing so.
