# S24.1.2 — Export joins the resource's forward relations

Brief for
[S24.1.2](../F24.1-django-transfer-limits.md#s2412-export-joins-the-resources-forward-relations),
at `3192c81`.

## Goal

`ResourceExportMixin` costs a constant number of queries per export when its
resource reads forward foreign-key or one-to-one fields, whether or not the
viewset's queryset calls `select_related`.

## Settled

- Settled by the reviewer, 2026-11-17: in
  `packages/rn-forge-django/src/rn_forge/django/drf/transfer.py`,
  `ResourceExportMixin.list` builds the resource first, then applies
  `queryset.select_related(*paths)` before `resource.export(...)` when `paths`
  is non-empty. The cap `count()` stays on the unjoined queryset.
- `paths` comes from a private module function,
  `_forward_relation_paths(model, resource) -> list[str]`: for each field in
  `resource.get_export_fields()` whose `attribute` is a non-empty string,
  split it on `__` and walk from `model`. A segment extends the path while
  `model._meta.get_field(segment)` exists and is `concrete`, `is_relation` and
  `many_to_one or one_to_one`; the walk moves to its `related_model`. The
  first other segment (a plain column, a reverse or many-to-many relation, a
  property, or a name `get_field` does not know, which raises
  `FieldDoesNotExist`) ends the walk. A non-empty path joined with `__` is
  added once; order follows the fields.
- No public hook or setting. A viewset that already calls `select_related` keeps
  working; the extra `select_related` is additive. Prefetching many-to-many
  stays the viewset's job.
- `ResourceExportMixin`'s docstring gains one sentence: forward foreign-key and
  one-to-one paths the resource reads are joined with `select_related`.
- The settled contract on S22.9.3 ("Export stays constant only for a viewset
  that shapes its queryset") is superseded; the reviewer updates that spec at
  close, not the implementer.
- Changelog: `packages/rn-forge-django/CHANGELOG.md`, `[Unreleased]`,
  `### Fixed`: a tabular export no longer issues one query per row for
  foreign-key columns when the viewset's queryset has no `select_related`.

## Current behaviour

At `3192c81`, `tests/drf/test_transfer.py` `TestQueryCounts` measures only
`/shaped` (`Member.objects.select_related("team")`). The unshaped `Members`
viewset (`/members`) exports `MemberExport`, whose `team` field reads
`team__code`; each row with a team costs one extra query, so exporting 12 rows
costs 9 more queries than 3 rows, and an equality assertion fails by 9.

## Change
