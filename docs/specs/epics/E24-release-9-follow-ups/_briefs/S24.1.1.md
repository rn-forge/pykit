# S24.1.1 — Request field limits are a 400 problem

Brief for
[S24.1.1](../F24.1-django-transfer-limits.md#s2411-request-field-limits-are-a-400-problem),
at `c3fc2b8`.

## Goal

A request that trips Django's `DATA_UPLOAD_MAX_NUMBER_FIELDS` or
`DATA_UPLOAD_MAX_NUMBER_FILES` gets a 400 problem from
`problem_details_exception_handler`, not a 500. The visible case is
`GET :batchGet` with more than 1,000 `ids`.

## Settled

- Settled by the reviewer, 2026-11-17: map
  `django.core.exceptions.TooManyFieldsSent` and `TooManyFilesSent` to
  `rn_forge.web.BAD_REQUEST` in `problem_registry()`
  (`packages/rn-forge-django/src/rn_forge/django/drf/exceptions.py`), next to
  the existing `RequestDataTooBig` row.
- Details, set in `problem_details_exception_handler` beside the
  `RequestDataTooBig` branch:
    - `TooManyFieldsSent`: `Request has more fields than the configured limit`
    - `TooManyFilesSent`: `Request has more files than the configured limit`
      Django's own message is never echoed.
- No change to `batch_get_ids`, `transfer.max_rows` or `rn-forge-web`. The
  `transfer.max_rows` 400 for an over-cap batch below Django's limit is
  unchanged.
- `BatchGetMixin`'s docstring gains one sentence: Django's
  `DATA_UPLOAD_MAX_NUMBER_FIELDS` (1,000 by default) also bounds `ids`, and
  more is a 400 problem.
- Changelog: `packages/rn-forge-django/CHANGELOG.md`, `[Unreleased]`, a
  `### Fixed` entry: more query or form fields (or files) than Django's upload
  limits is a 400 problem instead of a 500.

## Current behaviour

Observed at `c3fc2b8` with a throwaway test on the `Books` viewset in
`tests/drf/test_transfer.py`:

- `client.get("/books:batchGet", {"ids": [pk] * 1000})` → 200.
- `client.get("/books:batchGet", {"ids": [pk] * 1001}, raise_request_exception=False)`
  → 500 `application/problem+json`, `detail: "An unexpected error occurred."`.
  The same with `RN_FORGE_DJANGO={"DRF": {"TRANSFER": {"MAX_ROWS": 5}}}` →
  500\. `request.query_params.getlist` raises `TooManyFieldsSent`, which the
  registry does not map. Without `raise_request_exception=False` the Django
  test client re-raises the signalled exception, so the new test must pass it.

## Change

1. `drf/exceptions.py`: import `TooManyFieldsSent` and `TooManyFilesSent` from
   `django.core.exceptions`; register both to `BAD_REQUEST` in
   `problem_registry()`; extend its docstring's mapping sentence; add the two
   details in `problem_details_exception_handler`.
1. `drf/transfer.py`: the `BatchGetMixin` docstring sentence above.
1. The changelog entry.
