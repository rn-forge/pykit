# F6.1 — Structured-log secret redaction

Commons logging should strip secrets from structured events, so applications stop carrying their own redaction code. Account Portal's `logging.py::redact` is the prior art; no other reviewed application redacts anything, and two log request context straight to stdout.

## Design

No library fits: `logredactor` works only on formatted strings, `scrubadub` is a PII-in-prose cleaner with a heavy dependency tree, and `pii-redact` needs `torch`. Both exemptions to design principle 1 apply, so the module hand-rolls a few dozen lines.

**Build.** In `src/rn_forge/commons/logging/`:

- `redaction.py`, whose docstring names the exemption. It holds `REDACTED: Final = "[redacted]"`; a frozen `RedactionPolicy` dataclass (`field_pattern: re.Pattern[str]`, `scrub_credentials: bool`, `scrub_url_passwords: bool`) whose `RedactionPolicy.default()` matches `authorization`, `token`, `password`, `secret` and `cookie`; and `redact(value, *, policy=None, key="") -> Any`.
- A `RedactFilter(logging.Filter)` beside `EnrichFilter` in `logger.py`. It redacts `record.args` and any `extra` fields, and is registered in `AppLogger._configure_logging`'s `filters` so the JSON, Rich and plain handlers all apply it. It is gated on a new `LoggingConfig.redact: bool`, default `True`, plumbed through `AppLogger.initialize(redact=...)` and `LoggingConfig.defaults()`.
- A structlog processor, `redact_processor`, in `logging/structlog.py` behind the existing `structlog` extra, inserted before the renderer in `_configure_once`.

**Rules.** Never mutate the caller's mapping or sequence. Preserve `None` and `""` rather than replacing them. Leave unmatched fields untouched. Keep structured context structured; never flatten it to a string. Do not carry over Account Portal's `*env` key exemption or its fixed logger name: both are application policy.

**Tests:** nested dict, list and tuple mixes; input unchanged after a call; case-insensitive key match; a `Bearer <token>` inside a message; a password in URL user-info; a field named `token_count` whose value is not redacted by a key match; a custom policy; `redact=False` disabling the filter; and one integration test asserting a `use_json=True` record emits redacted output.

## Stories

### S6.1.2 — Build redaction in commons logging

**State:** New

**Acceptance:**

- `tests/logging/test_redaction.py` in `rn-forge-commons` covers every case listed under *Design*, and passes.
- A `use_json=True` record with a secret-bearing field emits `[redacted]` in its output.
- `LoggingConfig(redact=False)` disables the filter.
- The module docstring names the design-principle-1 exemption.
- The commons logging guide and its API page document redaction, and the package site builds with `--strict`.

## Acceptance

S6.1.2 is the feature's only story, so its acceptance is the feature's. Its integration test is a host application in miniature, so no scaffolded application is needed ([ADR-0008](../../../adr/ADR-0008.md)).

```bash
set -euo pipefail
cd packages/rn-forge-commons
uv run pytest -q tests/logging/test_redaction.py
uv run --group docs mkdocs build --strict
```
