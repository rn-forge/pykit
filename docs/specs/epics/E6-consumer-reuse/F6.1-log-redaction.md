# F6.1 — Structured-log secret redaction

This feature would remove configured secrets from structured log output in `rn-forge-commons`. It is for implementers and the application that accepts the shared behavior.

**Status:** planned

**Readiness:** not ready

**Readiness basis:** The accepting consumer and its required event/exception behavior are not settled; see Open questions.

**Owner:** pykit.

**Depends on:** Consumer acceptance and the [logging boundary](../../../adr/ADR-0001.md).

**Source:** `web-api-reuse-plan.md`, Phase 2 and finding 2.

[Back to E6](index.md)

## Stories

### S6.1.1 — Implement shared redaction

**Status:** planned

**Acceptance:** Commons logging redacts configured secrets in structured events; a consumer can remove its local copy.

## Design

Keep redaction in `rn_forge.commons.logging`, where structured events are emitted. The source survey found no maintained candidate that covered the required event and exception shapes. No implementation exists yet.

## Acceptance

- Configured secret values are removed from structured events and nested values without changing non-secret fields.
- A consuming application removes its local redaction copy after matching behavior is demonstrated.

## Open questions

Which consumer will prove removal of its local copy, and which event and exception shapes must redaction cover?

Release selection is tracked in [F9.4](../E9-release-readiness/F9.4-batch-scope.md#open-questions); it is separate from implementation readiness.
