# F6.2 — Server-sent events

|  |  |
| -- | -- |
| **State** | New |
| **Parent** | [E6](index.md) |
| **Tags** | deferred |
| **Predecessors** | [F9.8](../E9-release-readiness/F9.8-scaffolded-acceptance.md)'s FastAPI scaffold, for S6.2.4 |
| **Entry criteria** | the owner schedules it for a release |

Three applications hand-rolled server-sent-event framing, each slightly
differently: IntelliBuild's run stream, Apollo's job stream and PhotoTidy's
event broker. `sse-starlette` already does the framing, heartbeat and disconnect
handling correctly. This feature adds a thin `rn-forge-fastapi` wrapper for the
things it does not do, so applications can stop writing their own frame code.

## Context

Apollo's rebuild is a concrete consumer ready to adopt this feature. Its job
stream hand-writes the frame function, sends a comment heartbeat every 30
polling ticks, and drives a `StreamingResponse` loop; `sse_response` replaces
all three. It does not wait: it keeps its own code until this ships and its pins
move.

Recommendation: schedule this feature for a release, ahead of
[F17.6](../E17-local-first-web-app-extraction/F17.6-durable-job-queue.md), whose
job-event stream is built on it. The owner decides; the `deferred` tag stays
until then.

## Design

**One module, `src/rn_forge/fastapi/sse.py`, behind the `sse` extra.** It ships
no frame encoder and no `rn_forge.web.sse` module. It contributes only what
`EventSourceResponse` lacks:

```python
DEFAULT_PING_SECONDS: Final = 15.0
DEFAULT_RETRY_MS: Final = 5_000

def sse_response(
    events: AsyncIterable[ServerSentEvent],
    *,
    ping: float | None = DEFAULT_PING_SECONDS,
    retry: int | None = DEFAULT_RETRY_MS,
    registry: ProblemRegistry | None = None,
    instance: str = "",
    headers: Mapping[str, str] | None = None,
) -> EventSourceResponse: ...
```

1. **Validation instead of silent mangling.** `sse-starlette` strips newlines
   from `id` and `event`: `ServerSentEvent(id="1\nevent: forged")` encodes as
   `id: 1event: forged`. `sse_response` wraps *events* in an internal async
   generator that rejects `\r`, `\n` and `\x00` in `id` or `event` by raising
   `WebError`. The check is in the wrapper, not a factory, so no frame can
   bypass it.
1. **A terminal problem frame.** An exception escaping *events* becomes one
   final `ServerSentEvent(event="error", data=<problem JSON>)` built by
   `registry.build(exc, instance=instance)`, defaulting to
   `default_registry()`. The stream then closes cleanly.
   `ProblemRegistry.build` keeps 5xx internals off the wire and puts the
   current trace id in `traceId`.
1. **A reconnection delay.** Unless *retry* is `None`, the stream opens with one
   `ServerSentEvent(retry=retry)` frame, so a browser `EventSource` waits that
   many milliseconds before re-establishing a dropped connection instead of
   its own default of a few seconds. This is the reconnection control the
   WHATWG server-sent-events standard gives the server; clients rely on it
   rather than closing and reopening the stream, which keeps `Last-Event-ID`.
   A non-integer or negative *retry* raises `ValueError` when `sse_response`
   is called.
1. **Caller headers merge last**, so an application can override a default.

**Resuming is the application's.** A browser reconnecting on its own sends the
last `id` it received as the `Last-Event-ID` request header. The route reads it
like any header and passes it to *events*; `sse_response` neither reads nor
stores it, since only the application knows what an id means.

Media type, `cache-control`, `x-accel-buffering`, the ping, disconnect handling
and graceful shutdown all stay `EventSourceResponse`'s. Tracing needs nothing
here: the OpenTelemetry response propagator already adds `traceresponse`
([F4.2](../E4-standards-rebaseline/index.md)).

**Why an extra.** Importing `sse-starlette` monkey-patches
`uvicorn.Server.handle_exit` (`sse_starlette.sse.AppStatus`) to drain streams on
shutdown, a process-wide side effect. The module docstring says so. As an
extra-gated module it is imported directly, like `rn_forge.web.oidc`
([ADR-0003](../../../adr/ADR-0003.md)).

**No conformance case.** Both framework drivers run every case with no skips,
and `rn-forge-django` has no SSE adapter, so a case would break the Django
suite. The module docstring says so.

**Tests** (`packages/rn-forge-fastapi/tests/test_sse.py`, opening with
`pytest.importorskip("sse_starlette")`): `TestClient` streaming a few frames and
asserting the wire bytes; the first frame carrying `retry: 5000` by default, a
custom *retry*, no `retry` field with `retry=None`, and `ValueError` for a
negative one; an `id` or `event` containing a newline raising `WebError`; the
heartbeat under an idle generator with a small `ping`; the error frame's body
validating as a `ProblemDetail` with the expected status; caller headers
overriding a default.

**Changed from the 2026-09-19 design.** That design also set a correlation
header on the response from `get_correlation_id()` and took a
`correlation_header` parameter. Trace Context
([F4.2](../E4-standards-rebaseline/index.md)) removed both symbols; the
parameter and that behavior are dropped, since Trace Context covers them.

## Stories

### S6.2.1 — Approve the `sse-starlette` dependency

**State:** New (completed 2026-09-26, before the feature was deferred)

**Acceptance:** The owner approves `sse-starlette>=3.4.11` as the only
dependency of a new `rn-forge-fastapi[sse]` extra. Approved 2026-09-26.

### S6.2.2 — Build `rn_forge.fastapi.sse`

**State:** New

**Acceptance:**

- `rn-forge-fastapi` declares the `sse` extra, and its `dev` and `docs` groups
  include `rn-forge-fastapi[sse]`.
- `tests/test_sse.py` covers every case listed under *Design*, and passes with
  the extra installed.
- `rn_forge.fastapi.sse` is not re-exported from `rn_forge.fastapi`.
- `rn_forge.web.conformance.CASES` gains no SSE case.
- `uv run pyright` and `uv run lint-imports` pass.

### S6.2.3 — Document it

**State:** New

**Acceptance:** `docs/reference/sse.md` exists in `rn-forge-fastapi`, the wiring
guide has an SSE section, and the package site builds with `--strict`.
`rn-forge-web`'s docs are unchanged.

### S6.2.4 — Stream from a scaffolded application

**State:** New

**Acceptance:** the FastAPI application that
[F9.8](../E9-release-readiness/F9.8-scaffolded-acceptance.md) scaffolds,
installed with `rn-forge-fastapi[sse]` from built wheels, serves an
`sse_response` endpoint; a client reads its data frames, a heartbeat, and a
terminal problem frame when the generator raises.
