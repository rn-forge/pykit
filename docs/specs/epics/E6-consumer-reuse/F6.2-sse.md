# F6.2 — Server-sent events

This feature would provide a small server-sent-event frame contract through `rn-forge-fastapi`. It is for implementers and the PhotoTidy/Apollo acceptance consumers.

**Status:** planned

**Readiness:** not ready

**Readiness basis:** The public adapter/frame contract and acceptance consumer need to be specified; see Open questions.

**Owner:** pykit.

**Depends on:** Owner approval before adding `sse-starlette`; consuming application acceptance.

**Source:** `web-api-reuse-plan.md`, Phase 3 and finding 3.

[Back to E6](index.md)

## Stories

### S6.2.1 — Add the SSE adapter

**Status:** planned

**Acceptance:** Owner approves the dependency, the extra and frame contract work, and a named consumer removes its local copy.

## Design

Wrap the maintained `sse-starlette` event surface thinly. The proposed `sse` extra is not present in the manifest. The frame contract and adapter must be verified before a consumer deletes its local implementation.

## Acceptance

- The extra installs the required event dependency and exposes the documented frame shape.
- FastAPI streams frames with the expected event, data and reconnect fields.
- PhotoTidy or Apollo removes its duplicate implementation after an integration check.

## Open questions

What public frame/adapter API and extra contract will be exposed, and which named consumer will verify it?

## Considered and rejected

A hand-written encoder and a framework-neutral `web.sse` module were rejected during the Phase 3 evaluation.

Release selection is tracked in [F9.4](../E9-release-readiness/F9.4-batch-scope.md#open-questions); it is separate from implementation readiness.
