# F6.2 — Server-sent events

**Status:** deferred · **Owner:** pykit · **Epic:** [E6](index.md)

**Entry criteria:** the owner schedules it for a release.

**Depends on:** [F9.8](../E9-release-readiness/F9.8-scaffolded-acceptance.md)'s FastAPI scaffold, for S6.2.4.

Three applications hand-rolled server-sent-event framing, each slightly differently: IntelliBuild's run stream, Apollo's job stream and PhotoTidy's event broker. `sse-starlette` already does the framing, heartbeat and disconnect handling correctly. This feature adds a thin `rn-forge-fastapi` wrapper for the three things it does not do, so applications can stop writing their own frame code.

## Design

**One module, `src/rn_forge/fastapi/sse.py`, behind the `sse` extra.** It ships no frame encoder and no `rn_forge.web.sse` module. It contributes only what `EventSourceResponse` lacks:

```python
DEFAULT_PING_SECONDS: Final = 15.0

def sse_response(
    events: AsyncIterable[ServerSentEvent],
    *,
    ping: float | None = DEFAULT_PING_SECONDS,
    registry: ProblemRegistry | None = None,
    instance: str = "",
    headers: Mapping[str, str] | None = None,
) -> EventSourceResponse: ...
```

1. **Validation instead of silent mangling.** `sse-starlette` strips newlines from `id` and `event`: `ServerSentEvent(id="1\nevent: forged")` encodes as `id: 1event: forged`. `sse_response` wraps *events* in an internal async generator that rejects `\r`, `\n` and `\x00` in `id` or `event` by raising `WebError`. The check is in the wrapper, not a factory, so no frame can bypass it.
2. **A terminal problem frame.** An exception escaping *events* becomes one final `ServerSentEvent(event="error", data=<problem JSON>)` built by `registry.build(exc, instance=instance)`, defaulting to `default_registry()`. The stream then closes cleanly. `ProblemRegistry.build` keeps 5xx internals off the wire and puts the current trace id in `traceId`.
3. **Caller headers merge last**, so an application can override a default.

Media type, `cache-control`, `x-accel-buffering`, the ping, disconnect handling and graceful shutdown all stay `EventSourceResponse`'s. Tracing needs nothing here: the OpenTelemetry response propagator already adds `traceresponse` ([F4.2](../E4-standards-rebaseline/index.md)).

**Why an extra.** Importing `sse-starlette` monkey-patches `uvicorn.Server.handle_exit` (`sse_starlette.sse.AppStatus`) to drain streams on shutdown, a process-wide side effect. The module docstring says so. As an extra-gated module it is imported directly, like `rn_forge.web.oidc` ([ADR-0003](../../../adr/ADR-0003.md)).

**No conformance case.** Both framework drivers run every case with no skips, and `rn-forge-django` has no SSE adapter, so a case would break the Django suite. The module docstring says so.

**Tests** (`packages/rn-forge-fastapi/tests/test_sse.py`, opening with `pytest.importorskip("sse_starlette")`): `TestClient` streaming a few frames and asserting the wire bytes; an `id` or `event` containing a newline raising `WebError`; the heartbeat under an idle generator with a small `ping`; the error frame's body validating as a `ProblemDetail` with the expected status; caller headers overriding a default.

**Changed from the 2026-09-19 design.** That design also set a correlation header on the response from `get_correlation_id()` and took a `correlation_header` parameter. Trace Context ([F4.2](../E4-standards-rebaseline/index.md)) removed both symbols; the parameter and that behavior are dropped, since Trace Context covers them.
