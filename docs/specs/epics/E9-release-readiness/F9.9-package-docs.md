# F9.9 — Publish each package's documentation

**Status:** done (2026-09-26) · **Epic:** [E9](index.md)

**Depends on:** [ADR-0009](../../../adr/ADR-0009.md). S9.9.4 must land before the tag cut ([S9.6.1](F9.6-tag-cut.md)), because release-1's package metadata links to the versioned sites it publishes.

**Source:** owner decision, 2026-09-26, recorded in ADR-0009.

Every package already builds a standalone site, but only the root site is deployed, from `main`. A package user who arrives from an index page has no documentation that matches the version they pinned, no changelog, and a README whose relative links break outside GitHub.

## Stories

### S9.9.1 — Record the decision

**Status:** done (2026-09-26)

**Acceptance:** [ADR-0009](../../../adr/ADR-0009.md) is accepted and listed in the decision index.

### S9.9.2 — Package metadata and landing READMEs

**Status:** done (2026-09-26)

**Acceptance:** every package's `[project.urls]` names `Documentation` (its `latest` site), `Source`, `Changelog` and `Issues`. Every link in a package README is absolute, and each README opens with links to the documentation, changelog, source and root site. Every package `mkdocs.yml` sets `site_url` and `repo_url`.

### S9.9.3 — A changelog per package

**Status:** done (2026-09-26)

**Acceptance:** every package has a `CHANGELOG.md` in Keep a Changelog form. Its `docs/changelog.md` includes the file through `pymdownx.snippets` and is in the package nav, and the root and package sites render it under `--strict`.

### S9.9.4 — Deploy versioned package sites

**Status:** done (2026-09-26)

**Acceptance:** on a push to `main` that creates a package tag, CI deploys that package's site to `https://rn-forge.github.io/pykit/packages/<package>/<major>.<minor>/` and points `latest` at it, and the root site stays at `https://rn-forge.github.io/pykit/`. After release-1's tag cut, all seven packages' `latest` pages and the root page load.

## Acceptance

```bash
set -euo pipefail
absent() { local rc=0; rg -q --hidden --glob '!.git' "$@" </dev/null || rc=$?; [ "$rc" -eq 1 ]; }

test -f docs/adr/ADR-0009.md                                            # S9.9.1
grep -q 'ADR-0009.md' docs/adr/index.md                                 # S9.9.1

for pkg in packages/rn-forge-*; do
  for key in Documentation Source Changelog Issues; do                  # S9.9.2
    grep -q "^$key = \"https://" "$pkg/pyproject.toml"
  done
  grep -q '^site_url: https://' "$pkg/mkdocs.yml"                       # S9.9.2
  grep -q '^repo_url: https://' "$pkg/mkdocs.yml"                       # S9.9.2
  test -f "$pkg/CHANGELOG.md"                                           # S9.9.3
  grep -q 'Changelog: changelog.md' "$pkg/mkdocs.yml"                   # S9.9.3
  (cd "$pkg" && uv run --group docs mkdocs build --strict -q --site-dir "$(mktemp -d)")  # S9.9.3
done
absent --pcre2 '\]\((?!https?://|#)' packages/rn-forge-*/README.md     # S9.9.2
uv run --group docs mkdocs build --strict -q --site-dir "$(mktemp -d)" # S9.9.3

for pkg in commons cli tooling web django fastapi sqlalchemy; do        # S9.9.4, after S9.6.1
  curl -fsS -o /dev/null "https://rn-forge.github.io/pykit/packages/rn-forge-$pkg/latest/index.html"
done
curl -fsS -o /dev/null https://rn-forge.github.io/pykit/index.html     # S9.9.4
```

## Design

S9.9.4 changes the `docs` job in `.github/workflows/main.yml`. It adds `mike` to the root `docs` dependency group; the owner approved the new dependency on 2026-09-26.

- **Where the versions live.** `mike` commits each package version to the `gh-pages` branch under `packages/<package>/`. The branch is storage only: Pages keeps deploying from GitHub Actions. The job builds the root site, copies the branch's `packages/` tree into it, and uploads the result as the Pages artifact. The root site mounts packages at `/pykit/<package>/` (the monorepo plugin mounts each one under its `site_name`), so the two layouts never collide.
- **What triggers a deploy.** The package jobs push their tags with `GITHUB_TOKEN`, and a tag pushed that way starts no workflow run, so a tag-triggered workflow would never fire. After the package jobs finish, the `docs` job instead lists the `<package>-v<version>` tags that point at the pushed commit, and deploys each of those packages from the repository root with `uv run --group docs mike deploy --deploy-prefix packages/<package> -F packages/<package>/mkdocs.yml --alias-type copy --update-aliases --push <major>.<minor> latest`. Aliases are copies, not symlinks, so the Pages artifact holds plain files. The first deploy of a package also runs `mike set-default latest`.
- **One writer.** All `mike` pushes happen one after another in that single job, so seven parallel package jobs never race on `gh-pages`.
- **Skipped package jobs.** Once S9.3.3 skips unaffected packages, the `docs` job's condition must still run it when some of the jobs it needs were skipped.
- **Version selector.** Each package `mkdocs.yml` sets `extra.version.provider: mike`, and the mike plugin's `canonical_version: latest`, so a versioned page's canonical URL is its `latest` copy.
- **Old tags.** Tags cut before this feature (`rn-forge-commons` and `rn-forge-django` up to `v0.2.2`) are not backfilled.
- **The README link check.** The job also runs S9.9.2's check that package READMEs hold only absolute links.

The local check is a `mike deploy` to a scratch branch, which produced `versions.json` and the versioned tree. The live pages exist only after a push to `main` creates a tag, so the `curl` lines above run after [S9.6.1](F9.6-tag-cut.md).
