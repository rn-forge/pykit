# F9.5 — Prove external installability

**Status:** planned · **Owner:** pykit · **Epic:** [E9](index.md) · **Release:** [release-1](../../../releases/release-1/index.md)

**Depends on:** [F9.6](F9.6-tag-cut.md): this runs after the tags exist.

A tag is only a release if a consumer outside this repository can install it. CI cannot show that: every job runs `uv sync --all-packages --all-extras --locked`, which resolves internal dependencies from the workspace, not from their pins. This check runs in CI after tagging, as its own job.

## Stories

### S9.5.1 — Verify remote tags and clean installs

**Status:** planned

**Acceptance:** a CI job that runs on a push to `main` after the package jobs checks, for each package tagged in that run, that the tag exists on the remote and that a fresh virtual environment installs the package from its Git direct URL and imports it, with no workspace source override. For release-1, the release page records the tags and the job's result.

```bash
set -euo pipefail
# PACKAGES holds release-1's "<package> <tag>" pairs, one per line.
tmp=$(mktemp -d)
while read -r pkg tag; do
  git ls-remote --exit-code --tags origin "refs/tags/$tag" >/dev/null
  uv venv -q "$tmp/$pkg"
  VIRTUAL_ENV="$tmp/$pkg" uv pip install -q \
    "$pkg @ git+https://github.com/rn-forge/pykit@$tag#subdirectory=packages/$pkg"
  "$tmp/$pkg/bin/python" -c "import rn_forge.${pkg#rn-forge-}"
done <<<"$PACKAGES"
```
