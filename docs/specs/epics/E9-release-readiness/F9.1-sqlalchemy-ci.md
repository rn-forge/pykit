# F9.1 — Add SQLAlchemy CI coverage

**Status:** planned · **Owner:** pykit · **Epic:** [E9](index.md) · **Release:** [release-1](../../../releases/release-1/index.md)

**Depends on:** the reusable `_package-ci.yml` workflow.

`.github/workflows/main.yml` runs a package job for six packages; `rn-forge-sqlalchemy` has none, so its tests, lint and types never run in CI. The new job behaves exactly like the other six, including tagging on a push to `main`, so the publish decision in [F9.3](F9.3-release-mechanism.md) covers it with the rest.

## Stories

### S9.1.1 — Add the package job

**Status:** planned

**Acceptance:** `main.yml` calls `_package-ci.yml` for `rn-forge-sqlalchemy`, the `sonar` and `docs` jobs list it in `needs`, and a pull request shows the job passing.

```bash
set -euo pipefail
grep -q 'package-name: rn-forge-sqlalchemy' .github/workflows/main.yml
grep -q 'package-dir: packages/rn-forge-sqlalchemy' .github/workflows/main.yml
```
