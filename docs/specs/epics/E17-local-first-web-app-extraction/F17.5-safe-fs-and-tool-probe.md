# F17.5 — Safe filesystem mutation

|  |  |
| -- | -- |
| **State** | New |
| **Parent** | [E17](index.md) |
| **Predecessors** | — |
| **Source** | Owner request, 2026-10-21 |

An application that rewrites user files in place needs three small, easy to get
wrong operations: replace a file atomically after editing a copy, move a file
without ever overwriting its destination, and remove the empty directories a
move leaves behind without climbing out of the library. Apollo wrote all three.
This feature adds them to `PathUtils` in `rn-forge-commons`.

## Context

Apollo does not wait for it; it keeps its helpers on today's pins and adopts
these after release and a pin bump. Only the generic parts of its code move: the
step that writes tags through a third-party library is specific to that library
and stays in the application.

## Design

**On `PathUtils`** (`fs/paths.py`), next to `atomic_write`:

```python
@staticmethod
@contextmanager
def atomic_replace(
    path: str | Path, *, copy: bool = True, mode: int | None = None
) -> Iterator[Path]: ...

@staticmethod
def move_no_clobber(source: str | Path, destination: str | Path) -> Path: ...

@staticmethod
def prune_empty_parents(start: str | Path, stop: str | Path) -> None: ...
```

1. **`atomic_replace`** yields a sibling temporary path, named
   `.<name>.<random>.tmp` as `atomic_write` names its own, pre-filled with a
   copy of *path* (`shutil.copy2`) when *copy* is true. On a clean exit it
   `fsync`s the temporary file, applies `atomic_write`'s permission rule (an
   explicit *mode* wins, else the existing file's mode is kept), publishes it
   with `os.replace` and best-effort `fsync`s the parent directory. On any
   `BaseException` it removes the temporary and leaves *path* untouched. The
   caller edits the yielded path with whatever tool it has. `atomic_write` is
   rebuilt on it, so the kit has one durable-publish path; its contract and
   tests do not change.
1. **`move_no_clobber`** creates *destination*'s parent directories, then
   publishes with `os.link(source, destination)` and unlinks *source*. The
   link fails with `FileExistsError` when *destination* exists, atomically, so
   nothing that appears there between a check and the move is overwritten; a
   rename would replace it silently. Across filesystems (`EXDEV`) it copies
   *source* with `shutil.copy2` to a temporary beside *destination*, `fsync`s
   it, links that to *destination* and removes the temporary, then *source*. A
   filesystem without hard links raises the `OSError` it reports. Permission
   errors come from the operations themselves; there is no `os.access`
   pre-check. It returns *destination*.
1. **`prune_empty_parents(start, stop)`** resolves both, then `rmdir`s *start*
   and each ancestor in turn, stopping at the first directory that is not
   empty, and never removing *stop* or anything outside it. It uses `rmdir`,
   never a recursive delete. Prior art: Apollo's filesystem mutation module.

**Tests** (`tests/fs/test_paths.py`): `atomic_replace` publishes edited content,
leaves the original and no temporary on an exception in the body, preserves the
original when the body raises `KeyboardInterrupt`, keeps the original's mode,
and applies an explicit *mode*; the existing `atomic_write` tests pass
unchanged; `move_no_clobber` refuses an existing destination and leaves both
files, refuses a destination created after the call starts (patch `os.link` to
create it first), creates missing parents, raises on a read-only parent, and
moves across devices with `os.link` patched to raise `EXDEV` on the first call;
`prune_empty_parents` removes a chain of empty directories, stops at a non-empty
one, never removes *stop*, and does nothing when *start* is outside *stop*, and
leaves a non-empty directory's files untouched.

## Considered and rejected

- **`exists()` then `Path.replace`, as Apollo does.** The rename overwrites
  anything created between the check and the move.
- **An `O_EXCL` fallback for filesystems without hard links.** It reserves the
  name but leaves a partly written destination visible while the copy runs.
- **Extending `atomic_write` with a callback.** Its contract is content in, file
  out; an edit that needs a file path does not fit it.
- **`Process.tool_version`.** Its version parsing carries Apollo's fallbacks,
  and one application probes tools; it is parked in the
  [ideas list](../../ideas.md#tool-version-probe).
- **A recursive prune.** Removing anything but an empty directory is how a
  library gets deleted; `rmdir` fails safely instead.
