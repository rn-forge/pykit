# S28.1.1 — The home contract, and `install` writes `env.sh`

Brief for
[S28.1.1](../F28.1-home-contract-and-completions.md#s2811-the-home-contract-and-install-writes-envsh),

## Goal

Publish the rn-forge home contract as a guide page, and make every `install`
(and so `upgrade`) write `$RNF_HOME/env.sh` inside its transaction and say how
to source it when `$RNF_HOME/bin` is not on `PATH`.

## Settled

- The contract text, the `env.sh` text, the writing rule, the hint, and the
  `rn_forge.tooling.install.home` additions are the feature's
  [Design](../F28.1-home-contract-and-completions.md#design) and
  [ADR-0017](../../../../adr/ADR-0017.md). Read both.
- Reviewer, 2026-11-20, filling the gaps the Design leaves:
    - `EnvWrite` is a `StrEnum` in `home.py` with members `WRITTEN = "written"`,
      `CURRENT = "current"`, `FOREIGN = "foreign"`.

    - `ENV_SCHEMA = 1`. `ENV_TEMPLATE` is the `env.sh` text with the literal
      placeholder `<home>` (not `str.format` braces: the text contains
      `${PATH}`). `render_env(root: Path) -> str` returns it with every `<home>`
      replaced by `str(Path(root).expanduser().absolute())` — not `resolve()`,
      which would rewrite `/tmp` to `/private/tmp` on macOS.

    - The schema line is the file's first line, when it matches
      `^# rn-forge home environment, schema (\d+)\.`. `write_env(root)` writes
      when the file is missing or its schema is lower than `ENV_SCHEMA` (→
      `WRITTEN`); leaves a same-or-higher schema alone (→ `CURRENT`); leaves a
      file whose first line does not match alone (→ `FOREIGN`). It writes with
      `PathUtils.atomic_write`, creating `root` if needed.

    - `env_hint(root: Path) -> str | None` in `home.py`: `None` when
      `os.path.abspath(entry) == os.path.abspath(root / "bin")` for some entry
      of `os.environ["PATH"].split(os.pathsep)`; otherwise exactly these three
      lines (no trailing newline), `<home>` as in `render_env`:

        ```text
        <home>/bin is not on PATH. To use it in this shell, run:
          source "<home>/env.sh"
        and add that line to your shell's rc file, before compinit.
        ```

    - `ToolHome.env_path` is `root / "env.sh"`; `ToolHome.completions_dir` is
      `root / "completions"`. Add `EnvWrite`, `ENV_SCHEMA`, `ENV_TEMPLATE`,
      `render_env`, `write_env` and `env_hint` to `home.py`'s `__all__`, and
      `EnvWrite`, `write_env` and `env_hint` to
      `rn_forge.tooling.install.__all__`.

    - In `lifecycle._activate`, right after the `for link in product.artifacts()`
      loop and before `undo.append(("restore state.json", ...))`:
      `undo.append(("restore env.sh", _restore_file(home.env_path)))`, then
      `env = write_env(home.root)`. `_activate` and `_install` return that
      `EnvWrite`.

    - `InstallResult` gains two trailing fields, both defaulting to `None`:
      `env: str | None` (the `EnvWrite` value; `None` when nothing was
      installed, i.e. `already-current`, `removed`, `not-installed`) and
      `hint: str | None` (`env_hint(home.root)`). `install` sets `hint` on both
      the `installed` and the `already-current` result; `uninstall` never sets
      either. Document both fields in the class docstring's `Args:`.

    - CLI (`cli/lifecycle.py`): `install` and `upgrade` both render through one
      new helper. In JSON mode it emits the record as today (the new fields are
      in it). Otherwise it prints, in order: the success line as today; when
      `env == "foreign"`,
      `console.warning("{} has no rn-forge schema line; left it alone", ToolHome(product.name).env_path)`;
      when `hint` is set, `console.info("{}", hint)` — so the hint is the last
      stdout output. `already-current` does not touch `env.sh`.
- Out of this story: `doctor` rows (S28.1.2), completions and the `PythonTool`
  link (S28.1.3), the version bump to 0.4.0 (S28.1.3).

  `RNF_HOME_ENV`, `ToolHome`, `rnf_home`. There is no `env.sh` support; any
  test importing `write_env`, `EnvWrite`, `ENV_TEMPLATE`, `render_env` or
  `env_hint` fails with `ImportError` at collection.

  leaves no `env.sh`.
