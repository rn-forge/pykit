# S28.1.3 — `PythonTool` links a zsh completion script

Brief for
[S28.1.3](../F28.1-home-contract-and-completions.md#s2813-pythontool-links-a-zsh-completion-script),
at `620aee09`. Paths are relative to `packages/rn-forge-tooling/` unless they
start with `docs/`.

## Goal

A Python tool installed by `PythonTool` completes on `<TAB>` in a zsh that has
sourced only `$RNF_HOME/env.sh`. Its build asks the built command for Typer's
zsh completion script, and its default `artifacts()` links that script into
`$RNF_HOME/completions/`. This prepares `rn-forge-tooling` 0.4.0.

## Settled

- The feature's
  [Design](../F28.1-home-contract-and-completions.md#rn-forge-tooling)
  `PythonTool` section and [ADR-0017](../../../../adr/ADR-0017.md). Read both.

- Reviewer, 2026-11-20, from running Typer 0.27.2's script in `zsh -f`:

    - Typer's `source_zsh` output **starts with a blank line**. zsh's `compinit`
      reads only a file's first line for `#compdef`, so the unmodified file is
      never registered. The build strips leading blank lines (`lstrip("\n")`)
      before checking and writing.
    - Autoloaded as is, the script's body only defines
      `_<name_underscored>_completion` and runs `compdef <fn> <name>`, so the
      first `<TAB>` in each shell completes nothing. **Owner, 2026-11-20:** the
      build appends one line, `<fn> "$@"`, where `<fn>` is taken from the
      script's own line matching `^compdef (\S+) <name>$` (with `re.MULTILINE`,
      `<name>` escaped). That line missing is an `AppException`, like a bad
      first line. This is a post-process of the command's output, not a template;
      the Design's choice to ask the command stands.

- Exact build behaviour, after `uv tool install` (`python.py:56-58`):

    1. `var = f"_{self.name.upper().replace('-', '_')}_COMPLETE"`.
    1. `Process.execute("completion script", str(version_dir / "bin" / self.name), env={**os.environ, var: "source_zsh"})`
       — `Process.execute` already raises `AppException` on a non-zero exit.
    1. `script = result.stdout.lstrip("\n")`. When
       `script.splitlines()[0] != f"#compdef {self.name}"` (or the script is
       empty):
       `AppException("{} did not print a zsh completion script for {}; it must be a Typer or Click command", self.name, var)`.
    1. Find `<fn>` as above, else the same kind of `AppException` naming the
       missing `compdef` line.
    1. Write `script.rstrip("\n") + f'\n{fn} "$@"\n'` to
       `version_dir / "completions" / f"_{self.name}"` with
       `PathUtils.atomic_write`, creating the directory.

    - Put steps 1–5 in a private helper (e.g. `_write_completion`), called at the
      end of `build`. Update `build`'s docstring: it now also leaves
      `<version_dir>/completions/_<name>`, and raises when the command does not
      answer the completion variable.

- `artifacts()` returns
  `(Link(f"bin/{self.name}", f"bin/{self.name}"), Link(f"completions/_{self.name}", f"completions/_{self.name}"))`;
  its docstring names both. The class docstring says the console script must
  be a Typer (or Click) command, because the build asks it for completion.

- A failed completion step is a failed `build`, so the install transaction's
  existing undo (`lifecycle.py`, the `remove versions/<target>` step) removes
  the version directory. No lifecycle change is needed.

- **Test tool.** The uv tests build a minimal **Typer** app (a `CliApp` is a
  Typer app, and its completion is Typer's; building `rn-forge-cli` inside a
  throwaway uv tool environment would need workspace paths). Its
  `pyproject.toml` declares `dependencies = ["typer==0.27.2"]` (the version in
  `uv.lock`), so the uv build resolves it from the uv cache or PyPI, as the
  existing uv tests already need for `setuptools`. The module:

    ```python
    import typer

    app = typer.Typer()


    @app.command()
    def hello() -> None:
        print("pytool ok")


    @app.command()
    def bye() -> None:
        print("bye")


    def main() -> None:
        app()
    ```

    Keep the current non-Typer module (`MODULE`, whose `main` prints `pytool ok`
    and ignores the variable) for the "ignores the variable" test. The existing
    uv tests switch to the Typer tool; a command check becomes
    `bin/pytool hello` → `pytool ok\n`.

- **zsh test.** Verified by the reviewer: in `zsh -f` driven by `zpty`, with the
  appended line, the first `<TAB>` after `pytool ` beeps (ambiguous) and the
  second lists `bye    hello`. Without `PATH` holding the command, the stub
  cannot call it. A driver that works, run as
  `subprocess.run(["zsh", "-f", str(driver)], env={"HOME": str(tmp), "PATH": "/usr/bin:/bin"}, capture_output=True, text=True, timeout=60)`:

    ```zsh
    zmodload zsh/zpty
    zpty t 'zsh -f -i'
    zpty -w t 'PS1="> "; source "<home>/env.sh"; autoload -Uz compinit; compinit -u -d "<tmp>/zcompdump"; echo RE""ADY'
    zpty -r -m t out '*READY*'
    sleep 1; while zpty -r -t t chunk; do :; done
    buf=""
    for keys in $'pytool \t' $'\t'; do
      zpty -w -n t "$keys"
      sleep 2
      while zpty -r -t t chunk; do buf+=$chunk; done
    done
    print -r -- "$buf"
    zpty -d t
    ```

    (`RE""ADY` keeps the echoed input from matching `*READY*`; the drain after it
    lets the inner shell's prompt finish before keys arrive, without which the
    TABs race ZLE startup and the listing is lost; `<home>` and `<tmp>` are
    filled in by the test.) Assert `hello` and `bye` are in stdout. `env.sh`
    puts `<home>/bin` on `PATH`, so the stub finds the command.

- **Release.** `pyproject.toml` `version = "0.4.0"`. `CHANGELOG.md`: the

  `<version_dir>/completions/_pytool` fails with
  `FileNotFoundError`/`AssertionError` (absent).
- The hyphen test (monkeypatching `python_module.Process.execute`) fails because
  only the `uv tool install` call is made: no call carries
  `_MY_TOOL_COMPLETE`.

  raises nothing (`pytest.raises` fails with `DID NOT RAISE`).
- After the change, the existing uv tests in `tests/install/test_python.py`

  its `main` ignores the variable; that is why they move to the Typer tool.
  `:117` `test_uninstall_leaves_no_file_under_the_home` keeps expecting only
  `env.sh` left over: uninstall removes both links.
- `docs/guides/lifecycle.md:100-118` ("Python tools") does not mention

## Tests first

In `tests/install/test_python.py`. Mark every test that runs `uv` with the
existing `needs_uv`, and the zsh test also with a `skipif` on
`shutil.which("zsh") is None`.

1. `test_artifacts_link_the_command_and_its_completion` (replaces
   `test_artifacts_link_the_named_command`): the two links. Fails:
   `AssertionError`.
1. `test_build_writes_a_completion_script` (uv): build the Typer tool;
   `<version_dir>/completions/_pytool`'s first line is `#compdef pytool` and
   its last line is `_pytool_completion "$@"`. Fails: file absent.
1. `test_the_completion_variable_follows_clicks_naming` (no uv): a
   `PythonTool(name="my-tool", ...)`; monkeypatch
   `python_module.Process.execute` with a recorder that returns an object
   whose `stdout` is
   `"\n#compdef my-tool\n\n_my_tool_completion() { :; }\n\ncompdef _my_tool_completion my-tool\n"`;
   call `build`; assert the second call's `env` has
   `_MY_TOOL_COMPLETE == "source_zsh"`, and the written script starts with
   `#compdef my-tool` and ends with `_my_tool_completion "$@"\n`. Fails: no
   such call.
1. `test_a_script_without_compdef_fails_the_build` (no uv): same recorder,
   `stdout` without the `compdef ...` line → `AppException`.
1. `test_a_command_that_ignores_the_variable_rolls_back` (uv): install the
   non-Typer tool; `AppException`; `home.installed_versions() == []`, nothing
   under `home.versions_dir`, no `bin/pytool` or `completions/_pytool` link.
   Fails: `DID NOT RAISE`.
1. `test_install_links_the_completion_through_current` (uv): after install,
   `home.root / "completions/_pytool"` is a symlink whose resolved path is
   under `home.current.resolve()`; uninstall removes it and `bin/pytool`.
1. `test_zsh_completes_the_installed_tool` (uv, zsh): install; run the Settled
   driver; stdout contains `hello` and `bye`. Fails before the change: no
   completion file, so no listing.
