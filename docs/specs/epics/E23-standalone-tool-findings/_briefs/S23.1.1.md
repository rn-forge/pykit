# S23.1.1 — Square brackets in a docstring show in `--help`

Brief for
[S23.1.1](../F23.1-help-text.md#s2311-square-brackets-in-a-docstring-show-in-help),
at `79d0db5`.

## Goal

A declared command's help shows `[kiln]` and `[project]` literally, while a real
Rich style tag such as `[bold]…[/bold]` still styles its text.

## Settled

- Settled by the reviewer, 2026-11-17: the fix is in
  `packages/rn-forge-cli/src/rn_forge/cli/app.py`. Markup mode stays Typer's
  default (`rich`).
- A private module function, `_escape_markup(text: str) -> str`, escapes each
  `[...]` group (regex `\[([^\[\]]*)\]`) that is not Rich markup, by prefixing
  its `[` with a backslash (Rich's escape). A group is kept as markup when its
  content starts with `/` (a closing tag) or `rich.style.Style.parse(content)`
  succeeds. `Style.parse` raises `rich.errors.StyleSyntaxError` for `kiln` and
  `project` and accepts `bold`, `red` and `link https://…`. An empty `[]`, or
  a group that is already escaped (`\[`), is left alone.
- `CliApp.add_declared` passes `help=_escape_markup(text)` for both a command
  and a namespace, where `text` is `command.help` when set. Otherwise it is
  `inspect.getdoc(target)` for a callable, and for a `typer.Typer` it is
  `target.info.help` when that is a string. When there is no text, it passes
  `None` as today.
- `CliApp.from_surface` escapes `surface.help` the same way. The `CliApp(...)`
  constructor and hand-registered `@app.command()` commands are unchanged.
- No new dependency: `rich` already comes with Typer.
- Changelog: `packages/rn-forge-cli/CHANGELOG.md`, `[Unreleased]`, `### Fixed`:
  square brackets that are not Rich markup, such as `[kiln]`, show in a
  declared command's `--help` instead of being dropped.

## Current behaviour

At `79d0db5`, a command whose docstring is "Set the current repository's
`` `[kiln] ref` ``, and [bold]bold[/bold] [project] name." renders in both its
own `--help` and the parent's command list as "Set the current repository's
`` ` ref` ``, and bold name." (with `bold` styled). Typer's rich mode reads
`[kiln]` and `[project]` as unknown style tags and drops them. The new bracket
assertions fail with the substring missing. The `[bold]` assertion already
passes today and must keep passing.

## Change

1. `app.py`: `_escape_markup`, and its use in `add_declared` and `from_surface`.
1. The changelog entry.
