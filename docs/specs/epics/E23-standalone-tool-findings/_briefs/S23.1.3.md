# S23.1.3 — A command starts with no logger notice, and a timestamp shows its milliseconds once

Brief for
[S23.1.3](../F23.1-help-text.md#s2313-a-command-starts-with-no-logger-notice-and-a-timestamp-shows-its-milliseconds-once),
at `79d0db5`.

## Goal

Configuring `AppLogger` at the default level writes nothing to stdout or stderr,
and a plain-format record's timestamp is `YYYY-MM-DD HH:MM:SS,mmm` with one
millisecond field.

## Settled

- Settled by the reviewer, 2026-11-17: in
  `packages/rn-forge-commons/src/rn_forge/commons/logging/logger.py`,
  `AppLogger.initialize` logs "App Logger Configured -> {} | {}" with
  `logger.debug(...)` instead of `logger.notice(...)`. The message text is
  unchanged.
- `_DEFAULT_FORMAT` and `_OTEL_FORMAT` drop `,%(msecs)03d`. The default
  `logging.Formatter` `asctime` already ends in `,<msecs>`, which is the one
  millisecond field. `datefmt` is not set. The Rich formats are unchanged:
  Rich renders its own time column.
- The release part of the acceptance (the commons and cli versions kiln's caps
  accept) is the reviewer's, at the Release 9 cut. Do not change any version.
- Changelog: `packages/rn-forge-commons/CHANGELOG.md`, `[Unreleased]`,
  `### Fixed`: configuring the logger no longer logs a `NOTICE` (it is `DEBUG`
  now), and a plain-format timestamp shows its milliseconds once.

## Current behaviour

At `79d0db5`, `task docs:generate` in this repository prints
`2026-11-17 16:17:38,549,549 MainThread[17632] kiln.notice NOTICE [svc=kiln env=unknown] App Logger Configured -> INFO | None`
before its output. It is the same line the feature reports: the notice is logged
at `NOTICE` (25), above `INFO`, and the timestamp repeats `,549`.

- A test that initializes at `INFO` with a non-TTY console handler and checks
  that captured stderr/stdout has no "App Logger Configured" fails today: the
  line is present.
- A test that formats a record with the configured console handler's formatter
  and matches `^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2},\d{3} ` (with nothing like
  `,\d{3},\d{3}`) fails today, because the timestamp ends in `,mmm,mmm`.

Read how `initialize` chooses the plain or the Rich handler (TTY detection,
`LoggingConfig`) and force the plain one in the tests. Check the two failures
above before you change the code; if either does not fail as described, stop and
report.
