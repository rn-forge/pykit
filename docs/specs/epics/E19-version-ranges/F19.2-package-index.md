`rn-forge-devops index` writes a PEP 503 simple index of every published
`rn-forge-*` release file, and the docs job publishes it at
`https://rn-forge.github.io/pykit/simple/` after every release. A guide tells
consumers how to declare it.

## Design

**Core, `packages/rn-forge-devops/src/rn_forge/devops/index.py`** (new). It
imports no adapter: add `rn_forge.devops.index` to the
`devops-core-has-no-adapter` contract's `source_modules`, beside
`rn_forge.devops.ci`, and `rn_forge.devops.releases` to its `forbidden_modules`.

Neither new module goes in `ci.py` or `github.py`. Those are the planner, which
moves to kiln as `kiln-devops` (kiln F6.7) and leaves `rn-forge-devops` at the
cutover
([S16.3.4](../E16-kiln-adoption/F16.3-cutover.md#s1634-the-planner-leaves-and-e19s-files-are-declared)).
The index and the range check stay in pykit, so neither imports a planner module
(`ci`, `uv`, `github`). A test in `test_cli.py` imports `rn_forge.devops.index`
and `rn_forge.devops.releases` in a subprocess and asserts none of the three is
loaded.

```python
@dataclass(frozen=True, slots=True)
class ReleaseFile:
    project: str      # normalized distribution name, e.g. "rn-forge-commons"
    filename: str     # e.g. "rn_forge_commons-0.7.0-py3-none-any.whl"
    url: str          # the release asset's download URL
    sha256: str       # hex digest


def render_index(files: Sequence[ReleaseFile]) -> dict[str, str]:
    """The index's pages, keyed by relative path."""
```

`render_index` returns:

- `"index.html"`: one `<a href="<project>/">project</a>` per project, sorted.
- `"<project>/index.html"`: one `<a href="<url>#sha256=<hex>">filename</a>` per
  file, sorted by filename.

Each page is an HTML5 document carrying
`<meta name="pypi:repository-version" content="1.0">` (PEP 629). All text goes
through `html.escape`. Project names are normalized per PEP 503
(`re.sub(r"[-_.]+", "-", name).lower()`).

**Adapter, `rn_forge.devops.releases`** (new):
`release_files(repo: str) -> list[ReleaseFile]`. It reads
`gh api repos/<repo>/releases --paginate`, keeping each non-draft,
non-prerelease release whose tag matches
`^(rn-forge-[a-z0-9-]+)-v\d+\.\d+\.\d+$`. It takes each asset ending `.whl` or
`.tar.gz`, with its `browser_download_url`, and its `digest` when that is
`sha256:<hex>`. Otherwise it downloads the asset and hashes it.

**CLI**: a subcommand `rn-forge-devops index --repo <owner/name> --out <dir>`
writes `render_index(release_files(repo))` under `<dir>` and prints the number
of projects and files.

**Composite action, `.github/actions/package-index/action.yml`** (new,
pykit-owned). It has no inputs, because a kiln hook passes none. It reads the
site directory from `SITE_DIR`, and has one step:

```yaml
    - name: Write the package index
      shell: bash
      env:
        GH_TOKEN: ${{ github.token }}
      run: uv run rn-forge-devops index --repo "$GITHUB_REPOSITORY" --out "$SITE_DIR/simple"
```

**Workflow** (`.github/workflows/main.yml`, `docs` job): after *Add versioned
package sites* and before `configure-pages`, add a step
`uses: ./.github/actions/package-index` with `env: SITE_DIR: .out/site`. The
`docs` job already runs after `release` on every push to `main`, so a new tag is
indexed in the same run that publishes it.

At the cutover, kiln's generated `docs` job runs the same action through a
`[ci.hooks] docs` entry, the extension-by-reference pattern of kiln F4.11, so
the action survives unchanged. That anchor is kiln's work (kiln S4.11.7): it
runs after `task ci:docs-publish` and before the Pages upload, with `SITE_DIR`
in the step's `env`.

**Docs**:

- The root `README.md`'s *Installing a package* section shows the
  `[[tool.uv.index]]` entry and one range requirement, and keeps the
  direct-URL form as the alternative.
- A new root guide, `docs/guides/consuming-packages.md`, covers:
    - the index entry;
    - why `first-index` keeps `rn-forge-*` names off PyPI;
    - the pip caveat;
    - how to pin one exact version (`==0.7.0`) when a consumer wants that;
    - how to fall back to a direct URL.
- `rn-forge-devops`' README lists `index`.

**Changelog** (devops, `[Unreleased]`, *Added*): the `index` command.

**Tests** (`packages/rn-forge-devops/tests/`):

- `test_index.py`:
    - two projects give a root page with both links in order, and one page each;
    - the `#sha256=` fragment is on every link;
    - names are normalized (`rn_forge_commons` → `rn-forge-commons/`);
    - HTML-special characters in a filename are escaped;
    - the PEP 629 meta tag is present.
- `test_releases.py`:
    - `release_files` with a stubbed `gh` response keeps a published release's
      wheel and sdist and drops a draft, a prerelease, a non-package tag and a
      `.txt` asset;
    - it uses the asset's digest when present and hashes the download when not
      (stub the download).
- `test_cli.py`: `index --out` writes the pages from a stubbed `release_files`.
