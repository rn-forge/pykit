| **Source** | Owner request, 2026-10-24 |

Every requirement from one `rn-forge-*` package on another becomes a name and a
range, and CI rejects one that is not. The release that ships this re-tags
every dependent, and it is the last release that has to.

## Design

**Requirements.** In each `packages/*/pyproject.toml`, rewrite every
`rn-forge-<x>[extras] @ git+https://github.com/rn-forge/pykit@rn-forge-<x>-v<ver>#subdirectory=packages/rn-forge-<x>`
in `dependencies`, `optional-dependencies` and dependency groups as
`rn-forge-<x>[extras]>=<ver>,<<next breaking>>`:

- `<ver>` is the dependency's version in the workspace at the cut.
- `<next breaking>` is `0.<minor+1>` before 1.0, and `<major+1>` from 1.0.

Example: `rn-forge-commons[pydantic]>=0.7.0,<0.8`. Delete each manifest's
comment explaining pinned direct URLs, and replace it with one line naming
ADR-0004. `[tool.uv.sources]` is unchanged.

**The cut's versions.** Release 6 also carries
[E18](../E18-kiln-extraction/index.md), so one cut releases E18's code and moves
every dependent to ranges on it:

| Package | Version | Floors it sets |
| -- | -- | -- |
| `rn-forge-commons` | 0.6.0 → 0.7.0 | — |
| `rn-forge-cli` | 0.1.0 → 0.1.1 | commons ≥ 0.7.0 |
| `rn-forge-tooling` | 0.2.0 → 0.3.0 | commons ≥ 0.7.0, cli ≥ 0.1.1 |
| `rn-forge-web` | 0.2.0 → 0.2.1 | commons ≥ 0.7.0 |
| `rn-forge-data` | 0.1.0 → 0.1.1 | commons ≥ 0.7.0 |
| `rn-forge-sqlalchemy` | 0.2.0 → 0.2.1 | web ≥ 0.2.1 |
| `rn-forge-django` | 0.5.0 → 0.5.1 | commons ≥ 0.7.0, web ≥ 0.2.1, data ≥ 0.1.1 |
| `rn-forge-fastapi` | 0.3.1 → 0.3.2 | web ≥ 0.2.1, data ≥ 0.1.1 |

`rn-forge-devops` requires no rn-forge package; it takes the minor bump F19.2's
`index` command needs.

**The check (`rn-forge-devops requirements`).** Add core
`rn_forge.devops.requirements.check_requirements(root: Path) -> list[str]`, in
a module of its own, for the reason F19.2 gives. It reads the root
`[tool.uv.workspace]` members and each member's `pyproject.toml` with
`tomllib`, and imports nothing from `ci`, `uv` or `github`: the planner's
`Workspace` keeps requirement names, not specifiers, and leaves at the cutover; the CLI prints
each problem and exits 1 when there is one. For every requirement on another
workspace member, it reports:

- a URL (`req.url is not None`): `"<package>: <dep> is a URL; use a range (ADR-0004)"`;
- a specifier that does not contain the member's current workspace version:
  `"<package>: <dep><spec> excludes the workspace's <version>"`;
- a specifier with no upper bound (no `<` or `<=` clause):
  `"<package>: <dep><spec> has no ceiling"`.

It parses requirements with `packaging.requirements.Requirement`, already a
dependency of `rn-forge-devops`. Add `rn_forge.devops.requirements` to the
`devops-core-has-no-adapter` contract's `source_modules`.

**The CI job.** A pykit-owned reusable workflow,
`.github/workflows/internal-ranges.yml`, `on: workflow_call` only, with one job:
`permissions: {contents: read}`, a `timeout-minutes`, a checkout with
`persist-credentials: false`, `./.github/actions/setup`, then
`uv run rn-forge-devops requirements`. `main.yml` calls it as a job
`internal-ranges` (`uses: ./.github/workflows/internal-ranges.yml`,
`permissions: {contents: read}`), and `ci-ok` needs it. At the cutover the
same file becomes a `[[ci.jobs]]` entry, kiln F4.11's extension by reference,
and its step calls a pykit-owned task instead of `uv`
([S16.3.4](../E16-kiln-adoption/F16.3-cutover.md#s1634-the-planner-leaves-and-e19s-files-are-declared)).

**The runbook** (`docs/runbooks/releasing-packages.md`, *Before the merge*):

- Replace *Restore tag pins* with: *Run `rn-forge-devops requirements`. A
  package's ceiling must admit each dependency version this release tags. A
  breaking release of a dependency needs each dependent to widen its ceiling,
  after its tests pass on the new version, and to be released with it.*
- The step that confirms each package's version states the bump rule
  (ADR-0004): before 1.0, minor for a breaking change and patch otherwise.
- In *How CI tags*, drop the consequence that a dependent's pin to a missing tag
  is the risk; a range has no such pin.

**External install** is unchanged: it installs each new tag by direct URL,
and kiln generates it after the cutover. The by-name install from the live
index is a step in the runbook's *After the merge*, run once the `docs` job has
deployed, and this feature's after-cut acceptance.

**Docs**:

- The root `README.md`'s *Installing a package* and design principle 4 say
  packages depend on each other by range.
- `docs/architecture/workspace.md` replaces any sentence about pinned internal
  tags.
- `docs/guides/choosing-packages.md` drops any pin-bump advice that ranges make
  unnecessary.

**Changelogs**: each package, *Changed*: requires its rn-forge dependencies by
version range from pykit's index (ADR-0004), not by git URL.

**Tests** (`packages/rn-forge-devops/tests/test_ci.py`):

- `check_requirements` on a fixture workspace reports a URL, a range that
  excludes the workspace version, and a range without a ceiling, and passes a
  correct range;
- extras (`rn-forge-commons[pydantic]>=0.7.0,<0.8`) parse and pass;
- a requirement on a package outside the workspace is ignored;
- the module imports no planner module (`ci`, `uv`, `github`), checked as F19.2's
  boundary test does.

## Stories

### S19.3.1 — `rn-forge-devops requirements`

**State:** Closed

**Acceptance:**

  `internal-ranges.yml`, and `ci-ok` needs it.

### S19.3.2 — Every internal requirement becomes a range

**State:** Active · **Depends on:** S19.3.1

**Acceptance:**

- No `packages/*/pyproject.toml` names a pykit git URL.
- `rn-forge-devops requirements` passes.
- The runbook, README, architecture and changelog lines hold.
- After the cut, every dependent installs by name from the index.

## Acceptance

```bash
set -euo pipefail
absent() { local rc=0; rg -q --hidden --glob '!.git' "$@" </dev/null || rc=$?; [ "$rc" -eq 1 ]; }
(cd packages/rn-forge-devops && uv run pytest -q tests/test_ci.py)        # S19.3.1
absent 'git\+https://github.com/rn-forge/pykit@' --glob 'packages/*/pyproject.toml'   # S19.3.2
uv run rn-forge-devops requirements                                      # S19.3.1 S19.3.2
uv lock --check && uv run lint-imports && uv run pyright                 # S19.3.2
uv run --group docs mkdocs build --strict                                # S19.3.2
# After the cut (S19.3.2): a consumer locks the newest compatible set by name.
tmp=$(mktemp -d); cd "$tmp"
uv init -q --no-workspace demo && cd demo
printf '\n[[tool.uv.index]]\nname = "rn-forge"\nurl = "https://rn-forge.github.io/pykit/simple/"\n' >> pyproject.toml
uv add -q rn-forge-tooling rn-forge-django rn-forge-fastapi rn-forge-sqlalchemy 'rn-forge-data[pandas]'
uv run python -c 'import rn_forge.tooling, rn_forge.django, rn_forge.fastapi, rn_forge.sqlalchemy, rn_forge.data.pandas, rn_forge.commons.generation'
```

## Considered and rejected

- **Floors only (`>=0.7.0`), no ceiling.** A breaking release of a dependency
  would install under a dependent never tested against it.
- **`~=0.7.0`.** Before 1.0 it means `>=0.7.0,<0.8`, which is right. But it
  changes meaning at 1.0 (`~=1.0.0` is `<1.1`), so the explicit pair stays
  correct across the 1.0 boundary.
- **Ranges only within a release batch, URLs to anything outside it.** It
  keeps the cascade for every package that was not released in the batch,
  which is most of them.
