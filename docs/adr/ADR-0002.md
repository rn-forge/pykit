# ADR-0002: Packages release independently through pinned git tags

This decision defines package identity and dependency pins for maintainers preparing a release. A release batch coordinates independent packages; it does not create one pykit distribution.

**Status:** accepted

**Recorded:** 2026-09-24

**Scope:** All `rn-forge-*` packages

## Decision

Each package has its own version and a tag named for that package and version. Consumers declare package dependencies as pinned Git direct URLs with the package subdirectory. The workspace source override serves local development. The declared direct URL is the contract for an installation outside this checkout.

A coordinated batch records the selected packages and tag evidence in the [release index](../releases/index.md). Package scope for the first coordinated batch remains an owner decision in [F9.4](../specs/epics/E9-release-readiness/F9.4-batch-scope.md). The tag cut remains an owner action in [F9.6](../specs/epics/E9-release-readiness/F9.6-tag-cut.md).

## Consequences

Versions can advance independently. A release needs actual tag and external-installability evidence. The [release runbook](../runbooks/releasing-packages.md) describes current automation and dependency ordering. A documentation edit or a local build does not establish a release.

## Influences

This decision shapes [E9 release readiness](../specs/epics/E9-release-readiness/index.md) and the [release index](../releases/index.md). [ADR-0001](ADR-0001.md) supplies the package graph used to plan an order.

## Alternatives considered

One version for the whole workspace would couple packages that have separate dependency and release needs. Bare PyPI names cannot resolve this Git-tag distribution model.

## Background

The pinned-tag contract appears in the root `README.md`, `commons-upgrade-plan.md` D.7–D.8 (kiln D46), and package manifests. The intended order in historical plans is not a claim that CI enforces it. The current workflow can create missing package tags on a push to `main`; [F9.3](../specs/epics/E9-release-readiness/F9.3-release-mechanism.md) tracks its documentation and any enforcement decision. The first-batch scope (Q5) and kiln's SQLAlchemy tag-order correction (Q10) remain open.
