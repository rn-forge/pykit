# ADR-0008: pykit is accepted by its own specs and tests

**Status:** accepted (2026-09-26) · **Scope:** all pykit specs, releases and acceptance criteria

## Decision

pykit is a product in its own right. Its specs, acceptance criteria and release gates are things pykit can check inside this repository. Downstream products and applications are sources of requirements: they explain why a feature exists, but no pykit feature or release waits on work in another repository.

When acceptance needs a host application, a pykit test scaffolds one in a temporary directory, installs the packages under test into it, and exercises the behavior there.

## Consequences

Every acceptance line can be verified by running pykit's own tests or CI. pykit's docs do not track another repository's plans, corrections or IDs. A scaffolded application proves pykit's contract; whether a particular application integrates correctly is that application's own test concern.

## Influences

This decision shapes [E9 release readiness](../specs/epics/E9-release-readiness/index.md), in particular [F9.8](../specs/epics/E9-release-readiness/F9.8-scaffolded-acceptance.md), and the acceptance section of every feature.

## Alternatives considered

Accepting features in a downstream golden repository or application makes a pykit release depend on someone running another repository and reporting back, and makes pykit's docs restate another product's plans.

## Background

Decided by the owner on 2026-09-26. Before then, acceptance for several features was assigned to kiln's golden repositories and to named applications; the [migration ledger](../plans/context.md) records where each went.
