# ADR-0018: Typed settings wrap pydantic-settings behind a commons extra

**Status:** accepted (2026-11-22) · **Scope:** typed settings in
`rn-forge-commons`, and every application on pykit that loads settings from
environment variables

## Decision

Typed settings from environment variables wrap `pydantic-settings`, behind a new
`settings` extra of `rn-forge-commons`. pykit does not write its own loader.

The API is `rn_forge.commons.lang.settings`, next to `lang.models` and, like it,
outside the `rn_forge.commons` facade ([ADR-0003](ADR-0003.md)):

- `EnvSettings`, a `pydantic_settings.BaseSettings` subclass that an application
  subclasses. It is frozen, sets an `env_prefix` such as `APP_`, and reads no
  `.env` file or secrets directory unless the subclass asks for one.
- `EnvSettings.load(environ: Mapping[str, str] | None = None)`, a classmethod
  that reads the given mapping, or `os.environ` when it is `None`, and never
  changes `os.environ`.
- `SettingsError`, an `AppException` that `load` raises in place of pydantic's
  `ValidationError`. Its message names every invalid or missing variable by
  its environment name, such as `APP_ENABLED`, and its `variables` attribute
  holds those names.

The owner approved the new dependency on 2026-11-22. It brings in
`python-dotenv`.

## Consequences

- An application installs `rn-forge-commons[settings]`. A web application
  already has pydantic through `rn-forge-web`, so the extra adds
  `pydantic-settings` and `python-dotenv`.
- A boolean field takes the tokens `AppUtils.parse_bool` takes, not pydantic's
  own set. That is one validator over pydantic's parsing.
- A command-line tool without pydantic pays for pydantic when it loads settings.
  That cost is accepted.
- Nested models, secrets directories and `.env` files come from
  `pydantic-settings` when a subclass turns them on. pykit adds nothing for
  them.

## Influences

- [F32.3](../specs/epics/E32-database-app-foundations/F32.3-typed-env-settings.md)
  implements this decision, and S32.3.1 recorded it.
- [ADR-0001](ADR-0001.md) rule 1: a maintained library comes first.

## Alternatives considered

- **A stdlib loader for frozen dataclasses in core `rn-forge-commons`.** It
  needs no dependency. It was ruled out because it parses each field type by
  hand, and every new type makes it bigger, which ADR-0001 rule 1 forbids when
  a maintained library does the job.
