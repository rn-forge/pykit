# ADR-0006: pykit verifies tokens but does not issue them

**Status:** accepted (2026-09-13) · **Scope:** authentication across all `rn-forge-*` packages

## Decision

pykit is not an authorization server. OAuth2 authorization code and PKCE flows, and token issuance in general, belong to the identity provider. The kit verifies tokens an identity provider issued, maps them to a `Principal`, and applies the shared 401/403 contract.

## Consequences

Every stack accepts the same externally issued tokens through the same verification path. An application that needs to issue tokens uses an identity provider or its own code, not pykit. Which login and session flows a framework package offers is a scope question for that package, tracked in [E8](../specs/epics/E8-django-scope-and-auth/index.md) and described in [authentication across packages](../architecture/authentication.md); the auth review ([F8.2](../specs/epics/E8-django-scope-and-auth/F8.2-auth-review.md)) may change those flows but not whether pykit becomes an issuer.

## Influences

This decision shapes [E8 Django scope and auth](../specs/epics/E8-django-scope-and-auth/index.md) and [authentication across packages](../architecture/authentication.md).

## Alternatives considered

Building authorization-code and PKCE flows into the kit would make every consumer carry token-issuance security it does not need, and would duplicate what identity providers already do.
