# ADR-0004: Packages release independently through pinned git tags

**Status:** accepted (2026-09-10) · **Scope:** all `rn-forge-*` packages and every consumer of them

## Decision

Each package has its own version and a tag named for that package and version. Consumers declare package dependencies as pinned Git direct URLs with the package subdirectory. The workspace source override serves local development. The declared direct URL is the contract for an installation outside this checkout.

**Until release-1's tag cut, internal pins name the `feature/upgrade` branch instead of a tag.** This suspends the tag rule; it does not reverse it. A consumer's lockfile records the resolved commit, so its build stays reproducible. The interim ends at the first coordinated release, [release-1](../releases/release-1/index.md), whose tag cut restores tag pins before the tags are created.

A coordinated batch records the selected packages and tag evidence on its release page.

## Consequences

Versions can advance independently. A release needs actual tag and external-installability evidence; a documentation edit or a local build does not establish one. During the interim, integration fixes land without a release, and a consumer outside the workspace can resolve every internal dependency. The cost is that `feature/upgrade` must stay installable: a push that breaks it breaks every consumer's next lock. The [release runbook](../runbooks/releasing-packages.md) describes the tagging automation and how a failed package job is handled.

## Influences

This decision shapes [E9 release readiness](../specs/epics/E9-release-readiness/index.md), in particular [F9.7](../specs/epics/E9-release-readiness/F9.7-interim-branch-pins.md), and the [release pages](../releases/index.md). The [workspace boundaries](../architecture/workspace.md) supply the package graph used to plan an order.

## Alternatives considered

One version for the whole workspace would couple packages that have separate dependency and release needs. Bare PyPI names cannot resolve this Git-tag distribution model. Cutting early `rn-forge-commons` and `rn-forge-web` tags would make outside consumers resolvable sooner, but it releases packages before the batch scope is decided.

## Background

Decided by 2026-09-10; recorded here 2026-09-24. The interim rule was added 2026-09-25, when the owner chose branch pins over early tags because consumers outside the workspace could not resolve the uncut tags; the pins landed 2026-09-26. The pinned-tag contract appears in the root `README.md` and the package manifests.
