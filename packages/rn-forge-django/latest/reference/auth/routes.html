    Auth routes¶

    The /auth HTTP surface, its sessions, CSRF protection, rate limits and audit events. See the Auth guide.

    Routes¶

    rn_forge.django.auth.routes ¶

    The shared HTTP auth surface (/auth/...) as Django views and a URLconf.

    Mount it with :func:auth_urlpatterns::

    urlpatterns = [*auth_urlpatterns(config), ...]

    The project supplies django.contrib.sessions and its middleware. The identity providers, account resolver and authorization context provider are :mod:rn_forge.auth objects the project builds and passes in :class:AuthRoutesConfig.

    TRANSACTION_COOKIE = '__Host-login-tx' module-attribute ¶

    The cookie that binds a callback to the browser that began the login.

    Sessions¶

    rn_forge.django.auth.sessions ¶

    The login session, kept in django.contrib.sessions.

    Every read of the session goes through :meth:Sessions.read, which enforces the absolute timeout and the revocation checks. Idle expiry is Django's own session expiry: a normal read pushes it forward and a read that passes touch=False leaves it alone. SESSION_SAVE_EVERY_REQUEST must be false (see :data:SESSION_SETTINGS).

    SESSION_SETTINGS = {'SESSION_ENGINE': 'django.contrib.sessions.backends.cached_db', 'SESSION_COOKIE_NAME': SESSION_COOKIE, 'SESSION_COOKIE_SECURE': True, 'SESSION_COOKIE_HTTPONLY': True, 'SESSION_COOKIE_SAMESITE': 'Lax', 'SESSION_COOKIE_PATH': '/', 'SESSION_COOKIE_DOMAIN': None, 'SESSION_SAVE_EVERY_REQUEST': False} module-attribute ¶

    Django settings for the session and its cookie.

    Spread into your settings module: globals().update(SESSION_SETTINGS). The __Host- cookie requires Secure, Path=/ and no Domain. SESSION_SAVE_EVERY_REQUEST must stay false: reading the session then does not extend it.

    start(request, info) ¶

    Store info under a new session ID, so a pre-login ID is never reused.

    check_session_settings(*, cache_aliases) ¶

    Refuse session settings that cannot work or are unsafe.

    SESSION_SAVE_EVERY_REQUEST must be false in every mode. Outside DEBUG, the cookie settings must equal :data:SESSION_SETTINGS, the session engine must be db or cached_db (a signed-cookie engine cannot revoke sessions), and neither the session cache nor cache_aliases may be Django's local-memory cache.

    Raises:

    Type Description
    ImproperlyConfigured

    A setting is refused.

    rotate_session(request) ¶

    Give the request's session a new ID and keep its content.

    Call it after a change of the account's privileges, so a session ID that was seen before the change is useless afterwards.

    CSRF¶

    rn_forge.django.auth.csrf ¶

    CSRF protection for the session-authenticated routes.

    Django's CsrfViewMiddleware checks the token and, for an Origin or (over HTTPS) Referer header, that the origin is the request's own or in CSRF_TRUSTED_ORIGINS. The request's scheme and host come from forwarded headers only when SECURE_PROXY_SSL_HEADER and USE_X_FORWARDED_HOST say so. :class:AuthCsrfMiddleware also rejects Sec-Fetch-Site: cross-site and skips requests that carry a Bearer Authorization header.

    CSRF_SETTINGS = {'CSRF_COOKIE_NAME': 'XSRF-TOKEN', 'CSRF_HEADER_NAME': 'HTTP_X_XSRF_TOKEN', 'CSRF_COOKIE_HTTPONLY': False, 'CSRF_COOKIE_SECURE': True, 'CSRF_COOKIE_SAMESITE': 'Lax', 'CSRF_COOKIE_PATH': '/', 'CSRF_COOKIE_DOMAIN': None, 'CSRF_USE_SESSIONS': False, 'CSRF_FAILURE_VIEW': CSRF_FAILURE_VIEW} module-attribute ¶

    Django settings for the CSRF cookie and header.

    Spread into your settings module with globals().update(CSRF_SETTINGS), and add :data:CSRF_MIDDLEWARE to MIDDLEWARE. The names are Angular's HttpClient defaults, and the cookie is readable by script, which Angular needs to copy it into the header.

    check_csrf_settings() ¶

    Refuse CSRF settings that leave the auth routes unprotected.

    Always: :data:CSRF_MIDDLEWARE is installed, and the cookie and header names, HttpOnly, CSRF_USE_SESSIONS and the failure view match :data:CSRF_SETTINGS. Outside DEBUG, the other cookie settings must match too. RN_FORGE_DJANGO["AUTH"]["PROBLEM_TYPE_BASE"] must be set in every mode; csrf-failed and forbidden then differ in type.

    Raises:

    Type Description
    ImproperlyConfigured

    A requirement is not met.

    csrf_failure_view(request, reason='') ¶

    Answer a CSRF rejection with the 403 csrf-failed problem.

    The reason is logged and never sent.

    enforce_csrf(request) ¶

    Run the check :class:AuthCsrfMiddleware runs, for a view it cannot guard.

    DRF wraps its views in csrf_exempt, so a session authentication class calls this for the requests it authenticates. A safe method, and a request with a Bearer Authorization header, pass.

    Stores¶

    rn_forge.django.auth.stores ¶

    Login transactions, replay records and revoked session IDs in Django's cache.

    The records are shared between processes only when the cache is, as Django's Redis backend (the redis extra) is. The local-memory cache is for tests and single-process development.

    Rate limits¶

    rn_forge.django.auth.rate_limit ¶

    Fixed-window rate limiting over Django's cache.

    FixedWindowLimiter(*, alias='default', prefix='rn-forge:rate:', clock=time.time) ¶

    Counts hits per key in fixed windows.

    The counter is cache.add followed by cache.incr, so the processes that share the cache share the count. Windows are aligned to the clock, so a client can use a limit twice around a window boundary.
