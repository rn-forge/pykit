    Session authentication¶

    rn_forge.django.auth.drf.session ¶

    Session authentication for DRF: the login session as a :class:~rn_forge.auth.Principal.

    PrincipalSessionAuthentication ¶

    Bases: BaseAuthentication

    Authenticate the login session into a mechanism="session" principal.

    Subclass and set sessions, typically to sessions_for(config) of the :class:~rn_forge.django.auth.routes.AuthRoutesConfig given to auth_urlpatterns. request.auth is the session's :class:~rn_forge.auth.SessionInfo. The read extends the idle timeout.

    A request with an Authorization header is never authenticated here: list a bearer class first and the header alone decides, so an invalid token is a 401 even with a valid session cookie.

    An unsafe method also passes the CSRF check of :func:~rn_forge.django.auth.csrf.enforce_csrf; a failure is the 403 csrf-failed problem.

    As the first authentication class of a view, an unauthenticated request is a 401 problem with no WWW-Authenticate header, provided the view uses :func:~rn_forge.django.drf.exceptions.problem_details_exception_handler. A bearer class first keeps the Bearer challenge.

    sessions_for(config) ¶

    A :class:Sessions with the same collaborators and timeouts as the routes of config.

    Authorization¶

    rn_forge.django.auth.drf.authorization ¶

    DRF permission and resource-policy hooks over :mod:rn_forge.auth.

    PermissionKeyPermission ¶

    Bases: BasePermission

    Require the permission key a view's action maps to.

    The view declares permission_key and, optionally, permission_action_map. The requirement is :func:rn_forge.auth.requirement_for of the key and the view's action (the HTTP method, lowercased, outside a viewset), checked against the request's :class:~rn_forge.auth.Principal. A view without a permission_key requires only an authenticated principal. A request without a principal is denied.

    ResourcePolicyViewMixin ¶

    Bases: GenericAPIView

    Apply a :class:~rn_forge.auth.ResourcePolicy to a generic view.

    :meth:get_queryset is narrowed by resource_policy.scope, so list results, their counts and their pages contain only permitted rows, and a detail lookup of any other row is a 404. :meth:get_object then asks resource_policy.allows and raises 403 when it is denied, or 404 when policy_hides_existence is true.

    Attributes:

    Name Type Description
    resource_policy ResourcePolicy[Any, QuerySet[Any]]

    The policy. Required.
    policy_hides_existence bool

    Report a denied object as 404 instead of 403.
